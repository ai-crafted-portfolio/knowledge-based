    Fibre Channel性能¶

    fcstatのポート識別と速度

    分類: Fibre Channel性能 ・ 難易度: 中級

    FCポート実体は、VIOSのFibre Channel性能で統計対象をSAN側ポートへ結び付ける識別情報である。fcstatのWWPN、Port Speed、Port FC ID、Port Typeを記録し、エラー値を正しいファブリック接続へ対応させる。

    出典: IBM Power Systems: Virtual I / O Server and Integrated Virtualization Manager commands p8hcg / https: / public.dhe.ibm.com / systems / power / docs / hw / p8 / p8hcg / IBM Power Systems Virtual I / O Server Commands: fcstat command / www.ibm.com / en / power10 / 9105-42A?topic=commands-fcstat-command

    確認問題（1問）

    問題. ポート識別と速度（fcstat）について、fcs0の統計をSANスイッチ側記録と突き合わせる際に必要なfcstat項目はどれか。

    • A. Framesの合計だけを物理ポート識別子としてSANへ渡す。
    • B. Option ROM VersionをクライアントLPARのWWPNとして扱う。
    • C. Seconds Since Last ResetをPort FC IDへ変換する。
    • D. World Wide Port NameとPort FC IDと実行中Port Speedを記録する。 ✅ 正解

    正解: D ／ 難易度: 中級

    解説: ポート実体（FC）でDを正答とする理由は、WWPNとFC IDはファブリック上のポートを対応させ、running speedは現在のリンク速度を示すことです。 ポート識別と速度（fcstat）の仕組みとして、同一VIOSに複数fcsアダプターがあると、装置名だけではSAN側の接続先と一致しない場合がある。物理位置とWWPNを組にして統計を渡すと対象の取り違えを防げる。 ポート識別と速度（fcstat）の誤答は、AはFramesは通信量で恒久識別子ではない、BはOption ROMはアダプターファームウェア情報でクライアントWWPNではない、Cはリセット後経過秒数とFC IDに変換関係はない。 ポート識別と速度（fcstat）で使うWWPNとはWorld Wide Port Nameの略で、Fibre Channelポートをファブリック内で識別する64ビット値。

    fcstatのリンク障害カウンター

    分類: Fibre Channel性能 ・ 難易度: 中級

    FCリンク品質は、VIOSのFibre Channel性能で物理ポートとSAN接続の異常を示す統計である。fcstatのLink Failure、Loss of Sync、Loss of Signal、Invalid CRCなどを増分で追い、I/O量と分けて評価する。

    出典: IBM Power Systems: Virtual I / O Server and Integrated Virtualization Manager commands p8hcg / https: / public.dhe.ibm.com / systems / power / docs / hw / p8 / p8hcg / IBM Power Systems Virtual I / O Server Commands: fcstat command / www.ibm.com / en / power10 / 9105-42A?topic=commands-fcstat-command

    確認問題（1問）

    問題. リンク障害カウンター（fcstat）について、リンク品質（FC）について、FCポートの物理リンク不安定を疑うとき、fcstatで優先して比較するカウンター群はどれか。

    • A. Input Bytesだけを読みCRCと同期損失を同じ値として扱う。FCリンク品質の判定にも同じ前提を広げ、Loss of Syncの表示値を確認せずに結論を確定する。
    • B. Link FailureとLoss of SyncとLoss of SignalとInvalid CRCを前回値と比較する。 ✅ 正解
    • C. World Wide Port Nameの桁数からLink Failureを推定する。
    • D. Control Requestsが0なら物理リンクは必ず正常とする。

    正解: B ／ 難易度: 中級

    解説: リンク品質（FC）でBを正答とする理由は、リンク障害、同期喪失、信号喪失、CRC不正は物理・伝送品質の異常を直接表すカウンターであることです。 リンク障害カウンター（fcstat）の仕組みとして、fcstatはトラフィック量とエラー統計を同時に示す。累積値の単発採取だけでは発生時期が分からないため、時刻付き差分とSAN側ポート統計を対応させる。 リンク障害カウンター（fcstat）の誤答は、AはI/O量と伝送エラーは別の統計欄である、CはWWPNは識別子で障害回数を含まない、DはControl Requestsの有無だけでは信号品質を判定できない。 リンク障害カウンター（fcstat）で使うLoss of SyncとはFibre Channel受信側が信号の同期を維持できなかった回数を示すリンク統計。

    NPIV¶

    NPIVログイン状態とポート数

    分類: NPIV ・ 難易度: 中級

    SANログイン状態は、VIOSのNPIV構成で仮想FCアダプターがターゲットへ到達しているかを示す。lsmap -npivのStatusとPorts logged inを読み、未接続とポート不足を物理バインディングから分けて扱う。

    出典: IBM Power Systems: Virtual I / O Server and Integrated Virtualization Manager commands p8hcg / https: / public.dhe.ibm.com / systems / power / docs / hw / p8 / p8hcg / IBM Power Systems Virtual I / O Server Commands: lsmap command / www.ibm.com / en / power10?topic=commands-lsmap-command

    確認問題（1問）

    問題. ログイン状態とポート数（NPIV）について、lsmap -npivでStatusがNOT_LOGGED_INと表示されたときの解釈として適切なものはどれか。

    • A. vfchostの存在だけで到達済みとせずSANログインと接続状態を追加調査する。 ✅ 正解
    • B. NOT_LOGGED_INはvSCSIのLUNがAvailableであることを示す。
    • C. Ports logged inが0なら物理FCアダプターは必ず故障している。
    • D. ClntOSがAIXならStatus表示を無視して正常と判定する。

    正解: A ／ 難易度: 中級

    解説: ログイン状態（SAN）でAを正答とする理由は、NOT_LOGGED_INはVFC側のログイン未成立を示すため、ゾーニング、クライアント状態、物理ポート対応を確認する必要があることです。 ログイン状態とポート数（NPIV）の仕組みとして、ログイン状態（SAN）について、NPIVでは仮想アダプター定義、VIOS物理ポート割当、SANファブリックのログインが段階的に成立する。定義が存在してもクライアント停止中などでログインしない場合がある。 ログイン状態とポート数（NPIV）の誤答は、BはvSCSIのStatusとは別のNPIV状態欄である、Cは0は接続未成立を示すが原因を物理故障一つに限定できない、DはクライアントOS種別はログイン成功の代替証拠にならない。 ログイン状態とポート数（NPIV）で使うNOT_LOGGED_INとは仮想FCアダプターからSANターゲットへのポートログインが成立していない状態表示。

    分類: NPIV ・ 難易度: 中級

    VFC物理ポート対応は、VIOSのNPIV構成でvfchostを物理Fibre Channelアダプターへ結び付ける情報である。lsmap -npivはクライアント名、状態、FC name、FC loc code、ログインポート数を表示する。

    出典: IBM Power Systems: Virtual I / O Server and Integrated Virtualization Manager commands p8hcg / https: / public.dhe.ibm.com / systems / power / docs / hw / p8 / p8hcg / IBM Power Systems Virtual I / O Server Commands: lsmap command / www.ibm.com / en / power10?topic=commands-lsmap-command

    確認問題（1問）

    問題. バインディング（lsmap / npiv / VFC）について、vfchost0がどの物理FCアダプターへ結び付くかを確認するlsmap -npivの項目はどれか。

    • A. VTDのBacking deviceを物理FCポート名として読む。
    • B. vfchost0のグループ内にあるFC nameとFC loc codeを確認する。 ✅ 正解
    • C. ClntIDをWorld Wide Port Nameへ変換して採用する。
    • D. Ports logged inの数値をfcsアダプター番号とみなす。VFC物理ポート対応の判定にも同じ前提を広げ、VFCの表示値を確認せずに結論を確定する。

    解説: 物理ポート対応（VFC）でBを正答とする理由は、NPIV表示のFC nameはfcs0などの物理アダプター名を、FC loc codeはそのハードウェア位置を示すことです。 バインディング（lsmap / npiv / VFC）の仕組みとして、vfchostはクライアントVFCアダプターのVIOS側終端であり、物理FCポートへのバインディングを介してSANへ到達する。状態とポート対応は別欄なので両方を保存する。 バインディング（lsmap / npiv / VFC）の誤答は、AはVTDとbacking deviceはvSCSI表示の概念である、CはClntIDはLPAR識別子でWWPNではない、Dはログイン数はアダプター論理名を符号化しない。 バインディング（lsmap / npiv / VFC）で使うVFCとはVirtual Fibre Channelの略で、NPIVによりクライアントへ仮想FC接続を提供する方式。

    問題. 割当余力（lsnports / NPIV）について、fcs0とfcs1のNPIV割当余力を判断する際、lsnportsで比較すべき値の組合せはどれか。

    • A. aportsで利用可能ポート数を見てawwpnsで利用可能WWPN数も確認する。 ✅ 正解
