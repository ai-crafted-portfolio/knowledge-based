目的
ドメインネームシステム・セキュリティ拡張(DNSSEC)キーのキータイミングのメタデータを設定する。

説明
dnssec-settime
コマンドはDNSSEC秘密鍵ファイルを読み込み、「
-P
、「
-A
、 「
-R
、「
-I
、「
-D
オプションで指定された鍵タイミングの メタデータを設定する。
dnssec-signzone
コマンドや他の署名ソフトウェアが使用するメタデータは、鍵がいつ 公開されなければならないか、ゾーンの署名に使用されなければならないか、 その他の詳細を決定する。
これらのオプションが設定されていない場合、'
dnssec-settime
コマンドは、すでにキーに格納されているキー・ タイミングのメタデータを表示する。 鍵メタデータ・フィールドが変更されると、鍵ペアの両方のファイル (
Knnnn.+aaa+iiiii.key
と
Knnnn.+aaa+iiiii.private
) が再生成されます。
メタデータ・フィールドは、プライベート・ファイルに保管されます。 キー・ファイルには、人間が理解できるメタデータの記述もコメントとして配置されます。 プライベート・ファイルのパーミッションは、常に所有者以外がアクセスできないように設定されている（モード0600）。
ステート・ファイルを扱う場合、'
-s
フラグを使用することで、それらのファイルのタイミング・メタデータを更新することができる。 このオプションを使用すると、
-d
(DS)、
-k
(DNSKEY)、
-r
(KSK の RRSIG)、または
-z
(ZSK の RRSIG) フラグを使用して、鍵の状態を更新することもできます。 許可される状態は、
HIDDEN
、
RUMOURED
、
OMNIPRESENT
、および
UNRETENTIVE
です。
鍵の目標状態は、
-g
フラグを使用して設定することもできます。 この値は'
HIDDEN
または'
OMNIPRESENT
どちらかでなければならず、 そのキーがゾーンから削除されなければならないのか、それとも公開されなければ ならないのかを表す。
注：
テスト目的以外では、ステートファイルを手動で操作することはできません。

構文
dnssec-settime [ -f ] [ -K ディレクトリー ] [ -L ttl ] [ -P date/offset ] [ -P ds date/offset ] [ -P sync date/offset ] [ -A date/offset ] [ -R date/offset ] [ -I date/offset ] [ -D date/offset ] [ -D ds date/offset ] [ -D sync date/offset ] [ -S key ] [ -i interval ] [ -h ] [ -V ] [ -v level ] [ -E エンジン ] { keyfile } [ -s ] [ -g state ] [ -d state date/offset ] [ -k state date/offset ] [ -r state date/offset ] [ -z state date/offset ]

オプション
フラグ
表 1. フラグ
項目 | 説明
-f | メタデータ・フィールドのない古い形式のキーを強制的に更新します。 このオプションがないと、' dnssec-settime コマンドはレガシー・キーを更新しようとして失敗する。 このオプションでは、鍵は新しい形式で再作成されるが、元の鍵データは保持される。 キーの作成日は現在に設定される。 他の値が指定されていない場合、鍵の発行日と有効化日も現在時刻に設定される。
-K ディレクトリー | 鍵ファイルが存在する必要があるディレクトリーを設定します。
-L トル | この鍵がDNSKEY RRに変換される際に使用されるデフォルトのTTL(time-to-live)を設定する。 この TTL は、DNSKEY RRset が存在しない限り、鍵がゾーンにインポートされるときに使用されます。DNSKEY RRset が存在する場合は、既存の TTL が優先されます。 この値が設定されておらず、DNSKEY RRset が使用可能でない場合、TTL はデフォルトで SOA TTL になります。 デフォルトの TTL を 0 または none に設定すると、TTL は鍵から削除されます。
-h | 使用法メッセージを表示して終了します。
-V | バージョン情報を印刷します。
-v レベル | デバッグのレベルを設定します。
-E エンジン | 使用する必要がある暗号ハードウェアを指定します (該当する場合)。 BIND 9 がOpenSSL,とともにビルドされる場合、このフラグには暗号アクセラレータまたはハードウェア・サービス・モジュールを駆動するOpenSSLエンジン識別子を設定しなければなりません（通常はpkcs11）。
