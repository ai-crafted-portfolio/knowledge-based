目的

DNS サーバーを動的に更新します。

構文

nsupdate [-d] [-D] [-i] [-L レベル] [ [-g] | [-o] | [-l] | [-y [hmac:]キーネーム:シークレット] | [-k キーファイル] ] [-t タイムアウト] [-u udptimeout] [-r 未分類] [-v] [-T] [-P] [-V] [ [-4] | [-6] ] [ファイル名]

説明

nsupdate コマンドは、 RFC 2136で定義されている動的 DNS 更新要求をネーム・サーバーに送信します。 このコマンドを使用すると、ゾーンファイルを手動で編集することなく、 リソースレコードをゾーンに追加したり削除したりすることができる。 1 つの更新要求に、複数のリソース・レコードの追加または除去の要求を含めることができます。

nsupdate コマンドまたは DHCP サーバーを使用して動的に制御されるゾーンは、手動で編集してはなりません。 手動による編集は、動的更新と衝突し、データ損失を引き起こす可能性があります。

nsupdate コマンドを使用して動的に追加または削除されるリソース・レコードは、同じゾーン内になければなりません。 リクエストはゾーンのプライマリサーバに送られ、そのプライマリサーバは ゾーンの権威開始(SOA)レコードの'MNAMEフィールドで識別される。

トランザクション署名 (TSIG) を使用して、動的 DNS 更新を認証できます。 トランザクション署名は、 RFC 2845に記述されている TSIG リソース・レコード・タイプ、 RFC 2535 および RFC 2931に記述されている SIG (0) レコード、または RFC 3645に記述されている GSS-TSIG を使用します。

TSIG は、 nsupdate コマンドおよびネーム・サーバーにのみ認識される必要がある共有秘密鍵に依存します。 例えば、適切な鍵およびサーバー・ステートメントが /etc/named.conf ファイルに追加されます。これにより、ネーム・サーバーは、適切な秘密鍵およびアルゴリズムを、TSIG 認証を使用するクライアント・アプリケーションの IP アドレスに関連付けることができます。 ddns-confgen コマンドは、適切な構成フラグメントを生成できます。 nsupdate コマンドは、 -y オプションまたは -k オプションを使用して、TSIG 共有秘密鍵を指定します。 これらのオプションはどちらか一方を使用します (両方を指定することはできません)。

SIG (0) 鍵は公開鍵暗号方式を使用します。 SIG (0) 鍵を使用するには、ネーム・サーバーによって提供されるゾーン内の KEY レコードに公開鍵を保管する必要があります。 Generic Security Service Algorithm - Transaction Signature (GSS-TSIG)は、Kerberosクレデンシャルを使用する。 標準GSS-TSIGモードは、「-gフラグを使用することで有効になる。

フラグ

-4
IPv4 のみを使用する必要があることを示します。
-6
IPv6 のみを使用する必要があることを示します。
-d
ネームサーバーから受信した更新リクエストと返信に関するトレース情報を提供するデバッグモードを設定します。
-D
追加のデバッグ・モードを設定します。
-g
標準のGSS-TSIGモードを有効にする。
-i
標準入力が端末でない場合でも、対話モードを強制します。
-k keyfile
TSIG 認証鍵を含むファイルを示します。 キーファイルの形式は以下の通り：
  • ddns-confgen コマンドによって自動的に生成される named.conf-format キー・ステートメントを含む単一のファイル。
  • K{name}.+157.+{random}.keyと'K{name}.+157.+{random}.private書式を持つファイルの組で、'dnssec-keygenコマンドを使って生成することができる。

-kフラグを使用して、ダイナミックDNS更新要求の認証に使用する SIG(0)キーを指定することもできる。 この場合、指定された鍵はHMAC-MD5鍵ではない。

-l
ローカルホストのみのモードを設定し、サーバーアドレスを「localhost」に設定する（サーバーアドレスを上書きできないようにサーバーを無効にする）。 ローカル・サーバーへの接続では、 /var/run/named/session.key ファイルにある TSIG 鍵が使用されます。この鍵は、いずれかのローカル 1 次ゾーンで update-policy オプションが localに設定されている場合に、 named デーモンによって自動的に生成されます。 この鍵ファイルの場所は、 -k オプションを使用してオーバーライドできます。
-L レベル
デバッグ・ロギング・レベルを設定します。 値がゼロの場合、ロギング操作は無効になります。
-o
Windows 2000で使用されているGSS-TSIGの非標準準拠版を有効にする。
-p port
ネーム・サーバーへの接続に使用する必要があるポートを設定します。 デフォルト値は 53 です。
-P
nsupdate コマンドによってフォーマットが識別される、BIND 固有の専用リソース・レコード・タイプのリストを印刷します。 また、 -T オプションも参照してください。
-r 未分類
User Datagram Protocol （ UDP ）の再試行回数を設定します。 デフォルト値は 3 です。 値がゼロの場合、1 つの更新要求のみが処理されます。
-t timeout
更新要求が打ち切られるまでの最大時間を設定します。 デフォルト値は 300 秒です。 値が 0 の場合、 Transmission Control Protocol （ TCP ）モードではタイムアウト処理が無効になります。 UDP モードでは、オプション -u が0に設定されていない限り、オプション -u が -t オプションよりも優先されます。 この -u オプションが 0 に設定されている場合、間隔は、この -t オプションで指定されたタイムアウト値と、 UDP の再試行回数に基づいて計算されます。 UDP モードでは、タイムアウトを無効にすることはできず、および -u オプション -t の両方が0に設定されている場合、タイムアウトは1秒に切り上げられます。
-T
nsupdate コマンドによってフォーマットが識別される Internet Assigned Numbers Authority (IANA) 標準リソース・レコード・タイプのリストを印刷します。 nsupdate コマンドは、リストの印刷後に終了します。 -T オプションを -P オプションと組み合わせることができます。

その他のタイプは、「TYPEXXXXX使用して入力することができる。ここで、XXXXXは、先頭のゼロを除いたタイプの10進数値である。 rdata値が存在する場合、UNKNOWN'rdataフォーマットを使用して解析される。 UNKNOWN 'rdataフォーマットは '<backslash> <hash> <space> <length> <space> <hexstring> 。

-u udptimeout
UDP 再試行間隔を設定します。 デフォルト値は 3 秒です。 値がゼロの場合、間隔はタイムアウト間隔と UDP の再試行回数に基づいて計算されます。
-v
小さな更新リクエストであっても、 TCP を使用する必要があることを指定します。 デフォルトでは、この nsupdate コマンドは UDP を使用してネームサーバーに更新リクエストを送信します。ただし、 UDP リクエストが使用できない場合は、 TCP が使用されます。 TCP 更新リクエストがまとめて受信された場合、この方法が望ましい。
-V
バージョン番号を表示して終了します。
--y[hmac:]キーネーム:シークレット
リテラル TSIG 認証鍵を設定します。 keynameは鍵の名前、secretは Base64エンコードされた共有秘密である。 hmac引数は鍵アルゴリズムの名前である。 以下のアルゴリズムが有効な鍵アルゴリズムである：
  • hmac-md5
  • hmac-sha1
  • hmac-sha224
  • hmac-sha256
  • hmac-sha384
  • hmac-sha512
hmacオプションが指定されていない場合、デフォルト値は'hmac-md5、MD5が無効の場合、デフォルト値は'hmac-sha256となる。
注: 共有秘密鍵は平文のコマンド・ライン引数として指定されるため、 -y フラグは慎重に使用してください。 共有秘密は、「ps1プロンプトの出力や、ユーザーのシェルが管理する 履歴ファイルで見ることができるかもしれない。

入力フォーマット

nsupdate コマンドは、指定された filename または標準入力から入力を読み取ります。 各コマンドは、正確に 1 行の入力で指定されます。 いくつかのコマンドは管理目的に使用される。 その他のコマンドは、更新指示か、ゾーンの内容に関する前提条件チェックを実行する ために使用される。 これらの検査は、特定の名前またはリソース・レコードのセット (RRset) がゾーンに存在するかまたは存在しないかの条件を設定します。 更新要求全体を完了するには、これらの条件を満たす必要があります。 前提条件のテストが失敗すると、更新は拒否されます。

どの更新要求も、ゼロ以上の前提条件と、ゼロ以上の更新からなります。 この機能により、ゾーン内に指定されたリソースレコードが存在するか 存在しないかのどちらかである場合に、適切に認証された更新リクエストを 実行することができる。 ブランクの入力行 (または send コマンド) は、累積したコマンドを 1 つの動的 DNS 更新要求としてネーム・サーバーに送信します。

入力ファイルには以下のコマンドが含まれている：

server サーバー名 ポート
このコマンドは、すべての動的更新要求をネーム・サーバー servernameに送信します。 サーバー・ステートメントが指定されていない場合、 nsupdate コマンドは、正しいゾーンの 1 次サーバーに更新を送信します。 そのゾーンのSOAレコードの'MNAMEフィールドは、そのゾーンのプライマリサーバを識別する。 ポートは、動的更新リクエストを送信するサーバー名のポート番号です。 ポート番号が指定されていない場合は、デフォルトの DNS ポート番号 53 が使用されます。
local アドレス・ポート
このコマンドは、ローカル・アドレスを使用してすべての動的更新要求を送信します。 ローカルステートメントが指定されていない場合、「nsupdateコマンドは、システムによって選択されたアドレスとポートを使用して更新を送信する。 ポートを使って、特定のポートからのリクエストを強制することもできる。 ポート番号が指定されていない場合、システムはポートを割り当てます。
zone ゾーン名
このコマンドは、すべての更新をゾーン zonenameに対して行う必要があることを指定します。 ゾーン・ステートメントが指定されていない場合、 nsupdate コマンドは、入力に基づいて更新する正しいゾーンを判別しようとします。
class クラス名
このコマンドは、デフォルト・クラスを指定します。 クラスが指定されていない場合、デフォルトのクラスは「IN（インターネット）である。
ttl 秒
このコマンドは、追加されるレコードのデフォルトのTTL（秒）を指定する。 値 none は、デフォルトの TTL をクリアします。
key hmac:keyname シークレット
このコマンドは、すべての更新が keyname-secret ペアを使用して TSIG 署名されている必要があることを指定します。 hmac を指定すると、署名アルゴリズムが設定されます。 デフォルト値はhmac-md5です。 MD5が無効の場合、デフォルト値は「hmac-sha256である。 key コマンドは、 -y フラグまたは -k フラグを使用して、コマンド・ラインで指定されたすべてのキーをオーバーライドします。
gsstsig
このコマンドは、GSS-TSIG を使用して更新に署名します。 このコマンドは、コマンド・ラインで -g フラグを指定するのと同等です。
oldgsstsig
このコマンドは、Windows 2000 バージョンの GSS-TSIG を使用して更新に署名します。 このコマンドは、コマンド・ラインで -o フラグを指定するのと同等です。
realm[レルム名］
GSS-TSIG を使用する場合、このコマンドは、 krb5.conf ファイル内のデフォルト・レルムの代わりに realm_name パラメーターを指定します。 レルムが指定されていない場合、保存されたレルムはクリアされます。
check-names [はい|いいえ]
このコマンドは、追加されるレコードのチェック名処理をオンまたはオフにします。 チェック名は、削除したい前提条件またはレコードには影響しません。 デフォルトでは、check-names 処理はオンになっています。 check-names コマンドの実行が失敗した場合、レコードは UPDATE メッセージに追加されません。
prereq nxdomain ドメイン名
このコマンドは、domain-nameという名前を持つ、いかなるタイプのリソースレコードも存在しないという前提条件をアサートする。
prereq yxdomain ドメイン名
このコマンドは、 domain-name (任意のタイプのリソース・レコードを少なくとも 1 つ) が存在しなければならないという前提条件を表明します。
prereq nxrrset ドメイン名 クラスタイプ
このコマンドは、指定されたタイプ、クラス、およびドメイン名のリソース・レコードが存在しないことを必要とします。 class を省略すると、 IN (インターネット) が想定されます。
prereq yxrrset ドメイン名クラス・タイプ
このコマンドは、指定されたタイプ、クラス、ドメイン名のリソースレコードが存在することを要求する。 クラスが省略された場合は、「IN」とみなされる。
prereq yxrrset ドメイン名 クラス タイプ データ
このコマンドを使用すると、タイプ、クラス、およびドメイン名を共有するこの形式の前提条件の各セットのデータが結合され、RRのセットが形成される。 この RRs のセットは、指定されたタイプ、クラス、およびドメイン・ネームのゾーンに存在する RRs のセットと正確に一致する必要があります。 データは、リソース・レコードの RDATA の標準テキスト表現で書き込まれます。
update delete ドメイン名 ttl クラス タイプ データ
このコマンドは、 domain-nameという名前のすべてのリソース・レコードを削除します。 typeと dataが指定された場合、一致するリソースレコードは削除される。 class が指定されていない場合は、 IN クラスが想定されます。 ttl は無視され、互換性のためにのみ許可されます。
update add ドメイン名 ttl クラス タイプ データ
このコマンドは、指定されたTTL、クラス、データを持つリソースレコードを追加する。
show
このコマンドは、前回の送信操作以降に指定されたすべての前提条件と更新を含む現在のメッセージを表示する。
send
このコマンドは現行メッセージを送信します。 この操作は、ブランク行を入力するのと同等です。
応答
このコマンドは、応答を表示します。
デバッグ
このコマンドはデバッグをオンにします。
バージョン
このコマンドは、バージョン番号を出力します。
ヘルプ
このコマンドは、コマンドのリストを印刷します。

セミコロン (;) で始まる行はコメントであり、無視されます。

例

以下の例は、 example.com ゾーンのリソース・レコードを挿入および削除するための nsupdate コマンドの使用法を示しています。 各例の入力には末尾ブランク行が含まれているため、コマンドのグループを 1 つの動的更新要求として 1 次ネーム・サーバー example.comに指定することができます。

  1. 既存のゾーンからリソースレコードを削除し、新しいゾーンにリソースレコードを追加するには、以下のコマンドを入力する：
    # nsupdate
> update delete oldhost.example.com A
> update add newhost.example.com 86400 A 172.16.1.1
> send

    oldhost.example.com」のAレコードはすべて削除され、IPアドレス172.16.1.11の「newhost.example.com」のAレコードが追加される。 新規レコードの TTL は 1 日 (86400 秒) です。

  2. DNS サーバーを更新する前に前提条件を指定するには、次のコマンドを入力します。
    # nsupdate
> prereq nxdomain nickname.example.com
> update add nickname.example.com 86400 CNAME somehost.example.com
> send
    前提条件は、「nickname.example.comいかなるタイプのリソースレコードも存在しないことを検証するよう、ネームサーバーを指定する。 ゾーンにリソース・レコードがある場合、更新要求は失敗します。 この名前が存在しない場合、CNAMEが追加され、前提条件がRFC 1034で規定されている長年のルールと衝突しないことを保証する。 RFC1034で規定されているルールは、名前がCNAMEとして存在する場合、他のレコードタイプとして存在してはならないというものである。
    注：このルールはRFC2535のDNSSECのために更新され、CNAMEがRRSIG、 DNSKEY、NSECリソースレコードを持つことを許可している。
