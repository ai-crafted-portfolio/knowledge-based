構文
restvg [ -b Blocks ] [ -d FileName ][ -f Device ] [ -l ] [ -q ] [ -r ] [ -s ] [ -n ] [ -P PPsize ] [ -S ] [ DiskName ... ]

オプション
フラグ
表 1. フラグ
項目 | 説明
-b blocks | 1 回の入力操作で読み取る 512 バイト・ブロックの数を指定します。 このパラメータが指定されない場合、「 restore コマンドではデフォルトの100が使用される。 値が大きくなるほど、テープ・デバイスへの物理的な転送量は大きくなります。
DiskName... | vgname .data ファイルに列挙されているディスク・デバイスの代わりに使用する ディスク・デバイスの名前を指定する。 ターゲット・ディスク・デバイスは空の物理ボリュームとして定義する必要があります。これは、物理ボリューム識別子を含み、ボリューム・グループに属していないことを意味します。 ターゲット・ディスク・デバイスが新しい場合は、「 mkdev コマンドを使用してシステムに追加する必要がある。 ターゲット・ディスク・デバイスがボリューム・グループのものである場合は、 reducevg コマンドを使用してボリューム・グループから除去しなくてはなりません。
-d FileName | -d フラグはオプションである。 -d フラグを指定する場合は、その後にファイル名をつけなければならない。 このファイルは、リストアされるバックアップ・イメージに含まれるものではなく、「 vgname .data ファイルとして使用される。 ファイル名は相対パス名でも絶対パス名でも指定できる。
-f device | バックアップ・メディアのデバイス名を指定します。 デフォルトは /dev/rmt0 です。
-l | ボリューム・グループ・バックアップに関する有効な情報を表示します。 このフラグには、 -f device フラグが必要です。 このフラグを指定すると、' restvg にボリューム・グループ、バックアップが作成された日付と時刻、バックアップされたシステムからのuname出力、oslevel、推奨メンテナンスと技術レベル、バックアップ・サイズ（メガバイト単位）、バックアップ縮小サイズ（メガバイト単位）などの情報が表示される。 圧縮サイズは、すべてのファイルシステム上のデータのサイズです。 フルサイズは、各ファイルシステムの合計サイズです (未使用 + データ)。 lsvg -l vgname -l フラグは、バックアップされたボリュームグループの論理ボリュームと ファイルシステム情報も表示する。

-n | 既存の MAP ファイルが無視されることを指定します。 -n フラグは、「 vgname .data ファイルのlogical_volume_policyスタンザ中の 「 EXACT_FIT フィールドの値を上書きする。
-P PPサイズ | それぞれの物理区画のメガバイト数を指定します。 指定されない場合、' restvg は、リストアされる最大のディスクに依存する PPsize の最適な値を使用する。 PPsize の値が' vgname .data ファイルで指定されたサイズと同じでない場合、各論理ボリュームのパーティション数は新しい PPsize に従って変更される。 指定された PPsize の値が適切なディスクサイズの値より小さい場合、大きい方の PPsize が使用される。 指定された PPsize の値が適切なディスクサイズの値よりも大きい場合、指定された大きい方の PPsize の値が使用される。
-q | ボリューム・グループ・イメージの復元前に通常のプロンプトを表示しないように指定します。 このフラグを指定しないと、プロンプトがボリューム・グループ名とターゲット・ディスク・デバイス名を表示します。
-r | ボリュームグループ構造のみを再作成します。 -r フラグを指定すると、' restvg コマンドはファイルやデータをリストアすることなく、バックアップからボリュームグループ、論理ボリューム、ファイルシステムを（指定されたバックアップ FileName または Device に対して）作成することができます。 この機能は、データの復元にサードパーティ製ソフトウェアを使用し、すべての AIX 論理ボリューム構造を必要とするユーザーにとって便利である。 注: -r フラグは、 -f Device フラグまたは -d FileName フラグと一緒に使用できます。 この制限は、' restvg コマンドがボリュームグループの論理ボリューム構造を再作成するために必要なすべての情報を取得するために、バックアップイメージまたは' vgname .data ファイルを必要とするためです。

-s | 論理ボリュームをファイルシステムにおさまるようにできるだけ小さいサイズで作成するように指定します。 このサイズは、' ブグネーム vgname .data ファイルの' lv_data スタンザ内の' LV_MIN_LPS フィールドの値で指定される。 -s フラグは、' vgname .data ファイルの' logical_volume_policy スタンザにある' SHRINK と' EXACT_FIT フィールドの値を上書きする。 -s フラグを指定すると、 SHRINK=yes および EXACT_FIT=no の値を指定した場合と同じ結果を得ます。
-S | ターゲット物理ボリュームは、ソース物理ボリュームと同じ暗号化ポリシーを持つ必要があることを指定します。 ソース物理ボリュームの少なくとも1つが暗号化されている場合、ソース物理ボリュームは暗号化されているとみなされる。 ただし、すべての対象物理ボリュームが暗号化されている場合、それらの物理ボリュームは暗号化されていると見なされます。 ソース物理ボリュームが暗号化されておらず、ターゲット物理ボリュームが暗号化されている場合、コマンド restvg はターゲット物理ボリュームの暗号化を無効化するよう要求します。 ソース物理ボリュームが暗号化されており、ターゲット物理ボリュームが暗号化されていない場合、コマンド restvg はターゲット物理ボリュームの暗号化を有効にするよう要求します。 注: restvg コマンドに「 -S フラグを付けた場合、すべての認証タイプのうち、パスフレーズとPKS認証タイプはユーザー・ボリューム・グループでのみ復元されます。 ユーザー・ボリューム・グループの復元が完了した後で、他の認証タイプを追加することができます。 暗号化ポリシーは、パスフレーズ認証およびプラットフォームキーストア（PKS）暗号化認証方式に適用されます。 ボリュームグループのバックアップイメージに、パスフレーズのみで暗号化された物理ボリュームが含まれている場合、この restvg -S コマンドは対象の物理ボリュームから追加の暗号化方式を削除しません。 ターゲット物理ボリュームがキーファイル、キーサーバー、その他の暗号化メカニズムなどの方法を使用して暗号化されている場合、これらの追加の暗号化方法はターゲット物理ボリューム上に残ります。
