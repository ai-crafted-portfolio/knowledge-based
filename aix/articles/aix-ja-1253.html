目的
サブシステムまたはサブシステム・グループのリフレッシュを要求します。

説明
refresh
コマンドは、サブシステムに送られるサブシステム・リフレッシュ要求をシステム・リソース・コントローラーに送信します。 リフレッシュ・アクションは、サブシステムによって異なります。
注:
サブシステムの通信方式がシグナルの場合、
refresh
コマンドは失敗します。

構文
refresh [ -h ホスト ] { -g グループ | -p SubsystemPID | -s Subsystem }

オプション
フラグ
項目 | 説明
-g グループ | リフレッシュの対象となるサブシステム・グループを指定します。 グループ 名がサブシステム・オブジェクト・クラスに含まれていない場合、 リフレッシュ コマンドは失敗します。
-h ホスト | このリフレッシュ・アクションの要求先となる外部の Host コンピューターを指定します。 ローカル・ユーザーは、 “ ルート ” として実行する必要があります。 リモート・システムは、リモート・システム・リソース・コントローラー要求を受け入れるように構成しておく必要があります。 つまり、 srcmstr デーモン ( /etc/inittab を参照) を -r フラグで開始し、かつ、リモート要求を許可するよう /etc/hosts.equiv ファイルまたは .rhosts ファイルを構成しておく必要があります。
-p SubsystemPID | リフレッシュの対象となるサブシステムの特定のインスタンスを指定します。
-s サブシステム | リフレッシュの対象となるサブシステムを指定します。 Subsystem 名には、実際のサブシステム名、またはサブシステムの同義語名が使えます。 サブシステム 名がサブシステム・オブジェクト・クラスに含まれていない場合、 リフレッシュ コマンドは失敗します。

例
グループをリフレッシュするには、以下のようにします。
tcpip
次のように入力します。
refresh
-g
tcpip
サブシステムをリフレッシュするには、次のようにします。
xntpd
次のように入力します。
refresh
-s
xntpd
