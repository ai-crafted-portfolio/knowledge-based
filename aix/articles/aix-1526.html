目的

フィックスサーバーからのテクノロジーレベル（TL）とサービスパック（SP）のダウンロードを自動化するタスクを作成します。

構文

サービス更新管理アシスタント（SUMA）タスクを作成、編集、またはスケジュールするには
suma { { [ -x ] [ -w ] } | -s CronSched } [ -a Field=Value ]... [ TaskID ]
SUMAのタスクをリストアップする
suma -l [ TaskID ]...
デフォルトのSUMAタスクを一覧表示または編集するには
suma -D [ -a Field=Value ]...
SUMAのグローバルコンフィギュレーション設定を一覧表示または編集するには
suma -c [ -a Field=Value ]...
SUMAタスクのスケジュールを解除するには
suma -u TaskID
SUMAタスクを削除するには
suma -d TaskID

説明

suma コマンドは、SUMAタスクまたはポリシーに対して以下の操作を実行する：
  • 作成
  • 編集
  • リスト
  • スケジュール
  • スケジュール解除
  • 削除
一意のタスクIDは、指定された操作が実行されるSUMAタスクを表します。 create 、新しいSUMAタスクの作成に使用されるため、 create 、 タスクIDは指定されない。 edit 操作の場合、 タスク ID が指定されないと、システムは新しい SUMA タスクを作成し、新しく作成された SUMA タスクに一意のタスク ID を生成します。

フラグ

項目
説明
-c SUMA グローバル構成設定値をリストまたは編集します。 1つ以上のコンフィギュレーション設定を更新するには、 -c フラグに -a フラグを使用します。 フラグなしで -c 。 -a フラグなしで使用された場合、すべてのSUMAコンフィギュレーション設定がリストされます。
以下のコンフィギュレーション設定を Field=Value 形式で編集するには、 フラグとともに -a-c フラグを使用します。
FIXSERVER_PROTOCOL
転送操作が https （セキュア）プロトコルを使用してfixサーバーと通信することを指定します。 サポートされているプロトコルは https 。
DOWNLOAD_PROTOCOL

転送操作がファイルセットのダウンロードに http プロトコルを使用するか、 https プロトコルを使用するかを指定します。 http プロトコルはマルチスレッド性能を使用し、ファイルセットのダウンロードにはダウンロード・ディレクター・プロトコルを使用する。 https プロトコルはシングルスレッドである。 デフォルト値は https。 有効な値は http と https です。

注： AIX® 7.3 TL4 以降、 DOWNLOAD_PROTOCOL のコンフィギュレーション設定はサポートされなくなった。
DL_TIMEOUT_SEC
ダウンロード操作中にフィックス・サーバーからの応答を待つ時間 (秒数) を指定します。 Fixサーバーは内部サーバーである。 デフォルト値は180。 有効な値は、ゼロより大きい整数です。
注： AIX 7.3 TL4 以降、 DL_TIMEOUT_SEC のコンフィギュレーション設定はサポートされなくなった。
HTTP_PROXY および HTTPS_PROXY
http または https の転送に使用するプロキシサーバーとポートを指定する。 suma コマンドは、プロキシ接続設定を Electronic Service Agent と共有する。 システム管理インターフェイスツール（SMIT）を使用して、 http または https プロキシサービス構成を設定できます。 SMITツールの「 サービス設定の作成/変更」 メニューを使用して、IPアドレス、ポート番号、オプションのユーザーIDおよびパスワードなどのサーバー設定を指定できます。 suma コマンドは HTTP_PROXY と HTTPS_PROXY パラメータの設定をサポートしなくなった。 デフォルト値は「使用不可」です。 有効な値はブランクです。
注： AIX 7.3 TL4 以降、 HTTP_PROXY と HTTPS_PROXY のコンフィギュレーション設定はサポートされなくなりました。
DIRECT_LAN_CONNECT
suma コマンドが fix-central のウェブサイトと通信するために使用する LAN 直接接続オプションを有効または無効にします。 LAN直接接続オプションを使用するには、システムにインターネットへの直接アクセスが必要です。 デフォルト値は yes である。 有効な値は yesと no である。
注： DIRECT_LAN_CONNECT の設定は、 AIX 7.3 TL4 で紹介されている。

注： DIRECT_LAN_PRIORITY の設定は、 AIX 7.3 TL4 で紹介されている。

  3. DIRECT_LAN_CONNECT が yesで、 suma コマンドが直接LAN接続できない場合、 PROXY_CONNECT が yesの場合、優先順位の高い順にプロキシ接続に切り替わる。 それでも接続できない場合は、 suma 、適切なエラーメッセージを表示して終了する。

  5. 詳細については、 プロキシ設定を使用するためのSUMAの設定を参照してください。
-d に関連付けられている SUMA タスクを削除する。 TaskID フラグで作成されたこのタスクのすべてのスケジュールを削除する。 -s フラグで作成されたスケジュールを削除する。
-D デフォルト SUMA タスクをリストまたは編集します。 フラグを使うことで、デフォルトタスクの1つ以上のフィールドを指定された値に更新できる。 -a フラグを使います。 フラグなしで使用された場合は -a フラグなしで使用すると、デフォルトのSUMAタスクがリストされる。
-l SUMA タスクを一覧表示します。 TaskIDなしで使用すると、すべてのSUMAタスクがリストされます。 は、リストする1つ以上のタスクIDを指定するために使用される。 TaskID はリストする1つ以上のタスクIDを指定するために使われる。
-s CronSched SUMA タスクをスケジュールします。 新しいタスクの作成時に指定された場合、保存が暗示される (-w フラグ関数)。 CronSched は、スペースで分離された 5 つのエントリー (分、時、日、月、曜日) を引用符で囲んだリストです。 以下の値は、スペースで区切られた5つのエントリーに有効な値である：
  • 分数の範囲は0～59
  • 営業時間は0～23時間
  • 日数は1日から31日まで
  • 月の範囲は1～12
  • 平日は0～6（日曜～土曜の場合）

詳細は crontab コマンドをご覧ください。
-u SUMA タスクのスケジュールを解除します。 このフラグは、指定された TaskIDのすべてのスケジューリング情報を除去します。
-w SUMA タスクを書き込むか保管します。 フラグの代わりにこのフラグを使うと、タスクは保存される。 -s フラグの代わりにこのフラグが使われた場合、タスクは保存され、後でスケジューリング情報を追加できます。 もし -x フラグと一緒に使うと、タスクは直ちに実行され、保存される。
-x SUMA タスクを即時に実行し、スケジュールしないことを指定します。 もし -w フラグなしで使われた場合、タスクは将来の使用のために保存されない。
-a フィールド = 値 ... 指定された Value を指定された Field に代入します。 以下の値は、SUMAタスクの作成または編集操作でサポートされるフィールドと 値です：
RqType
RqType に Latestを指定して suma コマンドを実行する場合、 RqType が唯一の必須フィールドです。 suma 、値を指定せずにコマンドを実行した場合に使用されるデフォルト値については、 例1を参照のこと。 その他の RqType の値(TL, SP, ML, PTF)は、 Field=Value 情報の指定を必要とする。
ML
特定のメンテナンスまたはTLのダウンロード要求を指定する。 例えば、 5300-11。
TL
特定のTLのダウンロード要求を指定する。 例えば、 6100-03。
PTF
プログラム一時修正プログラム（PTF）のダウンロード要求を指定します。 例えば、 U813941。 特定のPTFだけが個別のファイルセットとしてダウンロードされる場合があります。 例えば、 bos.rte.install、 bos.alt_disk_install.rte を含むPTFや、SPの間に出てくるPTFなど。 それ以外の場合は、 TL または SP をダウンロードする必要があります。
SP
特定の SP のダウンロード要求を指定する。 例は 6100-02-04 です。
Latest
最新のフィックスのダウンロード要求を指定します。 この RqType の値は、 FilterML で指定された TL の最新の SP を返す。
-a (続き)
RqName
リクエストされたアイテムの名前を指定します。 例えば、 6100-03 や 6100-04-03。 RqType が Latestの場合、 RqName フィールドはブランクでなければなりません。
Repeats
タスクが1回実行されシステム上に残らないか、アイテムが見つかるまでタスクを繰り返すか、タスクを永遠に繰り返すかを指定する。 Repeats フィールドは、 Action が Download、 Clean、または Metadata である cron コマンドから実行されるスケジュールされたタスクにのみ適用されます。 コマンド・ラインから実行する場合または Action が Preview の場合は、このフィールドは無視され、タスクは除去されません。
y
繰り返しタスクを設定し、そのタスクに CronSched フラグを持つ -s フラグが必要である。 RqType が TL、 SP、 PTF、 ML に等しい場合、アイテムが見つかればタスクは削除される。 RqType が Latest である場合、 タスクは永久に繰り返すようにセットアップされます。
n
タスクは一度だけ実行され、システム上には残らない。
-a (続き)
DisplayName
SUMA タスクが利用可能な場合、SUMA タスクの表示名を示す。 例えば、 Download TL 6100-04。 このオプションは、SMIT で既存の SUMA タスクを表示するために使用します。
Action
Preview
ダウンロード・プレビューの実行を指定します。 ファイルセットはダウンロードされない。
Download
ポリシーに基づいてファイルセットが DLTarget にダウンロードされることを指定します。
Clean
ポリシーに基づいてファイルセットが DLTarget にダウンロードされ、その後にクリーン操作が行われることを指定します。 この lppmgr コマンドは、不要なファイルセットを DLTarget から削除するのに使われる。 以下の3つの設定可能な lppmgr コマンドフラグオプションは、SUMAグローバルコンフィギュレーション設定にリストされています：
  • REMOVE_CONFLICTING_UPDATES
  • REMOVE_DUP_BASE_LEVELS
  • REMOVE_SUPERSEDE
Metadata
ファイルセットの更新ではなく、メタデータファイルをダウンロードするように指定します。 以下の RqType 値がサポートされています。
TL
特定のTLのメタデータをダウンロードする。
SP
特定の SP のメタデータをダウンロードする。
Latest
FilterML フラグに指定された TL のすべての SP のメタデータをダウンロードする。
DLTarget
ダウンロードされたファイルを保管するディレクトリーの場所が入ります。 このフィールドが指定されない場合、値 /usr/sys/inst.images が与えられ、ファイルは画像タイプに基づいたディレクトリに保存される。 例えば、 /usr/sys/inst.images/installp/ppc や /usr/sys/inst.images/RPMS/ppc。
NotifyEmail
ファイルセットのダウンロードまたはプレビュー後に通知を送信する1つまたは複数の電子メールアドレスが含まれています。 複数のメールアドレスはカンマ区切りで入力してください。 タスクが将来の時刻に実行するようにスケジュールされている (CronSched が指定されている) 場合にのみ、通知が送信されます。
-a (続き)
FilterDir

重複するフィックスがダウンロードされないようにフィルタリングするフィックス・リポジトリー・ディレクトリーの名前を指定します。 このオプションを使用すると、 DLTarget 以外のディレクトリーをフィルターに掛けることができます。 たとえば、このディレクトリにダウンロードすることなく、NIM lpp_source に対してフィルターをかけることができる。 ブランクのままにすると、DLTarget が使用されます。

FilterDir フィールドの値が /installp/ppc フィックス・リポジトリー・ディレクトリーで終わる場合、 suma コマンドは指定されたディレクトリー内のフィックスをフィルタリングします。

FilterDir フィールドの値の末尾が /installp/ppc フィックス・リポジトリー・ディレクトリーでない場合、 suma コマンドは、 /installp/ppc ディレクトリー内のフィックスを検索してフィルタリングしようとします。

FilterDir 」フィールドで指定された修正リポジトリー・ディレクトリーに「 /installp/ppc 」ディレクトリーがあれば、フィルター処理は成功です。

FilterDir 」フィールドで指定された修正リポジトリ・ディレクトリが「 /installp/ppc 」ディレクトリを持たない場合、フィルター処理は失敗します。

FilterML
フィルタリングするTLを指定する。 例えば、6100-03。 指定がない場合は、ローカル・システムの oslevel -r コマンドが返す値が使用される。
MaxDLSize
単一のポリシー実行によってダウンロードされるデータの最大許容量を MB 単位で指定します。 ダウンロードがこのサイズを超えると判断された場合は、ダウンロードは行われません。 値 unlimited または -1 は、ダウンロードするデータ量に上限がないことを示す。
Extend
yを指定すると、 DLTarget が存在するファイルシステムが自動的に拡張される。 nが指定され、ダウンロードにそれ以上のスペースが必要な場合、ダウンロードは行われない。
-a (続き)
MaxFSSize

DLTarget ファイルシステムを拡張できる最大許容サイズを MB 単位で指定する。 ダウンロードがこの限度を超えると判断された場合は、ダウンロードは行われません。 値 unlimited または -1 は、ファイルシステムのサイズにそれ以上の制限がないことを示す。 ファイルシステムのサイズに高い制限が設定されていなければ、物理的なディスク容量がなくなるまでファイルシステムを拡張することができる。

拡張後の DLTarget ファイルシステムの実際のサイズは、要求されたサイズよりわずかに大きいかもしれない。 DLTarget ファイルシステムの拡張処理は、ボリュームグループ（VG）の物理パーティション（PP）サイズを使用します。 必要なファイルシステムのサイズは、ファイルシステムが拡張されるときに、PPの次の倍数に切り上げられる。 suma コマンドは、TL と SP のダウンロードに必要なファイル・システム・メモリを計算するために、TL と SP の合計ダウンロード・サイズに 1.15 のファッジ・ファクターを乗算する。

MaxFSize オプションの値は、以下の数式を使用して計算できます。

Y = X * 1.15 / (1024 * 1024)

ここで、 Y は必要なファイルシステムサイズ（MB）、 X はダウンロードされたアップデートの合計バイト数である。

ファイルシステムで利用可能な空きメモリ（MB単位）が Z で示され、 Y の値が Z より大きい場合、TLとSPをダウンロードするためにファイルシステムでより多くのメモリが必要となる。 ファイルシステムに必要な余分なメモリは、 Y と Z の値の差（MB）として計算できる。 ファイルシステムの総サイズが T （単位：MB）で示される場合、ファイルシステムは F の値まで拡張される。 F は以下の式で計算される：

F = T + ( Y - Z )

MaxFSize オプションを F の値より大きい値に設定することで、修正プログラムのダウンロードを正常に完了できるサイズまでファイルシステムが拡張されます。

例

  1. SUMAのグローバルコンフィギュレーション設定を一覧表示するには、以下のコマンドを入力します：
    suma -c
    以下のサンプル画面のような出力が表示される：

REMOVE_SUPERSEDE=yes
TMPDIR=/var/suma/tmp
  2. SUMAのグローバルコンフィギュレーション設定を編集して、最大ログファイルサイズを2MBに変更するには、次のコマンドを入力します：
    suma -c -a MAXLOGSIZE_MB=2
  3. SUMAタスクのデフォルトを一覧表示するには、以下のコマンドを入力する：
    suma -D
    以下のサンプル画面のような出力が表示される：
    DisplayName=
Action=Download
RqType=Latest
RqName=
Repeats=y
DLTarget=/usr/sys/inst.images
NotifyEmail=root
FilterDir=/usr/sys/inst.images
FilterML=7300-02
MaxDLSize=-1
Extend=y
MaxFSSize=-1
  4. 例えば、毎月15日の午前2時30分に最新のフィックスをダウンロードするタスクを作成してスケジュールするには、次のコマンドを入力します：
    suma -s "30 2 15 * *" -a RqType=Latest \
-a DisplayName="Latest fixes - 15th Monthly"
    注: この新しく作成されたタスクのタスク ID が返されます。 この例では、 suma -D コマンドで表示されるように、SUMAタスクのデフォルトの一部が使用されていると仮定している。 例えば、タスクのデフォルトが DLTarget=/usr/sys/inst.images の場合、installpイメージは /usr/sys/inst.images/installp/ppc ディレクトリにダウンロードされる。
  5. suma -s CronSched コマンドを実行した際に設定されるSUMAスケジューリング情報を表示するには、以下のコマンドを入力します：
    crontab -l root
  6. 特定のTLを週に1回、例えば毎週木曜日の午前3時にチェックし、利用可能になったらダウンロードし、リモート・システムのユーザーに電子メール通知を送信するタスクを作成し、スケジュールするには、次のコマンドを入力する：
    suma -s "0 3 * * 4" -a RqType=TL -a RqName=6100-04 \
-a NotifyEmail="bob.smith@host2,ann@host2"
    注： TLを毎週チェックするには、 Repeats フィールドを y に設定する。 この場合、TL が検出されると、タスクは削除されます。 Repeats=n の場合は、タスクの削除の前に単一の検査だけが行われます。
  7. 例えば、毎月20日の午前4時30分にクリティカルな修正をチェックするタスクを作成してスケジュールするには、次のコマンドを入力します：
    suma -s "30 4 20 * *" -a RqType=Latest -a RqName= \
-a RqLevel=latest -a Repeats=y
    注： Repeats=y を設定すると、このタスクは永遠に繰り返され、ダウンロードに成功しても削除されない。
  8. 例えば月曜日の午後 11 時など、指定した時刻に、5300-11 推奨メンテナンス・パッケージを含む AIX バージョン 7.1 全体を /lppsrc/5311 ディレクトリにダウンロードするタスクを作成し、スケジュールするには、次のコマンドを入力します：
    suma -s "0 23 * * 1" -a Action=Clean -a RqType=ML -a RqName=5300-11 \
-a DLTarget=/lppsrc/5311
    このコマンドはまた、ダウンロード操作の後に lppmgr コマンドcleanオペレーションを実行し、古いアップデート、重複するベースレベル、競合するアップデートを削除します。
    注： Action=Clean を指定するタスクを実行する前に、 suma -c コマンドを実行し、 lppmgr コマンドを実行したときに使用される SUMAグローバル構成設定を確認します。 REMOVE_SUPERSEDE、 REMOVE_DUP_BASE_LEVELS、 REMOVE_CONFLICTING_UPDATES フィールドは、クリーン・オペレーションを実行するために yesに設定されなければならない。
  9. 指定された時間に、 AIX バージョン 7.1 と 5300-11 推奨メンテナンスパッケージ全体を /tmp/lppsrc/5311 ディレクトリにダウンロードするタスクを作成し、スケジュールします。 たとえば、月曜日の午後11:00に、 /lppsrc にすでに含まれている更新をフィルタリングする場合、次のコマンドを入力する：
    suma -s "0 23 * * 1" -a RqType=ML -a RqName=5300-11 \
-a DLTarget=/tmp/lppsrc/5311 -a FilterDir=/lppsrc -a FilterSysFile=/dev/null
    注: タスクが正常に完了すると、 RqType=TL はタスクが見つかるまで繰り返されるため、タスクは削除されます。 ただし、 Repeats=nの場合は、5300-03 TL に対して単一の検査のみが行われ、TL がフィックス・サーバーで検出されない場合は、タスクが繰り返さないようにセットアップされているため、タスクは削除されます。
  10. フィックスサーバー上にSPが存在するかどうかを確認するためのプレビューを実行するタスクを実行し、SPがまだ存在しない場合にこのタスクを後で実行するように作成してスケジュールするには、次のコマンドを入力します：
    suma -x -w -a Action=Preview -a RqType=SP -a RqName=6100-04-02
    注: この新しく作成されたタスクのタスク ID が返されます。
  11. 例 10 から新しく作成したタスクを実行し（タスク ID 23 が返されたと仮定する）、SP をダウンロードしてタスク ID 23 の Action=Download 設定を保存しようとするには、以下のコマンドを入力する：
    suma -x -w -a Action=Download 23
    注意: このタスクはコマンドラインから実行され、 cron コマンドでスケジュールされないので、 Repeats フィールドは無視され、SPが見つかっても見つからなくてもタスクは削除されない。
  12. 例えば毎週木曜日の午前3時に特定のSPをチェックし、利用可能になったらダウンロードするようにタスクID 23をスケジュールするには、以下のコマンドを入力する：
    suma -s "0 3 * * 4" -a Repeats=y 23
    注: このタスクは、SP が検出されると削除されます。
  13. /var/spool/cron/crontabs ディレクトリの crontab ファイルからそのタスクのスケジュール情報を削除するタスクをアン・スケジュールするには、次のコマンドを入力します：
    suma -u 23
  14. タスクが存在する場合、そのスケジュール情報も削除するには、以下のコマンドを入力する：
    suma -d 23
  15. 4 、 23 はタスクIDを表す。複数のSUMAタスクをリストするには、以下のコマンドを入力する：
    suma -l 4 23
  16. すべての SUMA タスクをリストするには、次のコマンドを実行します。
    suma -l
  17. 毎月（例えば、毎月15日の午前2時30分）、指定された FilterML 属性の最新の SP をチェックし、 /tmp/latest リポジトリにまだない SP をダウンロードするタスクを作成し、スケジュールするには、以下のコマンドを入力する：
    suma -s "30 2 15 * *" -a RqType=Latest -a FilterML=6100-02 \
-a DLTarget=/tmp/latest -a FilterDir=/tmp/latest
    注: この新しく作成されたタスクのタスク ID が返されます。
