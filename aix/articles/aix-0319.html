目的

クラスター・セキュリティー・サービス ACL ファイルの内容を 検査します。

構文

ctaclfck-f ACL_FILE_NAME [-s][-c][-u ユーザー名 ] [-v][-h]

説明

ctaclfck コマンドは、 -f フラグによって指定されたクラスター・セキュリティー・サービス ACL ファイルの内容を検査します。 この検査 は、構文エラーに限定され、意味検査は実行されません。

このコマンドは、ACL ファイルをオープンし、ACL エントリーを一度に 1 つずつ読み取って、コンパイル します。 コマンドがエラーを検出した場合は、そのエラーを標準出力に報告 します。 -c フラグが指定されている場合、コマンドはエラーが発生した後、ファイルの終わりに達するまで処理を続行します。 それ以外の場合は、最初のエラーが検出され、報告された後で、処理は 停止します。

-u フラグは、指定されたオペレーティング・システム・ユーザー ID が所有する ACL ファイルの内容を検査するようにコマンドに指示します。 コマンド・ユーザーは、 -u フラグで指定されたユーザーのホーム・ディレクトリーに変更する許可を持っている必要があります。また、そのディレクトリー内のファイルを読み取る許可も持っている必要があります。 -s フラグが -u フラグとともに指定されている場合、コマンド・ユーザーは、その有効なユーザー ID をこの ID に設定する許可も持っている必要があります (例については、オペレーティング・システム・コマンド su のマニュアル・ページを参照してください)。

-u フラグが指定されている場合、 -f フラグで指定されるファイル名は、指定されたユーザーのホーム・ディレクトリーにあるファイルのベース名であると想定されます。 この場合、 -f フラグによって指定されるファイル名には、 ./ および ../ ディレクトリーを含むディレクトリー名を含めることはできません。

-s フラグを指定すると、コマンドは ACL ファイルのコンパイル済み内容を含むファイルを作成します。 これによって、アプリケーションでは、ACL データ・バッファーを使用するアプリケーションの 開始に先立って、ACL データ・バッファーをコンパイルして、これを処理するアプリケーションをその始動手順中 またはその ACL 読み取りプロセス中に保管することができます。 コンパイルされた ACL ファイルは、拡張子 .caclを持つ ACL ファイルと同じ名前になります。 新しい *.cacl ファイルの所有権とファイル・システム許可は、ACL ファイルと同じ所有権と許可に設定されます。 ACL ファイルがコマンド・ユーザーによって所有されていない場合は、コマンド・ ユーザーは、その有効なユーザー ID を ACL ファイルを所有するユーザーの ID に変更できる 必要があります。 コマンドはこれができない場合は、ACL バッファー・ファイルを 作成しませんが、ACL ファイルの検査は 完了します。

このコマンドは、正しい ACL エントリー・タイプ、適正な ID フォーマット、および有効な許可かどうかを 検査します。 有効な許可は、許可テンプレートによって定義されている操作のみが含まれる許可として 定義されます。 クラスター・セキュリティー・サービスによって 定義され、このコマンドで使用される許可テンプレート・セットは、次の とおりです。

-u フラグが指定されている場合、コマンドは、指定されたユーザーのホーム・ディレクトリーで ACL ファイルを検索します。 ユーザーがファイルを所有している必要があり、許可は、ユーザーによる書き込み専用である必要があります。 -u フラグを指定する場合、 -f フラグで指定する ACL ファイル名には、ファイルへの相対パスまたは絶対パスを含めることはできません。ファイル名のみを指定する必要があります。

フラグ

--f acl_ファイル名
検査するクラスター・セキュリティー・サービス ACL ファイルを指定します。 ファイル名は、 -u フラグが指定されていない限り、絶対パス名または相対パス名にすることができます。
-s
(ACL ファイルのコンパイルの結果である) ACL バッファーをファイル内でキャッシュに 入れます。 ACL ファイルがコマンド・ユーザーによって所有されていない場合は、コマンド・ユーザーには、その有効なユーザー ID を ACL ファイルの所有者に設定できる必要があります。
-c
コマンドに対して、エラーの検出後、ファイルの終わりに達するまで、継続するよう指示 します。 -v フラグが指定されているかどうかに関係なく、発生したすべてのエラーが報告されます。 指定されていない場合は、コマンド処理は、最初の エラーの検出および報告の後で停止します。
-ユーザー名
ACL ファイルがホーム・ディレクトリー内にあるユーザー名を指定します。 このフラグを使用する場合、 -f フラグで指定するファイル名は、指定されたユーザーのホーム・ディレクトリーにあるファイルのベース名でなければなりません。このファイルには、 ./ および ../ ディレクトリー名を含むディレクトリー情報を入れることはできません。
-v
コマンドの詳細メッセージを標準出力に書き込みます。
-h
コマンドの使用ステートメント (使用法) を標準出力に書き込みます。

セキュリティー

ACL ファイルのファイルシステム許可は、エンド・ユーザーまたはそのファイルを所有しているアプリケーション によって決まります。 呼び出し側にファイルを読み取ったり、所有権が同じ、要求されたコンパイル済み ACL ファイルを作成したりするために十分な権限がない場合は、コマンドは失敗します。

制約事項

ctaclfck コマンドは、クラスター・セキュリティー・サービス用にフォーマットされた ACL ファイルに対してのみ機能します。

例

  1. ACL ファイル /my_acl_fileの内容を検査するには、以下のようにします。
    ctaclfck -f /my_acl_file
  2. ACL ファイル ../my_acl_file の内容を (現行ディレクトリーに対して相対的に) 検査し、詳細な出力を提供するには、次のようにします。
    ctaclfck -f ../my_acl_file -v
  3. オペレーティング・システム・ユーザー fluffyが所有する ACL ファイル /u/fluffy/my_acl_fileの内容を完全に検査し、コンパイル済み ACL バッファーを後で使用するためにファイルに保管するには、次のようにします。
    ctaclfck -c -u fluffy -f  my_acl_file  -v -s

場所

/opt/rsct/bin/ctaclfck
ctaclfck コマンドが入っています。
