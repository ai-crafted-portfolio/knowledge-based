目的
チューナブル・パラメーターが入っているファイルを検証します。

説明
tuncheck
コマンドは、チューナブル・パラメーターが入っているファイルを検証します。 指定ファイル内にリストされたすべてのチューナブル・パラメーターは、範囲と依存関係について検査されます。 問題が検出されると、警告が発行されます。
tuncheck
コマンドは、以下の項目を検証します。
現行コンテキストに対する検証
指定されたファイルにあるチューナブル・パラメーターが、すぐに適用可能であるかどうかを検査します。
Filename
にリストされていないチューナブル・パラメーターは、現行値として解釈されます。 タイプが
Incremental
の
チューナブルに現行値よりも小さな値が表示されていると、検査は失敗します。
さらに、タイプが
Bosboot
また
は
Reboot
のチューナブルに現行値よりも大きな
値が表示されている場合も失敗します。
次のブート・コンテキストに対する検証
指定されたファイルにあるチューナブル・パラメーターが、リブートの間に適用可能であるかどうか
(つまり、そのファイルが有効な
nextboot
ファイルであるかどうか) を検査します。 タイプが
Incremental
のチューナブル・パラメーターに現行値よりも小さな値が指定されていると、ファイル検証は失敗しません。 タイプが
Bosboot
また
は
Reboot
のチューナブルに現行値よりも大きな
値が表示されている場合は、警告が発行されますが、検査は失敗しません。
次のライブ・アップデート・コンテキストに対する検証
指定されたファイルにあるチューナブル・パラメーターが、ライブ・アップデート操作の間に適用可能であるかどうか
(つまり、そのファイルが有効な
nextliveupdate
ファイルであるかどうか) を検査します。 タイプが
Incremental
のチューナブル・パラメーターに現行値よりも小さな値が指定されていると、検証は失敗しません。 タイプが
Bosboot
または
Reboot
のチューナブル・パラメーターに、指定されたファイルで現行値よりも大きな値が表示されている場合は、警告が表示されますが、ファイル検証は失敗しません。
さらに、
Filename
に不明なスタンザ、既知のスタンザ
内に不明なチューナブルがあると、警告が発行されます。 ただし、検査は
失敗しません。
正常終了すると、検査したファイルの情報スタンザに
ある
AIX_level, Kernel_type
およ
び
Last_validation
の各フィールドが更新されます。

構文
チューンチェック [ - [ -K (K) ] | P- ] 「-f」 ファイル名

オプション
フラグ
項目 | 説明
-f ファイル名 | 検査するチューナブル・ファイルの名前を指定します。 この名前に「 / 」(スラッシュ) 文字が含まれていない場合は、 この名前は /etc/tunables に関連しています。
-K | ブート・コンテキストおよびライブ・アップデート・コンテキストに指定されたファイルを検査します。
-p | 現行コンテキストとブート・コンテキストの両方に ついて Filename を検査します。 この操作 は、 tuncheck を 2 回実行し、1 回目はフラグ なし、2 回目は -r フラグを使用するのと同じことです。
-r | ブート・コンテキストで Filename を検査します。
-p
または
-r
が指定されていない
場合は、
Filename
は、現行コンテキストに従って検査されます。

例
mytunable
を即時適用できるかどうか
を確認するには、次のように入力します。
tuncheck -f ./mytunable
/etc/tunables/nextboot
をリブート時に適用
できるかどうかを確認するには、次のように入力します。
tuncheck -r -f nextboot
/etc/tunables/nextboot
を即時およびリブート後に
適用できるかどうかを確認するには、次のように入力します。
tuncheck -p -f nextboot
mytunables
ファイルにあるチューナブル・パラメーターが、リブート操作およびライブ・アップデート操作の間に適用可能であるかどうかを確認するには、次のコマンドを入力します。
tuncheck -r -K -f ./mytunable
