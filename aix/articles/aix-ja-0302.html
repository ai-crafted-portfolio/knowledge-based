目的
ローカル・システム用のクラスター・セキュリティー・サービス秘密鍵および公開鍵を生成し、それらのキーをローカルにマウントされたファイルに保管します。

説明
ctskeygen
コマンドは、RSCT ホスト・ベース認証 (HBA) でクラスター・セキュリティー・サービス・ライブラリー (
libct_sec
) によって使用されるホスト ID 鍵 (秘密鍵と公開鍵のペア) を生成します。 このコマンドは、そのノード用の秘密鍵を新規作成して、その新規秘密鍵から公開鍵を導き出し、それらのキーをそのローカル・ノード上のファイルに保管します。
ノードの秘密鍵および公開鍵が変更されるたびに、そのノードの新規公開鍵がそのクラスター内のすべてのノードに必ず配布され、それらのノード上のトラステッド・ホスト・リスト・ファイルに入れられて、そのファイル内でこのノード用として保管されていた前の値がこの新規公開鍵に交換されなければなりません。 これが行われないと、新規の秘密鍵と公開鍵を生成したノードは、そのクラスター内のその他のノードとの間で HBA 認証を使用した認証を行えなくなります。

構文
ctskeygen -n [ -f ] [ -m method ] [ -p public-file ] [ -q private-file ] | -d | -i | -h

オプション
フラグ
-n
ホスト ID キー (秘密鍵と公開鍵) を生成します。
-f
秘密鍵ファイルと公開鍵ファイルが既に存在している場合は、
ctskeygen
がそれらのファイルに生成した鍵を記録するように強制します。 デフォルトでは、このコマンドはこれらのファイルが存在する場合はそれらを上書きしません。なぜなら、これらのファイルが存在するということは、クラスター・セキュリティー・サービスのサービスがアクティブになっている可能性があるということだからです。 公開鍵の値の変更をその他のノードに通知せずにこれらのファイルを除去または変更すると、このノードでの HBA 認証は失敗するようになります。 このフラグは、
-h
または
-i
フラグと一緒の場合は無効です。
-
メソッド
ホスト ID キーを作成する際には指定されたキー生成方式を使用するようコマンドに指示します。 このフラグの有効なパラメーターは、
-i
フラグを使用して表示できます。 このフラグは、
-h
フラグおよび
-i
フラグと一緒に使用することはできません。
-
パブリックファイル
ローカル・ホストの公開鍵を保管するのに使用されるファイルの完全修飾パス名を指定します。 このファイルが存在する場合、
-f
フラグも指定されていない限り、コマンドはこのファイルの内容を上書きしません。
-p
フラグが指定されていない場合、コマンドはこのキーを
/var/ct/cfg/ct_has.pkf
ファイルに記録します。 このフラグは、
-h
フラグおよび
-i
フラグと一緒に使用することはできません。
-q 専用ファイル
ローカル・ホストの秘密鍵を保管するのに使用されるファイルの完全修飾パス名を指定します。 このファイルが存在する場合、
-f
フラグも指定されていない限り、コマンドはこのファイルの内容を上書きしません。
-q
オプションが指定されていない場合、コマンドはこのキーをファイル
/var/ct/cfg/ct_has.qkf
に記録します。 このフラグは、
-h
フラグおよび
-i
フラグと一緒に使用することはできません。
-d
ローカル・システムの現行の公開鍵値を表示します。
-i
このコマンドのこのバージョンでサポートされるキー生成方式に関する情報を表示します。
ctskeygen
は、
-m
フラグの引数として現在サポートされている値、およびコマンドが
-m
フラグのデフォルト設定として使用する内容を示すメッセージを表示します。
-h
コマンドの使用ステートメント (使用法) を標準出力に書き込みます。

例
サポートされているキー生成方式のリストを取得するには、次のように入力します。
ctskeygen -i
デフォルト設定を使用してローカル・システム用のホスト ID キーを新規作成するには、次のように入力します。
ctskeygen -n
512 ビット RSA 秘密鍵を使用してローカル・システム用のホスト ID キーを新規作成し、それらのキーをデフォルトの場所以外の場所に保管するには、次のように入力します。
ctskeygen -n -m rsa512 -p /mysec/public -q /mysec/private
