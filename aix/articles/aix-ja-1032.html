目的
AIX
環境における新しいハードウェアの導入を容易にします。

説明
nim_move_up
コマンドを使用すると、既存の
AIX
環境のユーザーは、新しい POWER ® サーバーで使用可能な機能を利用できます。 このコマンドは、既存の
AIX
システムを POWER サーバー上の
LPAR
にマイグレーションするインターフェースを提供します。 元のマシンの
AIX
のレベルが、新しいハードウェアでの操作をサポートするレベルに引き上げられます。 元のシステムのハードウェア・リソースは、より新しいハードウェア上で厳密に複製されます。 マイグレーションの終了までに、同じシステムが新しい
LPAR
上で完全に稼働しています。
さらに、
nim_move_up
は、オプションで仮想化ハードウェア (仮想ディスクや仮想イーサネットなど) にクライアントをマイグレーションすることにより、POWER サーバーの仮想入出力機能を使用できます。
nim_move_up
コマンドは、NIM の機能と、ネットワーク上の NIM クライアントをリモートで管理およびインストールする NIM マスターの機能に依存します。
nim_move_up
コマンドは、NIM マスターと
nimadm
コマンドを使用して、既存の NIM クライアントに対して以下のアクションを実行しようとします。
クライアントのシステム・バックアップを作成する。
バックアップのレベルの
AIX
のマイグレーション
新しい POWER サーバーにある
LPAR
にバックアップをインストールします。このサーバーは、NIM 環境では新しいスタンドアロン・クライアントとして表されます。
新規ハードウェアのインストール前に、NIM マスター (
nim_move_up
コマンドが実行される場所) と、既存ハードウェア上の NIM クライアントを構成する必要があります。 クライアントはマイグレーションの開始点であり、最終的には新しい
LPAR
になります。
移行が正常に終了した後の状態は、次のとおりです。
NIM マスターはそのまま変わりありません。
新しい POWER サーバー上の
LPAR
は、元の NIM クライアントに対応し、NIM マスターによって制御されます。
HMC は、SSH を介して NIM マスターと通信することにより、新しい POWER サーバー上の
LPAR
を制御します。
元の NIM クライアントは影響を受けないままの状態で、依然として NIM マスター
の制御下に置かれています。
移行全体は、元のクライアントの一部では必要とされた停止時間もなく行

われます。 このプロセスは、順番に実行して行く各フェーズの中で完了させることができます。
これにより、このプロセスに対する一層の制御が可能となります。また、別の方法
としてフェーズの全体を一気に実行可能であり、それによって処理時にユーザー
応答のための介入は不要となります。 このコマンドは、
bos.sysmgt.nim.master
ファイルセットの一部として配布され、実行するには NIM 環境が機能している必要があります。

構文
nim_move_up {[ -S ] | [ -K [ -h control_host ]] | [ -r [ -R ] [ -u ]]} | {[ -c NIM_client ] [ -i target_ip [ -ending_ip ]] [ -s subnet_mask ] [ -g gateway ] [ -h control_host ] [ -m managed_sys ] [ -V vio_server [ -e ] [ -D ]] [ -I img_src ] [ -l resource_dir ] [ -t 秒 ] [ -p ループ ] [ -j nimadm_vg ] [ -L lpp_source ] [ -U spot ] [ -B bosinst_data ] [ -E exclude_files ] [ -C script_resource ] [ -b installp_bundle ] [ -f fix_bundle ] {{[ -n ] [ -d ]} | -O } [ -q ] [ -T ] [ -M manual_configuration_filenames ]}

例
最初のフェーズを実行し、すべての必須指定のオプションを構成するには (
nim_move_up
が既に構成され、実行されていてはなりません)、次のように入力します。
nim_move_up -c client1 -i 192.168.1.100 -s 255.255.255.0 -g 192.168.1.1 -h hmc1.mydomain.com -m \
my-p5 -l /big/dir -I /dev/cd0 -n
nim_move_up
コマンドの環境の状況 (保管されたすべての構成入力および次に実行するフェーズを含む) を表示するには、次のように入力します。
nim_move_up -S
保管済みのホスト名を新しい名前に変更して、出力を抑止しながら次のフェーズを実行するには、次のように入力します。
nim_move_up -h hmc2.mydomain.com -n -q
残る全フェーズをバックグラウンドで実行し、全ライセンスの受け入れ合意を保管
して、フェーズの実行開始後にプロンプトを戻すようにするには、次のように入力します。
nim_move_up -Y -d
nim_move_up
を構成解除し、保存されているすべての入力を破棄し、フェーズ 1 を実行するようにコマンドをリセットするには、次のように入力します。
nim_move_up -r
nim_move_up
によって以前に作成されたすべての NIM リソースは、NIM 環境では影響を受けず、別のクライアントを移行するために必要に応じて
nim_move_up
によって使用されます。
