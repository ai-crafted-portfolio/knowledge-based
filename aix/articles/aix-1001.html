目的

ゾーンファイルまたは名前付き設定ファイルの変換ツールの有効性チェック。

構文

named-checkzone[ '-d] [ '-h] [ '-j] [ '-q] [ '-v] [ '-c class] [ '-f format] [ '-F format] [ '-J filename] [ '-i mode] [ '-k mode] [ '-m mode] [ '-M mode] [ '-n mode] [ '-l ttl] [ '-L serial] [ '-o filename] [ '-r mode] [ '-s style] [ '-S mode] [ '-t directory] [ '-T mode] [ '-w directory] [ '-D] [ '-W mode]{zonename}{filename}

named-compilezone [ -d ] [ -h ] [ -j ] [ -q ] [ -v ] [ -c クラス ] [ -f フォーマット ] [ -F フォーマット ] [ -J ファイル名 ] [ -i モード] [ -k モード ] [ -m モード ] [ -M モード ] [ -n モード ] [ -l トル ] [ -L シリアル ] [ -r モード ] [ -s スタイル ] [ -S モード ] [ -t ディレクトリ ] [ -T モード ] [ -w ディレクトリ ] [ -D ] [ -W モード ] ゾーン名 [ -o ファイル名 ] { ゾーン名 } { ファイル名 }

説明

named-checkzone コマンドはゾーン・ファイルの構文と整合性をチェックします。 named このため、 named-checkzone コマンドは、ネームサーバーに設定する前にゾーンファイルをチェックするのに便利である。

named-compilezone コマンドは named-checkzone コマンドに似ていますが、named-compilezone コマンドは、常時、ゾーン内容を指定フォーマットで指定ファイルにダンプします。 また、ダンプ出力は'namedデーモンがロードする実際のゾーンファイルとして 使用されるため、デフォルトでは厳しいチェックレベルが適用される。 手動で指定する場合、チェック・レベルは少なくとも、指定されたコンフィギュレーション・ファイルで指定されたものと同程度に厳密でなければならない。

フラグ

項目
説明
-c class ゾーンのクラスを指定します。 指定しない場合、クラスはデフォルトで IN に設定されます。
-d デバッグを使用可能にします。
-D 標準フォーマットでゾーン・ファイルをダンプします。 このオプションは、「named-compilezoneコマンドでは常に有効である。
-f フォーマット ゾーン・ファイルのフォーマットを指定します。 可能な形式は、 text (デフォルト) および rawです。
-F フォーマット
指定された出力ファイルの形式を指定し、ゾーンの内容がダンプされた後 にのみ効果を持つ。
  • text（デフォルト）：このフォーマットはゾーンの標準的なテキスト表現である。
  • raw」と「raw=N: このフォーマットでは、指定されたコマンドで素早く読み込めるように、 ゾーンをバイナリ形式で保存する。 raw=Nフォーマットは、生のゾーンファイルのフォーマットバージョンを指定する。 Nの値が0の場合、namedコマンドのどのバージョンでも生ファイルが読み込まれる。 Nの値が1の場合、ファイルはリリース9.9.0以降で読み込まれる。 n のデフォルト値は 1 です。
-h 使用状況の要約を表示して終了する。
-i mode ポストロードのゾーン整合性チェックを行う。 modeパラメータは以下の値を取る：
フル
MXレコード、サービス（SRV）レコード、および委任NSレコードがAまたはAAAAレコード（ゾーン内およびゾーン外のホスト名）を参照しているかどうかをチェックする。 また、ゾーン内のglueアドレスレコードが、子プロセスがアドバタイズする ものと一致するかどうかもチェックする。
full-sibling
兄弟のグルー・チェックを使用不可にしますが、その他の点では、モード full と同じです。
ローカル
MXレコード、SRVレコード、および委任NSレコードがゾーン内のホスト名を 参照しているかどうか、あるいはネームサーバーが子ゾーンにある場合に 必要なグルーが存在するかどうかだけをチェックする。
local-sibling
兄弟のグルー・チェックを使用不可にしますが、その他の点では、モード local と同じです。
none
チェックを使用不可にします。
-j ゾーンファイルのロード時にジャーナルが存在すれば、それを読み込む。 ジャーナルファイル名は、ゾーンファイル名に文字列'.jnlを付加したものとする。
-J ファイル名 ゾーン・ファイルのロード時にジャーナル・ファイルの読み取り元となるファイルを指定します。 -J フラグは、 -j フラグを暗黙指定します。
-k mode 指定された障害モードで check-names 検査を実行します。 可能なモードは「fail、「warn（デフォルト）、「ignore。
-l トル 入力ファイルに許容される最大存続時間 (TTL) を設定します。 TTL がこの値より大きいレコードがあると、ゾーンはリジェクトされます。 このフラグは、「named.confファイルの「max-zone-ttlオプションに似ている。
-L シリアル ゾーン・ファイルがロー・フォーマットまたはマップ・フォーマットにコンパイルされるときに、ヘッダー内のソース・シリアル値を、指定されたシリアル番号に設定します。 このフラグはテスト目的でのみ使用する。
-m mode MX レコードがアドレスであるかどうかを知るために、それらをチェックする必要があるかどうかを指定します。 可能なモードは「fail、「warn（デフォルト）、「ignore。
-M mode MXレコードが正規名(CNAME)を参照しているかどうかを調べる。 可能なモードは「fail、「warn（デフォルト）、「ignore。
-n mode NS レコードがアドレスであるかどうかを知るために、それらをチェックする必要があるかどうかを指定します。 可能なモードは「fail、「warn（デフォルト）、「ignore。
-o ファイル名 ゾーン出力をfilename値で指定されたファイルに書き込む。 ファイル名変数の値が'-場合、ゾーン出力は標準出力に書き出される。 このオプションはnamed-compilezoneでは必須である。
-q 抑止モードを示します (出口コードのみ)。
-r mode Domain Name System Security Extensions (DNSSEC)では異なるレコードとみなされるが、Domain Name System (DNS)では意味的に等しいレコードをチェックする。 modeパラメータに有効な値は、「fail、「warn（デフォルト）、「ignoreである。
-s スタイル ダンプされたゾーン・ファイルのスタイルを指定します。 可能なスタイルは、 full (デフォルト) および relativeです。 ゾーンファイルの'fullフォーマットは、別のスクリプトでゾーンファイルを 自動的に処理するのに適している。 あるいは、'relative形式はより人間が読みやすく、ゾーンファイルを手動で 編集するのに適している。 このフラグは、ゾーンファイルの内容がダンプされた後にのみ効果を発揮する。 また、出力フォーマットがテキストでない場合は何の意味もありません。
-S mode SRVレコードがCNAMEを参照しているかどうかを調べる。 可能なモードは「fail、「warn（デフォルト）、「ignore。
-t ディレクトリ 設定ファイル中の '$INCLUDEディレクティブが処理されるように、 ルートディレクトリを指定されたディレクトリに変更する。
-v named-checkzoneコマンドのバージョンを表示して終了する。
-w ディレクトリ 主ファイル $INCLUDE ディレクティブの相対ファイル名が機能するように、カレントディレクトリを指定したディレクトリに変更します。 -wオプションは、「named.confファイルのディレクトリ節に似ている。
-W mode 非端末のワイルドカードの有無をチェックするかどうかを指定します。 非端末のワイルドカードは、ワイルドカード・マッチング・アルゴリズム (RFC 1034) の解釈に失敗した結果として発生する場合がほとんどです。 可能なモードは、 warn (デフォルト) および ignoreです。
zonename チェックするゾーンのドメイン名を指定する。
ファイル名 ゾーン・ファイルの名前を指定します。
