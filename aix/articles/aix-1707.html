目的

コマンドを別の UNIX ベースのシステムで実行します。

構文

ユクス [ -c | -C ] [ -n | -z ] [ - ] [ -a名称 ] [ -b ] [ -gグレード ] [ -j ] [ -p ] [ -e ] [ -r ] [ -sファイル ] [  -xデバッグレベル ] CommandString

説明

uux コマンドは、ローカル・システム上でのユーザーの作業は継続しながら、 指定された UNIX ベースのシステム上で指定コマンドを実行する基本ネットワーク・ユーティリティー (BNU) コマンドです。 要求されたコマンドを実行する前に、 uux コマンドは指定されたシステムから必要なファイルを収集します。 コマンドの出力データは、特定システム上の特定ファイルに送信することができます。 セキュリティーのために、ほとんどのインストール・システムでは、 uux コマンドは rmail コマンドしか実行できないようになっています。

他のシステム上の uux コマンドは実行されます (X.*)。 ローカル・システムでコマンドを実行するファイル。 さらに、ローカル・システム上の uux コマンドは両方のコマンド (C. *) を作成します。 ファイルおよびデータ (D. *) ファイルを他のシステムに転送します。 実行ファイルには指定されたシステムで実行されるコマンド・ストリングが入ります。 コマンド・ファイルには uucp コマンドで作成するのと同じ情報が入ります。 データ・ファイルには、リモート・コマンド実行用のデータが含まれているか、または X.* になります。 リモート・コマンド実行のためのリモート・システム上のファイル。

実行ファイルの絶対パス名の形式は、以下のとおりです。

/var/spool/uucp/System/X.SystemNxxxx

スプール・ディレクトリー内にファイルを作成すると、 uux コマンドは uucico デーモンを呼び出して、 それらのファイルをローカル・システム上のスプール・ディレクトリーから指定されたリモート・システムに転送します。 ファイルが転送されると、リモート・システム上の uuxqt デーモンは、 指定したシステム上で CommandString を実行し、 コマンドのすべての出力データを元の uux コマンド要求に指定されたファイルに入れます。

CommandString 引数は、 オペレーティング・システムのコマンド・ラインと同じような 1 つ以上の引数から構成されます。 ただし、CommandString の前には、 System! という形式でリモート・システムの名前が接頭部として付けられます。 デフォルトの System はローカル・システムです。 uux コマンドを入力するユーザーが -n フラグを指定しない限り、リモート・システムがコマンドを実行しない場合、コマンドはそのユーザーに通知します。 この応答はリモート・システムからメールで送信されます。

ソース・ファイル名と宛先ファイル名

  • コマンドの出力の宛先を指定する場合、 uux コマンドは以下のいずれかの形式で入力できます。
    • uux[Options]"CommandString> Destination"
    • uux[Options]CommandString {Destination}.
  • 宛先名は、以下のいずれかにすることができます。
    • 絶対パス名
    • 前に ~Userが付いた絶対パス名。ここで、 User は指定されたシステム上のログイン名です。 uux コマンドは、このパス名をユーザーのログイン・ディレクトリーに置き換えます。
  • シェル・パターン・マッチング文字? (疑問符)、* (アスタリスク)、および [...] (大括弧) は、ソース・ファイル ( diff コマンドによって比較されるファイルなど) のパス名に使用できます。該当するシステムがそれらを展開します。 しかし、* 文字を使用すると、予想外の結果になることがあります。 したがって宛先ファイルのパス名にはシェル・パターン・マッチング文字を使用しないでください。
  • 円記号を 2 つ (¥.) にします。 \) または引用符のペア (".... 「) ローカル・シェルが uux コマンドが指定されたシステムにコマンドを送信する前にパターン・マッチング文字を解釈できないようにするために、パス名の中でパターン・マッチング文字を囲みます。
  • パス名に特殊シェル文字> (より大)、< (より小)、; (セミコロン)、または | (垂直バー) を使用している場合は、いずれかを ¥. ¥ または "..." 個々の文字を囲むか、コマンド・ストリング全体を囲むかを指定します。
  • パス名にシェル・リダイレクト文字 < < または>> を使用しないでください。
  • uux コマンドは、コマンド行に指定されたすべてのファイルを指定されたシステムに移動しようとします。 出力ファイルはすべて括弧で囲み、 uux コマンドで転送されないようにしてください。
  • Systemを指定する場合は、常にエントリー内の CommandString 引数の前に配置してください。 システム名には ASCII 文字以外は使用できません。
  • ! コマンド内でローカル・システムの名前の前にある (感嘆符) はオプションです。 「!」を含めることを選択した場合は、 2 つの異なるリモート・システムからのファイルを使用してローカル・システムでコマンドを実行するには、! Systemの代わりに ローカル・システムを表し、 Systemを追加します。 リモート・システム上の任意のパス名の最初の項目として使用することができます。
  • BNU 構文のシステムを表す感嘆符は、C シェルでは異なる意味を持ちます。 uux コマンドを C シェルで実行するときには、 システム名の感嘆符の前に &#xa5; (円記号) を入れてください。

    “注 : ~ (ティルド) は公開スプール・ディレクトリー /var/spool/uucppublic を指定する短縮形です。”

フラグ

項目
説明
- uux コマンドへの標準入力を CommandString 引数への標準入力にします。
-a名前 コマンドを発行するユーザーのユーザー ID を Name 変数に指定されたユーザー ID に置換します。
-b 終了状態が 0 でないとき、標準入力をコマンドへ戻します。
-c 指定されたシステム上の宛先にソース・ファイルを転送します。 ソース・ファイルをスプール・ディレクトリーにコピーし、 直後に uucico デーモンを呼び出します。 このフラグはデフォルトです。
-C ソース・ファイルをスプール・ディレクトリーに転送します。 設定時間 (uusched プログラムで指定する) が経過すると、 uucico デーモンはファイルを指定コンピューターの宛先に転送します。

ソース・ファイルの転送で問題が起きることがあります。 例えば、リモート・マシンが稼働していなかったり、ログインができない場合などです。 このような場合は、ファイルは正しく転送されるまで、 または uucleanup コマンドで除去されるまで、 スプール・ディレクトリーに残ります。
項目
説明
-e ファイルの拡張を可能にします。
-gグレード 指定の接続の際に、ファイルを転送する時期を指定します。 Grade 変数には、 1 桁の数値 (0 から 9 まで) または文字 (A から Z まで、a から z まで) を指定します。 下位の ASCII シーケンス文字を使用すると、 上位のシーケンス番号の場合よりも早いファイルが転送されます。 数値 0 はグレードとしては最上位 (最も早い) であり、z は最下位 (最も遅い) となります。 デフォルトは Nです。
-j 指定システムでコマンドを実行しているプロセスのジョブ識別番号を表示します。 このジョブIDをBNUuustatコマンドで使用してコマンドのステータスをチェックするか、uustat-kフラグでプロセスを終了する。
-n コマンドの成功または失敗が、 mail コマンドによってユーザーに通知されるのを抑制します。 デフォルトではコマンドが失敗したかどうかが、ユーザーに通知されます。
-p uux コマンドへの標準入力を CommandString 引数への標準入力として使用します。 - (マイナス) を指定しても同じ働きとなります。
-r システム間でファイルを転送するスプール・プログラムの始動を抑制します。 デフォルトではスプール・プログラムが始動されます。
-sファイル 指定システム上にある、File 変数に指定されたファイル内の転送状況を通知します。 ファイル名には ASCII 文字以外は使用できません。
-xデバッグレベル デバッグ情報をローカル・システムの画面に表示します。 DebugLevel 変数は、0 から 9 までの数値でなければなりません。 数値が大きいほど、より詳細なレポートが作成されます。
-Z コマンドが正しく実行されたかどうかをユーザーに通知します。 このフラグは、エラー・イベントだけを通知するシステム・デフォルトとは反対の動作をします。

例

  1. リモート・システムで qprt コマンドを実行するには、次のように入力します。
    uux merlin!qprt /reports/memos/lance
    この例では、リモート・ファイル /reports/memos/lanceリモート・システムで印刷されるmerlin... -n フラグも -z フラグも指定されていないため、 uux コマンドがユーザーに通知するのは、リモート・システムがコマンドの実行に失敗した場合だけです。 リモート・システムからの応答は mail コマンドによって通知されます。
  2. 2 つのリモート・システムでコマンドを実行するには、以下のように別々のコマンド行に情報を入力します。
    uux merlin!qprt /reports/memos/lance
uux zeus!qprt /test/examples/examp1
    この例では、/reports/memos/lanceファイルはリモート・システムで印刷されますmerlin、およびリモート/test/examples/examp1ファイルはリモート・システムで印刷されますzeus... -n フラグも -z フラグも指定されていないため、 uux コマンドがユーザーに通知するのは、リモート・システムがコマンドの実行に失敗した場合だけです。 リモート・システムからの応答は mail コマンドによって通知されます。
  3. ローカル・システム上のファイルとリモート・システム上のファイルを比較するジョブを、ローカル・システム上の diff コマンドを使用してキューに入れ、ジョブのジョブ ID を取得するには、次のように入力します。
    uux  -j "/usr/bin/diff /usr/amy/f1 hera!/home/amy/f2 > ~/f1.diff"
    この例では、/usr/amy/f1ローカル・システム上のファイルと比較されます。/home/amy/f2リモート・システム上のファイルhera出力は次の場所に置かれます。f1.diffローカル・パブリック・ディレクトリー内のファイル (このファイルの絶対パス名は以下のとおりです。/var/spool/uucppublic/f1.diff)。 宛先名は、> の前にコマンド・ストリング全体を "" (引用符) で囲んで入力するか、または ¥ { DestinationName ¥}のように中括弧と円記号で囲んで入力する必要があります。 -j フラグを指定すると、 uux コマンドはそのジョブの BNU ジョブ ID を戻します。
  4. ローカル・システムで diff コマンドを使用して、2 つの異なるリモート・システムにあるファイルを比較するには、次のように入力します。
    uux "!/usr/bin/diff hera!/usr/amy/f1 venus!/home/amy/f2 > \ !f1.diff"
    この例では、/usr/amy/f1リモート・システムからのファイルhera以下と比較されます。/home/amy/f2リモート・システムからのファイルvenus出力はファイルに入れられます。f1.diffローカル・システム上の現行作業ディレクトリーにあります。

    出力ファイルは書き込み可能でなければなりません。 特定の目標出力ファイルの許可状況がわからない場合には、 出力結果の宛先は公開ディレクトリーにしてください。 ローカル・システムを表す感嘆符はオプショナルです。 宛先名は、> の前にコマンド・ストリング全体を "" (引用符) で囲んで入力するか、または ¥ { DestinationName ¥}のように中括弧と円記号で囲んで入力する必要があります。

  5. 異なるシステムの 2 つの別個のファイルで diff コマンドを実行するには、次のように入力します。
    uux "hera!/usr/bin/diff /tmp/out1 zeus/tmp/out2 > ~/DF"
    この例では、diffファイルがリモート・システム上にあるhera最初のソース・ファイルはリモート・システム上にあります。hera2 次ファイルはシステム上にあります。zeus. (zeusローカル・システムまたは別のリモート・システムである可能性があります。) 出力はローカル・システム上の公開ディレクトリーのファイル DF に入ります。
  6. 別のリモート・システム上の出力ファイルを指定するには、次のように入力します。
    uux hera!uucp venus!/home/amy/f1 \{merlin!/home/geo/test\}
    この例では、 uucpuucp Command コマンドがリモート・システム上で実行されます。hera、および/home/amy/f1ファイル、システムに保管されるvenusはユーザーに送信されますgeoシステム上merlinとしてtest宛先名は、中括弧と円記号で囲んで入力します。
  7. リモート・システム上のファイルから選択したフィールドを取得し、それらをローカル・システム上のファイルに入れるには、次のように入力します。
    uux "cut -f1 -d: hera\!/etc/passwd > ~/passw.cut"
    cut コマンドはローカル・システムで実行されます。 システム上のパスワード・ファイルの各行の最初のフィールドheraが次の場所に配置されるpassw.cutローカル・システム上の公開ディレクトリー内のファイル。 uux コマンドは C シェルで実行されているので、\(円記号) は、リモート・システムの名前の感嘆符の前になければなりません。
  8. uux パイプ・オプションを使用してリモート・コピーを指定するには、次のようにします。/tmp/exampleファイルから/tmp/examplecopyシステム上mercury使用する構文は、次のとおりです。
    uux -p mercury!
cp /tmp/example /tmp/examplecopy
    コマンド入力を終了するには、Ctrl-D を入力しなければなりません。 Ctrl-D を押すと、コマンドはシステム上でリモート実行のためにスプールされます。 mercury.
