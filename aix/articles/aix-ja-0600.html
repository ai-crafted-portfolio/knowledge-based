目的
IKE データベース中の情報を検索、更新、削除、インポート、エクスポートします。

説明
ikedb
コマンドによって、ユーザーは IKE データベースへの書き込み (
put
)、または IKE データベースからの読み取り (
get
) ができます。 入出力フォーマットは XML (Extensible Markup Language) ファイルです。 XML ファイルのフォーマットは、その DTD (Document Type Definition) で指定されます。
ikedb
コマンドによって使用されている DTD を確認し、put を実行する際に XML ファイルの妥当性を検査できます。
-e
フラグを使用して DTD にエンティティーの宣言を追加できます。これが DTD に対して行える唯一の変更です。
入力 XML ファイルのすべての外部 DOCTYPE 宣言は無視されます。また、内部 DOCTYPE 宣言はエラーの原因となる場合があります。 DTD を使用して XML ファイルを構文解析するために従う規則は、XML 標準で指定されています。
/usr/samples/ipsec
には、一般的なトンネル・シナリオを定義する標準的な XML ファイルのサンプルがあります。

構文
イケドブ P- [ F 秒 ] [ -e (E) エンティティー・ファイル ] [ XML ファイル ] イケドブ - [ R ] [ T タイプ [ N 名前 | I ID -y (Y) ID タイプ ] ] イケドブ -d 年 T タイプ [ N 名前 | I ID -y (Y) ID タイプ ] イケドブ 「-c」 [ F 値 ] [ - Linux ファイル ] [ -k (K) シークレット・ファイル ] [ 「-f」 XML ファイル ] イケドブ -x (X) イケドブ -

オプション
フラグ
LDAP でサポートされた操作を使用するには、ホストを LDAP クライアントとして構成します。
項目 | 説明
-p | XML-file の指定に基づいてデータベースに書きこむ put を実行します。 -F 指定されたトンネル、保護、プロポーザル、グループ、または事前共有キーがデータベース内に存在するデータを上書きする場合でも、put を強制します。 デフォルトでは、このような put 動作は失敗します。 -R スイッチが存在するとき、名前が構成内のホストで該当するポリシーの一部として指定された名前と重複している場合、ローカル・エンティティーが上書きされます。 -s すべてのトンネルのローカル ID とリモート ID を交換します。 このフラグによって、ピア・システムによって生成されたトンネルのインポートが容易になります。 このフラグはトンネルにのみ影響を与えます。 このオプションは、トンネルのリモート ID のいずれかがグループの場合には無効です。 --e 実体ファイル entity-file によって定義された <!ENTITY ...> 行を含むファイルの名前を指定します。 これらの行は内部 DTD に追加され、ユーザーが XML ファイルを他の XML ファイルにインクルードできるようになります。 XML ファイル 使用される XML-file を指定します。これは、コマンド・ライン中の最後の引数である必要があります。 XML-file は、書き込みの対象がトンネル、保護、プロポーザル、事前共有キー、またはそれらのすべてのいずれであるのかを決定します。 XML-file が指定されない場合、入力は stdin から読み取られます。 stdin を指定するには、- (ハイフン) が使用できます。 -R LDAP 有効な値は LDAP です。 -p が -R スイッチと結合して使用される場合、該当する IPSec 構成ポリシーに関連付けられた XML 構成ファイルを LDAP サーバーからインポートすることによって PUT 操作が行われます。
-h | ホスト名または IP アドレスを -A フラグまたは -D フラグと一緒に指定します。 IP アドレスには IPv4 または IPv6 を指定できます。

-g | get を実行します。IKE データベースに保管されたものが表示されます。 出力は XML フォーマットで stdout に送信されます。これは、 ikedb -p での処理に適しています。 -r 再帰。 このフラグをフェース 1 トンネルに指定すると、情報はすべての関連付けられたフェーズ 2 トンネルおよび両方のトンネルに関連付けられたすべての保護とプロポーザルにも返されます。 --t タイプ 要求された出力の type を指定します。 Type には、 IKETunnel 、 IPSecProtection などのような AIX_VPN に基づく任意の XML エレメントを指定できます。 これが省略された場合、データベース全体が出力されます。 - 名 要求されたオブジェクトの name を指定します。 Name には、 -t フラグの値に応じて、プロポーザル、保護、トンネル、またはグループの名前を指定できます。 -n フラグは、 IKEPresharedKey を除き、 -t フラグで指定されたすべての値で有効です。 これが省略された場合には、指定された type のすべてのオブジェクトが出力されます。 - ID 事前共有キーに関連付けられた ID を指定します。 -i フラグが有効なのは、 -t フラグの値 IKEPresharedKey と共に使用される場合だけです。 これが省略された場合には、指定された type のすべてのオブジェクトが出力されます。 -i フラグは -y フラグと共に使用する必要があります。 --y IDタイプ I フラグで定義された ID タイプ を指定します。 ID-type には、 User_FQDN 、 IPV4_Address などのような XML ファイルで有効な任意のタイプを指定できます。 -y フラグは -i フラグと共に使用する必要があります。 -R LDAP 有効な値は LDAP です。 -g フラグが -R スイッチと結合して使用される場合、ローカル・ホストに関連付けられたポリシーについて LDAP サーバーに保管された XML 構成ファイルを表示することによって GET 操作が行われます。 ポリシー名も提供される場合は、ポリシーの一部として保管された xml ファイルが stdout に表示されます。
-d | データベースの指定された項目に対して delete を実行します。 このフラグは、 -r がサポートされていないことを除き、 -g フラグと同じです。

-C | 関連付けられたクライアントで使用される IPSec 証明書を指定するために使用されます。
-c | Linux®IPSec構成ファイルからXML形式の AIX IPSec構成ファイルへの変換を実行します。 これは、 Linux 環境からの 1 つまたは 2 つのファイル、構成ファイル、および場合によっては事前共有鍵を持つ秘密ファイルを入力として必要とします。 -F 指定されたトンネル、保護、プロポーザル、グループ、事前共有キーがデータベース中の既存のデータを上書きする場合でも、 put を実行します。 デフォルトでは、このような put 動作は失敗します。 -f フラグも使用されている場合、 -F フラグには効果はありません。 --l Linuxファイル Linux ファイル によって定義される Linux 構成ファイルを指定します。 ファイルが指定されない場合、システムは現行ディレクトリー中で ipsec.conf ファイルを検索します。 - 秘密ファイル シークレット・ファイル パラメーターで定義されている Linux 事前共有鍵ファイルを指定します。 ファイルが指定されない場合、システムは現行ディレクトリー中で ipsec.secrets ファイルを検索します。 --f XMLファイル Linux 構成ファイルの変換先の XML 構成ファイルを指定します。 デフォルトの動作は、IKE データベースに直接 PUT 操作を行うことです。 ファイル名にハイフン (-) がある場合、結果は stdout に送信されます。 このフラグは、-R スイッチもコマンド・ラインにある場合は無効です。
-x | データベース上で expunge 操作を実行します。 このフラグはデータベースを空にします。 このフラグは、 -R フラグもコマンド・ラインにある場合は無効です。
-o | ikedb コマンドで使用される XML ファイルのすべてのエレメントおよび属性を指定する DTD の output を実行します。 DTD は stdout に送信されます。 -R スイッチがある場合、LDAP 上の構成ポリシーの一部として保管することを許可された XML ファイルについてすべてのエレメントおよび属性を指定する DTD が stdout に送信されます。

-A | 提供された IP アドレスをポリシー名と関連付けます。 IP アドレスが提供されていない場合、ローカル・ホスト用の最初のローカル IPV6 アドレスが選択され、ポリシーと関連付けられます。 ポリシー構成は、LDAP から XML ファイルをダウンロードして、データベースにそれを put することによって実行されます。 このように定義されたトンネルが活動化されます。 -f < -path to XML file > XML ファイルが提供されている場合、定義されたポリシーに適用できる新規の XML として LDAP サーバーに保管されます。 ポリシーが存在していない場合は、このフラグが必須です。 -R LDAP 有効な値は LDAP です。 このスイッチはコマンド・ラインで提供されている必要があります。
-D | LDAP サーバーで構成ポリシーと IP の関連付け解除を実行します。 このフラグは、 -R スイッチなしでは無効です。 R スイッチに有効な唯一の値は LDAP です。 - F 指定されたポリシーに関連付けられた最後の IP アドレスが除去されると、このスイッチにより、対応するポリシー・データ (XML 構成ファイル) が LDAP サーバーから削除されます。 このフラグが使用されていない場合は、ポリシーが LDAP サーバーから削除されることはありません。

例
ピア・マシン上で生成された XML ファイルから IKE データベースに定義を
put
し、データベース中の既存のオブジェクトを同じ名前で上書きするには、次のように入力します。
ikedb -pFs peer_tunnel_conf.xml
peer_tunnel_conf.xml
は、ピア・マシン上で生成された XML ファイルです。
tunnel_sys1_and_sys2
という名前のフェーズ 1 トンネルと、それぞれのプロポーザルと保護を持つすべての従属フェーズ 2 トンネルの定義を
取得
するには、次のように入力します。
ikedb -gr -t IKETunnel -n tunnel_sys1_and_sys2
データベースからすべての事前共有キーを
delete
するには、次のように入力します。
ikedb -d -t IKEPresharedKey
IP アドレス 10.10.10.1 を持つホストを、XML ファイル ldap.xmlを持つ証明書
/C=US/O=IBM/CN=test01.austin.ibm.com
を持つ Poll という名前の構成ポリシーに
関連付ける
には、次のように入力します。
ikedb -R LDAP -A Pol1 -f ldap.xml -h 10.10.10.1 -C /C=US/O=IBM/CN=test01.austin.ibm.com
