目的
リソースまたはリソース・クラスの永続属性値を変更します。

説明
chrsrc
コマンドは、リソースまたはリソース・クラスの永続属性値を変更します。 デフォルトでは、このコマンドは、
リソース
の永続
属性値を変更します。
resource_handle
にリンクされているリソースの永続属性値のみを変更するには、
-r
フラグを使用します。
selection_string
と一致するすべてのリソースの永続属性値を変更するには、
-s
フラグを使用します。
リソース・クラス
の永続属性を変更するには、
-c
フラグを使用します。
selection_string
に複数のノード名を指定する代わりに、
-N
node_file
フラグを使用して、ノード名がファイル内にあることを示すことができます。 標準入力からノード名を読み取るには、
-N "-"
を使用します。
chrsrc
コマンドは、動的属性を変更することも、
read_only
として指定された永続属性を変更することもできません。 コマンド行または
resource_data_input_file
に指定されたすべての属性名が永続属性として定義されており、
read_only
として指定されて
いない
ことを確認するには、
-v
フラグを使用します。
-v
フラグを指定して
chrsrc
コマンドを実行すると、指定された属性は変更されませんが、代わりに単に永続であることが検証され、
read_only
として指定されません。
chrsrc
-v
を実行して、コマンド行または
resource_data_input_file
で指定された属性が有効であることを確認したら、
-v
フラグを指定せずに
chrsrc
コマンドを発行して、実際に属性値を変更することができます。 ただし、
chrsrc
-v
の実行時に属性が「渡される」という理由だけでは、属性を変更できないことに注意してください。 指定されたリソースを制御する基礎となるリソース・マネージャーが、
chrsrc
コマンドで変更できる属性を決定します。
chrsrc
が
-v
フラグなしで実行されると、指定された属性を変更できなかったかどうかを示すエラー・メッセージが表示されます。
システムにクラスター・システム・マネージメント (CSM) がインストールされている場合は、CSM 定義のノード・グループをノード名の値として使用して、複数のノードを参照できます。 CSM ノード・グループの処理および CSM
nodegrp
コマンドの使用については、「
CSM: 管理ガイド
」および「

CSM: コマンドおよびテクニカル・リファレンス
」を参照してください。

構文
次のデータを使用して、 リソース の永続 属性値を変更するには、次のようにします。 コマンド・ラインで入力する場合: chrsrc -s " 選択ストリング " [ -a │ -N { ノード・ファイル │ "-" } ] [ -v ] [ -h ] [ -TV ] リソース・クラス属性 = 値 … chrsrc -r [ -v ] [ -h ] [ -TV ] resource_handle attr = value ... 入力ファイルでは次のように事前定義されています。 chrsrc -f resource_data_input_file -s " selection_string " [ -a | -N { node_file | "-" }] [ -v ] [ -h ] [ -TV ] resource_class chrsrc -f リソースデータ入力ファイル -r [ -v ][ -h ][ -TV リソースハンドル 次のデータを使用して、 リソース・クラス の永続 属性値を変更するには、次のようにします。 コマンド・ラインで入力する場合: chrsrc { -c | -C domain_name ...} [ -v [ -a ] [ -h ] [ -TV ] resource_class attr = value ... 入力ファイルでは次のように事前定義されています。 chrsrc -f resource_data_input_file { -c | -C domain_name ...} [ -v ][ -a ][ -h ][ -TV リソースクラス

オプション
フラグ
-a
このコマンドをクラスター内のすべてのノードに適用することを指定します。 CT_MANAGEMENT_SCOPE 環境変数は、クラスターの有効範囲を決定します。 CT_MANAGEMENT_SCOPE が設定されていない場合、コマンドにとって有効な範囲になるまで、最初に管理ドメイン有効範囲 (存在する場合) を選択し、次にピア・ドメイン有効範囲 (存在する場合) を選択し、次にローカル有効範囲を選択します。 コマンドは、最初に見つかった有効範囲に対して、1 回実行されます。 例えば、管理ドメインとピア・ドメインの両方が存在する場合に CT_MANAGEMENT_SCOPE が設定されていないと、このコマンドは管理ドメインに適用されます。 このコマンドをピア・ドメインに適用する場合は、CT_MANAGEMENT_SCOPE を
2
に設定してください。
-c
resource_class

ドメイン名...

管理サーバーで定義されているすべてのピア・ドメイン上のグローバル化されたリソース・クラスのクラス属性を変更するには、
-C

-a

-c

-N

node_file

1 桁目の番号記号 (

ノード名の左のブランク文字はすべて無視されます。

CT_MANAGEMENT_SCOPE 環境変数は、クラスターの有効範囲を決定します。 CT_MANAGEMENT_SCOPE が設定されていない場合、コマンドにとって有効な範囲になるまで、最初に管理ドメイン有効範囲 (存在する場合) を選択し、次にピア・ドメイン有効範囲 (存在する場合) を選択し、次にローカル有効範囲を選択します。 コマンドは、最初に見つかった有効範囲に対して、1 回実行されます。 例えば、管理ドメインとピア・ドメインの両方が存在する場合に CT_MANAGEMENT_SCOPE が設定されていないと、このコマンドは管理ドメインに適用されます。 このコマンドをピア・ドメインに適用する場合は、CT_MANAGEMENT_SCOPE を
2

resource_handle

"selection_string
