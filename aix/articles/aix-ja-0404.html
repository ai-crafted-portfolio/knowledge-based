目的
指定された引数のある CDE アクションを起動します。

説明
dtaction
コマンドを使用すると、CDE 開発環境に接続されていないアプリケーションまたはシェル・スクリプトがアクション要求を呼び出すことができます。
action_name
と呼ばれるアクションが、コマンド・ラインで提供される
action_arg
と一緒に起動されます。
単一の
action_name
が必要です。ユーザーは任意の数の
action_args
を提供できます。
action_name
および
action_args
の解釈は、アクション・データベース内のアクションの定義によって決まります。
アクションは、システム・アクション・データベース・ファイルの 1 つまたはユーザーの私用アクション・データベース・ファイルの 1 つに定義できます。
action_args
は、ファイルの絶対パス名または相対パス名です。
dtaction
コマンドは、このファイルのリストを指定されたアクションに渡します。
以下の条件が検出されると、エラー・ダイアログが通知されます。
デスクトップ環境が初期化できない
ユーザーまたはパスワードが無効
要求されたユーザーに ID を変更できない
アクション名が指定されていない

構文
dtaction [ -contextDir context_dir ] ¥ [ -execHost ホスト名 ] [ -termOpts ターミナル引数］ [ -user ユーザー名 ] アクション名 [ action_arg ]...

オプション
フラグ
項目 | 説明
contextDir コンテキスト・ディレクトリ | コマンド・アクションの現在の作業ディレクトリーが action_name の定義内で定義されていない場合は、デフォルトのディレクトリー・コンテキストを指定します。
execHost ホスト名 | コマンド・アクションの代替実行ホスト host_name を指定します。 アクションがコマンド・アクションでない場合、 dtaction コマンドはこのオプションを無視します。 アクションの EXEC_HOST 仕様で指定されたホストではなく、 host_name に対してアクションが試行されます。 指定されたアクションがいずれかの適格ホストで起動できない場合は、エラーが通知されます。
termOpts ターミナル引数 | タイプ NO_STDIO 以外のコマンド・アクション用に提供される端末エミュレーターを対象とする引数を指定します。 terminal_arguments 文字列の中にホワイト・スペース文字がある場合、その文字列を引用符で囲んで、シェルから保護する必要があります。 これらの引数は変更されずに端末エミュレーターに渡されるので、ユーザーは妥当な文字列を使用する必要があります。 特に、 terminal_arguments では、コマンドを指定する引数を端末エミュレーター・ウィンドウで (つまり、 -e フラグを指定した dtterm1 を使用して) 実行することはできません。
user ユーザー名 | ユーザー名を指定します。 dtaction が現在そのユーザーとして実行されていない場合、プロンプト・ダイアログで、指定されたユーザー・パスワードまたは root ユーザー・パスワードを収集します。 有効なパスワードを入力すると、 dtaction コマンドは、要求されたユーザーとして実行されるように変更され、要求されたアクションを開始します。

例
アクションを起動するには、次のように入力します。
dtaction Xterm
X Windows端末エミュレータ(Xterm)を起動します。
リモート・ホストでアクションを起動するには、次のように入力します。
dtaction -execHost hostname Xterm
これで、指定されたリモート・ホスト上で Xterm が実行されます。
別のユーザーとしてアクションを起動するには、次のように入力します。
dtaction -user username Xterm
これで、指定されたユーザーとして Xterm が実行されます。
