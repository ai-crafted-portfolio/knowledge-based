目的
低帯域幅 X プロキシー。

説明
lbxproxy
コマンドはクライアントの接続を受け入れ、単一接続を通じてそれらを X サーバーに多重接続し、
低帯域幅または高待ち時間接続 (あるいはその両方) によってより高速な通信を行うために、X プロトコル上で各種の最適化を実行します。 X への低帯域幅拡張機能を利用したいアプリケーション (
LBX
)
lbxproxy
への接続を確立する必要があります。 これらのアプリケーションは、何も知らない必要があります。
LBX
通常のサーバーであるかのように、単に
lbxproxy
に接続します。
認証/許可に関しては、
lbxproxy
はクライアントが提示したクリデンシャルをサーバーに伝えます。 X クライアントは
lbxproxy
に接続するので、ユーザーの
.Xauthority
ファイルに、
プロキシーのネットワーク ID に関連した有効なキーを持つエントリーが含まれていることが重要です。
lbxproxy
は、これらのエントリーがどのようにして
.Xauthority
ファイルに追加されるかについては関与しません。 このファイルの設定はユーザーの責任で行います。
lbxproxy
プログラムには各種のフラグがあり、そのすべてがオプションです。
: <
Display
>
が指定されている場合、プロキシーは接続を listen するときに
Display
ポートを使用します。 このディスプレイ・ポートはポート 6000 からのオフセットで、通常の X ディスプレイ接続が指定される方法と同一です。 コマンド・ラインにポートを指定しないと、
lbxproxy
はデフォルトとしてポート 63 を使用します。 プロキシーが listen を試行したポートが使用中の場合、プロキシーはエラー・メッセージを出して終了します。
lbxproxy
は始動時に、アトムの構成可能なリストをプリインターンします。 これにより
lbxproxy
は、アトムのグループを 1 回の往復でインターンし、
その結果を即時にキャッシュに格納することができます。 実行中、
lbxproxy
は発見的手法を使用して、ウィンドウ属性データのサーバーへの送信をいつ遅らせるかを決定します。 発見的手法は、データのサイズ、属性の名前、およびウィンドウ・マネージャーが同じ
lbxproxy
を通じて実行中かどうかによって決まります。 アトム制御は
AtomControl
ファイルに指定され、
lbxproxy
のインストール時に、コマンド・ラインの指定変更によって設定されます。

このファイルは単純なテキスト・ファイルです。 行の形式には、コメント、長さ制御、および名前制御の 3 通りがあります。
!
(感嘆符) で始まる行は、 コメントと見なされます。 形式 z 長の行は、属性データを遅らせる前の最小の長さ (バイト単位) を指定します。 形式オプション atomname の行は、所定のアトムを制御します。
ここで、オプションは次の文字の任意の組み合わせとなります。
すなわち、
i
はアトムがプリインターンされることを意味し、
w
は、
ウィンドウ・マネージャーも同じ
lbxproxy
を通じて実行中の場合にのみ、
この名前を持つ属性のデータを遅らせる必要があることを意味します。

構文
lbxproxy [ :< 表示 >] [ -ヘルプ ] [ -表示 表示 ] [ -モーション 数値 ] [ -終了 | -リセット ] [ -再接続 ] [ -I (I) ] [ -nolbx (N) ] [ -非圧縮 ] [ -デルタなし ] [ -タグなし ] [ -nogfx ] [ -noimage (イメージなし) ] [ -ノスクイッシュ ] [ -nointernsc ] [ -noatomsfile ] [ -atomsfiles ファイル ] [ -非属性 ] [ -noグラブマップ ] [ -norgbfile ] [ -rgbfile パス ] [ -tagcachesize ] [ -zlevel レベル ] [ -比較統計 ] [ -ノゼロパド ] [ -cheaterrors (エラー) ] [ -虎の巻 ]

オプション
フラグ
項目 | 説明
-atomsfile ファイル | デフォルトの AtomControl ファイルを指定変更します。
-詐欺師 | パフォーマンスの改善のために X プロトコル上の詐取を可能にします。 X プロトコルは、直前の要求によって生成された返信、イベントまたはエラーのどれでも、 後の要求で生成されたものより先に送信することを保証します。 これにより、 lbxproxy がいつ要求を短絡できるかについて実質的な制限が設けられます。 -cheaterrors フラグは、 lbxproxy がエラーに関しては X プロトコルの規則に違反することを可能にします。 このオプションはユーザーの責任において使用してください。
-イベント | -cheatevents フラグは、 lbxproxy がエラーはもちろんイベントに関しても X プロトコルの規則に違反することを可能にします。 このオプションはユーザーの責任において使用してください。
-コンプスタッツ | プロキシーがリセットするつど、または SIGHUP シグナルを受信するつど、ストリーム圧縮統計情報を報告します。
-display 表示 | 以下をサポートする X サーバーのアドレスを指定します。 LBX 拡張。 このフラグが指定されていない場合、表示は以下によって取得されます。 DISPLAY 環境変数。
-help | コマンド・ライン・フラグに関する簡潔なヘルプ・メッセージを出力します。
-I | 残りの引数はすべて無視されます。
-motion 数値 | フライト中であることが可能なイベントの最大数 Number を指定します。 限定された数のポインター・モーション・イベントが、所定の時刻であればいつでも、 サーバーとプロキシーの間をフライト中であることが許されます。 デフォルトは 8 です。
-ノアトムズファイル | AtomControl ファイルの読み取りを使用不可にします。
-非圧縮 | ストリーム圧縮を使用不可にします。
-デルタなし | デルタ要求の置換を使用不可にします。
-ノグフックス | グラフィックス要求の再エンコードを使用不可にします (イメージ関連の要求は含みません)。
-noグラップ・マップ | カラー・マップのグラブを使用不可にします。
-ノーイメージ | イメージ圧縮を使用不可にします。
-ノインターンスク | InternAtom 要求の短絡を使用不可にします。
-ノルベックス | すべて使用不可にする LBX 最適化。

-ノルグファイル | プロキシーで RGB 解像度に対するカラー名を使用不可にします。
-ノスキッシュ | X イベントの圧縮を使用不可にします。
-タグ | タグを使用不可にします。
-非属性 | GetWindowAttributes / GetGeometry の 1 回の往復でのグループ化を使用不可にします。
-ノゼロパッド | X 要求、返信、およびイベント内の未使用埋め込みバイトをゼロにリセットしないことを示します。
-再接続 | lbxproxy をリセットし ( -reset を参照)、サーバーへの接続が切断されたときにサーバーへの再接続を試行します。 lbxproxy のデフォルトの動作は、終了することです。
-rgbfile パス | RGB 解像度に対するカラー名のための代替 RGB データベース Path を指定します。
-タグキャッシュサイズ | プロキシーのタグ・キャッシュのサイズ (バイト単位) を設定します。
-[終了 | リセット] | lbxproxy のデフォルトの動作では、最後のクライアントの終了時に通常どおり実行を継続します。 -terminate オプションを指定すると、 lbxproxy は最後のクライアントの終了時に終了することになります。 -reset オプションを指定すると、 lbxproxy は、最後のクライアントの終了時に自らをリセットします。 リセットを行うと、 lbxproxy はその状態をクリーンアップし、サーバーに再接続します。
-zlevel レベル | Zlib 圧縮レベル (ストリーム圧縮に使用される) を設定します。 デフォルトは 9 です。 1 = 最低の圧縮、最速。 9 = 圧縮率は最高で、最低速。
