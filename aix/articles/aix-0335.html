目的

Reliable Scalable Cluster Technology (RSCT) コンポーネントについての構成、ログ、およびトレース情報を収集します。

構文

CT スナップ [ -a 値 ] [ 「-c」 クラスター名のパターン ] [ -C クラスター ID パターン (cluster_ID_pattern) ] [ -d 年 出力ディレクトリー ] [ -D daemon_name_pattern ] [ -k (K) stackdump_default ] [ N ノード名パターン ] [ -N (N) ノード ID パターン ] [ P- 日 | { 「-f」 開始日 T 終了日 } ] [ -s スプール・ディレクトリー ] [ -S (S) サイズ ] [ -x (X) runrpttr ] [ -h ] [ -z ]

説明

ctsnap コマンドは、 AIX® または PowerHA®とともにインストールされた RSCT コンポーネントに関する構成情報、ログ情報、およびトレース情報を収集します。 このコマンドは、コマンドが実行されているローカル・ノードのデータのみを収集します。 インストールされるプログラムに応じて、以下のコンポーネントについての情報が含まれます。
  • 監査ログ・リソース・マネージャー (IBM.AuditRM)
  • クラスター・セキュリティー・サービス (ctsec)
  • 共通情報モデル・リソース・マネージャー (IBM.CIMRM)
  • 構成リソース・マネージャー (IBM.ConfigRM)
  • イベント管理 (ha_em)
  • イベント応答リソース・マネージャー (IBM.ERRM)
  • ファイル・システム・リソース・マネージャー (IBM.FSRM)
  • First Failure Data Capture (ct_ffdc)
  • グループ・サービス (cthags)
  • ホスト・リソース・マネージャー (IBM.HostRM)
  • 最小特権リソース・マネージャー (IBM.LPRM)
  • 低レベル・アプリケーション・プログラミング・インターフェース (lapi)
  • 管理ドメイン・リソース・マネージャーIBM®.MgmtDomainRM)
  • マイクロセンサー・リソース・マネージャー (IBM.MicroSensorRM)
  • リカバリー・リソース・マネージャー (IBM.RecoveryRM)
  • リソースのモニターと制御 (ctrmc)
  • センサー・リソース・マネージャー (IBM.SensorRM)
  • ストレージ・リソース・マネージャー (IBM.StorageRM)
  • トポロジー・サービス (cthats)
  • 仮想共用ディスク (vsd) ( AIX 6.1)
  • リカバリー可能仮想共用ディスク (rvsd) ( AIX 6.1)

これらのコンポーネントのどれかに問題が発生する場合は、このコマンドを実行して ソフトウェア・サービス部門に情報を提供できます。

ctsnap コマンドの出力は、圧縮 tar ファイル (ctsnap.node_name.nnnnnnnn.tar.Z) およびログ・ファイル (ctsnap.node_name.nnnnnnnn.log) です。 ここで、node_name は ctsnap が実行されたノードの名前、nnnnnnnn は ctsnap コマンドの実行時のタイム・スタンプです。 これらのファイルの両方をソフトウェア・サービス部門に提供してください。 デフォルトで、ctsnap は、これらのファイルを /tmp/ctsupt ディレクトリーに入れます。 別の出力ディレクトリーを指定するには、-d フラグを使用します。

必要な場合、ctsnap によりスプールされたトレース・ファイルの情報を収集できます。 -c、-C、-D、-f、-n、-N、-p、-s、-S、および -t フラグを使用して、トレース情報のサブセットを取り込めます。 ctsnap -k stackdump_default コマンドを使用して以下の RSCT サブシステムのスタック・ダンプを作成できます。
  • 監査ログ・リソース・マネージャー (IBM.AuditRM)
  • 共通情報モデル・リソース・マネージャー (IBM.CIMRM)
  • 構成リソース・マネージャー (IBM.ConfigRM)
  • イベント応答リソース・マネージャー (IBM.ERRM)
  • ファイル・システム・リソース・マネージャー (IBM.FSRM)
  • 汎用リソース・マネージャー (IBM.GblResRM)
  • グループ・サービス (cthags)
  • 最小特権リソース・マネージャー (IBM.LPRM)
  • マイクロセンサー・リソース・マネージャー (IBM.MicroSensorRM)
  • リカバリー・リソース・マネージャー (IBM.RecoveryRM)
  • リソース・モニターおよび制御 (ctrmc)
  • センサー・リソース・マネージャー (IBM.SensorRM)
  • ストレージ・リソース・マネージャー (IBM.StorageRM)
  • トポロジー・サービス (cthats)

RSCT リソース・マネージャーのトレース・ファイルの内容をフォーマットするには、-x フラグを使用します。

また、RSCT File 構成ファイル (ctfile.cfg) からトレースとルート・ディレクトリーのログ記録を入手するのに、ctsnap コマンドも使用できます。

フラグ

-a
Linux® オペレーティング・システム上の High Availability Cluster Multi-Processing (HACMP) クラスターにのみ関連する情報を収集します。
--c クラスタ名パターン
トレース収集を特定のクラスター名に限定する選択パターンを指定します。 パターンは、Perl 言語の正規表現として解釈されます。
--C cluster_ID_pattern
トレース収集を特定のクラスター ID に限定する選択パターンを指定します。 パターンは、Perl 言語の正規表現として解釈されます。
--d output_dir
出力ディレクトリーを指定します。 デフォルトのディレクトリーは /tmp/ctsupt です。
--D デーモン名パターン
トレース収集を特定のデーモンに限定する選択パターンを指定します。 パターンは、Perl 言語の正規表現として解釈されます。
--f from_date
情報を収集するいつからの日付を指定します。 from_date パラメーターのフォーマットは次のとおりです。
yyyy-mm-dd[.hh[:mm[:ss]]]
注: -f は -t フラグと一緒に使用してください。
-k stackdump_default
これらの RSCT サブシステムのスタック・ダンプを生成します：cthags、cthats、ctrmc、IBM.AuditRM、IBM.CIMRM、IBM.ConfigRM、IBM.ERRM、IBM.FSRM、IBM.GblResRM、IBM.LPRM、IBM.MicroSensorRM、IBM.RecoveryRM、IBM.SensorRM、およびIBM.StorageRM。
--n ノード名パターン
トレース収集を特定のノード名に限定する選択パターンを指定します。 パターンは、Perl 言語の正規表現として解釈されます。
--N node_ID_pattern
トレース収集を特定のノード ID に限定する選択パターンを指定します。 パターンは、Perl 言語の正規表現として解釈されます。
-日
収集するスプール済みトレース情報の価値が、何日前まであるかを指定します。
--s spool_dir
トレース・ファイルを指定したスプール・ディレクトリーに取り込みます。
--S サイズ
収集するすべてのトレース・ファイルの最大累積サイズ (メガバイト) を指定します。
--t to_date
情報を収集するいつまでの日付を指定します。 to_date パラメーターのフォーマットは次のとおりです。
yyyy-mm-dd[.hh[:mm[:ss]]]
注: -t は -f フラグと一緒に使用してください。
-x runrpttr
すべての RSCT リソース・マネージャーのトレース・ファイルの内容をフォーマットします。

このフラグを使用すると、ctsnap 出力ファイルのサイズが増加し、出力ディレクトリーを含むファイルシステムのサイズを増加しなければならない場合があります。

-h
コマンドの使用ステートメント (使用法) を標準出力に書き込みます。
-z
Cluster Aware AIX (CAA) 環境であっても、 snap caa 情報を収集しないようにします。

セキュリティー

root ユーザーのみがこのコマンドを実行できます。

終了状況

0
コマンドは正常に実行されました。
1
コマンドは正常終了しませんでした。

標準出力

-h フラグを指定すると、このコマンドの使用状況ステートメントが標準出力に書き込まれます。

標準エラー

エラー・メッセージは、標準エラー (および ctsnap.host_name.nnnnnnnn.log ファイル) に書き込まれます。

実行の特性

このコマンドは、AIX® オペレーティング・システムの rsct.core.utils ファイルセットの一部です。

例

  1. RSCT サポート情報を集めるには、次のように入力します。
    ctsnap
  2. RSCT サポート情報を収集し、それを /tmp/mydir ディレクトリーに入れるには、次のように入力します。
    ctsnap -d /tmp/mydir
  3. /opt/traces ディレクトリーのすべてのトレース・ファイルを取り込むには、次のように入力します。
    ctsnap -s /opt/traces
  4. /opt/traces ディレクトリーのすべてのトレース・ファイルを構成リソース・マネージャー・デーモンに関して取り込むには、次のように入力します。
    ctsnap -s /opt/traces -D '.*ConfigRM.*'
  5. /opt/traces ディレクトリーのすべてのトレース・ファイルを日付範囲 (08-28-2008 から 08-29-2008 まで) について取り込むには、次のように入力します。
    ctsnap -s /opt/traces -f 08-28-2008 -t 08-29-2008
  6. /opt/traces ディレクトリーのすべてのトレース・ファイルを前 4 日間について取り込むには、次のように入力します。
    ctsnap -s /opt/traces -p 4
  7. /opt/traces ディレクトリーのすべてのトレース・ファイルをトレース情報の最新 50 MB について取り込むには、次のように入力します。
    ctsnap -s /opt/traces -S 50

場所

/opt/rsct/bin/ctsnap
ctsnap コマンドが入っています。

ファイル

/tmp/ctsupt
出力ファイルを含むデフォルト・ディレクトリーのロケーション。
/tmp/ctsupt/ctsnap.host_name.nnnnnn.log
コマンド実行のログ・ファイルのロケーション。ここで nnnnnnnn はタイム・スタンプであり、host_name は コマンドが実行されたホストの名前。
tmp/ctsupt/ctsnap.host_name.nnnnnn。 tar.Z
収集されたデータを含む圧縮 tar ファイルのロケーション。 ここで nnnnnnnn はタイム・スタンプであり、 host_name はコマンドが実行されたホストの名前。
