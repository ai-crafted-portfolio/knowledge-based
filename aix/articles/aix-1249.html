目的

Reliable Scalable Cluster Technology (RSCT) サブシステムを再構成します。

構文

/opt/rsct/install/bin/recfgct [ -i Node_ID | -n | -s | -h ]

説明

重要: このコマンドは、細心の注意を払って使用してください。

recfgct コマンドは、 /var/ct ディレクトリーの下にあるすべての RSCT データを除去し、新しいノード ID を生成して、RSCT コンポーネントがインストールされたばかりのように見せるために使用します。 このコマンドには破壊的な性質があるため、通常はシステム管理者がこれを始動することはありません。 このコマンドは、重複するノード ID を削除する必要がある場合、または IBM® サービス担当員から使用するよう指示された場合に のみ 使用してください。

RSCT が最初にインストールされると、ノード ID が自動的に生成されます。 ノード ID は真のランダム 64 ビット数値です。 RSCT がインストールされている各システムに、固有のノード ID が必要です。 RSCT がインストールされているオペレーティング・システム・イメージ (OSI) のコピーが、別のシステムにインストールされた場合には、別のシステムもコピー元のシステムと同じノード ID を持つようになります。 これはクローン作成と呼ばれます。 AIX® プラットフォームの場合、クローン作成は通常、 AIXでサポートされるコマンドおよび手順 ( mksysbなど) を使用して実行されます。 これらのコマンドおよびプロシージャーは、 recfgct を自動的に呼び出します。 その他のプラットフォームでは、複製された OSI がインストールされた直後に recfgct コマンドを実行する必要があります。

-s フラグを指定すると、 /var/ct ディレクトリーの下のすべてのデータが除去された後、 /etc/ct_node_id ファイルに含まれているノード ID を使用して /var/ct/cfg/ct_node_id ファイルが再作成されます。

フラグ

-i ノードID
使用する必要があるノード ID を指定します。 ノード ID は、9 から 16 桁の 16 進文字でなければなりません。
-n
新規ノード ID を生成します。 オプションが指定されていない場合、これがデフォルトの動作です。
-s
ノード ID を保存します。
-h
コマンド使用状況の説明文を標準出力に書き込んでから、終了します。

制約事項

-h フラグは、以下の RSCT レベルでサポートされます。
  • RSCT 2.4.9.1 (またはそれ以降) ( AIX 5.3 の場合)
  • AIX 6.1 およびすべての Linux® プラットフォームの RSCT 2.5.1.1 (またはそれ以降)
  • RSCT 3.1.0.0 (またはそれ以降) ( AIX 7.1 以降の場合)
以前のバージョンの RSCT で recfgct -h コマンドを実行しようとすると、 -h フラグは無視され、すべての RSCT データが除去されます。

ファイル

/etc/ct_node_id
RSCT ノード ID のコピーが入っています。
/var/ct/cfg/ct_node_id
RSCT ノード ID が入っています。

標準出力

-h フラグが指定されている場合、このコマンド使用状況ステートメントは標準出力に書き込まれ、その後コマンドは終了します。

終了状況

0
コマンドは正常に実行されました。
1
コマンドは正常に実行されませんでした。

セキュリティー

特権制御: root ユーザーのみが、このコマンドに対する実行 (x) アクセス権限を持っている必要があります。

実行の特性

このコマンドは、 AIX オペレーティング・システムおよび rsct.core-3.1.0.0-0.プラットフォーム.rpm パッケージ ( Linux、Solaris、および Windows オペレーティング・システム用) 用の rsct.core ファイルセットの一部です。ここで、 platform は i386、 ppc、 ppc64、 s390、または x86_64です。

場所

/opt/rsct/install/bin/recfgct

例

  1. クローンのオペレーティング・システム・イメージをインストールした後、次のように入力します。
    /opt/rsct/install/bin/recfgct
