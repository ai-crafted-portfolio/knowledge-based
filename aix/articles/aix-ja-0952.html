目的
ルート・ボリューム・グループのインストール可能なイメージを、ファイルまたはブータブル・テープ上に作成します。

説明
mksysb
コマンドは、ルート・ボリューム・グループ（rootvg）として知られるオペレーティング・システムのバックアップを作成します。 システムが破損した場合、
mksysb
コマンドで作成したバックアップを使用して、オペレーティング・システムを元の状態に再インストールすることができます。 バックアップをテープまたはユーザー定義ファイルシステム（UDFS）対応メディアに作成した場合、バックアップはブート可能です。 バックアップには、バックアップからインストールするために必要なインストールプログラムが含まれています。
メモ：
両方のインスタンスがマウントされている
multibos
環境の場合、
alt_disk_mksysb
コマンドのみを使用してバックアップをリストアできます。
mksysb
イメージを使って別のシステムを復元することができます。
ファイルシステムイメージはバックアップファイル形式である。 テープ・フォーマットには、ブート・イメージ、
bosinstall
イメージ、空の目次に続いてシステム・バックアップ（ルート・ボリューム・グループ）イメージが含まれる。
rootvg
イメージはバックアップファイル形式で、データファイルとオプションのマップファイルから始まる。
mksysb
コマンドが使用するデータファイルのひとつに、
/bosinst.data
データファイルがある。
/bosinst.data
ファイルが存在しない場合は、
/var/adm/ras/bosinst.data
ファイルがルート (
/
) にコピーされる。
mksysb
コマンドは、
bosinst.data
ファイル内の
target_disk_data
スタンザを更新し、
mksysb
コマンドが実行されるシステムのルート・ボリューム・グループにあるディスクと一致させる。
カスタマイズした
/bosinst.data
ファイルを使用していて、更新される
target_disk_data
スタンザが不要な場合は、
/save_bosinst.data_file
ファイルを作成する必要があります。
/save_bosinst.data_file

mksysb
コマンドは
/bosinst.data
ファイルを更新しない。
注:
mksysb
コマンドを実行する際、システムの活動が最小限であることを確認してください。
mksysb

コマンドが作成するイメージには、ローデバイス上のデータやユーザー定義のページングスペース内のデータは含まれません。
リモートマウントされた
/usr
ファイルシステムを使用している場合、 バックアップイメージからシステムを再インストールすることはできません。
mksysb
コマンドは、
/dev/netbios
ファイルや製品に同梱されていないデバイス・ドライバなど、特別な機能のデバイス・コンフィギュレーションをすべてリストアできない場合があります。
backup
コマンドを使って
mksysb
コマンドを実行すると、アーカイブ・イメージが作成される。
mksysb
コマンドは、バックアップされた拡張ジャーナル・ファイル・システム ( JFS2 ) の拡張属性 (EA) フォーマットを保存します。 情報の保存には
/usr/bin/mkszfile
シェルスクリプトを使用する。
mksysb
コマンドを実行する前に
/dev/ipldevice
ファイルを削除すると、

テープバックアップを作成し、ファイルシステムを暗号化するには、
-Z
フラグを使用する。 暗号化されたファイルシステムを含むテープバックアップイメージからシステムを再インストールすることはできません。
オペレーティング・システムのバックアップをCDに作成するには

オペレーティング・システムのバックアップをDVDに作成するには、

構文
mksysb [ -a ] [ -A ] [ -b number ] [ -e ] [ -F filename ] [ -i ] [ -m ] [ -p ] [ -P ] [ -t argument ] [ -v ] [ -V ] [ -x file ] [ -X ] [ -Z ] [ -G | -N ] [ -M ] [ -T ] [ -C ] device | file

オプション
フラグ
項目 | 説明
-a | 拡張属性またはネットワーク・ファイルシステム・バージョン 4 (NFS4) のアクセス制御リスト (ACL) をバックアップしません。
-A | データ管理 API (DMAPI) ファイルシステム・ファイルをバックアップします。
-b Number | 1 回の出力操作で書き込む 512 バイト単位のブロック数を指定します。 backup ・コマンドがテープ・デバイスに書き込む場合、デフォルトではバックアップ用に100ブロックが使用される。 書き込みサイズは、ブロック数にブロック・サイズを掛け合わせたものです。 テープ・デバイスに書き込む backup コマンドのデフォルトの書き込みサイズは、名前によるバックアップの場合、51200（100×512）である。 書き込みサイズは、テープの物理ブロック・サイズの偶数倍でなければならない。
-C | mksysb イメージを作成するときに、 /usr/lpp/bos.alt_disk_install/boot_images/bosboot.disk.chrp ブート・イメージを新しいブート・イメージに置き換えることができるかどうかを指定します。 カーネルに影響する暫定修正がシステムにインストールされており、 alt_disk_mksysb コマンドを使って mksysb イメージをインストールしたい場合は、 -C フラグを使用します。 –C フラグを使いたい場合は、 bos.alt_disk_install.boot_images ファイルセットがシステムにインストールされている必要がある。 –C フラグを使用する場合、 image.data ファイルを新規にビルドするには、 –i フラグを指定する必要がある。 新しい bosboot.disk.chrp イメージは、 mksysb イメージ作成の終わりに元のイメージに置き換えられます。 NIMリソースの定義時に mksysb イメージを作成する場合、 -C フラグは使用できません。 multibos 基本オペレーティング・システム (BOS) スタンバイ・インスタンスは、 -C フラグの影響を受けません。 注： -X フラグと -C フラグを併用することで、 /usr ファイルシステムのサイズを大きくして、新しいブートイメージを含めることができます。

-e | /etc/exclude.rootvg ファイルにリストされているファイルをバックアップから除外する。 除外規則は、 grep コマンドのパターン・マッチング規則に準拠します。 特定のファイルをバックアップから除外したい場合は、 /etc/exclude.rootvg ファイルを ASCII エディターで作成してください。 システムバックアップイメージに含めないファイル名のパターンを入力します。 このファイルのパターンは、 grep コマンドのパターンマッチング規約に入力され、バックアップから除外するファイルを決定する。 /etc/exclude.rootvg ファイルにリストされているファイルを除外したい場合は、 Exclude Files フィールドを選択し、 Tab キーを押してデフォルト値を yes に変更する。 次に例を示します。 スクラッチと呼ばれるディレクトリの内容をすべて除外するには、excludeファイルを以下のように編集する： /scratch/ /tmp として知られるディレクトリの内容を除外し、パス名に /tmp ディレクトリを含む他のディレクトリを除外しないようにするには、除外ファイルを以下のように編集する： ^./tmp/ これにより、 /tmp ディレクトリーのすべての内容が除外されますが、ファイルシステムの /tmp マウント・ポイントは保持されます。 /var 、 /adm 、 /sw 、 /tmp ファイルシステムなど、他のディレクトリやそのコンテンツは削除されない。 現在の作業ディレクトリ( . )に関連するファイルがバックアップされる。 検索が行頭の文字列と一致することが重要なファイルやディレクトリを除外するには、検索文字列の最初の文字としてキャレット文字（^）を使い、その後にドット文字（ . ）を続け、除外するファイル名またはディレクトリを続ける。 除外するファイル名やディレクトリが他のファイル名やディレクトリの部分文字列である場合、キャレット文字の後にドット文字（ ^. ）を使用する必要があります。これは、検索が行頭から開始されなければならないことを示す。 行末で検索を終了しなければならないことを示すには、ドル記号 ( $ ) を使用しなければならない。
-F ファイル名 | 以前に作成した mksysb イメージを指定します。そのイメージからバックアップ・テープが作成されます。 バックアップ・テープをブート可能にすることを試行します。 -F フラグはテープ・デバイスと一緒に使用しなければならない。

-G | システム・バックアップから WPAR ファイルシステムを除外します。 -G フラグは、 -N フラグとは併用できない。
-i | /image.data ファイルを生成する mkszfile コマンドを呼び出します。 /image.data ファイルには、ボリュームグループ、論理ボリューム、ファイルシステム、ページングスペース、物理ボリュームの詳細が含まれている。 この情報は、将来インストール・プロセスで使用できるように、バックアップに入れられます。 -i フラグを使用しない場合、システム・バックアップを復元するのに必要な十分な容量を含まない古い /image.data ファイルが保存される可能性があります。 注： mkszfile コマンドを実行する前に、 /tmp ファイルにブートイメージを保存できる十分なスペースがあることを確認してください。 /tmp 、バックアップやインストールを行う際に必要となります。 /tmp ファイル内で必要なスペースの量を判別するには、次のコマンドを入力します。 bosboot -q -a -d device /dev/usbms0 ファイルという名前のUDFS対応デバイスを使用している場合、 /dev/usbms0 デバイスは bosboot コマンドでサポートされていないため、デバイス名として /dev/cd0 ファイルを指定する必要があります。 mksysb コマンドで -X フラグを使用する場合、 /tmp ファイルに必要なスペースの量を判別するために bosboot コマンドを実行する必要はありません。
-m | -m フラグを付けて mkszfile コマンドを呼び出し、マップファイルを生成する。 注： -i フラグの機能を実行するには、 -m フラグを使用しなければならない。
-M | multibos コマンドとの使用が意図されているバックアップ・ファイルを作成します。 -M フラグは、 / 、 /usr 、 /var 、および /opt ファイルシステムをバックアップします。 システムを再インストールするためにバックアップを使用しないでください。 bos.alt_disk_install.boot_images ファイルセットをシステム・レベルにインストールする。

-N | システムバックアップで定義された状態の ワークロードパーティション （WPAR ）に属するファイルシステムを含む。 注： ファイルシステムをバックアップに含めるには、定義された状態の WPARに 属するファイルシステムが、 rootvg ボリュームグループに存在する必要があります。
-p | バックアップされるファイルのソフトウェアパッキングを無効にします。 磁気テープ・ドライブのなかには、独自のパッキングおよび圧縮アルゴリズムを使用するものもあります。
-P | /etc/exclude_packing.rootvg 、 /etc/exclude_packing.vgname 、または /etc/exclude_packing.WPARname の各ファイルに 1 行ずつリストされたファイルをパックされないように除外します。 例えば、 mksysb コマンドのバックアップ中に、 /etc/filesystems と /usr/bin/zcat ファイルがパックされないようにするには、 /etc/exclude_packing. type ファイルを編集して、連続する行に /etc/filesystems と /usr/bin/zcat を追加する必要があります。 この場合、 /etc/exclude_packing. type ファイルは以下のようにしなければならない： /etc/filesystems /usr/bin/zcat -P フラグと -p フラグは互いに排他的である。
-t argument | -F フラグで指定された mksysb ファイルからブートイメージを作成するために使用されるディレクトリまたはファイルシステムへのパスを指定します。 -F フラグとともに -t フラグを使用しない場合、ブートイメージはデフォルトで /tmp ファイルに作成されます。 約 100 MB のフリー・スペースが必要です。 ブート・イメージが作成された後にこのスペースは解放されます。

-T | スナップショットを使用して rootvg のバックアップを作成します。 このコマンドは、JFS2 ファイルシステムにのみ適用されます。 -T フラグを指定して、ボリューム・グループ・バックアップの作成にスナップショットを使用すると、外部 JFS2 スナップショットが作成されます。 スナップショットは、 JFS2 ファイルシステムのポイント・イン・タイムのイメージを可能にし、システムを一時的に非アクティブな状態にする必要はありません。 スナップショットのサイズは、ファイルシステムのサイズの2％から15％です。 スナップショット論理ボリュームは、バックアップが完了すると削除されます。 ただし、ファイルシステムに既に他のスナップショットがある場合は、スナップショットは除去されません。 ファイルシステムに内部スナップショットがある場合、外部スナップショットは作成できず、スナップショットはファイルシステムのバックアップ作成には使用されません。 -T フラグの使用は、バックアップされているボリューム・グループ内に存在する JFS ファイルシステムには影響を及ぼしません。 これらのファイルシステムは、以前に行われていたのと同じ方法でバックアップされます。 -T フラグを指定する場合は、 -i フラグも指定する必要があります。 -i フラグを指定しなかった場合、古い /image.data ファイルが十分なスペース要件を持たないことがあります。 そのため、スナップショットにデータを保存する際に障害が発生する可能性があります。
-v | 詳細モード。 バックアップされるファイルをリストで示します。
-V | テープ・バックアップを検証します。 -V フラグを指定すると、 mksysb コマンドがバックアップ・テープ上の各ファイルのファイル・ヘッダを検証し、読み取りエラーが発生した場合はそれを報告する。
-x file | ファイルでリストされたファイルシステムをシステム・バックアップから除外します。 ファイルシステムのマウント・ポイントは、1 行につき 1 つずつリストする必要があります。
-X | 必要に応じて、 /tmp ファイルシステムを自動的に拡張するように指定します。 /tmp ファイルシステムは、ブート可能バックアップをテープに作成する場合、ブート・イメージのために場所を空けるように拡張する必要のある場合があります。

-Z | すべてのファイル、ディレクトリ、およびファイルシステムの暗号化ファイルシステム（ EFS ）情報がバックアップされないように指定します。
重要:
オペレーティング・システムのバックアップからファイル・システムを除外する場合は、
-x
フラグを使用する際に注意してください。 結果のバックアップをシステムのリストアのために使用できなくなる可能性があります。

例
システム・バックアップを生成し、
mkszfile
コマンドで生成された
/image.data
ファイルを
/dev/rmt0
ファイルという名前のテープ・デバイスに作成するには、以下のコマンドを入力します：
mksysb -i /dev/rmt0
システム・バックアップを生成し、
mkszfile
コマンドで生成されたマップ・ファイルを含む
/image.data
ファイルを、
/dev/rmt1
ファイルという名前のテープ・デバイスに作成するには、以下のコマンドを入力します：
mksysb -m /dev/rmt1
新しい
/image.data
ファイルでシステム・バックアップを作成するが、
/home/user1/tmp
ディレクトリのファイルを除外するには、
/home/user1/tmp/
行を含む
/etc/exclude.rootvg
ファイルを作成し、以下のコマンドを入力する：
mksysb -i -e /dev/rmt1
このコマンドは
/home/user1/tmp
ディレクトリをバックアップするが、そこに含まれるファイルはバックアップしない。
/mksysb_images/node1
ファイルという名前のシステム・バックアップ・ファイルと、そのイメージ用の新しい
/image.data
ファイルを生成するには、以下のコマンドを入力します：
mksysb -i /mksysb_images/node1
注意：
このファイルはブート可能ではないため、ネットワークインストール管理（NIM）を使用してのみインストールできます。
mkszfile
コマンドを単独で実行し、テープ・デバイス
/dev/rmt0
にシステム・バックアップを生成した後、ファイル・ヘッダーの可読性を検証するために、以下のコマンドを入力する：
mksysb /dev/rmt0 -V
multibos
コマンドで使用する
/mksysb_images/mksysb1
ファイルという名前のシステム・バックアップ・ファイルを作成し、そのイメージの
/image.data
ファイルを作成するには、以下のコマンドを入力します：
mksysb -iM /mksysb_images/mksysb1
システム・バックアップを生成し、
mkszfile
コマンドで生成された
/image.data
ファイルを、
/dev/usbms0
ファイルという名前の UDFS 対応デバイスに作成するには、以下のコマンドを入力します：
mksysb -i /dev/usbms0
注：

ボリューム・グループのバックアップの詳細については
listvgbackup
コマンドを参照してください。 ボリューム・グループのバックアップから個々のファイルをリストアするには
restorevgfiles
コマンドを参照してください。
