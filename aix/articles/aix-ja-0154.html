目的
定義済み条件の任意の属性を変更します。

説明
chcondition
コマンドは、定義された条件の属性を、指定された値に変更します。 条件の名前が
-c
フラグを使用して変更された場合、条件/応答の関連付けは変更されません。
システム・ソフトウェアを適切に機能させるために特定の条件が必要な場合、その条件は
ロックされることがあります。 ロックされた条件はアンロックされない限り変更または取り除くことはできません。
chcondition
コマンドで指定した条件がロックされている場合、その条件は変更されません。代わりに、条件がロックされていることを通知するエラーが生成されます。 条件をアンロックするには、
-U
フラグを使用できます。 ただし、条件はシステム・ソフトウェアが
適切に機能するために必須であり、通常ロックされているので、これをアンロックする際は
注意が必要です。 条件を変更できないようにロックするには、
-L
フラグを使用します。
システムにクラスター・システム・マネージメント (CSM) がインストールされている場合は、CSM 定義のノード・グループをノード名の値として使用して、複数のノードを参照できます。 CSM ノード・グループの処理および CSM
nodegrp
コマンドの使用については、「
CSM: 管理ガイド
」および「
CSM: コマンドおよびテクニカル・リファレンス
」を参照してください。

構文
条件の属性を変更するには、次のようにします。 chcondition [ -r resource_class ] [ -e " event_expression " ] [ -E " rearm_expression " ] [ -d " event_description " ] [ -D " rearm_description " ] [ -b interval [ , max_events ] [ , retention_period ] [ , max_totalsize ] [ -m l | m | p ] [ -n node_name1 [ , node_name2 ...]] [ --qnotoggle | --qtoggle ] [ -s " selection_string " ] [ -S c | w | i ] [ -g 0 | 1 | 2 ] [ -h ] [ -TV ] 条件 [ : node_name ] 条件を名前変更するには、次のように入力します。 chcondition -c new_condition [ -h ][ -TV 条件[ ] 条件 : ノード名］ 条件をロックまたはアンロックするには、次のように入力します。 chcondition { -L | -U } [ -h ] [ -TV ] 条件 [ : node_name ]

オプション
フラグ
-b

1 つ以上のバッチ処理関連の属性を変更します。 コンマを使用して、属性値を区切ります。 値またはコンマの間にスペースを何も挿入しないでください。
interval
は、示された間隔でイベントを一緒にバッチすることを指定します。 バッチ処理は、間隔についてイベントが生成されなくなるまで継続します。 バッチ処理をオフにするには、0 の間隔を使用します。
max_events
は、
max_events
のイベント数が生成されるまでイベントが一緒にパッチされることを指定します。 間隔が期限になる前に
max_events
のイベント数に到達する場合、間隔は再始動します。
retention_period
は、保存期間を時間数で指定します。 バッチ処理されたイベント・ファイルは保存期間として指定された時間の間保存されます。 この時間に到達すると、ファイルは自動的に削除されます。
max_totalsize
は、バッチ処理されたイベント・ファイルの合計サイズをメガバイト (MB) 単位で指定します。 バッチ処理されるイベント・ファイルは、このサイズに達するまで保存されます。 このサイズに達すると、ファイルは自動的に削除されます。
max_events
、
retention_period
、および
max_totalsize
は、間隔が 0 より大きくない限り指定できません。
interval
が 0 より大きく、
max_events
が 0 である場合、イベントの最大数は使用されません。
retention_period
および
max_totalsize
が両方とも指定される場合、バッチ処理されたイベント・ファイルは、指定された時間またはサイズのうち、どちらかが最初に発生するまで保存されます。
1 つ、2 つ、または 3 つの属性値を変更したい場合、変更したい値に先行する属性について有効値または空のフィールドを指定する必要があります。 変更したい値に後続する属性については値を指定する必要はありません。 例えば、保存期間の変更だけを行う必要がある場合は、
interval
にも
max_events
にも値を指定する必要があります。 属性を変更する必要がない場合、空のフィールドを指定することができます。 例えば、
interval
および
max_events
の値を変更せずに保存期間を
36
時間に変更するには、次のように入力します。
chcondition -b ,,36

例
以下の例は、スタンドアロン・システムに適用されます。
条件名を「FileSystem space used」から「Watch FileSystem space」に変更するには、
次のコマンドを実行します。
chcondition -c "Watch FileSystem space" "FileSystem space used"
「tmp space used」という名前の条件に対するリアーム式およびリアームの説明を変更するには、
次のコマンドを実行します。
chcondition -E "PercentTotUsed < 80" \
-D "Start monitoring tmp again after it is less than 80 percent full" \
"tmp space used"
「File System space used」と呼ばれる条件に対して監査ログ情報の記録を使用不可にするには、次のコマンドを実行します。
chcondition -g 2 "File System space used"
「File System space used」と呼ばれる条件に対するバッチ処理されるイベント・ファイルの最大サイズを 100 MB に変更するには、次のコマンドを実行します。
chcondition -b ,,,100 "File System space used"
「File System space used」と呼ばれる条件に対してバッチ処理を使用不可にするには、次のコマンドを実行します。
chcondition -b 0 "File System space used"
このコマンドは、
max_event
、
retention_period
、および
max_totalsize
をリセットします (これらの値が前に指定された場合)。 必要に応じて、バッチ処理を再度使用可能にする場合は、これらの属性に値を指定する必要があります。

管理サーバー上の「FileSystem space used」という名前の条件を変更して、スペース使用率が
95% より大きいものがないか検査するには、次のコマンドを実行します。

chcondition -e "PercentTotUsed > 95" \
