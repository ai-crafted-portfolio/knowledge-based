目的

ローカル・システム用のクラスター・セキュリティー・サービス秘密鍵および公開鍵を生成し、それらのキーをローカルにマウントされたファイルに保管します。

構文

ctskeygen -n [-f] [ -m method ] [ -p public-file ] [ -q private-file ] | -d | -i | -h

説明

ctskeygen コマンドは、RSCT ホスト・ベース認証 (HBA) でクラスター・セキュリティー・サービス・ライブラリー (libct_sec) によって使用されるホスト ID 鍵 (秘密鍵と公開鍵のペア) を生成します。 このコマンドは、そのノード用の秘密鍵を新規作成して、その新規秘密鍵から公開鍵を導き出し、それらのキーをそのローカル・ノード上のファイルに保管します。

ノードの秘密鍵および公開鍵が変更されるたびに、そのノードの新規公開鍵がそのクラスター内のすべてのノードに必ず配布され、それらのノード上のトラステッド・ホスト・リスト・ファイルに入れられて、そのファイル内でこのノード用として保管されていた前の値がこの新規公開鍵に交換されなければなりません。 これが行われないと、新規の秘密鍵と公開鍵を生成したノードは、そのクラスター内のその他のノードとの間で HBA 認証を使用した認証を行えなくなります。

フラグ

-n
ホスト ID キー (秘密鍵と公開鍵) を生成します。
-f
秘密鍵ファイルと公開鍵ファイルが既に存在している場合は、 ctskeygen がそれらのファイルに生成した鍵を記録するように強制します。 デフォルトでは、このコマンドはこれらのファイルが存在する場合はそれらを上書きしません。なぜなら、これらのファイルが存在するということは、クラスター・セキュリティー・サービスのサービスがアクティブになっている可能性があるということだからです。 公開鍵の値の変更をその他のノードに通知せずにこれらのファイルを除去または変更すると、このノードでの HBA 認証は失敗するようになります。 このフラグは、 -h または -i フラグと一緒の場合は無効です。
-メソッド
ホスト ID キーを作成する際には指定されたキー生成方式を使用するようコマンドに指示します。 このフラグの有効なパラメーターは、 -i フラグを使用して表示できます。 このフラグは、 -h フラグおよび -i フラグと一緒に使用することはできません。
-パブリックファイル
ローカル・ホストの公開鍵を保管するのに使用されるファイルの完全修飾パス名を指定します。 このファイルが存在する場合、 -f フラグも指定されていない限り、コマンドはこのファイルの内容を上書きしません。 -p フラグが指定されていない場合、コマンドはこのキーを /var/ct/cfg/ct_has.pkf ファイルに記録します。 このフラグは、 -h フラグおよび -i フラグと一緒に使用することはできません。
-q 専用ファイル
ローカル・ホストの秘密鍵を保管するのに使用されるファイルの完全修飾パス名を指定します。 このファイルが存在する場合、 -f フラグも指定されていない限り、コマンドはこのファイルの内容を上書きしません。 -q オプションが指定されていない場合、コマンドはこのキーをファイル /var/ct/cfg/ct_has.qkfに記録します。 このフラグは、 -h フラグおよび -i フラグと一緒に使用することはできません。
-d
ローカル・システムの現行の公開鍵値を表示します。
-i
このコマンドのこのバージョンでサポートされるキー生成方式に関する情報を表示します。 ctskeygen は、 -m フラグの引数として現在サポートされている値、およびコマンドが -m フラグのデフォルト設定として使用する内容を示すメッセージを表示します。
-h
コマンドの使用ステートメント (使用法) を標準出力に書き込みます。

パラメーター

ネットワーク ID (network_ID)
マップするセキュリティー・ネットワーク ID を指定します。 これは、トラステッド・サービスのクライアント・アプリケーションが想定できる ID でなければなりません。

セキュリティー

ctskeygen コマンドに対する許可は、 root のみがコマンドを実行することを許可します。

制約事項

  • クラスター・セキュリティー・サービスは、それぞれ独自のファイル・フォーマット、秘密鍵フォーマット、および公開鍵フォーマットしかサポートしません。
  • トラステッド・ホスト・リストは、 ctsthl コマンドのみを使用して変更できます。
  • クラスター・セキュリティー・サービスには、クラスター全体を通じてトラステッド・ホスト・リストを作成、管理、および保守するための自動化されたユーティリティーは用意されていません。 これは、システム管理者またはクラスター管理ソフトウェアのいずれかに対する手順です。

標準出力

-h フラグを指定すると、このコマンドの使用状況ステートメントが標準出力に書き込まれます。 -d フラグを指定すると、公開鍵ファイルに保管されている公開鍵の値が標準出力に書き込まれます。

標準エラー

あらゆる検出済み障害条件に関する記述情報が標準エラーに書き込まれます。

例

  1. サポートされているキー生成方式のリストを取得するには、次のように入力します。
    ctskeygen -i
  2. デフォルト設定を使用してローカル・システム用のホスト ID キーを新規作成するには、次のように入力します。
    ctskeygen -n
  3. 512 ビット RSA 秘密鍵を使用してローカル・システム用のホスト ID キーを新規作成し、それらのキーをデフォルトの場所以外の場所に保管するには、次のように入力します。
    ctskeygen -n -m rsa512 -p /mysec/public -q /mysec/private

場所

/opt/rsct/bin/ctskeygen
ctskeygen コマンドが入っています。

ファイル

/opt/rsct/cfg/ctsec_map.global
デフォルトの ID マッピング定義ファイルです。 このファイルには、RSCT クラスター・トラステッド・サービスが必要とする定義が含まれています。それらの定義は、これらのシステムがソフトウェアのインストール後すぐに適切に実行されるために必要なものです。 クラスター全体の ID マッピング定義ファイル /var/ct/cfg/ctsec_map.global がシステム上に存在する場合、このファイルは無視されます。 したがって、クラスター全体の ID マッピング定義ファイルが存在する場合、その定義ファイルにはこのファイル内の定義もすべて含まれている必要があります。
/var/ct/cfg/ctsec_map.local
クラスター全体の ID マッピング定義に対するローカル・オーバーライドです。 このファイル内の定義をクラスター内のノード間で共有することは期待されません。
/var/ct/cfg/ctsec_map.global
クラスター全体の ID マッピング定義です。 このファイルにはクラスター全体を通じて共通の ID マッピング定義が含まれていることが期待されます。 このファイルがシステムに存在する場合、デフォルトの ID マッピング定義ファイルは無視されます。 したがって、このファイルが存在する場合は、デフォルトの ID マッピング定義ファイル内でも検出される可能性のあるすべてのエントリーがこのファイルにも含まれている必要があります。
