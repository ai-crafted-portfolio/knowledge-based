目的
アプリケーションの
ワークロード・パーティション
または仕様ファイルを作成します。

説明
wparexec
コマンドは、アプリケーション・
ワークロード・パーティション
を作成して開始するか、将来のアプリケーション・
ワークロード・パーティション
の作成を単純化するための仕様ファイルを作成します。
アプリケーション・
ワークロード区画
は、独自のネットワーク構成およびリソース制御プロファイルを持つことができる、分離された実行環境です。 この区画はグローバル・ファイルシステムのスペースを共有しますが、そこで実行されるプロセスは、同じ区画内の他のプロセスだけから確認できます。 この隔離された環境では、プロセスのモニター、リソースの収集、アカウンティングを行うことができます。また、予定したアプリケーションのクラスターのデータを監査することができます。
wparexec
コマンドは、この分離された環境内の単一アプリケーションを開始し、モニターします。
wparexec
コマンドは、
ワークロード・パーティション
内のすべてのプロセスが終了した場合にのみ、この追跡対象プロセスの戻りコードと同期的に戻ります。 例えば、トラッキングされたプロセスがデーモンを作成し、次のように終了したとします。
0
戻りコードの場合、
wparexec
コマンドは、デーモンとそのすべての子が終了するまでブロックしてから、次のコマンドで終了します。
0
デーモンまたはその子の戻りコードに関係なく、戻りコード。

フラグ

-1 | 構成のみを作成します。 アプリケーション WPAR の構成の作成後に wparexec コマンドを停止します。 startwpar コマンドを使用して、 WPAR を開始する必要があります。 上級者のみが -1 オプションを使用することができます。
-a | 必要なら、静的設定の競合を自動的に解決します。 解決可能な設定は、name、hostname、およびネットワーク構成です。
-c | この ワークロード・パーティション のチェックポイントを指定できるようにします。 このオプションは、追加のチェックポイント・リスタート・ソフトウェアがインストールされて構成済みであるときのみ有効です。 このオプションを使用する場合、この ワークロード・パーティション に関連付けられたすべてのファイル・システム (例えば、 -M オプションを使用) はリモートでなければなりません (例えば、 vfs = nfs )。
-e 既存wpar | 仕様データのソースとして既存のアプリケーション・ ワークロード・パーティション を使用します。 -e フラグを -f フラグと一緒に使用しないでください。 他の wparexec フラグによって指定された値は、既存の ワークロード・パーティション の値をオーバーライドします。
-f ファイル | デフォルト値を読み取るよう仕様ファイルに指示します。 -e フラグと一緒に使用しないでください。 他の wparexec フラグによって指定された値は、ロードされた仕様ファイルからの値をオーバーライドします。
-F | ほとんどのエラー条件を抑止あるいはオーバーライドします。 -F フラグを指定すると、 wparexec コマンドは警告を出して続行します。
-h ホスト名 | この ワークロード・パーティション のホスト名を指定します。 指定しない場合、 wparexec コマンドは ワークロード・パーティション 名をホスト名として使用します。

-H アーキテクチャー | アーキテクチャー互換のワークロード区画を作成します。 有効なアーキテクチャー値は pwr4, ppc970, pwr5, pwr6, および pwr7 です。 アーキテクチャーの値は、システムのハードウェアのバージョンより古いか、同じでなければなりません。 ワークロード区画内のアプリケーションは、指定されたアーキテクチャーの最低の共通基準で提示されます。 ワークロード区画がチェックポイントを作成できる場合、そのワークロード区画は、ワークロード区画アーキテクチャー以上の ハードウェア・レベルであるシステム間でマイグレーションできます。 注: POWER5 プロセッサー・ベースのシステムと BladeCenter JS21 Express システムは、相互に互換性がありません。 JS21 は POWER5 プロセッサー・ベースのシステムより低いバージョンのプロセッサーを使用しますが、 POWER5 プロセッサー・ベースのシステム上で JS21 互換の (ppc970) WPAR を作成することはできません。
-i | WPAR 固有の経路指定を ワークロード・パーティション に対して使用可能にします。 デフォルトでは、 ワークロード区画 からの発信ネットワーク・トラフィックは、特に以下のように、グローバル環境から送信されるように経路指定されます。 同じグローバル・システム上でホストされていたアドレス間のトラフィックは、ループバック・インターフェースを介して送信されます。 グローバル・システムで構成されているルーティング・テーブル・エントリー (デフォルト経路を含む) は、 ワークロード・パーティション ・トラフィックを送信するために使用されます。 -iフラグを 指定して WPAR固有 のルーティングを有効にすると、 ワークロードパーティション は独自のルーティングテーブルを作成し、送信トラフィックに使用します。 ブロードキャスト、ループバック、およびサブネット経路を収容するために、 ワークロード区画 のネットワーク・アドレスごとにルーティング項目が自動的に作成されます。 ネットワーク属性について詳しくは、 -N フラグを参照してください。 -I フラグを使用して、 ワークロード・パーティション のルーティング・テーブルに明示的な追加を作成できます。 特に、デフォルトの経路は自動的には作成されないため、 -I フラグを使用してデフォルトの経路を構成することができます。

-I attribute = 値 ... | WPAR 固有の経路指定が有効になったときに自動的に作成されるエントリーに、ルーティング・テーブル・エントリーを追加します。 多重経路を構成する場合は、複数の -I フラグを指定することができます。 -I フラグを使用すると、 -i フラグで説明されているように、 WPAR 固有の経路指定が自動的に使用可能になります。 以下の属性を -I フラグと一緒に指定することができます。 rtdest 属性と rtgateway 属性を指定する必要があります。
rtdest = 宛先 | 経路の宛先となるホストまたはネットワークを指定します。 シンボル名または数値アドレスを使用して、この値を指定することができます。 デフォルト経路を指定するには、 default キーワードを使用できます。 経路の rtdest 属性について詳しくは、 route コマンドの Destination パラメーターを参照してください。
rtgateway = ゲートウェイ | パケットのアドレス先のゲートウェイを指定します。 シンボル名または数値アドレスを使用して、この値を指定することができます。
rtnetmask = A . B . C . D | 宛先アドレスへのネットワーク・マスクを指定します。
rtprefixlen = n | 宛先の接頭部の長さ (ネットマスクのビット数) を指定します。 この値は正整数でなければなりません。
rttype = { net | ホスト } | rtdest 属性を、指定されたタイプとして強制的に解釈させます。
RtInterface = 条件 | インターフェース (例えば、 en0 ) を指定して、経路が選択されたときにこのインターフェースを使用してパケットが送信されるように、その経路と関連付けます。

rectory 属性で指定されたディレクトリーにマウントされます。 namefs マウントに適用できるその他の属性は、 mountopt 属性のみです。 ディレクトリー directory 属性で指定されたグローバル・ディレクトリーが存在しない場合は、作成されます。 マウントは実行されません。

のアドレスにつき 1 回) によって置換できます。 prefixlen 属性は、IPv6 アドレスをマスクし、接頭部を構成するために使用される上位ビットの数です。 prefixlen 属性の値の範囲は、0 から 128 です。 それぞれの -N フラグは、IPv4 属性または IPv6 属性のいずれかを受け入れられますが、両方を受け入れることはできません。

-u ユーザー・スクリプト | さまざまな管理ポイントで workload partition コマンドによって実行されるユーザー・スクリプトへのパスを指定します。 -u フラグのパラメーターは、スクリプトに渡される追加の引数を含む引用符付きストリングの場合もあります。 -u フラグのパラメーターの最初のコンポーネントは、必ず実在の実行可能ファイルへの絶対パスでなければなりません。 スクリプトは次のように呼び出されます。 /path/to/userScript<action>< WAPR> action 引数は、以下のように、実行される管理アクションを示します。 WPAR_LOAD : スクリプトは、カーネル構成後、追跡対象プロセスが作成される前にグローバル環境で実行されます。 スクリプトがゼロ以外の値を返すと、 ワークロード・パーティション は開始されません。 WPAR_START : スクリプトは、 ワークロード・パーティション がアクティブになった後、グローバル環境で実行されます。 アプリケーション ワークロード・パーティション の場合、追跡対象プロセスが開始されるとスクリプトが実行されます。 注: このコード・パスは、標準入出力ストリームがクローズまたはリダイレクトされた状態で、分離されたプロセスによって非同期に実行することができます。 内部メッセージングを適切に処理する必要があります。また、スクリプトは、スクリプトの実行中のいずれかの時点で短期間の ワークロード・パーティション が停止または停止する可能性があることを説明する必要があります。 スクリプトがゼロ以外の値を返すと、警告がログに記録されますが、それ以外に動作の変更はありません。 WPAR_STOP : スクリプトは、すべての ワークロード区画 プロセスが終了した後、カーネルが構成解除される前に、グローバル環境で実行されます。 注: このコード・パスは、標準入出力ストリームを閉じた分離プロセスによって実行できます。 内部メッセージングはそれに応じて処理されなければなりません。 スクリプトがゼロ以外の値を返すと、警告がログに記録されますが、それ以外に動作の変更はありません。
-v | 冗長モードで実行するコマンドを指定します。
-x | WPAR 間セマフォーおよび共有メモリー・セグメントへのアクセスを許可します。

-w | 仕様ファイルを書き込みます。 -o フラグと一緒に使用すると、 -w フラグにより、 wparexec コマンドは、実際には ワークロード・パーティション を作成せずに、新しい仕様ファイルを作成した後で終了します。
[--] [ 変数 = 値 ] /path/to/command [arg ...] | ワークロード・パーティション 内で実行するアプリケーション (トラッキング対象プロセス) を、必要な環境変数の設定および引数とともに指定します。 コマンドが ( -w フラグを指定して) 仕様ファイルのみを作成する場合を除き、このコマンド行構文または仕様ファイルの general.application 属性のいずれかでコマンドが必要です。 開始されると、提供されるコマンド行は常に ワークロード区画 内でシェル拡張されます。 コマンド・ラインを使用するとき、シェルのメタキャラクターは 早期拡張を防ぐため適切に拡張する必要があります。 特殊な二重マイナスのセパレーター (--) は、 後続のすべてのコマンド・ライン引数がトラッキングされたプロセスにより成り立つことを示すために使用されます。 例えば、この分離文字を使用して、 -N フラグへの属性間のあいまいさ、および追跡対象プロセスへの環境変数の割り当てを除去します。 ワークロード区画 ごとに 1 つのトラッキング対象プロセスのみがサポートされますが、このアプリケーションは他のプロセスを作成する可能性があります。 ワークロード区画 は、その中のすべてのプロセスが終了すると、自動的に停止し、除去されます。 ワークロード・パーティション は、 stopwpar コマンドによって早期に停止および除去される可能性があります。
