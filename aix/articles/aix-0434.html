目的

CDE ログイン・サービスを実行します。

構文

dtlogin [-config configuration_file ] [-daemon ] [-debug debug_level ] [-error error_log_file ] [-nodaemon ] [-resources resource_file ] [-server server_entry ] [-session session_program ] [-udpPort port_number ]

説明

dtlogin コマンドは、以下の主要なタスクをサポートします。
  • 明示的に管理されているローカル・ディスプレイおよびリモート・ディスプレイ、および XDMCP 管理のリモート・ディスプレイのための dtgreet ログイン画面の起動。
  • GUI ログイン画面から従来型端末 (キャラクター) ログインにアクセスする。
  • システム依存ユーザーの認証およびログインを行う。
  • 選択されたセッションを起動する。

dtlogin コマンドは、 init、 getty、および login が文字端末で提供するサービスに類似したサービスを提供します。これには、ログインとパスワードのプロンプト、ユーザーの認証、およびセッションの実行が含まれます。 セッション は、特定プロセスのライフタイムによって定義されます。 従来のキャラクター・ベースの端末の世界では、セッションはユーザーのログイン・シェル・プロセスです。DT のコンテキストでは、セッションは DT セッション・マネージャーです。 DT セッション・マネージャーを使用しない場合、終了オプションのあるウィンドウ・マネージャーまたはシェルを実行する端末エミュレーターのいずれかが、代表的な代替プログラムとなります。端末エミュレーターのライフタイムは実行されるシェル・プロセスのライフタイムです。 この場合、X セッションはキャラクター・ベース端末セッションのエミュレーションに縮小されます。 セッションが終了すると、 dtlogin は X サーバーをリセットし、(オプションで) プロセス全体を再始動します。

dtlogin コマンドは、X Display Manager Control Protocol バージョン 1.0を使用したリモート・ディスプレイの管理をサポートします。 リモート・ディスプレイの管理をサポートします。 dtlogin は、XDMCP から間接照会を受け取ると、選択機能プロセスを実行して、ディスプレイの代わりに XDMCP BroadcastQuery (または指定されたホストに対する XDMCP 照会) を実行し、XDMCP ディスプレイ管理を提供する使用可能なホストのメニューを提供することができます。 この機能は、ホスト・メニューを提供しない X 端末で役に立ちます。

dtlogin は、ユーザーに表示される最初のインターフェースを提供するため、使いやすく、特定のサイトのニーズに応じて簡単にカスタマイズできるように設計されています。

ログイン・ウィンドウ

ログイン・ウィンドウを使用すると、ユーザーは、ユーザー ID とパスワードを入力し、起動セッションを選択し、起動ロケールを選択することができます。 また、ユーザーは、X サーバーをリセットしたり、X サーバーを一時的に中断してキャラクター・ログイン・プロンプトにアクセスしたりすることができます。

ログイン・ウィンドウの内容は次のとおりです。
ログイン・フィールド
ユーザーが ID を入力できる入力フィールドを提供します。
パスワード・フィールド
ユーザーがパスワードを入力できる入力フィールドを提供します (エコーなし)。
「OK (了解)」ボタン
ユーザーを認証し、セッションを起動します。
「Clear (消去)」ボタン
ログイン・フィールドおよびパスワード・フィールドを消去します。
オプション
ユーザーはロケール名とログイン・セッション・タイプを選択できます。 また、ユーザーは、X サーバーを再始動したり、キャラクター・ログイン・プロンプト (ローカル・ディスプレイ用) に切り替えたりすることができます。 「Options (オプション)」メニューの内容は次のとおりです。
言語
「Languages (言語)」メニューを表示します。 ログイン画面の「オプション」メニューから言語を選択すると、即時にログイン画面がローカライズされ、次のセッションの LANG 変数が設定されます。 ログイン画面のローカライズと LANG は、セッションの終了時にデフォルト値に戻ります。 このメニューの内容は、システムにインストールされたロケールによって異なる場合があります。 これらは、 languageList リソースを使用してオーバーライドできます。 C のデフォルト・ロケールは、language リソースを使用して指定変更できます。 指定されたシステム・ロケールまたは languageList ロケールは、「言語」メニューのメニュー項目として表示されます。 表示する代替テキストは、 languageName リソースを使用して、特定のロケール名に対して指定できます。
「No-windows (ウィンドウなし)」
キャラクター・ログイン・プロンプトを表示します (ローカル・ディスプレイのみ)。
「Reload Login (再ロード・ログイン)」
X サーバーを再始動し、ログイン画面に戻ります。
リソース
使用されるリソースをリストします。
「Sessions (セッション)」
「Sessions (セッション)」メニューを表示します。 ユーザーは、ログインしたときに開始するセッション・タイプを選択できます。 以下のメニュー項目があります。
「DT Session (DT セッション)」
通常のデスクトップ・セッション (Xsession) を開始します。
「Fail-safe Session (復旧セッション)」
復旧セッション (Xfailsafe) を開始します。
ヘルプ
ヘルプ・メッセージを表示します。

サーバーの制御

dtlogin コマンドは、 POSIX シグナルを使用してローカル・サーバーを制御します。 SIGHUP シグナルにより、サーバーがリセットされ、すべてのクライアント接続がクローズされ、その他のクリーンアップ処理が実行されると予想されます。 また、SIGTERM シグナルにより、サーバーが終了すると予想されます。 これらのシグナルが予期されるアクションを実行しない場合、 resetSignal および termSignal リソースは代替シグナルを指定できます。

XDMCP を使用していないリモート・サーバーを制御するために、 dtlogin はディスプレイ上のウィンドウ階層を検索し、 KillClient X プロトコル要求を使用して、次のセッションのために端末をクリーンアップします。 しかし、ウィンドウが作成されたクライアントのみが検出されるため、すべてのクライアントが実際に kill されるとは限りません。 XDMCP は、より確実なメカニズムを提供します。 dtlogin が初期接続を閉じると、セッションは終了し、端末は他のすべての接続を閉じる必要があります。

dtlogin の制御

dtlogin コマンドは、SIGHUP および SIGTERM の 2 つのシグナルに応答します。 SIGHUP が送信されると、 dtlogin は、構成ファイルおよびサーバー・リソースによって指定されたファイルを再読み取りし、項目が追加または除去されたかどうかを判別します。 新しいエントリーが追加されると、 dtlogin は関連するディスプレイでセッションを開始します。 除去されたエントリーは即時に使用不可にされます。つまり、進行中のセッションは通知なしに終了し、新しいセッションは開始されません。 dtlogin は、SIGTERM に送信されると、進行中のすべてのセッションを終了し、終了します。 これは、システムをシャットダウンするときに使用します。

国際化対応

すべてのラベルおよびメッセージはローカライズ可能です。 dtlogin.cat メッセージ・カタログには、デフォルトのラベルとメッセージのローカライズされた表現が含まれています。 dtlogin コマンドは、 LANG 環境変数によって示される適切なメッセージ・カタログを読み取り、ローカライズされたストリングを表示します。 認証画面のオプションの 1 つを使用すると、ユーザーはデフォルトの言語を後続セッション用に指定変更することができます。 認証画面が選択された言語用にローカライズされている場合、画面はその言語で再表示されます。画面がローカライズされていない場合は、デフォルトの言語で表示されます。 いずれの場合も、結果のセッションに対して LANG 環境変数が適切に設定されます。

ディスプレイのデフォルトの言語を変更するには、dtlogin 構成ファイル内でリソース言語が使用可能です。 languageList リソースは、認証画面に表示されるデフォルトの言語セットをオーバーライドするために、 dtlogin 構成ファイルで使用できます。 languageName リソースは、ロケール名から「言語」メニューに表示されるテキストへのマッピングを提供するために使用できます。

認証と監査

dtlogin コマンドは、サービス名 dtloginを使用して PAM によって有効にされるログイン・サービスです。 dtloginクライアントは、従来のローカルUNIXログインと監査に加えて、PAM認証もサポートしている。 Kerberos や B1 などの追加の認証または監査機能が、個別ベンダーによって追加されることがあります。

システム全体の認証に PAM を使用するには、root ユーザー権限を設定し、 /etc/security/login.cfg ファイルの usw スタンザの auth_type 属性の値を PAM_AUTHに変更します。

PAM が有効になっている場合に使用される認証メカニズムは、 /etc/pam.confのログイン・サービスの構成によって異なります。 dtlogin コマンドには、 auth、 account、 password、および session の各モジュール・タイプの /etc/pam.conf エントリーが必要です。 dtlogin サービスの /etc/pam.conf では、以下の構成が推奨されます。
  dtlogin        auth               required       /usr/lib/security/pam_aix
  dtlogin        account            required       /usr/lib/security/pam_aix
  dtlogin        password           required       /usr/lib/security/pam_aix
  dtlogin        session            required       /usr/lib/security/pam_aix

X サーバー・セキュリティー

X サーバーでは、ユーザー・ベースのアクセス制御とホスト・ベースのアクセス制御の両方が提供されます。 デフォルトでは、 dtlogin は X サーバー (MIT-MAGIC-COOKIE-1) に対するユーザー・ベースのアクセス制御を使用します。 このレベルのセキュリティーでは、ユーザー単位でのアクセス制御が可能です。 このアクセス制御方式では、クライアントが渡した許可データがサーバー上の許可データに一致した場合に、クライアントはアクセスを許可されます。 ユーザーがログインすると、この許可データはデフォルトで $HOME/.Xauthority ファイルに保管され、保護されます。

しかし、非セキュア・ネットワークのある環境では、ホスト・ベースのアクセス制御メカニズムの使用が望ましい場合があります。ユーザー・ベースのアクセス制御の場合、どのようなホストでも秘密鍵を発見しさえすれば接続が可能になるという弱点があります。 また、ユーザー・ベースのアクセス制御には、R2 または R3 クライアントがサーバーに接続できないという欠点もあります。

authorize リソースは、 dtloginがユーザー・ベースまたはホスト・ベースのどちらのアクセス制御を使用するかを制御します。 詳しくは、 xhostおよび xauth コマンドを参照してください。

local を指定した場合は、このエントリーについて X サーバーを開始する必要があることを示します。 remote の値を指定した場合は、既存の X サーバーを接続する必要があることを示します。

X サーバーを開始する文字列。 dtlogin クライアントは常に、指定された DisplayName を使用して X サーバーに接続するため、X サーバーへのオプションとして明示的な接続番号 (前の例では:0 ) を指定することが必要になる場合があります。

dtlogin コマンド表示リソースは、すべての表示または特定の表示に対して指定できます。 特定のディスプレイを指定するには、Dtlogin と最終リソース名セグメントの間のリソース名にディスプレイ名を挿入します。 例えば、Dtlogin.expo_0.startup は、expo:0 ディスプレイ上の起動シェル・ファイルを定義するリソースの名前です。 リソース・マネージャーは、リソースの名前とその値をコロンで区切り、リソース名の部分をドットで区切ります。これにより、 dtlogin は、リソース名の生成時にドット (.) とコロン (:) に下線 (_) を使用します。

-config以外のすべてのフラグは、リソースとして構成ファイルにも指定できる値を指定します。 典型的な場合は、カスタマイズはコマンド・ライン・オプションではなく構成ファイルを使用して行われます。 これらのフラグは、デバッグおよび 1 回限りのテストで最も役に立ちます。

説明

環境リストへの追加

結果の環境変数の望ましいスコープに応じて、さらに次の 4 つのメソッドがあります。これらのメソッドは上記のリストを変更するか、上記のリストに追加されるものです。
  • exportList リソースは、親によって dtlogin プロセスに提供される変数のエクスポートを可能にするために使用できます。 この方式で指定される変数は、ディスプレイの X サーバー・プロセスとユーザーのセッションの両方で使用でき、デフォルト設定をすべて指定変更します。 このリソースは、少なくとも 1 つのスペースまたはタブで区切られた name=value の文字列を受け入れます。
  • environment リソースは、グローバルまたは表示ごとに環境変数を設定できるようにするために、 dtlogin 構成ファイルで使用できます。 この方式で指定される変数は、ディスプレイの X サーバー・プロセスとユーザーのセッションの両方で使用でき、デフォルト設定をすべて指定変更します。 このリソースは、少なくとも 1 つのスペースまたはタブで区切られた name=value の文字列を受け入れます。 この文字列を構文解析するシェルはないため、指定する値は定数でなければなりません。 次に例を示します。
    Dtlogin*environment:MAIL_HOST=blanco MAIL_SERVER=pablo
    注: LANG および TZ 環境変数は、構成ファイル内に独自の専用リソースを持っており、環境によって設定してはなりません。
  • シェルによる処理を必要とする環境変数、または別の環境変数の値に依存する環境変数は、起動スクリプト Xsessionで指定できます。 これらの変数はディスプレイ上のすべてのユーザーの環境にロードされますが、X サーバー・プロセスにはロードされません。 これらの変数は同じ変数の前の設定をすべて指定変更します。 Xsession スクリプトは、環境変数を設定するための ksh 構文を受け入れます。 次に例を示します。
    MAIL=/usr/mail/$USER
  • 個人用環境変数は、 $HOME/.dtprofile スクリプト・ファイルでユーザーごとに設定できます。 dtlogin コマンドは、このファイル内のコマンドに対して sh、 ksh、または csh のいずれかの構文を受け入れます。 これらのコマンドは、 tset または sttyを除き、端末入出力を実行するコマンドではなく、環境変数を設定するコマンドでなければなりません。 .dtprofile の最初の行が #!/bin/sh, #!/bin/ksh または #!/bin/cshの場合、 dtlogin は適切なシェルを使用して .dtprofileを解析します。 それ以外の場合は、ユーザーのデフォルト・シェル ($SHELL) が使用されます。

Xaccess ファイル

accessFile リソースによって指定されたデータベース・ファイルは、XDMCP サービスを要求するディスプレイからのアクセスを制御するために dtlogin が使用する情報を提供します。 このファイルには、直接照会およびブロードキャスト照会への応答を制御するエントリー、間接照会への応答を制御するエントリー、およびマクロ定義の、3 種類のエントリーが含まれています。

直接エントリーのフォーマットは、ホスト名またはパターンのいずれかです。 パターンがホスト名と相違する点は、1 つ以上のメタキャラクターを含んでいることです (* は 0 個以上の文字の任意のシーケンスに一致し、? は任意の単一文字に一致します)。メタキャラクターはディスプレイ・デバイスのホスト名と比較されます。 エントリーがホスト名の場合、比較はすべてネットワーク・アドレスを使用して行われるので、正しいネットワーク・アドレスに変換される名前はすべて使用できます。 パターンの場合は、正規のホスト名だけが比較に使用されるので、別名を突き合わせないようにする必要があります。 ホスト名またはパターンの前に感嘆符 (!) 文字を付けると、そのエントリーに一致するホストは除外されます。

間接エントリーにもホスト名またはパターンが入っていますが、その後に間接照会の送信先のホスト名またはマクロのリストが続きます。 間接エントリーは、ログイン画面を表示できるホストのメニューを提供するために、 dtlogin 実行 dtchooser を指定することもできます。

マクロ定義には、マクロ名と、ホスト名のリストとそのマクロが展開する他のマクロが入っています。 マクロをホスト名と区別するために、マクロ名の先頭には % 文字が付いています。 マクロはネスト可能です。

特定のディスプレイ・ホストへのアクセスを検査する場合、各エントリーが順にスキャンされ、最初に一致したエントリーが応答を決定します。 間接エントリーのスキャン中は直接エントリーおよびブロードキャスト・エントリーは無視されます。また、その逆もいえます。 ブランク行は無視され、 # はコメント区切り文字として扱われ、その行の残りは無視されます。 \newline は改行を無視し、間接ホスト・リストが複数行にまたがることができるようにします。

次に示すものは、Xaccess ファイルの例です。
#
# Xaccess - XDMCP access control file
#

#
# Direct/Broadcast query entries
#
!xtra.lcs.mit.edu # disallow direct/broadcast service for xtra
bambi.ogi.edu     # allow access from this particular display
*.lcs.mit.edu     # allow access from any display in LCS

#
# Indirect query entries
#

#define %HOSTS macro
%HOSTS                expo.lcs.mit.edu xenon.lcs.mit.edu \
                      excess.lcs.mit.edu kanga.lcs.mit.edu

#force extract to contact xenon
extract.lcs.mit.edu xenon.lcs.mit.edu

#disallow indirect access by xtra
!xtra.lcs.mit.edu   dummy

#all others get to choose among %HOSTS
*.lcs.mit.edu       %HOSTS

XDMCP アクセス権限が付与されている場合、X 端末の許可情報を含む一時ファイルを、 authDir によって指定されたディレクトリーに作成できます。 セッションが開始されると、この一時ファイルは削除されます。

ブロードキャスト照会または間接照会で使用するホスト・メニューを提供しない X 端末の場合、 chooser プログラムはそれらに対してこれを行うことができます。 Xaccess ファイルで、間接ホスト・リストの最初の項目として CHOOSER を指定します。 chooser プログラムは、リスト内の残りの各ホスト名に照会要求を送信し、応答するすべてのホストのメニューを表示します。 リストは BROADCASTという語で構成される場合があります。この場合、 chooser は代わりにブロードキャストを送信し、応答するすべてのホストのメニューを再び表示します。 オペレーティング・システムによっては、UDP パケットをブロードキャストできないものもあります。その場合、この機能は役に立ちません。

chooser プログラムを使用する Xaccess ファイルの例を以下に示します。
#offer a menu of these hosts to extract
extract.lcs.mit.edu CHOOSER %HOSTS

#offer a menu of all hosts to xtra
xtra.lcs.mit.edu    CHOOSER BROADCAST

chooser に使用するプログラムは、 chooser リソースによって指定されます。 このプログラム用のリソースは、resources によって名前を指定されたファイルに書き込むことができます。 デフォルトの Xaccess ファイルは /usr/dt/config/Xaccessです。 システム管理者は、 /usr/dt/config/Xaccess を /etc/dt/config/Xaccess にコピーしてから /etc/dt/config/Xaccessを変更することにより、 Xaccess をカスタマイズできます。 デフォルトの Xaccess ファイルには、エントリーが含まれていません。

Xservers ファイル

Xservers ファイルには、管理するディスプレイのリストが含まれています。 デフォルトの Xservers ファイルは /usr/dt/config/Xserversです。 システム管理者は、 /usr/dt/config/Xservers を /etc/dt/config/Xservers にコピーしてから /etc/dt/config/Xserversを変更することにより、 Xservers をカスタマイズできます。 デフォルトの Xservers ファイルには、1 つのローカル・ディスプレイ用の項目が含まれています。

Xresources ファイル

Xservers ファイルには、ログイン画面の外観を指定するリソース定義が含まれています。 デフォルトの Xresources ファイルは /usr/dt/config/Xresourcesです。 システム管理者は、 /usr/dt/config/Xresources を /etc/dt/config/Xresources にコピーしてから /etc/dt/config/Xresourcesを変更することにより、 Xresources をカスタマイズできます。

Xsetup ファイル

通常、 Xsetup ファイルはシェル・スクリプトです。 root ユーザーだけがこのスクリプトを実行できます。実行の際は特にセキュリティーに注意する必要があります。 このスクリプトはログイン画面が表示される前に実行されます。 どんな種類の引数もこのスクリプトには渡されません。 dtlogin コマンドは、ログイン画面を表示する前に、このスクリプトが終了するまで待機します。

デフォルトの Xsetup ファイルは /usr/dt/config/Xsetupです。 システム管理者は、 /usr/dt/config/Xsetup を /etc/dt/config/Xsetup にコピーしてから /etc/dt/config/Xsetupを変更することにより、 Xsetup をカスタマイズできます。 デフォルトの Xsetup ファイルには、ベンダー固有のコードが含まれていますが、通常は、キーボード・マップのセットアップなど、ログイン画面の表示前に X サーバーをセットアップするコードが含まれています。

Xstartup ファイル

通常、 Xstartup ファイルはシェル・スクリプトです。 root ユーザーだけがこのスクリプトを実行できます。実行の際は特にセキュリティーに注意する必要があります。 このスクリプトには、日替わりメッセージを表示したり、ユーザーに代わってその他のシステム・レベルの機能を実行したりするコマンドが書き込まれます。 このスクリプトを使用するために、以下の環境変数が設定されます。
表示
関連したディスプレイ名に設定されます。
HOME
ユーザーのホーム・ディレクトリーに設定されます。
PATH
systemPath リソースの値に設定します。
ユーザー
ユーザー名に設定されます。
SHELL
systemShell リソースの値に設定します。

どんな種類の引数もこのスクリプトには渡されません。 dtlogin コマンドは、このスクリプトが終了するまで待機してから、ユーザー・セッションを開始します。 このスクリプトの終了値がゼロ以外の場合、 dtlogin はセッションを即時に終了し、別の認証サイクルを開始します。

デフォルトの Xstartup ファイルは /usr/dt/config/Xstartupです。 システム管理者は、 /usr/dt/config/Xstartup を /etc/dt/config/Xstartup にコピーしてから /etc/dt/config/Xstartupを変更することにより、 Xstartup をカスタマイズできます。 デフォルトの Xstartup ファイルには、 /dev/console の所有権を、コンソールでセッションを実行しているユーザーに変更するコードが含まれています。

Xsession ファイル

Xsession スクリプトは、ユーザーのセッションを初期化し、デスクトップ・セッション・マネージャーを呼び出します。 このスクリプトは許可ユーザーのアクセス権によって実行され、いくつかの環境変数が事前設定されています。 事前設定変数のリストについては、 環境変数 を参照してください。

デフォルトの Xsession ファイルは /usr/dt/bin/Xsessionです。 システム管理者は、 /usr/dt/bin/Xsession を /etc/dt/config/Xsession にコピーしてから /etc/dt/config/Xsessionを変更することにより、 Xsession をカスタマイズできます。 Xconfig で定義されたセッション・リソースも、カスタマイズされた Xsession ファイルを参照するように変更する必要があります。 Xconfig ファイルの更新方法については、 Xconfig ファイル を参照してください。 デフォルトの Xsession ファイルには、セッション初期化コードが含まれています。 ベンダー固有のコードも入っていますが、このファイルの一般機能は次のとおりです。
  • ユーザーの $HOME/.dtprofile を提供します。
  • /etc/dt/config/Xsession.d/* スクリプトをソースとする
  • /usr/dt/config/Xsession.d/* スクリプトをソースとする
  • バックグラウンドでデスクトップ・ウェルカム・クライアント dthelloを起動します。
  • アプリケーション検索パス・セットアップ・スクリプト dtsearchpath を提供します。
  • ヘルプ・セットアップ・クライアント dthelpgenをバックグラウンドで起動します。
  • アプリケーション・マネージャー・ディレクトリー・セットアップ・クライアント dtappgatherをバックグラウンドで起動します。
  • デスクトップ・セッション・マネージャー dtsession を実行します。
システム管理者は、 Xsession ファイルをカスタマイズしないことをお勧めします。

Xreset ファイル

Xstartupと対称的に、 Xreset スクリプトは、ユーザー・セッションが終了した後に実行されます。 root ユーザーによって実行されるため、 Xreset スクリプトには、ファイル・サーバーからディレクトリーをアンマウントするなど、 Xstartupのコマンドの影響を取り消すコマンドを含める必要があります。 Xstartup に渡された環境変数の集合は、 Xresetにも提供されます。

デフォルトの Xreset ファイルは /usr/dt/config/Xresetです。 システム管理者は、 /usr/dt/config/Xreset を /etc/dt/config/Xreset にコピーしてから /etc/dt/config/Xresetを変更することにより、 Xreset をカスタマイズできます。 デフォルトの Xreset ファイルには、 /dev/console のコード変更の所有権が root に戻されます。

Xerrors ファイル

Xerrors スクリプトには、 dtlogin からのエラー・メッセージと、 Xsetup、 Xstartup 、または Xresetによって stderr に出力されるすべてのエラー・メッセージが含まれます。 システム管理者は、このファイルの内容を dtlogin のトラブルシューティングに使用できます。 errorLogSize リソースは、 Xerrors ファイルのサイズを制限し、バインドされていない状態で拡張されないようにすることができます。 ファイルが要求されたサイズより大きくなり、 dtloginによって切り捨てられた場合、ファイルにアクセスしているユーザー (例えば、 cat または tailを使用) は、ファイルに記録されている後続の情報を表示するために、ファイルを (ファイルが切り捨てられた後で) クローズし、アクセス用に再オープンする必要があります。

システム管理者は、 Xconfig ファイルで errorLogFile リソースを設定することにより、 Xerrors のパス名を変更できます。

Xpid ファイル

Xpid スクリプトには、マスター dtlogin プロセスのプロセス ID が含まれています。これは、 dtloginにシグナルを送信するときに使用できます。 システム管理者は、 Xconfig ファイルで pidFile リソースを設定することにより、 Xpid のパス名を変更できます。
