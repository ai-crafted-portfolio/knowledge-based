目的
論理ボリュームまたは物理ボリュームが、暗号化にキーサーバーのキー保護方式を使用する場合、暗号化キーサーバーに関連付けられたオブジェクトデータマネージャー（ ODM ）のデータベースエントリを管理します。

説明
暗号化キーサーバーは、暗号化キー情報を安全に保管します。 AIX® （ 7.3 ）オペレーティングシステムは、( IBM Security® Guardium® Key Lifecycle Manager (GKLM)) および Key Protect ( IBM Cloud® Key Protect ) キー
keyserv
サーバーをサポートしています。 クライアントとサーバー間の証明書のやり取りにより、サーバー
keyserv
へのアクセスが保護されます。 APIキーやアクセストークンなどの Key Protect の認証情報は、 Key Protect （KP）サーバーへのアクセスを保護します。 論理ボリュームが暗号化にキーサーバーによるキー保護方式を使用する場合、暗号化キーサーバーに関する情報は ODM データベースに格納されます。 暗号鍵サーバーに関連付けられている ODM データベース・エントリーを管理するには、
keysvrmgr
コマンドを使用できます。
注：
AIX 7.3 Technology Level (TL) 4 Service Pack (SP) 1 以降、 IBM では、 Hyper Protect Crypto Services (HPCS) が非推奨となり、 IBM Cloud Key Protect Dedicated Server に置き換えられます。 この
keysvrmgr
コマンドのオプションでは
-t
、有効な値として「
hpcs
」の代わりに「
kms
」が追加されました。 互換性の観点から、
hpcs
値は引き続き受け入れられていますが、
kms
値を使用する必要があります。 HPCSから Key Protect サーバーへ移行するには、
「HPCSから Key Protect サーバーへの移行」
のセクションを参照してください。
IBM AIX 7.2
（テクノロジーレベル 5： TL5 ）以降では、
action
パラメータを指定してコマンド
keysvrmgr
を実行することで、以下のいずれかの操作を実行できます：
add
: キーサーバーのエントリを追加します。
modify
: 既存のキーサーバーのエントリを変更します。
remove
: キーサーバーのエントリを削除します。
show
: キーサーバーのエントリに関する情報を表示します。
verify
: KPサーバーのエントリを確認します。
rekey
: ODM 内の KP サーバーエントリ用の API キーを作成します。

server_name
は、 ODM データベース内の ODM レコードを識別します。

構文
keysvrmgr action -t server_type [-h] { -a attribute=value ... } server_name

オプション
フラグ
表 1. フラグ
項目 | 説明
-t | この keysvrmgr コマンドがサポートするキーサーバーの種類を指定します。 keyserv IBM Security Key Lifecycle Manager kms IBM Cloud Key Protect
-a | attribute_name = attribute_value のペアを指定します。 attribute_name は ODM 属性の名前であり、 attribute_value は ODM データベース・レコードに保存されている指定された ODM 属性の値です。

例
ODM データベース内にある鍵サーバー・エントリーに関する情報を表示するには、以下のコマンドを実行します。
# keysvrmgr show -t keyserv
List of key servers:
ID PWD IP:PORT
sklm1 Y 10.11.12.13:5696
sklm_server2 N 210.211.212.213:569
Key Protect インスタンスを含むサーバータイプについて
kms
、既存の ODM エントリに関する情報を表示するには、次のコマンドを入力してください：
# keysvrmgr show -t kms
List of key servers:
SVR_NAME REGION INST_ID
kp-aix https://us-east.kms.cloud.ibm.com/crypto_v2 ad87c05a-79ff-4f51-a1ee-3cff2db5808b
hp-aix https://us-south.broker.hs-crypto.cloud.ibm.com/crypto_v2 f1a98698-a44f-4563-9149-d44494f5cb18
キー保護サーバー用の ODM エントリを追加するには、次のコマンドを入力してください：
# keysvrmgr add -t kms \
-a inst_id="f1a98698-a44f-4563-9149-d44494f5cb18" \
-a api_key="<your IBM Cloud API Key>" \
-a svr_region="https://us-east.kms.cloud.ibm.com/crypto_v2" <name>
name
変数の項目は、
keysvrmgr show
コマンドの
svr_name
パラメーターの値として使用されます。 新たに形成された ODM エントリーは、他のすべての操作の
name
変数によって参照されます。
キー保護サーバーに関する既存の ODM エントリを削除するには、次のコマンドを入力してください：
# keysvrmgr remove -t kms kp-aix
KMS server kp-aix successfully removed
キー保護サーバーの既存の ODM エントリを確認するには、次のコマンドを入力してください：
# keysvrmgr verify -t kms kp-aix

Start verifying the following ODM record:
Server name: kp-aix
Server region: https://us-east.kms.cloud.ibm.com/crypto_v2
Instance id: f1a98698-a44f-4563-9149-d44494f5cb18
ODM record kp-aix passed verification
検証処理が失敗した場合、次の画面のようなエラーメッセージが表示されます：
# keysvrmgr verify -t kms kp-aix
Start verifying the following ODM record:
Server name: kp-aix
Server region: https://us-east.kms.cloud.ibm.com/crypto_v2
Instance id: f1a98698-a44f-4563-9149-d44494f5cb18
3020-0560 curl_easy_perform() failed: Empty reply from server
ODM record kp-aix failed verification
ODM のエントリのAPIキーを再生成するには、次のコマンドを入力してください：
# keysvrmgr rekey -t kms kp-aix
Start rekey the following ODM record:
Server name: kp-aix
Server region: https://us-east.kms.cloud.ibm.com/crypto_v2
Instance id: f1a98698-a44f-4563-9149-d44494f5cb18
Update succeeded for ODM record kp-aix:
Old API_key: <old API key>
New API_key: <new API key>
Rekey succeeded for ODM record kp-aix
既存の ODM エントリの任意の属性を変更するには、次のコマンドを入力してください：
# keysvrmgr modify -t kms \
-a api_key=<new API key> \
-a inst_id=<new Instance ID> \
-a svr_region=<new region URL> kp-aix

KMS server kp-aix successfully modified
ODM エントリの変更内容を確認するには、次のコマンドを入力してください：
keysvrmgr verify -t kms kp-aix
