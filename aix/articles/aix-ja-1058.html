目的
DNS サーバーを動的に更新します。

説明
nsupdate
コマンドは、
RFC 2136
で定義されている動的 DNS 更新要求をネーム・サーバーに送信します。 このコマンドを使用すると、ゾーンファイルを手動で編集することなく、 リソースレコードをゾーンに追加したり削除したりすることができる。 1 つの更新要求に、複数のリソース・レコードの追加または除去の要求を含めることができます。
nsupdate
コマンドまたは DHCP サーバーを使用して動的に制御されるゾーンは、手動で編集してはなりません。 手動による編集は、動的更新と衝突し、データ損失を引き起こす可能性があります。
nsupdate
コマンドを使用して動的に追加または削除されるリソース・レコードは、同じゾーン内になければなりません。 リクエストはゾーンのプライマリサーバに送られ、そのプライマリサーバは ゾーンの権威開始(SOA)レコードの'
MNAME
フィールドで識別される。
トランザクション署名 (TSIG) を使用して、動的 DNS 更新を認証できます。 トランザクション署名は、
RFC 2845
に記述されている TSIG リソース・レコード・タイプ、
RFC 2535
および
RFC 2931
に記述されている SIG (0) レコード、または
RFC 3645
に記述されている GSS-TSIG を使用します。
TSIG は、
nsupdate
コマンドおよびネーム・サーバーにのみ認識される必要がある共有秘密鍵に依存します。 例えば、適切な鍵およびサーバー・ステートメントが
/etc/named.conf
ファイルに追加されます。これにより、ネーム・サーバーは、適切な秘密鍵およびアルゴリズムを、TSIG 認証を使用するクライアント・アプリケーションの IP アドレスに関連付けることができます。
ddns-confgen
コマンドは、適切な構成フラグメントを生成できます。
nsupdate
コマンドは、
-y
オプションまたは
-k
オプションを使用して、TSIG 共有秘密鍵を指定します。 これらのオプションはどちらか一方を使用します (両方を指定することはできません)。

SIG (0) 鍵は公開鍵暗号方式を使用します。 SIG (0) 鍵を使用するには、ネーム・サーバーによって提供されるゾーン内の KEY レコードに公開鍵を保管する必要があります。 Generic Security Service Algorithm - Transaction Signature (GSS-TSIG)は、Kerberosクレデンシャルを使用する。 標準GSS-TSIGモードは、「
-g
フラグを使用することで有効になる。

例
以下の例は、
example.com
ゾーンのリソース・レコードを挿入および削除するための
nsupdate
コマンドの使用法を示しています。 各例の入力には末尾ブランク行が含まれているため、コマンドのグループを 1 つの動的更新要求として 1 次ネーム・サーバー
example.com
に指定することができます。
既存のゾーンからリソースレコードを削除し、新しいゾーンにリソースレコードを追加するには、以下のコマンドを入力する：
# nsupdate
> update delete oldhost.example.com A
> update add newhost.example.com 86400 A 172.16.1.1
> send
oldhost.example.com
」のAレコードはすべて削除され、IPアドレス172.16.1.11の「
newhost.example.com
」のAレコードが追加される。 新規レコードの TTL は 1 日 (86400 秒) です。
DNS サーバーを更新する前に前提条件を指定するには、次のコマンドを入力します。
# nsupdate
> prereq nxdomain nickname.example.com
> update add nickname.example.com 86400 CNAME somehost.example.com
> send
前提条件は、「
nickname.example.com
いかなるタイプのリソースレコードも存在しないことを検証するよう、ネームサーバーを指定する。 ゾーンにリソース・レコードがある場合、更新要求は失敗します。 この名前が存在しない場合、CNAMEが追加され、前提条件が
RFC 1034
で規定されている長年のルールと衝突しないことを保証する。 RFC1034で規定されているルールは、名前がCNAMEとして存在する場合、他のレコードタイプとして存在してはならないというものである。
注：
このルールは
RFC2535
のDNSSECのために更新され、CNAMEがRRSIG、 DNSKEY、NSECリソースレコードを持つことを許可している。
