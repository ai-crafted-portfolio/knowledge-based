目的
ネーム・サーバー制御ユーティリティー。

説明
rndc
コマンドはネーム・サーバーの操作を制御します。 コマンドラインオプションや引数を指定せずに「
rndc
コマンドを実行すると、サポートされているコマンドの短い要約と、使用可能なオプションとその引数が表示される。
rndc
コマンドは TCP 接続を経由してネーム・サーバーと通信し、
デジタル署名を使用して認証されたコマンドを送信します。 現在のバージョンの'
rndc
コマンドと'
named
デーモンでは、以下のアルゴリズムのみが サポートされている認証アルゴリズムである：
HMAC-MD5（互換性のため）
HMAC-SHA1
HMAC-SHA224
HMAC-SHA256（デフォルト）
HMAC-SHA384
HMAC-SHA512
サポートされている認証アルゴリズムは、接続の各エンドで共有秘密を使用し、 ネームサーバーのコマンド要求と応答にTSIGスタイルの認証を提供する。 サーバーが知っている
key_id
は、チャネル上で送信されるすべてのコマンドに署名しなければならない。
rndc
コマンドは構成ファイルを読み取って、ネーム・サーバーに連絡する方法を
決定し、どのアルゴリズムおよび鍵を使用すべきかを決めます。

rndc [ ' -b source-address ] [ -c config-file ] [ -k key-file ] [ -s server ] [ -p port ] [ -q ] [ -r ] [ -V ] [ -y key_id ] [[ -4 ] [ -6 ]]。 {コマンド｝

フラグ
表 1. フラグ
項目 | 説明
-4 | IPv4 のみを使用することを示します。
-6 | IPv6 のみを使用することを示します。
-b ソース・アドレス | サーバーへの接続用の送信元アドレスとして source-address を使用します。 IPv4 と IPv6 の送信元アドレスの両方の設定を許可するために、複数インスタンスが許されます。
-c config-file | デフォルトの' /etc/rndc.conf コンフィギュレーション・ファイルの代わりに、 コンフィギュレーション・ファイルとしてconfig-file の値を使用する。
-k key-file | デフォルトの' /etc/rndc.key ファイルではなく、 key-file の値をキーファイルとして使用する。 config-file 引数が存在しない場合、「 /etc/rndc.key ファイルのキーは、サーバーに送信されるコマンドの認証に使われる。
-s サーバー | rndc コマンドのコンフィギュレーション・ファイルの server 文にマッチするサーバーの名前またはアドレスを指定する。 server の値を指定しないと、コンフィギュレーション・ファイルのoption文のdefault-server句で指定されたホストが使われる。
-p port | デフォルトのコントロール・チャンネル・ポート953ではなく、TCPポートにコマンドを送信する。
-q | エラーが発生しない限り、サーバーによって戻されるメッセージ・テキストを印刷しないように抑制モードを設定します。
-r | named ユーティリティーが要求されたコマンド (例えば、ISC_R_SUCCESS、ISC_R_FAILURE) を実行した後に named ユーティリティーによって返された結果コードを出力します。
-V | 詳細ロギングを使用可能にします。

-y キーID | コンフィギュレーション・ファイルの key_id キーを使用する。 key_id 値は、制御メッセージの検証を成功させるために、同じアルゴリズ ムと秘密文字列を持つ「 named デーモンが知っていなければならない。 key_id の値を指定しなかった場合、' rndc コマンドはまず、使用中のサーバーのserver文の中からkey句を探す。 そのホストにserver文がない場合は、options文のdefault-key句が使われる。 注： 設定ファイルには、認証された制御コマンドをネームサーバーに送信するために使用される共有秘密が含まれている。 したがって、この構成ファイルは汎用読み取りアクセス権または汎用書き込みアクセス権を保有できません。
