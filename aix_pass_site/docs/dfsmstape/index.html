このガイドについて

位置づけ

このページは、IBMの英語原文を逐語訳したものではありません。原文の章立て、ラベル形式、処理フロー、制約を保ちながら、運用判断に使えるよう日本語で再構成した解説です。フィールド長、出口仕様、メッセージ条件などを実装判断に使う場合は、必ず原典も確認してください。

磁気テープ処理では、データそのものだけでなく、ボリュームとデータセットを識別するラベル、データセット境界を表すテープマーク、JCLから作られるJFCB、プログラムのDCB/DCBE、RACFやDFSMSrmmの管理情報が協調します。OPENはこれらを突き合わせて入力対象を位置決めし、出力先を検証してヘッダーラベルを作成します。EOVはボリューム切り替えを、CLOSEはデータセット終端の確定を担当します。

01識別

VOLSER、データセット名、シーケンス番号で、正しい媒体とデータセットかを確認します。

02記述

HDR2などからRECFM、LRECL、BLKSIZE、記録方式を補完します。

03保護

RACF、保存期限、DFSMSrmm、導入出口が上書き可否やマウント可否を制御します。

04境界

テープマークとEOF/EOVラベルでデータセット終端とボリューム継続を区別します。

ラベル方式の選び方

DD文のLABELパラメーターが、z/OSにどのラベル処理を要求するかを決めます。指定しない場合はIBM標準ラベルとして扱われます。

指定方式主な用途と注意
SLIBM標準ラベル通常のz/OSテープ。VOL1、HDR1/HDR2、EOF/EOVをシステムが処理します。ラベル種別を省略した場合の既定です。
SULIBM標準 + ユーザーラベルSLに加えてUHL/UTLを扱います。DCB出口リストにユーザーラベル処理ルーチンが必要です。
ALISO/ANSI標準ラベルASCIIベースの交換用ラベル。z/OSはVersion 3または4を作成します。
AULISO/ANSI + ユーザーラベルALに任意個数のユーザーヘッダー/トレーラーラベルを加えます。ASCII文字制約に注意します。
NSL非標準ラベル導入先独自形式。OPEN/EOV/CLOSEへ組み込む導入ルーチンを自作・管理します。DFSMSrmmはサポートしません。
NLラベルなしデータレコードとテープマークのみ。内部ラベルによる媒体識別ができないため、外部ラベルとオペレーター確認への依存が増えます。
LTM先頭テープマーク許容他システム由来のラベルなしテープで、先頭データセット前のテープマークを検出して読み飛ばします。
BLPラベル処理のバイパスNLに近い処理ですが、既存標準ラベルの確認も省略します。JES、RACF、DFSMSrmmで厳格に制限する前提の高リスク指定です。
BLPは通常運用の近道ではありません

BLPではOPEN/CLOSE/EOVがラベルの有無を判断できず、正しい位置決めを利用者側が担います。RACFのTAPEVOLクラスとFACILITYクラスのICHBLP、JESのジョブクラス制御、DFSMSrmmの検証を組み合わせ、許可対象を限定します。

単一データセット / 複数ボリューム

ボリューム集合全体をアグリゲートとして扱います。データセットの位置は、個々のボリューム内だけでなく集合全体に対する論理シーケンスで管理します。

DCB/DCBEが完成する順序

実行時の属性は、プログラムまたはコンパイラーが作るDCB/DCBE、DD文や動的割り振りから作られるJFCB、データクラス、既存ラベルから集められます。入力、INOUT、RDBACK、EXTEND、またはDISP=MODを伴う出力では、標準ラベルの情報がJFCBの空きフィールドへ前方向にマージされ、続いてJFCBからDCB/DCBEへ補完されます。出力では完成したDCBの情報がJFCBへ逆方向に反映され、新しいラベルの材料になります。

データセット構成で変わる指定

  • 連結: DD文の出現順に読みます。逆方向読み取りはできません。属性が異なる場合はDCBのunlike-attributes指定が必要です。
  • ジョブステップ間の受け渡し: 装置種別、VOLSER、シーケンス番号、ラベル種別は引き継げますが、密度やレコード形式などの属性は自動では引き継がれません。
  • 複数ボリューム: 特定VOLSERを列挙するか、VOLSERを省略してスクラッチ要求にします。使用しなかった特定ボリュームまでカタログ登録すると、後の検索が不正確になります。
  • 複数データセット: 2番目以降はLABELのデータセットシーケンス番号、またはカタログの位置情報を使います。
  • GDG: 相対世代名を使用できます。SMS管理の新世代では明示DCB属性、REFDD、LIKE、DATACLASが基礎になり、モデルDSCBは使用されません。
JCL例 - IBM標準ラベルの入力
//TAPEIN  DD  DSN=HLQ.INPUT.DATA,DISP=SHR,
//             UNIT=TAPE,VOL=SER=TAPE01,
//             LABEL=(1,SL),
//             DCB=(RECFM=FB,LRECL=80,BLKSIZE=27920)

環境の装置名、SMS方針、カタログ有無に合わせて調整する例です。

ブロック数検証

標準ラベルのBSAM/QSAM/EXCP処理では、読み取り終了時にトレーラーラベルの期待ブロック数と実績を照合します。カートリッジではハードウェアが保持する情報との追加照合も可能です。EXCPではDCB上のカウント維持とREPOS=Yが重要で、不一致はDCB ABEND出口またはABEND 117/237につながります。

IBM標準ラベル

IBM標準ラベルは、1ラベルにつき80文字（通常は80バイト）の固定長レコードです。カートリッジと9トラックではEBCDIC、7トラックではBCDICで記録されます。先頭3バイトがラベル識別子、4バイト目がラベル番号で、両者を合わせたVOL1、HDR1、HDR2などの4文字でレコードの種類を判別します。

HDR1とHDR2は、それぞれ80バイト

HDR1とHDR2を合わせて80バイトではありません。両者は連続して記録される別々の80バイト・レコードなので、標準ヘッダーだけで合計160バイトです。同様に、EOF1とEOF2、EOV1とEOV2もそれぞれ80バイトずつです。各ラベルレコードの後ろに固定長の余白を足すのではなく、以下のフィールド合計が厳密に80バイトになります。

テープマークとの境界

  • VOL1から最初のHDR1まで: 間にテープマークはありません。
  • ヘッダー群の後: テープマーク1個がヘッダー群の終端とデータ開始を示します。
  • データの後: テープマーク1個がデータ終端とEOV/EOFトレーラー群の開始を示します。
  • トレーラー群の後: テープマーク1個で群を閉じます。最終データセットが次ボリュームへ継続しない場合は、さらに2個目のテープマークが続きます。

入力と出力の要点

入力OPEN

  1. VOL1のVOLSERを要求値と照合します。
  2. 論理データセットシーケンスでHDR1の位置まで進めます。
  3. HDR1/HDR2を検証し、空いているDCB/JFCB属性を補完します。
  4. SULならUHL出口を呼び出します。
  5. テープマーク後からユーザーデータを読みます。

出力OPEN / EOV / CLOSE

  1. 既存VOL1、RACF権限、保存期限、上書き可否を確認します。
  2. JFCB/DCBからHDR1/HDR2を作成します。
  3. EOVではEOV1/2を書き、次ボリュームを検証してHDRを再作成します。
  4. CLOSEではEOF1/2を書き、最終終端をテープマークで確定します。
高速位置決め

カートリッジでは、JFCBの高速位置決め標識とブロックIDを使ってデータセット先頭または末尾へ移動できます。DFSMSrmmはブロックIDを保存して再利用し、3590以降のテープ技術ではOPENが既定で高速位置決めを行います。

ISO/ANSIラベル

ISO/ANSIラベルは情報交換を目的とするASCII系ラベルです。z/OSはVersion 3またはVersion 4を作成し、Version 1は入力できますがVersion 3/4相当の検証は行いません。

観点IBM標準ISO/ANSI
文字コードEBCDIC（7トラックはBCDIC）規格で許可されたASCII文字
ラベル長80バイト固定80バイト以上を許容。ただしz/OSの出力・再書き込みは80バイトで、超過部は失われます。
追加ボリュームラベルVOL1のみを処理VOL2-9、UVL1-9を受け入れますが、z/OSは作成せず、識別子と順序だけを確認します。
ユーザーラベルUHL/UTL各最大8件UHLa/UTLaは任意個数。連番である必要はありません。
追加HDR/EOF/EOVHDR1/2、EOF1/2、EOV1/23-9も入力上許容しますが、z/OSは作成しません。
作成バージョン該当なしVersion 3またはVersion 4。同一マルチボリューム内で混在不可です。
チェックポイント条件に応じて再位置決めISO/ANSIテープがOPEN中はCHKPT取得不可です。

文字と変換

Version 3のデータとVersion 3/4のラベルは基本ASCIIの制約を受けます。Version 4ではラベルにアンダースコアも使用できます。ASCII変換、CCSID変換、ブロックパディング、スパンレコード、ラベル検証出口の組み合わせを事前に設計してください。生のバイナリー、浮動小数点、パック10進数をVersion 3の交換媒体へそのまま載せる設計は避けます。

アクセス保護と互換性

RACFで保護されていないVersion 3/4媒体では、VOL1とHDR1のaccessibilityコードが導入出口の判断対象になります。出力時には密度だけでなくラベルバージョンの競合も検証されます。再ラベルにより80バイトを超える独自情報やVOL2-9/UVLが失われる可能性があるため、交換元の仕様を確認してから書き込みを許可します。

CHAPTER 4 · PRINTED PAGES 101-102

非標準ラベル

非標準ラベルは、IBM標準にもISO/ANSI標準にも従わない導入先独自形式です。長さ、形式、内容、個数は自由ですが、テープ先頭レコードをEBCDIC、BCDIC、ASCIIの標準VOL1にすることはできません。

タイミング処理メンバー名
OPEN入力ヘッダーNSLOHDRI
EOV入力ヘッダーNSLEHDRI
OPEN出力ヘッダーNSLOHDRO
EOV出力ヘッダーNSLEHDRO
EOV入力トレーラーNSLETRLI
EOV出力トレーラーNSLETRLO
CLOSE出力トレーラーNSLCTRLO
  • ルーチンはSYS1.LPALIBへ組み込みます。更新は許可されたシステムプログラマーがSMP/E管理で実施します。
  • DDRでボリューム検証する場合は、先頭48バイト以内で検証できるNSLREPOSが必要です。
  • OPEN用ボリュームラベルエディターはOMODVOL1、EOV用はEMODVOL1から開始します。
  • DFSMSrmmは非標準ラベル付きテープを管理対象としてサポートしません。
CHAPTER 5 · PRINTED PAGES 103-108

ラベルなしテープ

NLまたはLTMを指定したテープは、データレコードとテープマークだけで構成されます。z/OSが行う媒体検証は、先頭レコードがEBCDICまたはASCIIの標準VOL1でないことの確認に限られます。内部ラベルで媒体やデータセットを確実に同定できないため、外部ラベルとオペレーター確認が重要です。

NL

先頭データセットの前にテープマークがない構成を前提にします。先頭がテープマークなら、空データセットが1件あるものとして次のデータセットをシーケンス2と解釈します。

LTM

先頭テープマークがあれば読み飛ばし、なければNLと同様に処理します。他システム由来のマルチボリューム媒体で、各ボリュームの先頭マークを吸収する用途に適します。

位置決めとボリューム切り替え

  • データセットシーケンス番号は1から65535です。省略または0なら、非カタログデータセットは1番目とみなします。
  • 複数ボリュームでは、JCLまたはカタログに記録されたVOLSER列が切り替え判断の根拠です。テープマークが1個か2個かでは継続を判断しません。
  • 同一ボリュームで同時にOPENできるデータセットは1件だけです。
  • RDBACKでは可変長レコード、連結データセット、7トラックのデータ変換などに制約があります。
  • 要求前にラベルなし媒体を先行マウントすると識別できず、デマウント対象になり得ます。
標準ラベルを破壊する可能性

NL出力要求に標準ラベル付き媒体がマウントされた場合、RACF権限、パスワード、保存期限、オペレーター応答、導入出口、DFSMSrmmの判断を経て、標準ラベルをテープマークで上書きする処理へ進む可能性があります。出力ジョブではVOLSER、保存期限、スクラッチ状態、RACF権限を事前に確認してください。

CHAPTER 6 · PRINTED PAGES 111-112

他システムで作成したテープ

標準ラベル付き媒体

ラベル形式が同じでも、フィールドの使い方が同じとは限りません。特にHDR1のデータセット識別子に空白や特殊文字が含まれる場合は、DD文のデータセット名を引用符で囲むか、JFCBを補正して一致させます。HDR2がない媒体でも、RECFM、BLKSIZE、LRECL、記録方式などをDD文またはDCBで補えば処理できます。

非標準・ラベルなし媒体

独自ラベルを処理するなら導入ルーチンが必要です。独自ラベルを無視してデータだけを読む場合はラベルなしとして扱い、シーケンス番号でラベル群を越えて位置決めします。ラベルなし媒体は、z/OSが認識できるテープマークでデータセットが区切られている必要があります。

OS/400作成テープの短い可変長ブロック

18バイト未満の可変長ブロックは互換性上の注意点です。OS/400がX'80'とX'00'でパディングした短いformat-Vブロックは、z/OSでABEND 002になる場合があります。非スパンレコードでもRECFM=VSまたはRECFM=VBSとして、X'80'で始まるセグメント以降を無視させる回避策を検討できます。データ形式を確認したうえで検証環境から適用してください。

APPENDIX A · PRINTED PAGES 113-114

IBMテープライブラリー

SMS管理下のテープライブラリーは、テープボリュームとドライブの名前付き集合です。TCDB（ICFカタログ）がライブラリーと媒体の在庫を保持し、DFSMSrmmが媒体上のデータセットと移動・スクラッチ状態を管理します。

特定マウント

JCL要求VOLSER、外部ラベル、内部VOL1がすべて一致する必要があります。不一致なら要求は失敗し、手動モードではデマウント後に再要求されます。

非特定マウント

カートリッジ種別ごとのスクラッチプールから選択します。内部/外部ラベル不一致や読取不能時の処置は、自動・手動モードとRACF保護状態で変わります。

エラー分類

検証で拒否されたスクラッチ媒体はエラーカテゴリーへ移され、原因が解消されるまで次のスクラッチ要求に選ばれません。

  • ライブラリー内の内部ラベルと外部ラベルは一意で、同じVOLSERでなければなりません。
  • VOLSERで使用できる文字は大文字A-Zと数字0-9です。
  • 自動ライブラリーのIEC501A/IEC501E/IEC502Eは通常オペレーター画面ではなくシステムログへ記録されます。
  • 手動モードの不一致ではIEC704Aが発行され、オペレーターは外部ラベル情報を供給するか媒体を拒否します。
APPENDICES B-D · PRINTED PAGES 115-131

外部ラベル、コンポーネント対応、文字変換

外部ラベル

リール/カートリッジ識別ラベル

媒体受け入れ時に恒久接着し、一意のVOLSERと必要に応じて導入先識別を表示します。

内容ラベル

現在の内容を識別する一時ラベルです。保持でき、かつ交換時に容易にはがせる接着方法を使います。

チェックポイント保護ラベル

チェックポイントデータセットを含む媒体に一時表示し、誤使用を防ぎます。媒体搬送を妨げない大きさと位置にします。

鉛筆や消しゴムは媒体周辺に残留物を出すため使用せず、残りかすを生じにくいペンまたはフェルトペンを使用します。

コンポーネント対応の読み方

アセンブラー、リンケージエディター、DFSORT、ユーティリティー、各世代のCOBOLは、SL/AL、SUL/AUL、NSL、NL、BLP、属性の異なる連結データセットへの対応範囲が異なります。特にユーザーラベルとNSLは製品ごとの差が大きいため、ジョブ制御だけでなく使用プログラムの対応表も確認します。

ASCII / EBCDIC変換

システムの変換表は7ビットASCIIとEBCDICの対応を定義しますが、変換は常に可逆ではありません。ASCIIへ表現できないEBCDIC文字はX'1A'、EBCDICへ表現できないASCII文字はX'3F'へ置き換わります。往復変換が必要なデータでは、CCSIDと使用文字集合を先に固定し、置換文字の発生を監視してください。
