目的

互換性のあるインストール・パッケージ内の使用可能なソフトウェア・プロダクトをインストールします。

構文

適用のみ、または適用とコミットでインストールするには
installp [ -R path ] [ -a | -a -c [ -N ] ] [ -e LogFile ] [ -V Number ] [ -d Device ] [ -E ] [ -Y ] [ -b ] [ -S ] [ -B ] [ -D ] [  -I ] [ -p ] [ -Q ] [ -q ] [  -v ] [  -X ] [ -F | -g ] [ -O { [ r ] [ s ] [ u ] } ] [ -t  SaveDirectory ] [ -w ] [ -z BlockSize ] { FilesetName [ Level ]... | -f ListFile | all }
適用されたアップデートをコミットする
installp [ -R path ] -c [ -e LogFile ] [ -V Number ] [ -b ] [  -g ] [ -p ] [  -v ] [ -X ] [ -O { [ r ] [ s ] [ u ] } ] [ -w ] { FilesetName [ Level ]... | -f ListFile | all }
申請されたアップデートを拒否する
installp [ -R path ] -r [ -e LogFile ] [ -V Number ] [ -b ] [ -g ] [ -p ] [ -v ] [ -X ] [ -O { [ r ] [ s ] [ u ] } ] [ -w ] { FilesetName [ Level ]... | -f ListFile }
インストールしたソフトウェアをデインストール（削除）するには
installp [ -R path ] -u [ -e LogFile ] [ -V Number ] [ -b ] [ -g ] [ -p ] [ -v ] [ -X ] [ -O { [ r ] [ s ] [ u ] } ] [ -w ] { FilesetName [ Level ]... | -f ListFile }
失敗したインストールをクリーンアップするには
installp [ -R  path ] -C [ -b ] [ -e LogFile ]
メディア上のすべてのインストール可能なソフトウェアをリストする
installp { -l | -L } [ -e LogFile ] [ -d  Device ] [ -B ] [  -I ] [ -q ] [-E ] [ -z BlockSize ] [ -O { [ s ] [ u ] } ]
ソフトウェアで修正された、お客様から報告されたすべての問題をリストアップする、またはすべての補足情報を表示するには
installp { -A| -i } [ -e LogFile ] [ -d Device ] [ -B ] [ -I ] [ -q ] [ -z BlockSize ] [ -O { [ s ] [ u ] } ] { FilesetName [ Level ]... | -f ListFile | all }
適用されているがコミットされていないインストール済みアップデートを一覧表示する
installp -s [ -e LogFile ] [ -O { [ r ] [ s ] [ u ] } ] [ -w ] { FilesetName [ Level ]... | -f ListFile | all }
メディア上のプラットフォーム固有のインストール可能ソフトウェアをリストする
installp { -l | -L } { -M Platform } [ -e LogFile ] [ -d Device ] [ -B ] [ -I ] [ -q ] [ -z BlockSize ] [ -O { [ s ] [ u ] } ]
ソフトウェアの署名を検証する
installp -G -d Device { FilesetName [ Level ]... | -f ListFile | all }

説明

注:
  1. Korn または C シェルの noclobber オプションの設定を、インストールの実行元の環境から解除してください。
  2. すべてのアップデートはsmittyまたは'install_all_updatesコマンドで行うことができる。

installp コマンドは、ソフトウェアのインストールと更新を行います。

ファイルセットとは、インストール可能な最下位レベルの基本単位のことです。 例えば、bos.net.tcp.client 4.1.0.0 は、1 つのファイルセットです。 ファイルセットの更新は、異なるモディフィケーション・レベルまたは異なる修正レベルのイメージです。 例えば、'bos.net.tcp.client 4.1.0.2と 'bos.net.tcp.client 4.1.1.0はどちらも 'bos.net.tcp.client 4.1.0.0 のファイルセット更新である。

基本レベル (ファイルセット) は、システムにインストールされると自動的にコミットされます。 ファイルセットは、状態 (コミット済み、破壊、適用済み更新パッケージによるコミット済み、コミット済み更新パッケージによるコミット済みなど) と無関係に除去できます。

ファイルセット更新パッケージがシステムに適用されると、その更新パッケージがインストールされます。 インストール中のソフトウェアの現在のバージョンは、ディスク上の特別なセーブ・ディレクトリに保存されるので、後で必要に応じてそのバージョンに戻ることができる。 ソフトウェア製品の新バージョンがシステムに適用されると、そのバージョンが現在有効なバージョンとなる。

システムに適用されたアップデートは、後でコミットすることも、拒否することもできる。 installp -s コマンドを使用すると、コミットまたは拒否可能な適用済みの更新パッケージ内容のリストが得られます。

-c フラグを指定して更新パッケージをコミットすると、ユーザーはそのバージョンのソフトウェア・プロダクトに対するコミットメントを行うことになります。 そのソフトウェア・プロダクトのすべての旧バージョンからの保存済みファイルは、システムから除去され、そのソフトウェア・プロダクトの旧バージョンに戻ることは不可能になります。 ソフトウェアは、インストール時に -ac フラグの指定によりコミットできます。
注:
  • 既に適用済みの更新パッケージをコミットしても、ソフトウェア・プロダクトの現在アクティブなバージョンの変更はできません。 ソフトウェア・プロダクトの旧バージョンの保存ファイルを除去するだけです。
  • パッケージのインストール時に署名検査が行われます。 この検査はデジタル署名検査ポリシーのレベルに基づいています。

-u フラグの指定により基本レベルが除去されると、ソフトウェア・プロダクトの一部であるファイルおよびその更新内容は、システムから除去されます。 製品に関連するシステム構成情報のクリーンアップもほとんど行われるが、クリーンアップは製品によって異なり、必ずしも完全ではないかもしれない。

-r フラグの指定によりソフトウェア・プロダクトの更新が拒否されると、ソフトウェア・プロダクトの現行のバージョンは更新の直前のバージョンに変更されます。 拒否されたアップデートのために保存されたファイルと、適用されたすべてのアップデートは、システムから削除されます。

システムから除去対象のソフトウェア・プロダクトは、どのような状態でもかまいません。 製品のアップデートは、適用された状態かコミットされた状態のいずれかにすることができ、削除もされる。

以前に中断したインストールのために、ソフトウェアが適用済み状態またはコミット済み状態のままになっている場合は、-C フラグを指定してクリーンアップを実行しなければ、 それ以降のインストールをすることはできません。 installp -C コマンドは、コマンド・ライン上のソフトウェア・プロダクト名を受け付け、エラーは戻しませんが、 -C フラグを指定すると、必ずすべてのプロダクトをクリーンアップしようとします。 不完全なインストール部分があると、前回完了したインストール部分を除去することによりクリーンアップしようとします。 また、ソフトウェア・プロダクトの以前のバージョンがある場合は、そのバージョンに戻ってそれを現在アクティブなバージョンにしようとします。 ソフトウェア製品を以前のバージョンに戻すことができない場合、そのソフトウェア製品は壊れたものとしてマークされ、ユーザーがそれを使用しようとすると予測できない結果が発生する可能性があります。 したがって、ソフトウェア・プロダクトまたは更新パッケージが破壊した場合には、再度インストールすることをお勧めします。

-tフラグは、更新によって置き換えられるファイルを保存するセーブディレクトリの代替場所を指定する。 このオプションは、主に次の 2 つの場合に役立ちます。

  • 置き換えたファイルを保存するのに十分なローカルディスク容量があるが、ルートと'/usrファイルシステムを恒久的に拡張したくない場合。

    この場合、代替保存ディレクトリー用に別のファイルシステムを作成することを選択できます。 アップデートされたシステムに満足し、適用されたアップデートがすべてコミットされたら、保存ファイルシステムを削除することでディスクスペースを取り戻すことができます。

  • 置き換えるファイルを保存するためのローカル・ディスク・スペースが不十分だが、リモート・システムには十分なディスク・スペースがある。 この場合、リモート・ファイルシステムからマウントしたディレクトリーを指定できます。

    リモートファイルシステムを使用している場合は、できるだけ早く更新をコミットする。 apply」と「commit操作に「-acフラグを付けて、インストー ル操作を開始したいかもしれない。 不要なアップデートを拒否できるようにするためだけに『apply使いたいのであれば、新しくインストールされたアップデートをできるだけ早くテストし、コミットまたは拒否する。

    代替保管ディレクトリーを使用するときは、以下の事項を考慮してください。

  • installp コマンドを呼び出すときは、毎回同じ代替保存位置を使用することを強くお勧めします。
  • 別の保存ディレクトリが適用操作に使用される場合、そのディレクトリを含むファイルシステムがマウントされたままであることを確認してください。 リブート時に必要なマウントが自動的に行われるようにすることをお勧めします。
  • コミット操作時に代替保存ディレクトリーがなくなってしまった場合、コミット操作は行われますが、保存ディレクトリーを削除できないという警告が出ます。 この場合、ディスク容量を確保するために、使用しなくなった保存ディレクトリを削除する必要があります。
  • 拒否操作時に代替保存ディレクトリーがなくなってしまった場合は、保存済みのファイルがなくなってしまったので拒否操作は行われません。 この場合はエラーが発生し、拒否操作はすべて取り消されます。 保存ディレクトリーがなくなった理由が一時的な状態 (例えば、ネットワーク上のリモート・ディレクトリーにアクセスできないなど) によるものではない場合は、更新パッケージをコミットするか、 更新パッケージを無制限に適用済み状態にしておく以外に方法はありません。
  • システムのバックアップをとる場合、ルート・ボリューム・グループに存在しない代替保存ディレクトリーをバックアップするようにしてください。
  • インストールプロセスでは、リモートセーブディレクトリを持つユーザーを、2つの異なるシステムが同じリモートディレクトリを使用する可能性から保護します。 ただし、ディレクトリー・パス名には、各ユーザーのシステムを簡単で固有に識別できる名前を使用してください。 例えば、パス名にそのシステムのホスト名を入れる方法があります。
  • リモート保存ディレクトリーを使用してシステムの mksysb バックアップを作成し、元のシステムとは異なるシステム上に mksysb イメージを復元しないでください。 この場合、'mksysbイメージを使用して複数の同様のシステムをインストールすると、同じリモートセーブディレクトリの複数の所有者が発生します。

FilesetName パラメーターは、 ソフトウェア・プロダクト全体を指定するときにも、ソフトウェア・パッケージに入っている個別にインストール可能なファイルセットを指定するときにも使用できます。 たとえば、「bos.net」はソフトウェア・パッケージの名前で、そのソフトウェア・パッケージ内で個別にインストール可能なファイルセットは「bos.net.ncs.client、「bos.net.nfs.client、「bos.net.tcp.clientである。 ユーザーがFilesetNameパラメータに「bos.net指定した場合、リストされている個別にインストール可能なファイルセットがすべてインストールされる。 ユーザーがFilesetNameパラメーターに 'bos.net.tcp.clientを指定した場合、そのファイルセットのみがインストールされる。

Level パラメーターは、インストールするソフトウェア・プロダクトまたは更新パッケージのレベルを表します。 Levelパラメータはvv.rr.mmmm.ffffの形式である。

以下の例を使用して、/usr/sys/inst.images ディレクトリー内に入っている TCP/IP ソフトウェア・プロダクトとその更新パッケージの 1 つをインストールできます。

installp -a -d/usr/sys/inst.images bos.net.tcp.client 4.1.0.0
bos.net.tcp.client 4.1.0.2
注意:同じレベルでファイルセットが重複している場合、'installpはインストー ルの目次 ('.toc) で最初に見つかったものを使用します。この状況は、'bffcreateを使用して異なるメディアから同じインストールディレクトリにイメージを展開した場合に発生する可能性があります。 このため、更新イメージは、同じレベルにある同じファイルセットの基本レベル・イメージと 同じディレクトリーには抽出されないので注意してください。

例

  1. インストール・カートリッジ・テープに含まれるすべてのソフトウェア製品とインストール可能なオプションを一覧表示するには、次のコマンドを入力します：

  2. インストール・テープ上のすべてのソフトウェア製品で修正された、顧客から報告されたすべての問題を一覧表示するには、次のコマンドを入力します：
    installp -A -d /dev/rmt0.1 all
  3. bos.netソフトウェアパッケージ（「/usr/sys/inst.imagesディレクトリにある）内のすべてのファイルセットをインストール（自動的にコミット）し、必要に応じてファイルシステムを拡張するには、次のコマンドを入力する：
    installp -aX -d/usr/sys/inst.images bos.net
  4. すでにシステムにインストールされているNFSソフトウェア製品オプションを同じレベル（テープから）で再インストールしてコミットするには、次のコマンドを入力します：
    installp -acF -d/dev/rmt0.1 bos.net.nfs.client 4.1.0.0
  5. TCP/IPソフトウェア製品のディスケットに含まれる特定のアップデートをインストール（適用のみ）するには、以下のコマンドを入力します：
    installp -a bos.net.tcp.client 4.1.0.2 bos.net.tcp.server 4.1.0.1
  6. bos.net.tcp.server名前のファイルセットを削除するには、以下のコマンドを入力する：
    installp -u bos.net.tcp.server
  7. リモート・ファイル・システム上の代替ストレージ・ディレクトリを「-t/temp_space」で BOSNET TCP/IP更新に指定するには、以下のコマンドを入力する：.
    mount Server_Name:/Save_Area /temp_space
   
installp -a -t /temp_space/My_Hostname  \ 
bosnet.nfs.client 4.1.1.0

    保存ディレクトリは'/temp_space/My_Hostname/usr/lpp/bos.net/bos.net.nfs.client/4.1.1.0.saveになる。

  8. installp コマンドのすべての出力をログ・ファイルに取り出すには、script コマンドを次の例のように使用します。 出力は、現行ディレクトリーの typescript ファイルに書き込まれます。
    script
installp ...
<Ctrl>d
    または
    installp ... 2>&1 | tee /tmp/inst.out
    第 2 の例では、出力は画面に書き込まれ、コピーが保存されます。
  9. installpコマンドを使用してCDから「bos.net.tcp.clientファイルセットのインストー ルをプレビューするには、以下のコマンドを入力する：
     installp -pacgXd /dev/cd0 bos.net.tcp.client
  10. /usr/sys/inst.images」に含まれるTCP/IPとそのアップデートの1つをインストールするには、 以下の例のように「installpコマンドを使用する。

    installp コマンドの出力の最後には、インストールを試みた各ソフトウェア・プロダクトの状態をリストした要約報告があります。 次の例は、前回の「installpコマンドのサマリー・レポートの例である：

    Installp Summary
----------------
Name                 Level        Part       Event        Result
-----------------------------------------------------------------
bos.net.tcp.client   4.1.0.0      USR        APPLY        SUCCESS
bos.net.tcp.client   4.1.0.0      ROOT       APPLY        SUCCESS
bos.net.tcp.client   4.1.0.2      USR        APPLY        SUCCESS
    注：この要約は、次に「installp起動するまで「/var/adm/sw/installp.summary保存される。 /usr/includeディレクトリのヘッダーファイル'inuerr.hは、'installp.summaryファイルのレコードを構成するフィールドを記述している。
  11. POWERプロセッサー搭載マシンにインストール可能なソフトウェア製品（「/usr/sys/inst.imagesディレクトリにある）を一覧表示するには、以下のコマンドを入力する：
    installp -l -MR -d /usr/sys/inst.images
  12. システムにインストールされているCDのファイルセットをすべて更新するには、次のコマンドを入力する：
    lslpp -lc | awk -F ":" '{print $2}' | tail -n +2 > /tmp/lslpp
installp -agXd /dev/cd0 -e /tmp/install.log -f /tmp/lslpp
    ここで、'-eは出力を'/tmp/install.logファイルに記録する。
  13. bos.netソフトウェア・パッケージに含まれるすべてのファイルセットの署名を検証するには、以下のコマンドを入力する：
    installp -Gd /usr/sys/inst.images bos.net

    bos.netソフトウェア・パッケージは「/usr/sys/inst.imagesディレクトリにある。
