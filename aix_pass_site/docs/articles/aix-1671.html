目的

仮想共有ディスク・グローバル・ボリューム・グループ特性を変更します。

構文

updatevsdvg { -a | -g global_volgrp { -k VSD -p primary_node -b secondary_node | -k CVSD -l server_list [-c クラスター名]}}

説明

updatevsdvg コマンドは、仮想共用ディスクのグローバル・ボリューム・グループ特性を変更します。 このコマンドにより、グローバル・ボリューム・グループを並行仮想共有ディスク・ボリューム・グループからシリアル・アクセス (または、非並行) 仮想共有ディスク・ボリューム・グループに変更すること、およびその逆の変更が可能になります。 このコマンドは、 サーバー・ノード番号が変更された時 (例えば、サーバーを交換あるいは接続し直した時に新しいサーバー数が異なる場合)、 あるいはサーバーの削除が必要な場合にはいつでも使用できます。

このコマンドは以下の操作を実行します。
  1. このボリューム・グループの一部である仮想共有ディスクを、すべて中断します。
  2. このボリューム・グループの一部である仮想共有ディスクを、すべて停止します。
  3. ボリューム・グループに対して varyoffvg コマンドを発行します。
  4. ボリューム・グループが新規サーバーに存在することを検証し、 存在しない場合はボリューム・グループのインポートを試行します。
  5. グローバル・ボリューム・グループ特性を更新します。
  6. 該当するサーバーにボリューム・グループに対して varyonvg コマンドを発行します。
  7. このボリューム・グループの一部である仮想共有ディスクを、すべて開始します。
注:
  1. -a フラグを指定してこのコマンドを発行する場合は、リカバリー可能仮想共用ディスク・サブシステムをアクティブにしてはなりません。 このフラグを指定しない場合、このコマンドは、更新中のボリューム・グループの一部である仮想共有ディスクを使用している アプリケーションが存在しない限り、リカバリー可能仮想共有ディスク・サブシステムの活動中に実行できます。
  2. AIXSCSIデバイスドライバのSCSI-3パーシステント・リザーブ・モデルを実装したディスク、およびSSA（シリアル・ストレージ・アーキテクチャ）ディスクでは、同時仮想共有ディスクがサポートされています。

フラグ

-a
このノードがサービスを提供するすべての VSD ボリューム・グループに関して、Persistent Reserve 情報をオブジェクト・データ・マネージャー (ODM) で再設定することを指定します。 このフラグは、複数のクラスターが同じ仮想共有ディスクにアクセスできるようにするための初期セットアップ・フェーズを対象としています。 また、デバイスの ODM エントリーが誤って除去された後のリカバリー用にもこのフラグが役立ちます。

このフラグを使用すると、このノードがサービスを提供するすべてのボリューム・グループがオフラインに変更されます。 ボリューム・グループは、このノードとそれらのボリューム・グループの他のすべてのサーバーでオフラインに変更されます。 このため、このフラグを指定して updatevsdvg コマンドを発行する前に、リカバリー可能仮想共用ディスク・サブシステムを停止する必要があります。

--b secondary_node
2 次ノードを指定します。
-クラスタ名
並行アクセスされた共有ディスクにサービス提供するサーバー・ノードのクラスター名を指定します。 このフラグは、SSA (Serial Storage Architecture) ディスクにのみ適用されます。 そして、SSA に cluster_name を指定する必要があります。
--g global_volgrp
既存のグローバル・ボリューム・グループ名を指定します。
-VSD｜CVSD
ボリューム・グループが、並行仮想共有ディスクのタイプか、あるいは シリアル・アクセス (非並行) 仮想共有ディスクのタイプかを指定します。
--l server_list
並行仮想共有ディスク用サーバーのコロンで区切られたリストを指定します。
--p primary_node
1 次ノードを指定します。

パラメーター

VSAM 名
その基礎となる論理ボリュームに もう仮想共有ディスク・ノードがグローバルにアクセスしないようにしたい、仮想共有ディスクを指定します。

セキュリティー

このコマンドを実行するには、 root 権限が必要です。

終了状況

0
コマンドの正常終了を示します。
nonzero
エラーが発生したことを示します。

制約事項

このコマンドは、ピア・ドメインでオンラインのノードから実行する必要があります。 オンラインのピア・ドメインに移動するには startrpdomain コマンドを使用します。 既存のピア・ドメイン内で、オンラインの特定ノードに移動するには startrpnode コマンドを使用します。 RSCT ピア・ドメインの作成と管理の詳細については、「RSCT Administration Guide」を参照してください。

標準出力

現行の RVSD サブシステム実行レベル。

例

  1. ess_gvg という名前のグローバル・ボリューム・グループを、仮想共用ディスク・グローバル・ボリューム・グループから、3 つのサーバーを持つコンカレント・グローバル・ボリューム・グループに変更するには、ディスクが正しくケーブル接続されており、ディスク・サブシステムが ESS ディスクなどの永続保存をサポートしていることを前提として、次のように入力します。
    updatevsdvg -g ess_gvg -k CVSD -l 9:17:21
  2. ssa_gvgという名前の SSA グローバル・ボリューム・グループからサーバーを除去するには、次のように入力します。ここで、元のサーバー・リストは 9:10 であり、 cluster9_10という名前の SSA クラスターに属しています (つまり、コマンド vsdatalst -c は SSA クラスター情報を表示します)。
    updatevsdvg -g ssa_gvg -k CVSD -l 9 -c cluster9_10
  3. ess_gvg という名前のコンカレント・グローバル・ボリューム・グループを仮想共用ディスク・グローバル・ボリューム・グループに戻すには、次のように入力します。ここで、元のサーバー・リストは 9:17:21、新しい 1 次ノード番号は 9、新しい 2 次ノード番号は 21 です。
    updatevsdvg -g ess_gvg -k VSD -p 9 -b 21

場所

/opt/rsct/vsd/bin/updatevsdvg
