目的

システム間でファイルをコピーします。

構文

ユーシーピー [  -c |  -C ] [  -d |  -f ] [  -gグレード ] [  -j ] [  -m ] [  -nユーザー] [  -r ] [  -sファイル ] [  -xデバッグレベル ] SourceFile ... DestinationFile ...

説明

uucpコマンドはBasic Networking Utilities (BNU)コマンドの1つで、あるシステムの1つ以上のソースファイルを、別のUNIXシステムの1つ以上の宛先ファイルにコピーする。 ファイルのコピーは、ローカル・システム内、ローカル・システムとリモート・システムとの間、 リモート・システム間で行うことができます。

uucp コマンドは、2 つのステップでファイル転送を行います。まず、コマンド (C. *) を作成します。 ローカル・コンピューター上のスプーリング・ディレクトリーにファイルを作成してから、 uucico デーモンを呼び出して、指定されたコンピューターに要求を送信します。 コマンド・ファイルには、ソース・ファイルおよび宛先ファイルの絶対パス名や送信ユーザーのログイン名などの情報が入っています。 コマンド・ファイルの絶対パス名の形式を以下に示します。

/var/spool/uucp/SystemName/C.SystemNameNxxxx

N が要求のグレードで、xxxx は BNU で使われる 16 進数の通し番号です。

-C フラグを指定して uucp コマンドを使用し、転送のためにファイルをスプール・ディレクトリーにコピーすると、 uucp コマンドはコマンド・ファイルだけでなく、 データ (D. *) も 実際のソース・ファイルが入っているファイル。 データ・ファイルの絶対パス名は以下のような形式になっています。

/var/spool/uucp/SystemName/D.SystemNamexxxx###

コマンド・ファイル (必要ならばデータ・ファイルも) が作成されると、 uucp コマンドが uucico デーモンを呼び出し、 uucico デーモンがリモート・マシンに接続を試みてファイルを送信します。

uucp コマンドを出す前に、 uuname コマンドを出して、リモート・システムの正確な名前を判別すると便利です。 uulog コマンドは、別のシステムとの uucp アクティビティーに関する情報を提供します。

ソース・ファイル名と宛先ファイル名

ファイル名とシステム名には ASCII 文字以外は使用できません。 固有のファイル名はローカル・システム上のパス名か、あるいは以下の形式を取ります。

システム名PathName

SystemName は、BNU が認識しているシステム名のリストから取られます。

宛先 SystemName は、以下のような名前のリストの場合もあります。

システム名システム名！ . . . ！ システム名!PathName

この場合、指定された経路指定を使用してファイルを宛先へ送信する試みがなされます。 この経路指定の中間ノードに情報を転送する意志があり、実際に次のシステムと会話していることを確認します。

シェル・パターン・マッチング文字?(疑問符),*(アスタリスク)、および[ . . . ](大括弧と省略符号) は、ソース・ファイルのパス名に使用することができます。適切なシステムがそれらを展開します。 ただし、宛先ファイルのパス名にはシェル・パターン・マッチング文字を使用しないでください。

DestinationFile がファイルではなくディレクトリーである場合には、 uucp コマンドは SourceFile 名の最後の部分を使用して、リモート・システム上の転送ファイルに名前を付けます。

パス名

SourceFile パラメーター、 および DestinationFile パラメーターのパス名には、 ASCII 文字以外は使用できません。 ソース・ファイルのパス名は、以下のいずれの形式でも指定できます。

  • 絶対パス名
  • 相対パス名

DestinationFile パラメーターのパスは、 SourceFile パラメーターの形式で指定することも、 以下のいずれかの形式で指定することもできます。

  • ~User が前に付いたパス名 (例:~jkimble) ここで、 User はリモート・システム上のログイン名です。 指定されたユーザーのログイン・ディレクトリーは、転送の宛先と見なされます。 ユーザーが無効なログイン名を指定した場合には、 ファイルは公開ディレクトリー /var/spool/uucppublic (デフォルト) に転送されます。
  • パス名の前に ~/Destinationが付きます。 ここで、 Destination は /var/spool/uucppublicに追加されます。 宛先は、要求によって複数のファイルが転送される場合、 あるいは宛先が既にリモート・システム上にディレクトリーとして存在する場合、 あるいは宛先がディレクトリーとして指定されている場合には、ファイル名として扱われません。

    宛先をディレクトリーとして指定するときには、宛先名の後に / (スラッシュ) を付けます。 例:~/amy/宛先がディレクトリーを作成するとき/var/spool/uucppublic/amyまだ存在していない場合は、要求されたファイルをそのディレクトリーに入れます。

許可

  • システム管理者は、他のシステムのユーザーによるローカル・ファイルへのアクセスを制限する必要があります。
  • ファイルの送信時に、 uucp コマンドは実行許可を保持し、所有者、グループ、およびその他すべてのユーザーに読み取り許可と書き込み許可を付与します。 (uucp コマンドは、そのファイルを所有します。)
  • 他のシステム上の任意の DestinationFile パス名へのファイルの送信、または他のシステム上の任意の SourceFile パス名からのファイルの取得は、セキュリティー制限のために失敗することがよくあります。 パス名内で指定されたファイルは、ユーザーの同一グループだけでなく、 その他のあらゆるグループについても、読み取り許可または書き込み許可を与えなければなりません。
  • 保護されたファイル、および要求側が所有する保護されたディレクトリー内のファイルは、 uucp コマンドによって送信することができます。

フラグ

項目
説明
-c ファイルがコピーされるのを防ぎます。 このフラグはデフォルトで、-C フラグとともに使用することはできません。 両方のフラグを指定した場合には、-c フラグが無効になります。
-C 転送するためにローカル・ファイルをスプール・ディレクトリーにコピーします。 アンケート ファイルと システム ファイルの構成、および Uusched デーモンの実行頻度に応じて、ファイルはオンデマンド・ポーリング時または将来に即時に転送される可能性があります。

場合によっては、ソース・ファイルの転送中に問題が発生することがあります。 例えば、リモート・マシンが作動していないか、ログインに失敗した場合です。 その場合には、転送が完了するか、あるいはクリーンアップ・コマンドによって除去されるまで、 ファイルはスプール・ディレクトリーに残ります。

このフラグは、-c フラグと逆の働きをします。
-d ソース・ファイルをリモート・システムの宛先にコピーするために必要な中間ディレクトリーを作成します。 ディレクトリーを作成してからそれにファイルをコピーするのではなく、 宛先パス名を指定した uucp コマンドを入力すれば、 BNU プログラムが必要なディレクトリーを作成します。 このフラグはデフォルトであり、-f フラグと併用できません。
-f ファイル転送中に中間ディレクトリーを作成しません。 このフラグは、宛先ディレクトリーが既に存在し、 それを BNU でオーバーライドしたくない場合に使用します。 このフラグは、-d フラグと逆の働きをします。
-gグレード 指定の接続の際に、ファイルを転送する時期を指定します。 Grade 変数は、単一の数字 (0 から 9 まで) あるいは文字 (A から Z まで、あるいは a から z まで) です。 ASCII の下位シーケンス文字を使えば、上位シーケンス文字を使う場合よりも早く転送できます。 数字 0 が最高の (最も早い) グレードで、z は最低の (最も遅い) グレードです。 デフォルトは Nです。
-j 転送処理のジョブ識別番号を標準出力に表示します。 このジョブIDは、uustatまたはuuqコマンドで使用して特定のジョブのステータスを取得したり、uustat-kコマンドまたはuuq-dコマンドで使用して転送が完了する前に終了させることができる。
-m ソース・ファイルがリモート・システムの宛先ファイルに正常にコピーされると、 要求側にメール・メッセージを送信します。 メッセージは、要求側のメールボックス /var/spool/mail/User に送信されます。 mail コマンドは、ローカル転送のメッセージを送信しません。

-m フラグは、複数のファイルの送信、または単一のファイルの受信の場合にのみ機能します。 ファイル転送の場合には、機能しません。
-nユーザー User エントリーで識別されるリモート・システム上の受信者に、 ファイルが送信されたことを通知します。 メール・システムは、ローカル転送用のメッセージは送信しません。 ユーザー名には ASCII 文字以外は使用できません。 シェル・パターン・マッチング文字によって指定された複数のファイルの受信?(疑問符),*(アスタリスク)、および[ . . . ](大括弧と省略符号) は、 -n オプションを活動化しません。
-r リモート・システムへの呼び出しが許可されているときにコマンドが発行された場合でも、 uucico ファイル転送デーモンの開始を防止します。 (デフォルトでは、Poll ファイルおよび Systems ファイルに指定された期間中にコマンドが発行された場合に、 リモート・システムの呼び出しが試行されます。) -r オプションは、デバッグ時に役立ちます。
-sファイル 指定されたファイルの転送の状況を報告します。 この場合、File 変数には、絶対パス名を指定しなければなりません。
-xデバッグレベル デバッグ情報をローカル・システムの画面に表示します。 DebugLevel 変数は、0 から 9 までの数値です。 数値が大きいほど、レポートの詳細度が高くなります。

例

  1. ローカル・システムからリモート・システムにファイルをコピーするには、次のように入力します。
    uucp /home/geo/f1 hera!/home/geo/f1
    この例では、f1ローカル・システムからのファイルがリモート・システムにコピーされるhera.
  2. ファイルをリモート・システムからコピーして、公用ディレクトリーに入れるには、次のように入力します。
    uucp hera!geo/f2 /var/spool/uucppublic/f2
    この例では、f2リモート・システムからのファイルhera がコピーされ、公用ディレクトリーに置かれます。
  3. ファイルをリモート・システムからコピーして、公用ディレクトリー以外のディレクトリーに入れるには、次のように入力します。
    uucp hera!geo/f2 /home/geo/f2
    この例では、f2リモート・システムからのファイルheraがコピーされます。/home/geo/f2ディレクトリー。 このgeoログイン・ディレクトリーは、他のグループのメンバーへの書き込み許可を許可する必要があります (例えば、モード 777)。
