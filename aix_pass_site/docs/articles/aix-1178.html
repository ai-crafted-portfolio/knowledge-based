目的

プロキシー・マネージャー・サービス。

構文

proxymngr [ -config filename] [ -timeout seconds] [ -retries #] [ -verbose]

説明

proxymngr (プロキシー・マネージャー) は、 xfindproxy (およびその他の類似のクライアント) からの要求を解決し、必要に応じて新規プロキシーを開始し、使用可能なプロキシー・サービスを追跡します。 プロキシー・マネージャーは、できるだけ既存のプロキシーを再利用しようとします。

プロキシー・マネージャーが取り扱うプロキシーには、管理プロキシーと非管理プロキシーの 2 つのタイプがあります。

管理プロキシーは、プロキシー・マネージャーの要求時に始動されるプロキシーです。

非管理プロキシーは、システム・ブート時に始動されるか、システム管理者によって手動で始動されます。 プロキシー・マネージャーにはその存在は知らされますが、プロキシー・マネージャーが非管理プロキシーを始動しようとすることはありません。

フラグ

表 1. フラグ
項目
説明
-config デフォルト proxymngr config ファイルをオーバーライドします。 proxymngr config ファイルの詳細は、以下を参照してください。
-timeout プロキシー・マネージャーが非管理プロキシーの検出を試行する間隔 (秒数) を設定します。 デフォルトは 10 です。
-retries プロキシー・マネージャーが非管理プロキシーを検出するために行う再試行の最大回数を設定します。 デフォルトは 3 です。
-verbose 要求が受信され、プロキシーが始動されると、さまざまなデバッグ・レコードとトレース・レコードが表示されます。

プロキシー・マネージャー Config ファイル

プロキシー・マネージャーは、使用可能なプロキシー・サービスを記述するローカル構成ファイルを維持します。 この構成ファイルは、 proxymngrのインストール時に /usr/X11R6.3/lib/X11/proxymngr/pmconfig にインストールされます。 構成ファイルの場所は、 -config コマンド行フラグで上書きできます。

行を除いて、コメントの感嘆符で始まります。 構成ファイルの各行には、非管理プロキシー・サービスまたは管理プロキシー・サービスのいずれかが記述されています。

非管理プロキシーの場合のフォーマットは次のとおりです。

<service-name> unmanaged <proxy-address>

service-name は非管理プロキシー・サービスの名前であり、スペースを含めることはできません (例: XFWP)。 service-name は大/小文字を区別しません。

proxy-address は非管理プロキシーのネットワーク・アドレスです。 このアドレスのフォーマットは、service-name に特定されたものです。 例えば、XFWP サービスの場合、proxy-address は firewall.x.org:100 などというようになります。

構成ファイル内に同じ非管理対象 service-nameを持つエントリーが複数ある場合、プロキシー・マネージャーは、構成ファイルに示されている順序でプロキシーを使用しようとします。

管理プロキシーの場合、フォーマットは次のとおりです。

<service-name> managed <command-to-start-proxy>

service-name は管理対象プロキシー・サービスの名前であり、スペースを含めることはできません (例: LBX)。 service-name は大/小文字を区別しません。

command-to-start-proxy は、プロキシーの新規インスタンスを開始するためにプロキシー・マネージャーによって実行されるコマンドです。 command-to-start-proxy にスペースが含まれている場合は、完全なコマンドを単一引用符で囲む必要があります。 必要に応じて、 command-to- start-proxy を使用して、リモート・マシン上でプロキシーを開始できます。 これを行うために使用するリモート実行メソッドの詳細はここでは紹介しません。

サンプル構成ファイルの例

               ! proxy manager config file
               !
               ! Each line has the format:
               !    <serviceName> managed <startCommand>
               !        or
               !    <serviceName> unmanaged <proxyAddress>
               !
               lbx managed /usr/X11R6.3/bin/lbxproxy
               !
               ! substitute site-specific info
               xfwp unmanaged firewall:4444

プロキシー・マネージャーの詳細

プロキシー・マネージャーが xfindproxy (または同様の別のクライアント) から要求を受け取る場合、そのアクションは問題の service-name によって異なります。

管理対象プロキシー・サービスの場合、プロキシー・マネージャーは、このサービスに対して既に実行されているプロキシーのいずれかが新規要求を処理できるかどうかを検出します。 そうでない場合、プロキシー・マネージャーは ( command-to-start-proxy を使用して) 呼び出し元を検出したプロキシーの新規インスタンスを開始しようとします。

非管理プロキシー・サービスの場合、プロキシー・マネージャーは構成ファイルを調べて、このサービスのすべての非管理プロキシーを検出します。 構成ファイル内に同じ非管理対象 service-nameを持つエントリーが複数ある場合、プロキシー・マネージャーは、構成ファイルに示されている順序でプロキシーを使用しようとします。 非管理プロキシーがどれもその要求に応えることができない場合、プロキシー・マネージャーは、(-timeout またはデフォルトの 10 で指定された) 構成可能な時間の間だけタイムアウトになり、その要求に応じる意志のある非管理プロキシーの検出を再度試みます。 再試行の回数は、 -retries 引数で指定することも、デフォルトの 3 を使用することもできます。 再試行が失敗した場合、プロキシー・マネージャーはエラーを呼び出し元に返す以外に選択肢はありません (プロキシー・マネージャーは非管理プロキシー・サービスを開始できないため)。
