目的

最小特権 (LP) リソースの属性値を変更します。

構文

LP リソースの属性値を変更するための構文:
  • ローカル・ノードの場合:

    chlpcmd [ -l 0 | 1 ] [ -c 0 | 1 | 2 | 3 ] [-h] [-TV] resource_name attr1=value1 [attr2=value2...]

    chlpcmd-r [-h][-TVリソース名

  • ドメイン内のすべてのノードで以下のように入力します。

    chlpcmd -a [ -l 0 | 1 ] [ -c 0 | 1 | 2 | 3 ] [-h] [-TV] resource_name attr1=value1 [attr2=value2...]

    chlpcmd-a-r [-h][-TVリソース名

  • ドメイン内の一部のノードで以下のように入力します。

    chlpcmd -n host1 [,host2,...] [ -l 0 | 1 ] [ -c 0 | 1 | 2 | 3 ] [-h] [-TV] resource_name attr1=value1 [attr2=value2...]

    chlpcmd -n host1 [,host2,...] -r [-h][-TVリソース名

説明

chlpcmd コマンドを使用して、LP リソースの読み取り/書き込み属性値のいずれかを変更します。 LP リソース は、 LP アクセス制御リスト (ACL)内のアクセス権に基づいてユーザーにアクセス権限を付与する root コマンドまたはスクリプトです。 CheckSum 属性を再計算して割り当てるには、 -r フラグを使用します。 ControlFlags 属性を変更するには、 -c フラグを使用します。 Lock 属性を変更するには、 -l フラグを使用します。 attr=value パラメーターを使用して、属性 Name、 CommandPath、 RunCmdName、 FilterScript、 FilterArg、および Descriptionを変更します。

このコマンドはどのノードでも実行できます。 ドメイン内のすべてのノードでこのコマンドを実行する場合は、 -a フラグを使用します。 ドメイン内のノードのサブセットでこのコマンドを実行する場合は、 -n フラグを使用します。 それ以外の場合、このコマンドはローカル・ノードで実行されます。

フラグ

-a
ドメイン内のすべてのノードで リソース名 の属性 値 を変更します。 CT_MANAGEMENT_SCOPE 環境変数の設定によって、クラスターの有効範囲が決まります。 CT_MANAGEMENT_SCOPE が設定されていない場合、LP リソース・マネージャーは次の順序で有効範囲設定を使用します。
  1. 管理ドメイン (あれば)
  2. ピア・ドメイン (あれば)
  3. Local 有効範囲
chlpcmd コマンドは、LP リソース・マネージャーが最初に検出した有効な有効範囲に対して 1 回実行されます。 例えば、管理ドメインとピア・ドメインが存在し、 CT_MANAGEMENT_SCOPE 環境変数が設定されていないとします。 この場合、 chlpcmd –a は管理ドメインで実行されます。 ピア・ドメインで chlpcmd –a を実行するには、 CT_MANAGEMENT_SCOPE を 2に設定する必要があります。
--n ホスト1[host2,...]。
LP リソースを変更するドメインの中の 1 つ以上のノードを指定します。 デフォルトでは、LP リソースは、ローカル・ノードで 変更されます。 このフラグが有効なのは、管理ドメインまたはピア・ドメインでのみです。 CT_MANAGEMENT_SCOPE 環境変数が設定されていない場合、LP リソース・マネージャーは次の順序で有効範囲設定を使用します。
  1. 管理ドメイン (あれば)
  2. ピア・ドメイン (あれば)
  3. Local 有効範囲
chlpcmd コマンドは、LP リソース・マネージャーが最初に検出した有効な有効範囲に対して 1 回実行されます。
–r
この LP リソースの CheckSum 属性値を再計算して割り当てます。 以下の場合に -r フラグを使用します。
  • この LP リソースが表すコマンドまたはスクリプトを変更したとき。
  • コマンドまたはスクリプトがシステム上で使用可能になった後で、 CheckSum 値を 0 から正しい値に変更したい。
-l 0 | 1
リソースをロックまたはアンロックします。 このフラグを使用すると、リソースが誤って削除されないようにすることができます。 デフォルト値は 0です。これは、ロックが設定されていないことを意味します。 リソースをロックするには、 chlpcmd -l 1を使用します。
--c0│1│2│3
LP コマンドの制御機能を指定するために使用される ControlFlags 属性を設定します。 ControlFlags を指定しない場合、デフォルトで 1 に設定されます。 このフラグを使用して、次のいずれかの値を指定します。
0
CheckSum 値を検証しません。
1
CheckSum 値を検証しません。 これはデフォルトです。
2
CheckSum 値を検証します。
3
CheckSum 値を検証します。

runlpcmd コマンドを使用して LP リソースを実行しようとすると、 ControlFlags 属性の値によって、リソースによって表されるコマンドを実行する前に実行される検査が決まります。

このリリースの RSCT では、 ControlFlags 属性値は、 CheckSum 値が妥当性検査されるかどうかを指定します。

以前のリリースの RSCT では、 ControlFlags 属性値は、 runlpcmd への入力引数に特定の文字が存在することを許可しないかどうかも指定していました。 しかし、これらの文字の検査は不要と なりました。

以前のリリースの RSCT で定義された LP リソースとの互換性を維持するために、 CheckSum 値の妥当性検査に関しては、 ControlFlags 属性値は同じままです。 したがって、値 0 および 1 は、 CheckSum 値が検証されないことを示し、値 2 および 3 は、 CheckSum 値が検証されることを示します。

-h
コマンドの使用ステートメント (使用法) を標準出力に書き込みます。
-T
コマンドのトレース・メッセージを標準エラーに書き込みます。
-V
コマンドの詳細メッセージを標準出力に書き込みます。

パラメーター

リソース名
変更する LP リソース名を指定します。
属性 1=値 1 [属性 2=値 2…]
1 つ以上の読み取り/書き込み属性およびその新規の値を指定します。

セキュリティー

chlpcmd コマンドを実行するには、以下が必要です。
  • IBM.LPCommands リソース・クラスの Class ACL 内の読み取り許可。
  • Resource ACL の中の書き込み許可。

    代わりに、この許可が Resource Shared ACL の中に存在する場合は、Resource ACL が Resource Shared ACL の使用を指示できます。

アクセス権は、連絡先システムの LP ACL で指定されています。 それらの変更については、 lpacl ファイル LP ACL に関する一般情報 および「 RSCT 管理ガイド 」を参照してください。

環境変数

CT_CONTACT
RMC デーモンとのセッションに使用されるシステムを決めます。 CT_CONTACT がホスト名または IP アドレスに設定されている場合、コマンドは指定されたホスト上の RMC デーモンと連絡を取ります。 CT_CONTACT が設定されていない場合、コマンドは、コマンドが実行されているローカル・システム上の RMC デーモンと連絡を取ります。 RMC デーモン・セッションのターゲットおよびその管理有効範囲によって、処理される LP リソースが決まります。
CT_IP_AUTHENT
CT_IP_AUTHENT 環境変数が存在する場合は、RMC デーモンは、IP ベース・ネットワーク認証を使用して、CT_CONTACT 環境変数が設定されている IP アドレスで指定されるシステム上の RMC デーモンと連絡を取ります。 CT_CONTACT が IP アドレスに設定されている場合のみ、CT_IP_AUTHENT が意味を持ちます。CT_IP_AUTHENT はドメイン・ネーム・システム (DNS) サービスに依存しません。
CT_MANAGEMENT_SCOPE
LP リソースを処理するために RMC デーモンとのセッションに使用される管理有効範囲を決定します。 管理有効範囲は、リソースを処理できる、可能なターゲット・ノードのセットを決定します。 有効な値は以下のとおりです。
0
local 有効範囲を指定します。
1
local 有効範囲を指定します。
2
peer domain (ピア・ドメイン) 有効範囲を指定します。
3
management domain (管理ドメイン) 有効範囲を指定します。
CT_MANAGEMENT_SCOPE が設定されていない場合は、 ローカル ・スコープが使用されます。

実行の特性

このコマンドはAIX用のReliable Scalable Cluster Technology(RSCT)ファイルセットの一部です。

標準出力

-h フラグを指定すると、このコマンドの使用状況ステートメントが標準出力に書き込まれます。 -V フラグを指定すると、このコマンドの詳細メッセージが標準出力に書き込まれます。

標準エラー

トレース・メッセージはすべて、標準エラーに書き込まれます。

例

  1. ローカル・ノード上のリソースを削除する前に、 Lock LP リソースの属性 lpcommand1 を変更するには、次のように入力します。
    chlpcmd -l 0 lpcommand1
  2. nodeA が管理ドメインにあり、 CT_MANAGEMENT_SCOPE が 3に設定されているとします。 nodeA上の LP リソース lpcommand2 の CheckSum 属性値を再計算するには、次のように入力します。
    chlpcmd -r -n nodeA lpcommand2

場所
