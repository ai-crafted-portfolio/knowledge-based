目的

論理ボリュームまたは物理ボリュームが、暗号化にキーサーバーのキー保護方式を使用する場合、暗号化キーサーバーに関連付けられたオブジェクトデータマネージャー（ ODM ）のデータベースエントリを管理します。

構文

keysvrmgr action -t server_type [-h] { -a attribute=value ... } server_name

説明

暗号化キーサーバーは、暗号化キー情報を安全に保管します。 AIX® （ 7.3 ）オペレーティングシステムは、( IBM Security® Guardium® Key Lifecycle Manager (GKLM)) および Key Protect ( IBM Cloud® Key Protect ) キー keyserv サーバーをサポートしています。 クライアントとサーバー間の証明書のやり取りにより、サーバー keyserv へのアクセスが保護されます。 APIキーやアクセストークンなどの Key Protect の認証情報は、 Key Protect （KP）サーバーへのアクセスを保護します。 論理ボリュームが暗号化にキーサーバーによるキー保護方式を使用する場合、暗号化キーサーバーに関する情報は ODM データベースに格納されます。 暗号鍵サーバーに関連付けられている ODM データベース・エントリーを管理するには、keysvrmgr コマンドを使用できます。
注：AIX 7.3 Technology Level (TL) 4 Service Pack (SP) 1 以降、 IBM では、 Hyper Protect Crypto Services (HPCS) が非推奨となり、 IBM Cloud Key Protect Dedicated Server に置き換えられます。 この keysvrmgr コマンドのオプションでは -t 、有効な値として「 hpcs 」の代わりに「 kms 」が追加されました。 互換性の観点から、 hpcs 値は引き続き受け入れられていますが、 kms 値を使用する必要があります。 HPCSから Key Protect サーバーへ移行するには、 「HPCSから Key Protect サーバーへの移行」 のセクションを参照してください。
IBM AIX 7.2 （テクノロジーレベル 5： TL5 ）以降では、 action パラメータを指定してコマンド keysvrmgr を実行することで、以下のいずれかの操作を実行できます：
  • add: キーサーバーのエントリを追加します。
  • modify: 既存のキーサーバーのエントリを変更します。
  • remove: キーサーバーのエントリを削除します。
  • show: キーサーバーのエントリに関する情報を表示します。
  • verify: KPサーバーのエントリを確認します。
  • rekey: ODM 内の KP サーバーエントリ用の API キーを作成します。

server_name は、 ODM データベース内の ODM レコードを識別します。

action パラメーター

追加
構文
ODM データベースにkey protect serverのエントリを追加するには、次のコマンドを入力してください：
keysvrmgr add -t kms [-h] -a svr_name=value -a inst_id=value -a api_key=value -a svr_region=value
KeySvr の ODM データベースにサーバーエントリを追加するには keyserv 、次のコマンドを入力してください：
keysvrmgr add -t keyserv [-h] -a svr_name=value [ -a dev_grp=value ] -a svr_ip=value [ -a svr_port=value ] -a svr_cert=value -a cli_cert=value [ -a cert_pwd=[y|Y|n|N|p|P] ]
鍵サーバー ID は、 svr_name[:dev_grp] 形式で作成されます。

AIX 7.3(テクノロジー・レベル 1) 以降、以下の構文は非推奨になりました。

keysvrmgr add [-h] -i server_ip [-p server_port] [-g sklm_device_group] -s server_cert_path -c client_cert_path [-P type] server_id

この action パラメーターは、以下のフラグとともに指定できます。

-i
これは、次のフォーマットで暗号鍵サーバーの IP アドレスを指定します。
a.b.c.d
a、b、c、および d の各値は 0 から 255 までの範囲にあります。
-p
(オプション) これは、暗号鍵サーバーのポートを指定します。 ポート値は 0 から 65535 までの範囲で指定できます。 デフォルト値は 5696 です。
-g
（オプション） IBM Security Key Lifecycle Manager に関連付けられているデバイスグループ名を指定します。
-s
これは、暗号鍵サーバーに関連付けられている X.509 サーバー証明書の絶対パスを指定します。
-c
お使いのシステムに関連付けられている、Public Key Cryptography Standards #12 (PKCS #12) クライアント証明書の絶対パスを指定します。
-P
これは、クライアント証明書のパスワード保護のタイプを指定します。 このフラグに指定できる値は以下のとおりです。
y |Y
コマンドの実行中に、クライアント証明書のパスワードの入力を求められます。
n |N
クライアント証明書はパスワードで保護されていません。 この値はデフォルト値です。
p |P
クライアント証明書のパスワードは、プラットフォームのキーストア（ PKS ）に保存されています。
サーバー ID
これは、作成対象の暗号鍵サーバー・エントリーの ID を次のフォーマットで指定します。
server_name[:device_group]
ここで、 server_name はキーサーバーエントリの名前であり、 device_group は IBM Security Key Lifecycle Manager に関連付けられているデバイスグループの名前です。
変更
構文
以下のコマンドを入力して、 ODM エントリ（このエントリは、属性 svr_name の値によって識別されます）を、および api_key 属性の inst_id 新しい値を使用して変更します：
keysvrmgr modify -t kms [-h] -a svr_name=value [ -a inst_id=value ] [ -a api_key=value ] [ -a svr_region=value ]
次のコマンドを入力して、属性の svr_name 値によって識別される ODM エントリを、属性、 svr_portsvr_ipdev_grp、 svr_cert、 cli_cert、、および cert_pwd の新しい値を使用して変更するには、次のコマンドを実行してください：
keysvrmgr modify -t keyserv [-h] -a svr_id=value [ -a dev_grp=value ] -a svr_ip=value [ -a svr_port=value ] [ -a svr_cert=value ] [ -a cli_cert=value ] [ -a cert_pwd=[y|Y|n|N|p|P] ]

AIX 7.3(テクノロジー・レベル 1) 以降、以下の構文は非推奨になりました。

keysvrmgr modify [-h] -i server_ip [-p server_port] [-s server_cert_path] [-c client_cert_path] [-P type] server_id

この action パラメーターは、以下のフラグおよび値とともに指定できます。

-i
これは、次のフォーマットで暗号鍵サーバーの IP アドレスを指定します。
a.b.c.d
a、b、c、および d の各値は 0 から 255 までの範囲にあります。
-p
(オプション) これは、暗号鍵サーバーのポートを指定します。 ポート値は 0 から 65535 までの範囲で指定できます。 デフォルト値は 5696 です。
-s
これは、暗号鍵サーバーに関連付けられている X.509 サーバー証明書の絶対パスを指定します。
-c
お使いのシステムに関連付けられている PKCS #12 クライアント証明書の絶対パスを指定します。
-P
これは、クライアント証明書のパスワード保護のタイプを指定します。 このフラグに指定できる値は以下のとおりです。
y |Y
コマンドの実行中に、クライアント証明書のパスワードの入力を求められます。
n |N
クライアント証明書はパスワードで保護されていません。 この値はデフォルト値です。
p |P
クライアント証明書のパスワードは、プラットフォームのキーストア（ PKS ）に保存されています。
サーバー ID
これは、変更対象の鍵サーバー・エントリーの ID を次のフォーマットで指定します。
server_name[:device_group]
ここで、 server_name は暗号化キーサーバーの名前、 device_group は IBM Security Key Lifecycle Manager に関連付けられているデバイスグループの名前です。
remove
構文

ODM データベースからキープロテクトサーバーのエントリを削除するには、次のコマンドを入力します

keysvrmgr remove [-h] -t kms server_name

ODM データベースから削除するキー保護サーバーの名前を指定する必要があります。

keyserv サーバー・エントリーを KeySvr ODM データベースから除去するには、以下のコードを使用します。
keysvrmgr remove -t keyserv [-h] -a svr_id=value
ODM データベースから除去したい keyserv サーバーの ID を指定する必要があります。

AIX 7.3(テクノロジー・レベル 1) 以降、以下の構文は非推奨になりました。

keysvrmgr remove [-h] server_id

ODM データベースから削除するキーサーバーエントリのIDを指定してください。

show
構文
ODM データベース内で、属性の svr_name 値が指定するキープロテクトサーバーエントリに関する情報を表示するには、次のコマンドを入力します
keysvrmgr show [-h] -t kms server_name
KeySvrODM データベースにおいて、属性の svr_id 値で指定されたサーバー keyserv エントリに関する情報を表示するには、次のコードを使用します
keysvrmgr show -t keyserv [-h] [ -a svr_id=value ]

AIX 7.3(テクノロジー・レベル 1) 以降、以下の構文は非推奨になりました。

keysvrmgr show [-h] server_id
verify
構文

svr_name 属性の値で指定されている、 ODM データベース内のキープロテクトサーバーエントリに関する情報を確認するには、次のコマンドを入力してください：

kkeysvrmgr verify [-h] -t kms [ server_name ]

検証プロセスでは、 ODM レコードに追加された属性値を使用して、キー保護サーバーと通信を行います。

再入力
構文

ODM 内のキー保護サーバーエントリ用の API キーを作成するには、次のコマンドを入力してください：

keysvrmgr rekey [-h] -t kms server_name

この新しいAPIキーは、既存のキーに取って代わるものです。

この server_name 属性は、 ODM レコードを識別するために使用されます。 action パラメータは rekey 、 ODM レコードで利用可能な既存の属性を使用して、Key Protectサーバーと通信し、APIキーを作成します。 APIキーの作成に成功した場合、新しく作成されたAPIキーが ODM 内の既存のAPIキーに置き換えられます。 元のAPIキーは、キープロテクトサーバーから削除されません。

例

  1. ODM データベース内にある鍵サーバー・エントリーに関する情報を表示するには、以下のコマンドを実行します。
    # keysvrmgr show -t keyserv  
List of key servers: 
ID                          PWD     IP:PORT
sklm1                       Y       10.11.12.13:5696
sklm_server2                N       210.211.212.213:569
  2. Key Protect インスタンスを含むサーバータイプについて kms 、既存の ODM エントリに関する情報を表示するには、次のコマンドを入力してください：
    # keysvrmgr show -t kms
List of key servers:
SVR_NAME    REGION                                                          INST_ID                                
kp-aix      https://us-east.kms.cloud.ibm.com/crypto_v2                     ad87c05a-79ff-4f51-a1ee-3cff2db5808b
hp-aix      https://us-south.broker.hs-crypto.cloud.ibm.com/crypto_v2       f1a98698-a44f-4563-9149-d44494f5cb18
  3. キー保護サーバー用の ODM エントリを追加するには、次のコマンドを入力してください：
    # keysvrmgr add -t kms \
-a inst_id="f1a98698-a44f-4563-9149-d44494f5cb18" \
-a api_key="<your IBM Cloud API Key>" \
 -a svr_region="https://us-east.kms.cloud.ibm.com/crypto_v2" <name>

    name 変数の項目は、 keysvrmgr show コマンドの svr_name パラメーターの値として使用されます。 新たに形成された ODM エントリーは、他のすべての操作の name 変数によって参照されます。

  4. キー保護サーバーに関する既存の ODM エントリを削除するには、次のコマンドを入力してください：
    # keysvrmgr remove -t kms kp-aix
KMS server kp-aix successfully removed
  5. キー保護サーバーの既存の ODM エントリを確認するには、次のコマンドを入力してください：
    # keysvrmgr verify -t kms kp-aix
Start verifying the following ODM record:
Server name: kp-aix
Server region: https://us-east.kms.cloud.ibm.com/crypto_v2
Instance id: f1a98698-a44f-4563-9149-d44494f5cb18
ODM record kp-aix passed verification
    検証処理が失敗した場合、次の画面のようなエラーメッセージが表示されます：
    # keysvrmgr verify -t kms kp-aix
Start verifying the following ODM record:
Server name: kp-aix
Server region: https://us-east.kms.cloud.ibm.com/crypto_v2
Instance id: f1a98698-a44f-4563-9149-d44494f5cb18
3020-0560 curl_easy_perform() failed: Empty reply from server
ODM record kp-aix failed verification
  6. ODM のエントリのAPIキーを再生成するには、次のコマンドを入力してください：
    # keysvrmgr rekey -t kms kp-aix
Start rekey the following ODM record:
Server name: kp-aix
Server region: https://us-east.kms.cloud.ibm.com/crypto_v2
Instance id: f1a98698-a44f-4563-9149-d44494f5cb18
Update succeeded for ODM record kp-aix:
Old API_key: <old API key>
New API_key: <new API key>
Rekey succeeded for ODM record kp-aix
  7. 既存の ODM エントリの任意の属性を変更するには、次のコマンドを入力してください：
    # keysvrmgr modify -t kms \
-a api_key=<new API key> \
-a inst_id=<new Instance ID> \ 
-a svr_region=<new region URL> kp-aix
KMS server kp-aix successfully modified
  8. ODM エントリの変更内容を確認するには、次のコマンドを入力してください：
    keysvrmgr verify -t kms kp-aix
