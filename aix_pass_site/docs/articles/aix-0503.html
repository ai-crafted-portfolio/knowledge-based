目的

AIXのエラーログとBSDのシステムログに、障害や注目すべき状態に関する情報を記録する。

構文

/opt/rsct/bin/fclogerr { -e event > -t error_template_label -i error_template_headerfile -r resource > -s source_filename > -p line_of_code_pos -v sidlevel > -l lpp_name >-a assoc_fid { [ >-d detail_data_item[, >detail_data_item,...] -x > detail_data_type[,detail_data_type,...] -y detail_data_len[,detail_data_len,...] ] | [ >-f detail_data_file] } -b BSD_syslog_message_text } | -h

説明

このインターフェースは、情報を記録したいスクリプトプログラムによって使用されます。AIXエラー ログと BSD システム ログ。 このデバイスに書き込まれた情報は、 システム管理者またはシステム・オペレーターが、注意を必要とする、どのような障害状態または その他の注意すべき状態がシステムで発生したかを判別するときに使用します。 AIX エラー・ログおよび BSD システム・ログの目的は、どのような条件がどこで発生したかを検出するために条件を再作成することなく、条件の性質、影響、および応答をレポートから判別できるように、条件に関する十分な情報を記録することです。 何らかの直接的な介入が発生するまで持続する永続的な障害状態に遭遇したソフトウェア、またはシステム管理者に注意を喚起する必要がある状態に遭遇したソフトウェアは、fclogerrこの情報をAIXエラー ログと BSD システム ログ。

スクリプトは、fclogerr を使用する前に、基本 FFDC 環境 または FFDC エラー・スタック環境を作成するか継承して、この環境を 確立しておく必要があります。 fclogerr情報を記録するAIXこれらの環境が確立されていない場合でも、エラー ログと BSD システム ログが生成されますが、これらの環境のいずれかが存在しない限り、インターフェイスは FFDC 障害識別子を生成できません。

FFDC エラー・スタックを使用するように設計されているプロセスも fclogerr インターフェース を利用できます。また、解決するための管理者の注意または介入が必要な状態が発生する場合は、 このインターフェースを利用する必要があります。

状況とそれが発生した場所を適切に特定するために、FFDCポリシーでは次のことを推奨しています。fclogerrスクリプトのソース コード モジュール内でインラインで呼び出され、条件が検出されたときに呼び出される必要があります。 fclogerr条件に遭遇したソース コードを識別して見つけるのに役立つソース コード ファイル名とコード行情報を記録します。 この情報を記録する必要がある場合は、fclogerr を サブルーチンまたは自動ロードされたルーチンから呼び出すことができます。 ただし、この外部ルーチンが、場所に関する情報および障害に関する必要な詳細情報 のすべてを入手できる場合に限られます。 外部記録ルーチンは、 問題が検出された実際の場所を記録する必要があります。

それでもfclogerr情報を報告しますAIXエラー ログと BSD システム ログでは、各記録デバイスに対してこのインターフェイスに異なるオプションを指定する必要があります。 詳細データ情報は、AIXエラー ログは BSD システム ログにも記録されません。BSD システム ログ情報は、さまざまなコマンド オプションを通じて提供されます。 このため、場合によって、fclogerr ユーザーは、 この呼び出しで一部の情報を複写する必要があります。

フラグ

-a
このアプリケーションで使用されるソフトウェアによって報告され、現在記録されている状態の原因または影響を与えた障害状態の FFDC 障害 ID が含まれます。 この ID は、ソフトウェアの結果指示の一部として、このアプリケーションに戻されたはずです。 呼び出し元はここでこの識別子を提供するため、FFDC エラー スタックは、現在作成している障害レポートを以前に記録された障害レポートに関連付けることができます。 これにより、問題判別者は、 このアプリケーションやその他のアプリケーションのさまざまな症状から、 その他のソフトウェアの根本原因へと、障害の原因をトレースできるようになります。 その他のソフトウェア障害がこの状態の原因でない場合、あるいは、 その他のソフトウェアが、結果情報の一部として FFDC 障害 ID を戻さなかった場合は、 このオプションを省略する必要があります。
-b
BSD システム・ログに書き込まれる次のメッセージを指定します。
-d
状態に関する詳細情報を提供する1つ以上のデータ項目。詳細データを提供するために使用されます。AIXエラー ログ エントリ。 情報の詳細が長すぎる場合は、これらの詳細をファイルに書き込むことができます。 このファイルの名前は、detail_data_file パラメーター として指定します。 詳細なデータファイル名が指定されている場合は、このオプションを省略する必要があります。 もし、詳細データまたは詳細データファイルパラメータが指定されているか有効と思われる場合、詳細データにはnull情報が記録されます。AIXエラーログ。

このオプションを使用して、複数のデータ項目を指定することができます。 各データ項目は、 間にホワイト・スペース文字を入れずに、コンマ (,) で区切る必要があります。 データ項目に空白文字が埋め込まれている場合は、データ項目を二重引用符 (") で囲む必要があります。コマンドはフィールド区切り文字として解釈されるため、データ項目自体にコンマ (,) を含めることはできません。

このオプションしなければならないを伴う-xそして-yオプション。

-e
FFDC ログ・イベント・タイプを指定します。 現在有効な値は、FFDC_EMERG、FFDC_ERROR、FFDC_STATE、FFDC_TRACE、FFDC_RECOV、および FFDC_DEBUG です。 このコードは、ログに記録されるイベントのタイプ (緊急状態、永続状態、通知、デバッグ情報など) の一般的な説明を提供します。 および条件の重大度。 このオプションを指定しない場合は、イベント・タイプ FFDC_DEBUG が この問題レコードに割り当てられます。
-f
報告される状態に関する詳細を含むファイルの名前。 このオプションを使用するのは、 詳細が長すぎて、fclogerr がアプリケーションに残した、100 バイト の残りの詳細データ情報内に記録できない場合、あるいは詳細情報を分析できる ユーティリティーがある場合です。 このファイルの内容は、/var/adm/ffdc/dumpsディレクトリに移動し、ファイルの新しい場所は、AIXエラー ログ エントリ。
-h
ヘルプ・メッセージを標準出力に表示し、終了します。 指定したオプションにかかわりなく、 それ以外の処理は実行されません。
-i
エラーログテンプレート識別番号を含むヘッダーファイル（.h）の絶対パス名を指定します。エラーテンプレートラベル指定された-lオプション。 このテンプレートは、ノードのエラーログテンプレートリポジトリ（/var/adm/ras/errtmplt ）。このヘッダーファイルは、errupdateコマンドはソース コードのビルド手順の一部として実行され、ソフトウェアとともにノードにインストールされる LPP のパッケージに含まれている必要があります。 このオプションが指定されていない場合、またはスクリプトの実行時にヘッダーファイルが見つからない場合は、fclogerr独自のデフォルトエラーテンプレート（ラベルFFDC_DEF_TPLT_TR、識別子コード）を使用して障害情報を記録します。2B4F5CAB ）。
-l
出荷の際にこのソフトウェアが入っていたライセンス・プログラミング製品 の短縮名を指定します。 この値は LPP の受け入れ可能名として、お客様および アプリケーション・サポート・サービスの両者に認識できるものでなければなりません。 このような値の例としては、PSSP、GPFS、 LoadLeveler®、および RSCT があります。 このオプションが指定されていないか無効である場合、文字列PPS_PRODUCT使用されている。
-p
ソース・コード・モジュール内の、状態がレポートされているコード行の場所を 指定します。 提供される値は有効な整数値である必要があります。 状態を正しく識別し、位置指定するために、この値は、状態を検出したコード行 にできるだけ近いものでなければなりません。 Korn シェル・スクリプト では $LINENO の値を使用することができます。 特殊な行カウント変数を提供していないスクリプト言語 では、ここにシンボル値を指定することができます。この値を使用すると、 開発者は、fclogerr が使用されている、ソース・コード内の スポットを探し出すことができます。 このオプションが無効であるか、指定されていない場合は、 0 の値が使用されます。
-q
このコマンドからの警告メッセージの生成を抑止します。 警告は、コマンドが不足している情報をデフォルトの情報に置き換える必要がある場合、またはコマンドが不足している情報をコピーできない場合に生成されます。詳細データファイルに/var/adm/ffdc/dumpsディレクトリ。
-r

-s

-t
に与えられた記号ラベルを示しますAIXエラー ログ リポジトリ内のエラー ログ テンプレート。 エラー・ロギング・テンプレートを 作成する errupdate コマンドは、このラベルを整数コードに マップするマクロを生成します。 このラベルは ERRID_ の文字 で始まり、最大長は 19 文字です。 このオプションが指定されていない場合、またはスクリプトの実行時にヘッダーファイルが見つからない場合は、fclogerrを呼び出すerrloggerメッセージを作成するにはAIXOPMSG テンプレートを使用してエラー ログを作成します。

-x
指定されたデータ項目がどのように-dオプションは、この情報を記録する際に解釈される。AIXエラーログ。 これらの型は、AIXエラーログテンプレートは、-tオプション。 各タイプは、-d リストの対応するデータ項目をどのように解釈するか を示します。 このオプションの許容値は、ALPHA、HEX、および DEC です。 一致するタイプがリストされている必要があります-x各引数の引数-dリスト。

    FID=$(fclogerr -e FFDC_ERROR -t ERRID_SP_FFDCEXMPL_ER -i /usr/lpp/ssp/inc/
myprog.h -r myprog -s myprog.ksh -p $LINEPOS -v "1.1" -l PSSP -d $MINUSDOPTS -x
$MINUSXOPTS -y $MINUSYOPTS -b "myprog Configuration Failure - Exiting")
    RC=$?
    if ((RC == 0))

さて、先ほどの例を少し変えて、同じものを使って考えてみましょう。AIXエラー ログ テンプレートですが、今回は外部コマンドを使用して、このソース コードが提供するファイルから構成データを取得します。 このコマンドは非ゼロの終了状況で終了し、障害状態を検出すると、 FFDC 障害 ID を標準出力に表示します。 また、二重引用符の使い方を示すために、-dリストでは、構成ファイルの名前にスペースが埋め込まれています。

typeset CONFIG_FNAME
typeset INBUF
typeset MINUSDOPTS
typeset MINUSXOPTS
typeset MINUSYOPTS
typeset FID
typeset OUTPUT
integer MYCLIENT
integer RC
    :
MYCLIENT=$$
CONFIG_FNAME="This is a test"
OUTPUT=$(configdabeast $CONFIG_FNAME)
RC=$?
if ((RC != 0))
then
    # Create Detail Data Memory Block for AIX Error Log Template
    # Need to know the EXACT structure of the Template to do this correctly.
    #    Field 1 - filled in by fc_log_error
    #    Field 2 - filled in by fc_log_error
    #    Field 3 - filled in by fc_log_error
    #    Field 4 - name of configuration file being used - 16 bytes
    #    Field 5 - name of function call that failed - 16 bytes
    #    Field 6 - return code from failing function - 4 byte integer
    #    Field 7 - errno from failing function call (unused) - 4 byte integer
    #    Field 8 - user ID using this software - remaining space (62 bytes)
    # This source code supplied fields 4 through 8 in the "-d" option, and
    # describes the data types for each in the "-x" option.
    MINUSDOPTS="\""$CONFIG_FNAME"\""
    MINUSXOPTS="ALPHA"
    MINUSYOPTS="16"
    MINUSDOPTS="$MINUSDOPTS,configdabeast"
    MINUSXOPTS="$MINUSXOPTS,ALPHA"
    MINUSYOPTS="$MINUSYOPTS,16"
    MINUSDOPTS="$MINUSDOPTS,$RC"
    MINUSXOPTS="$MINUSXOPTS,DEC"
    MINUSYOPTS="$MINUSYOPTS,4"
    MINUSDOPTS="$MINUSDOPTS,0"
    MINUSXOPTS="$MINUSXOPTS,DEC"
    MINUSYOPTS="$MINUSYOPTS,4"
    MINUSDOPTS="$MINUSDOPTS,$MYCLIENT"
    MINUSXOPTS="$MINUSXOPTS,DEC"
    MINUSYOPTS="$MINUSYOPTS,60"
    FID=$(fclogerr -e FFDC_ERROR -t ERRID_SP_FFDCEXMPL_ER -i /usr/lpp/ssp/inc/
myprog.h -r myprog -s myprog.ksh -p $LINEPOS -v "1.1" -l PSSP -d $MINUSDOPTS -x
$MINUSXOPTS -y $MINUSYOPTS -a $OUTPUT -b "myprog Configuration Failure - Exiting")
    RC=$?
    if ((RC == 0))
    then
         fcdispfid $FID
         return 1
    else
         :
    fi
fi
