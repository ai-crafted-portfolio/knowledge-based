目的

rootvg上で基本オペレーティング・システム (BOS) の複数のバージョンを作成、更新、および管理します。

構文

multibos -s [-l 装置 {-a | -f ファイル | -b ファイル | -x (X) ファイル}] [-e ファイル] [-i ファイル] [-L ファイル] [-pntNX]

multibos-c-l デバイス {-a | -f ファイル | -b ファイル | -x ファイル } [-pnNX ]

multibos -m [-pnX]

multibos -u [-pnX]

multibos -B [-ntX]

multibos -S [-nX]

multibos -R [-ptX]

multibos -C [VG 名]

multibos -s -M ファイル [-pntNX]

説明

multibos コマンドを使用すると、root ユーザーが rootvg ボリューム・グループに基本オペレーティング・システム (BOS) のインスタンスを作成できます。

注: ミラーリングされた rootvg ボリューム・グループに対して multibos コマンドを使用することはできません。

multibos セットアップ操作は、別個のブート論理ボリューム (BLV) からブートするスタンバイ基本オペレーティング・システム (BOS) を作成します。 これにより、所定の rootvg上に BOS の 2 つのブート可能セットが作成されます。 管理者は、 bootlist コマンドの引数としてそれぞれの BLV を指定するか、システム・ファームウェアのブート操作を使用して、BOS のいずれかのインスタンスからブートすることができます。 BOS の 2 つのブート可能なインスタンスを同時に維持することができます。 ブート された BLV に関連する BOS のインスタンスは、アクティブ BOS と呼ばれます。 ブートされていない BLV に関連する BOS のインスタンスは、 待機 BOS と呼ばれます。 現在、 rootvgごとにサポートされる BOS のインスタンスは 2 つのみです。

multibos コマンドを使用すると、管理者は、セットアップ時またはそれ以降のカスタマイズ操作時に、スタンバイ BOS にアクセスし、その保守レベルとテクノロジー・レベルをインストールし、更新し、カスタマイズすることができます。 スタンバイ BOS に保守更新およびテクノロジー更新をインストールしても、アクティブな BOS上のシステム・ファイルは変更されません。 これにより、アクティブ BOS が実動状態のままで、スタンバイ BOSの並行更新が可能になります。

さらに、 multibos コマンドは、論理ボリュームとファイルシステムをコピーまたは共用します。 デフォルトでは、 BOS ファイルシステム (現在は /、 /usr、 /var、および /opt) とブート論理ボリュームがコピーされます。 管理者は、追加の BOS オブジェクトのコピーを作成できます ( -L フラグを使用)。

他のすべてのファイルシステムおよび論理ボリュームは、 BOSのインスタンス間で共用されます。 分離されているログ・デバイスの論理ボリューム (例えば、ファイルシステム内部に含まれていないもの) についてコピーはサポートされていませんが共有はされます。

AIX「5Lバージョン「5.3、技術レベル5300-09付きには、'AIXバージョン '6.1と 6100-02 テクノロジーレベルような後のバージョンをスタンバイインスタンスに入れることができる。 この機能は、後のバージョンではシステムの mksysb バックアップを作成し、そのバックアップを使用して待機インスタンスの取り込みを行うことによって実行されます。 例えば、システム A がレベル 5.3.9.0 で、システム B がレベル 6.1.2.0 とします。 mksysb -M コマンドを使用してシステム B のバックアップを作成し、mksysb バックアップを使用して、システム A にあるオペレーティング・システムの待機インスタンスの取り込みを行うことができます。
注:
  1. multibos コマンドの実行中に、システム活動状況が最小限であることを確認します。
  2. より高いレベルのオペレーティング・システムにとって新規のどの論理ボリューム属性またはファイルシステム属性も、待機インスタンスの作成時にインプリメントされません。その理由は、より低いレベルのオペレーティング・システムはそれらの属性を認識しないためです。
  3. AIX 6.1 インスタンスと AIX 5.3 インスタンスの両方を長期間保持しないでください。 互換性がないため、これらのインスタンスの間の切り替えができなくなる可能性があります。 いずれかのインスタンスにコミットし、もう一方を除去してください。
  4. オペレーティング・システムが、マルチボスで作成された「bos_hd*名を持つアクティブBOSの論理ボリュームで動作しており、「rootvgディレクトリにスタンバイBOSがない場合、AIX®7200-00から保存または移行タイプのインストールが発生する可能性があります。 システムに bos_hd* 名がある論理ボリュームは、bos_hd5、bos_hd4、bos_hd2、bos_hd9var、および bos_hd10opt です。 オペレーティング・システムに、論理ボリューム hd5、hd4、hd2、hd9var、または hd10opt があってはなりません。 -M フラグを指定した mksysb コマンドを使用して作成された mksysb イメージから multibos インスタンスを作成した場合、 hd8 論理ボリュームも bos_hd8に名前変更されている可能性があります。 この前提条件は、lsvg -l rootvg コマンドで確認できます。 移行する前に、必ずシステムをバックアップしてください。 また、/usr/lpp/bos/pre_migration ファイルを、メディアまたは移行先のレベルのネットワーク・インストール管理 (NIM) スポットからターゲット・システムにコピーして、ターゲット・システムでこのファイルを実行し、移行の警告が出されるかどうかを確認してください。

    この環境で移行タイプまたはプリザベーション・タイプのオペレーティング・システム・インストールを実行する前に、ディスク制御ブロックが rootvg に有効なレベルであることを確認してください。 /usr/lpp/bosinst/blvset -d /dev/hdiskN -g level コマンドを実行できます。ここで、hdiskN は、bos_hd5 論理ボリュームを収容しているディスクです。 このコマンドが 0.0 または予期しないレベルを返した場合は、bosboot -ad /dev/ipldevice コマンドを実行して修正し、blvset コマンドを再実行して確認します。 6.1 または 7.1 が返される必要があります。

  5. 『構文』セクションに示すフラグに加え、-V フラグを指定すると、ブート時に inittab から検証操作が実行されます。 このエントリーを変更しないようにすることが重要です。 検証操作を行うと、multibos ユーティリティーにより、論理ボリュームとファイルシステムの変更をアクティブ・インスタンスとスタンバイ・インスタンスの間で同期化することができます。 また、このエントリーにより、mksysb リストア後の初期ブート時に ODM とデバイスの同期化も行われます。 この操作を行わないと、アクティブ・インスタンスとスタンバイ・インスタンスがいずれも、ファイルシステムと論理ボリュームの通常の操作と整合しなくなる可能性が生じます。
mksysb バックアップのファイルシステム・タイプ (JFS または JFS2) は、multibos コマンドが実行されるシステムのタイプと同じである必要があります。 例えば、/usr ファイルシステムが JFS2 ファイルシステムの場合は、mksysb バックアップの /usr ファイルシステムも JFS2 ファイルシステムである必要があります。
multibos コマンドの実行後、ログは /etc/multibos/logs/op.alog ファイルに保管されます。 alog -f /etc/multibos/logs/op.alog -o コマンドを使用してログ・ファイルを表示できます。
注: 両方のインスタンスを含むバックアップを作成するには、まず ( -m フラグを使用して) スタンバイ・インスタンスをマウントしてから、バックアップを作成します。 ただし、バックアップをディスク上にリストアできる唯一の方法は、alt_disk_mksysb コマンドを使用することです。

制約事項

  • multibos コマンドは、 AIX 5L バージョン 5.3 (5300-03 推奨メンテナンス・パッケージ適用) 以降でサポートされます。
  • 現行の rootvg には、 BOS オブジェクト・コピーごとに十分なスペースが必要です。 BOS オブジェクト・コピーは、元のディスクと同じディスクに配置されます。
  • コピーされる論理ボリュームの総数は、128 を超えることができません。 コピーされる論理 ボリュームと共有論理ボリューム総数は、ボリューム・グループの制限数に応じて決まります。
  • ミラーリングされた rootvg ボリューム・グループで multibos コマンドを使用することはサポートされていません。 unmirrorvg コマンドを実行して、 rootvg ボリューム・グループのミラーを除去することができます。 alt_disk_copy コマンドを実行すると、 rootvg ボリューム・グループのコピーを必要に応じてアップグレードすることができます。 AIXの必要なインスタンスがある場合は、 alt_rootvg_op 操作を使用して不要になったボリューム・グループを削除し、 rootvg ボリューム・グループを再ミラーリングします。

フラグ

項目
説明
-a update_all インストール・オプションを指定します。 セットアップとカスタマイズ操作の場合に有効です。
-B ブート・イメージ作成操作。 スタンバイ・ブート・イメージは、 AIX bosboot コマンドを使用して作成され、スタンバイ BLV に書き込まれます。
-b ファイル セットアップまたはカスタマイズ操作時にインストールされるインストール・バンドルを指定します。 インストール・バンドルの構文は、 geninstall の規則に従う必要があります。
-c スタンバイ BOSのソフトウェアのカスタマイズ更新を実行します。
-C VG 名 rootvg ボリューム・グループのようにリブート時に自動的にオンに構成変更されないボリューム・グループを同期するために、ボリューム・グループを同期に対してオンに構成変更することができます。 multibos -C VG name コマンドは、 multibos コマンドがディスク上に代替ルート・ボリューム・グループ (オペレーティング・システム) を作成してブートした後に、自動的にオフに変更されたボリューム・グループで使用する必要があります。
-e ファイル セットアップ操作中に除外するアクティブな BOS ファイルを正規表現構文でリストします。
-f ファイル セットアップまたはカスタマイズ操作時にインストールされる修正情報 (APAR など) をリストします。 リストの構文は、 instfix の規則に従います。
-i ファイル 現行の rootvgから作成されたデフォルトの image.data ファイルの代わりに使用するオプションの image.data ファイルを指定します。
-L ファイル スタンバイ BOSに含める追加の論理ボリュームのリストを含むファイルを指定します。
-l 装置 セットアップまたはカスタマイズ操作時にソフトウェア更新の デバイスまたはディレクトリーをインストールします。
-m スタンバイ BOSをマウントします。
-M ファイル mksysb イメージを含むファイルを指定します。 mksysb イメージは、 AIX 6.1 (6100-02 適用)以降の mksysb -M コマンドを使用して作成されている必要があります。
-N ブート・イメージ処理をスキップします。 このフラグは、 AIX ブート・プロセスをよく理解している経験のある管理者のみが使用してください。
-n 失敗時に終結処理を行わないようにします。 このオプションは、操作が失敗した後に multibos データを保持するのに役立ちます。
-p 所定の操作のプレビューを行います。 セットアップ、除去、マウント、アンマウント 、およびカスタマイズの各操作の場合に有効です。
-R すべてのスタンバイ BOS オブジェクトを削除します。
-S スタンバイ BOS ファイル・システムへの chroot アクセスを使用して対話式シェルを開始します。
-s スタンバイ BOSのインスタンスを作成します。
-t multibos がブート・リストを変更しないようにします。
-u スタンバイ BOSをアンマウントします。
-x ファイル update_all (-a)、インストール・バンドル・ファイル (-b)、フィックス・リスト・ファイル (-f) などの他のすべてのカスタマイズ・パラメーターの前に、オプションのカスタマイズ・スクリプトを実行します。 スクリプトの絶対パス名を使用する必要があります。
-X multibosに関連したタスクを実行するためにスペースが必要な場合に、自動ファイル・システム拡張を可能にします。 すべての multibos 操作は、このフラグを指定して実行することをお勧めします。

セキュリティー

root ユーザーのみが multibos コマンドを実行できます。

例

  1. スタンバイ BOS セットアップ操作プレビューを実行するには、次のコマンドを入力します。
    multibos -Xsp
  2. スタンバイ BOSをセットアップするには、以下のコマンドを入力します。
    multibos -Xs
  3. オプションの image.data ファイル /tmp/image.data および除外リスト /tmp/exclude.listを使用してスタンバイ BOS をセットアップするには、次のコマンドを入力します。
    multibos -Xs -i /tmp/image.data -e /tmp/exclude.list
  4. スタンバイ BOS をセットアップし、バンドル・ファイル /tmp/bundle としてリストされ、イメージ・ソース /imagesにある追加ソフトウェアをインストールするには、次のコマンドを入力します。
    multibos -Xs -b /tmp/bundle -l /images
  5. update_all インストール・オプションを使用してスタンバイ BOS でカスタマイズ操作を実行するには、次のコマンドを入力します。
    multibos -Xac -l /images
  6. すべてのスタンバイ BOS ファイルシステムをマウントするには、次のコマンドを入力します。
    multibos -Xm
  7. スタンバイ BOS 除去操作プレビューを実行するには、次のコマンドを入力します。
    multibos -RXp
  8. スタンバイ BOSを削除するには、次のコマンドを入力します。
    multibos -RX
  9. 既存の mksysb ファイル /backups/mksysb1 を使用して rootvg の待機インスタンスを転送するには、次のコマンドを入力します。
    multibos -M /backups/mksysb1 -sX
