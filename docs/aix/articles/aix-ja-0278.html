目的
コマンドを自動的に実行します。

説明
cron
デーモンは、指定された日時にシェル・コマンドを実行します。 以下のイベント・タイプが、
cron
デーモンによってスケジュールされます。
crontab
コマンド・イベント
at
コマンド・イベント
batch
コマンド・イベント
sync
サブルーチン・イベント
ksh
コマンド・イベント
csh
コマンド・イベント
これらのイベントを操作する方法は、
/var/adm/cron/queuedefs
ファイルによって指定されます。
定期的に実行するコマンドは、
crontab
ファイルに入っている命令に従って指定することができます。
crontab
ファイルの実行を依頼するには、
crontab
コマンドを使用します。 一度しか実行しないコマンドの実行を依頼するには、
at
コマンドを使用します。
cron
デーモンは終了することがないので、一度だけ実行してください。
cron
デーモンは、
cron
が初期化されたときにのみ、
crontab
ファイルおよび
at
コマンド・ファイルを調べます。
crontab
コマンドを使って
crontab
ファイルを変更すると、
変更を示すメッセージが
cron
デーモンに送られます。 これにより、新しいファイルや変更されたファイルがあるかどうかを定期的に調べるオーバーヘッドがなくなります。
注:
ユーザーが使用できなくなると、そのユーザーの
cron
ジョブは実行されなくなります。 ユーザーがついに使用できるようになっても、そのユーザーの
cron
イベントはもうキューに入れられません。
cron
デーモンは、ユーザーの可用性に関する情報を
cronlog
ファイルに記録しません。
TZ
環境変数を
chtz
コマンドで、または SMIT を使用してのいずれかで変更したときは、
cron
デーモンを再始動する必要があります。 これにより、
cron
デーモンは新しい
TZ
環境変数に合った時間帯と夏時間変更情報を使用できるようになります。
注:
1:00 a.mの間に実行するようにスケジュールされているジョブがある場合。 および 2:00 a.m。 タイム・ゾーンが夏時間から標準時間に変わると、ジョブは 2 回実行されます。
2:01 a.mの間に実行するようにスケジュールされているジョブがある場合。 および 2:59 a.m。 タイム・ゾーンが標準時間から夏時間に変更された日には、ジョブは実行されません。 これらのジョブを実行する時間を変更したり、

ジョブを手動で実行したり、あるいは翌日に実行したりすることができます。
cron
デーモンを停止する必要はありません。 ただし、
TZ
環境変数を変更した場合は、
現行の
cron
デーモンを削除して、
デーモンが新しい
TZ
の設定を自動的に再作成し、認識するようにしてください。
2:00 a.mに実行するようにスケジュールされているジョブがある場合。 タイム・ゾーンが標準時間から夏時間に変わる日に、ジョブは 1 秒早く実行されます。
cron
デーモンは、ユーザーが提供した
/etc/cronlog.conf
構成ファイルを読み取って、情報をログに記録します。 構成ファイルが作成されていない場合、
cron
デーモンはそのアクティビティーのログを
/var/adm/cron/log
ファイルに作成します。
cron
デーモンは、活動化されたとき、およびハングアップ・シグナルを受信したときに、構成ファイルを読み取ります。
cron
デーモンは、ユーザー指定のログ・ファイルを作成または開くことができない場合、
/var/adm/cron/log
ファイルにアクティビティーのログを作成します。

構文
cron [ -f 構成ファイル ] [ -Q ]

オプション
フラグ
項目 | 説明
-f ConfigurationFile | 代替構成ファイルを指定します。
-Q | 抑制モード。 指定すると、 -Q は cron ロギングを使用不可にします。 このパラメーターは、デフォルトの /var/adm/cron/log ファイルだけでなく、ユーザー構成のログ・ファイルにも有効です。 このオプションは、 -f オプションの後に指定する必要があります ( -f が指定されている場合)。
