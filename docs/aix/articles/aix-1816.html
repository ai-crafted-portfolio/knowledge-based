目的

zicコマンドはタイムゾーンコンパイラを提供する。

構文

zic [ -v ] [ -p Posixrules ] [ -d Directory ] [ -L Leapseconds ] [ -b bloat ] [ -r [@lo][/@hi] ] [ -R @hi] [ --version ] [ --help ] [ FileName ...]

説明

zicコマンドは、コマンドラインで指定されたファイルのテキストを処理し、この入力で指定された時間変換バイナリファイルを作成する。 ファイル名として - (ハイフン) を指定すると、標準入力からタイムゾーン情報が処理されます。

指定ファイル内の入力行は、フィールドから構成されています。 フィールドの区切り文字には、任意の数の空白文字を使用できる。 入力ファイル内のポンド記号 (#) は、 コメントを表し、ポンド記号が現れる行の最後まで続きます。 ホワイトスペース文字とポンド記号は、フィールドの一部として使用する場合、ダブルクォーテーション（"）で囲むことができる。 ブランク行は無視されます。

ルール行は次のような形式です。
Rule  NAME  FROM   TO   TYPE   IN   ON   AT   SAVE   LETTER/S
以下は、ルールラインを構成するフィールドである：
NAME
このフィールドには、このルールが適用されるルール・セットのランダムな名前を指定します。
FROM
このフィールドは、ルールが適用される最初の年を示す。 minimum (min) を指定すると、 最小の年を表示可能な時刻値で表します。 maximum (max) を指定すると、 最大の年を表示可能な時刻値で表します。
TO
この欄には、ルールが適用される最終年度を記入する。 このオプションは、有効な時間値として、または最小値と最大値を指定することで示される。 only を指定すると、 「FROM」フィールドの値を繰り返すことができます。
TYPE
このフィールドは、ルールが適用される年のタイプを示す。
TYPE フィールドには、下記の値が入ります。
'-'
「FROM」から「TO」までの (両端を含めた) すべての年に、ルールを適用します。
uspres
このルールはアメリカ大統領選挙の年に適用される。
nonpres
このルールは、アメリカ大統領選挙の年以外にも適用される。
IN
このフィールドは、ルールの発効月を表す。 月名は省略可能。
ON
このフィールドは、ルールの発効日を表す。 以下は認められている形式である：
  • lastFri は、その月の最後の金曜日を表します。
  • lastMon は、その月の最後の月曜日を表します。
  • 月の曜日を表す数字。 例えば、5 はその月の 5 番目の日を表します。
  • lastSun は、その月の最後の日曜日を表します。
  • Sun>=8は、8日以降の最初の日曜日を表す。
  • Sun<=25 は25日以前の最後の日曜日。
曜日の名前は、省略形でも、フルスペルでも可能です。 ONフィールド内のスペースはサポートされていません。
AT
ルールの適用が有効となる時刻を表します。 以下は認められている形式である：
  • 時間を時間で表した数値。 例えば、2 は 2 時間を表します。
  • 2:00は午前2時を時分表示。
  • 15:00は、24時間形式の時間フォーマットで午後3時を表す。
  • 1:28:14は、時・分・秒の形式で1時間28分14秒を示す。
これらの形式の後に、指定された時刻が現地の壁掛け時計の時刻の場合はwを、指定された時刻が現地の標準時の場合はsを付けることができる。 w または s が無い場合は、 壁掛け時計 (wall-clock) 時間と見なします。

3 つ以上のローカル時間がある領域では、 最も早い遷移時間ルールの「AT」フィールドでローカル標準時間を用いてください。 それによってタイムゾーンのバイナリー結果として保存される最初の遷移時間が確かに正確なものとなります。

SAVE
このフィールドは、ルールが有効なときに、ローカル標準時に加算される時間を表す。 このフィールドは「ATフィールドと同じフォーマットである。 wと sの接尾辞はこのフィールドでは無効である。
LETTER/S
このフィールドは、このルールが有効なときに使用されるタイムゾーン略語の可変部分を提供する。 このフィールドに - (ハイフン) が含まれると、可変部は null になります。 S 文字は EST を 表すために使用され、D 文字は EDT を表すために使用されます。
ゾーン行は次のような形式です。
Zone   NAME   GMTOFF   RULES/SAVE   FORMAT   [UNTIL]
以下は、ゾーンラインを構成するフィールドである：
NAME
タイムゾーンの名前を指定します。 NAMEフィールドで指定される名前は、そのゾーンの時間変換情報を含む ファイルを作成するために使用される名前である。
GMTOFF
このゾーンで標準時間を得るために GMT へ追加する時間量を指定します。 このフィールドは、ルール行の「AT」や「SAVE」フィールドと同じ形式です。 GMT から時間を減算する必要がある場合は、 フィールドの最初に負符号を付けてください。
RULES/SAVE
そのタイムゾーンで適用されるルールの名前、または代わりに現地標準時に加算する時間の量を示す。 このフィールドの値が - (ハイフン) である場合は、 標準時間が常にタイムゾーンに適用されます。
FORMAT
このタイムゾーンで使用される、タイムゾーンの省略形を指定します。 %s 文字は、タイムゾーンの省略形の可変部の場所を示すために使用されます。
UNTIL
GMT オフセットまたはルールが地域によって変わる時刻を指定します。 年、月、日、時刻で指定します。 このフィールドが指定された場合、タイムゾーン情報は指定されたGMTオフセットから生成され、指定された時刻までルールが変更される。
次の行は継続行でなければならない。 継続行は、前の行の'UNTILフィールドで指定された時刻から始まる情報を、前の行が使用するファイルに配置する。 この行は、ゾーン行と同じ形式ですが、Zone という文字列と、名前が省略されているところが異なります。 継続行は、ゾーン行と同じように「UNTILフィールドを含むことができ、次の行がさらなる継続行であることを示す。
リンク行は次のような形式です。
Link    LINK-FROM    LINK-TO

LINK-TO LINK-FROMフィールドはゾーン行の'NAMEフィールドとして表示 されなければならない。

継続行以外は、行は、どの順に入力してもかまいません。

time_t zicコマンドには、1901年12月14日以前の日付を含む入力をコンパイルするという制限がある。

-rフラグは、出力バイナリファイルの適用範囲を、lo変数とhi変数で指定された範囲のタイムスタンプに限定する。 loと hi変数の値は、EPOCH（1970-01-01 00:00:00協定世界時）からの秒数を符号付き10進数で表したものである。 範囲はlo変数の値を含むが、hi変数の値は含まない。 loおよびhi変数が指定されていない場合、デフォルトの範囲は極端な値になる。 loおよびhi変数が指定されていない場合、出力バイナリ・ファイルは UT オフセット 0 と省略形 -00 を使用する。 例えば、'zic -r @0コマンドは、非負のタイムスタンプ（EPOCH後の時間）のバイナリデータを返す。 zic -r @0/@2147483648コマンドは、31ビットの符号付き整数に収まる非負のタイムスタンプのバイナリデータを返す。 GNU dateを持つプラットフォームでは、'zic -r @$(date +%s)コマンドは、指定された日付より前のタイムスタンプを対象とするバイナリデータを除外する。

-rフラグを使うと、出力バイナリファイルのサイズが小さくなる。 しかし、タイムスタンプ範囲の境界を表現する必要があるため、出力バイナリファイルのサイズが大きくなる可能性がある。 hi変数の値によって、タイムゾーン情報フォーマット（TZif）ファイルに、拡張された'POSIX TZフォーマット文字列で表す代わりに、pre-hi遷移のための明示的なエントリーが含まれるようになった場合、出力バイナリファイルのサイズが増大する可能性がある。

注：「-b slimオプションを使えば、バイナリーファイルのサイズを小さくすることもできる。
-R @こんにちは フラグ -R は、EPOCHからの秒数でhi 変数の指定値未満のタイムスタンプに対して、冗長な末尾明示遷移を生成します。 これらの遷移は、拡張 POSIX TZ 文字列を用いてより簡潔に表現できる。 フラグ -R は、表されるタイムスタンプに影響を与えません。 非標準の TZif リーダーで拡張 POSIX タイムゾーン文字列を無視する場合には、フラグ -R を使用して対応できます。 ただし、このオプションは出力バイナリファイルのサイズを増加させます。
-v データ・ファイルに表示される年が、システム時間値で表現可能な年の範囲（GMT1970年1月1日午前0時00分00秒からGMT2038年1月19日午前3時14分07秒）外の場合にメッセージを表示する。

  • 後衛：このDATAFORMフォーマットは、反復的な改良によって成熟するのに時間がかかった最先端のフォーマットからデータフォーマットをインストールする。

現在、主戦と 後衛のフォーマットは同じで、2018年のカレンダーと一致している。 ヴァンガード・フォーマットには、負のオフセット値をサポートする特別な機能がある。 前衛フォーマットのこの機能により、夏はアイルランド標準時（IST、UTC+01）、冬はグリニッジ標準時（UTC）に従うアイルランドのサポートが向上する。 tzcodeライブラリーは長い間、負のオフセット値をサポートしてきたが、すぐに「メインフォーマットに移行しなければならない。 しかし、一部のダウンストリーム・パーサーは負のオフセット値をサポートしていないため、「tzcodeライブラリーはすぐにリアガード・フォーマットに移行しないかもしれない。
