目的
ドメイン・ネーム・システム・セキュリティー拡張 (DNSSEC) キー生成ツール。

説明
dnssec-keygen
コマンドは、
RFC 2535
および
RFC 4034
で定義されているDNSSEC (Secure DNS)用の鍵を生成する。 また、
RFC 2845
で定義されているトランザクション署名(TSIG)や
RFC 2930
で定義されているトランザクション鍵(TKEY)で使用される鍵も生成する。
キーの名前はコマンド行で指定します。 DNSSEC鍵の場合、この鍵名は鍵が生成されるゾーンの名前と一致しなければ ならない。

構文
dnssec-keygen [ -3 ] [ -A date/offset ] [ -a algorithm ] [ -b keyize ] [ -C ] [ -c class ] [ -D date/offset ] [ -d bits ] [ -D sync date/offset ] [ -E engine ] [ -f flag ] [ -G ] [ -g generator ] [ -h ] [ -I date/offset ] [ -i interval ] [ -K directory ] [ -k policy ] [ -L ttl ] [ -l file ] [ -n nametype ] [ -P date/offset ] [ -P sync date/offset ] [ -p protocol ] [ -q ] [ -R date/offset ] [ -S key ] [ -s strength ] [ -T rrtype ] [ -t type ] [ -V ] [ -v level ] [ name］

オプション
フラグ
表 1. フラグ
項目 | 説明
-3 | NSEC3 対応アルゴリズムを使用してDNSSEC鍵を生成する。 このオプションを、「 NSEC 」と「 NSEC3 両方のバージョンを持つアルゴリズ ムで使用した場合、「 NSEC3 バージョンが選択される。 例えば、' dnssec-keygen -3a RSASHA1 はNSEC3RSASHA1アルゴリズムを指定する。
-a アルゴリズム | 暗号アルゴリズムを選択します。 DNSSEC鍵の場合、 algorithm の値は以下の値のいずれかでなければならない： RSASHA1 NSEC3RSASHA1 RSASHA256 RSASHA512 ECDSAP256SHA256 ECDSAP384SHA384 ED25519 ED448 -T KEY 場合、値はディフィー・ヘ ルマン（DH）でなければならない。 この値を指定すると、自動的に「 -T KEY オプションも設定される。 これらの値は大/小文字を区別しません。 ECDSAP256SHA256 を' ECDSA256 、' ECDSAP384SHA384 を' ECDSA384 のように省略することもできる。 RSASHA1 が -3 オプションと一緒に指定されている場合は、代わりに NSEC3RSASHA1 が使用されます。 このパラメーターは、 -S オプションを使用する場合を除き、指定する必要があります。このオプションは、先行キーからアルゴリズムをコピーします。 以前のリリースでは、TSIG鍵として使用するためにHMACアルゴリズムを生成することができたが、この機能はBIND9.13.00で削除された。 tsig-keygen コマンドを使用して、TSIG 鍵を生成します。
-b 鍵サイズ | キー内のビット数を指定します。 鍵サイズの選択は、使用するアルゴリズムに依存する。 RSA鍵は1024～4096ビット、DH鍵は128～4096ビットの範囲でなければならない。 楕円曲線アルゴリズムには、このパラメーターは必要ありません。 鍵サイズが指定されていない場合、一部のアルゴリズムには事前定義されたデフォルト値があります。 例えば、DNSSECのゾーン署名鍵として使われるRSA鍵のデフォルト・サイズは 1024ビットである。 鍵署名鍵（KSK、' -f KSK で生成）として使用されるRSA鍵のデフォルト・サイズは 2048ビットである。

-C | タイミング・メタデータなしで旧式のキーを生成する互換モードを有効にする。 デフォルトでは、「 dnssec-keygen コマンドは、秘密鍵とともに保存されるメタデータに鍵の作成日を含める。 その他、発行日やアクティベーション日なども設定できる。 このデータを含むキーは、古いバージョンのBINDと互換性がないかもしれない。 -C オプションは、このデータを抑制する。
-c class | キーを含むドメインネームシステム（DNS）レコードが指定されたクラスを持っていなければならないことを示す。 これが指定されない場合、クラス IN が使用されます。
-d ビット | 鍵のサイズをビット単位で指定します。 アルゴリズム「 RSASHA1 、「 NSEC3RSASA1 、「 RSASHA256 、「 RSASHA512 」の場合、鍵サイズは1024～4096ビットの範囲でなければならず、DHサイズは128～4096ビットの範囲でなければならない。 このオプションは、アルゴリズム ECDSAP256SHA256 、 ECDSAP384SHA384 、 ED25519 、および ED448 では無視されます。
-E エンジン | 使用する暗号ハードウェアを指定します (該当する場合)。 BIND 9 がOpenSSL,とともにビルドされている場合、このオプションには暗号アクセラレータまたはハードウェア・サービス・モジュールを駆動するOpenSSLエンジン識別子を設定する必要があります (通常は ' PKCS11 )。
-f フラグ | KEY または DNSKEY レコードの flag フィールドに指定のフラグを設定します。 唯一認められているフラッグはKSK DNSKEYである。
-G | 鍵を生成しますが、鍵を公開したり、鍵で署名したりすることはありません。 このオプションは、 -P フラグおよび -A フラグと互換性がありません。
-g 生成プログラム | DHキーの生成に使用しなければならないジェネレーターを示す。 使用できる値は 2 および 5 です。 ジェネレーターが指定されていない場合、可能であれば RFC2539 の既知のプライムが使用され、そうでなければデフォルト値は2である。
-h | dnssec-keygen コマンドのオプションと引数の簡単な要約を表示する。
-K ディレクトリ | 鍵ファイルを書き込む必要があるディレクトリーを設定します。

-k ポリシー | 特定の dnssec-policy 構成の鍵を作成します。 ポリシーが複数の鍵を使用する場合、 dnssec-keygen コマンドは複数の鍵を生成します。 このオプションは、鍵の状態を追跡するための .state ファイルも作成します。 このオプションは、 dnssec-policy 構成に従って鍵を作成します。 したがって、「 dnssec-keygen コマンドが提供する他のオプションと同時に使用することはできない。
-L トル | DNSSEC鍵をDNSKEYリソースレコード(RR)に変換する際に使用する デフォルトのTTLを設定する。 この TTL は、DNSKEY RR が既に設定されていない限り、鍵がゾーンにインポートされるときに使用されます。 この場合、既存の TTL が優先されます。 この値が設定されず、DNSKEY RRセットが存在しない場合、TTLのデフォルトは SOA TTLである。 TTLのデフォルト値が「 0 または「 none 」に設定されている場合は、TTLを設定しないのと同じである。
-l ファイル | このオプションは、 dnssec-policy ステートメント (ポリシー・セットを -k フラグと突き合わせる) を含む構成ファイルを提供します。
-n 名前タイプ | キーのオーナー・タイプを指定します。 nametype の値は以下の値のいずれかでなければならない： ZONE はDNSSECゾーンキー(KEYまたはDNSKEY)を表す HOST ENTITY ホスト(KEY)に関連付けられたキー ユーザ(KEY)に関連するキーは USER その他（DNSKEY） これらの値は大/小文字を区別しません。 DNSKEY生成時のデフォルト値は「 ZONE である。
-p Protocol | 生成されるキーのプロトコル値を設定します。 プロトコル値は0〜255の範囲である。 デフォルト値は 3 (DNSSEC) です。 この引数に指定できる他の値は、 RFC2535 とその後継に記載されている。

-q | クワイエットモードを設定し、進捗表示を含む不要な出力を抑制する。 このオプションを使わずに' dnssec-keygen コマンドを対話的に実行し、 RSA (Rivest-Shamir-Adleman)またはDSA (Digital Signature Algorithm)の鍵ペアを生成すると、シンボルの文字列が' stderr に出力される。 これはキー生成の進捗状況を示す。 ピリオド（ . ）は、最初のふるい分けテストに合格した乱数であることを示す。 プラス記号（ + ）は、ミラー・ラビンの一次性テストに合格したことを示す。 スペース（ ）は、その番号がすべてのテストに合格し、満足のいくキーであることを示す。
-S キー | 既存のキーの明示的な後継となる新しいキーを作成する。 キーの名前、アルゴリズム、サイズ、タイプは、既存のキーと一致するように設定される。 新しい鍵の活動化日は、既存の鍵の非活動化日に設定されます。 公開日は、アクティベーション日から公開前の間隔 (デフォルトは 30 日) を引いた日付に設定されます。
-s 強度 | キーのストレングスの値を指定します。 強度 は0から15の範囲の数値であり、現在のところDNSSECアルゴリズムにおいて 定義された目的はない。
-T RRTYPE | キーに使用する必要があるリソース・レコード・タイプを指定します。 rrtype は DNSKEY または KEY でなければなりません。 DNSSECアルゴリズムを使用する場合、デフォルト値はDNSKEYであるが、 「 SIG(0) キー・ペアを使用する場合は、値をKEYに上書きすることができる。
-t type | キーの使用を示します。 タイプ は以下の値のいずれかでなければならない： AUTHCONF NOAUTHCONF NOAUTH NOCONF デフォルト値は AUTHCONF です。 AUTH 」はデータを認証する能力を示し、「 CONF 」はデータを暗号化する能力を示す。
-V | バージョン情報を印刷します。
-v レベル | デバッグのレベルを設定します。

例
example.comゾーンのECDSAP256SHA256ゾーン署名鍵を生成するには、以下のコマンドを 入力する：
dnssec-keygen -a ECDSAP256SHA256 example.com
このコマンドは以下の形式の文字列を表示する：
Kexample.com.+013+26160
この例では、
dnssec-keygen
コマンドにより、
Kexample.com.+013+26160.key
ファイルと
Kexample.com.+013+26160.private
ファイルが作成されます。
一致する鍵署名キーを生成するには、以下のコマンドを入力する：
dnssec-keygen -a ECDSAP256SHA256 -f KSK example.com
