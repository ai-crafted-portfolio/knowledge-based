目的

論理ボリュームおよび物理ボリュームの暗号化管理を行います。

構文

hdcryptmgr action [ -h ] [ flags ] devicename

説明

この hdcryptmgr コマンドは、暗号化された論理ボリュームを管理します。 IBM® AIX® 7.3 Technology Level 1 ( TL1 ) 以降では、この hdcryptmgr コマンドを実行して、暗号化された論理ボリュームおよび暗号化された物理ボリュームを管理できます。 暗号化された論理ボリュームまたは物理ボリュームを管理し、以下のいずれかの操作を実行するには、 action パラメータを指定します

注： アクションパラメータの属性の一部は、論理ボリュームまたは物理ボリュームに固有である。 アクションパラメータの一部の属性は、論理ボリュームと物理ボリュームの両方で使用できます。

暗号化設定の表示

暗号化設定を表示するには、コマンド hdcryptmgr を使用して以下の操作を実行してください：

showvg
構文
hdcryptmgr showvg [ -h ] [ device ]
指定したボリューム・グループのデータ暗号化状況を表示します。 ボリューム・グループを指定しない場合、 hdcryptmgr コマンドはボリューム・グループの暗号化ステータスを表示します。
# hdcryptmgr showvg
VG NAME / ID          ENCRYPTION ENABLED  
EVG1                      yes                 
INSTALLVG                 yes                 
rootvg                    no
showlv
構文
hdcryptmgr showlv [ -h ] [ -v ] device

認証方式の制御

Key Protect (IBM Key Protect for IBM Cloud®)論理ボリュームおよび物理ボリュームの暗号化機能は、パスフレーズ、キーファイル、キーサーバー管理ソリューション（ IBM Security Guardium® Key Lifecycle Manager (GKLM) (keyserv)、および PKS などのキー保護方式に対応しています。 パスフレーズとキーファイルの保護方法について、パスワードまたはキーファイルの場所を手動で指定します。 キーサーバーの管理機能および PKS の保護機能を使用することで、暗号化されたボリュームのロックを自動的に解除し、アクティブ化することができます。 キーサーバーの認証方法を「自動」として指定するには、クライアント証明書のパスワードを PKS に保存するか、クライアント証明書のパスワードを設定しないようにしてください。 認証方法を制御するには、次のアクションをコマンドで hdcryptmgr 実行します：
authinit
構文
hdcryptmgr authinit [ -h ] [ -e algo_detail ] [ -n name ] device
暗号化されたボリュームの 1 次鍵と暗号化メタデータを初期化します。 暗号化された各ボリュームについて、プライマリキーと暗号化されたメタデータは、1回だけ初期化する必要があります。 鍵保護方式から取得された最初のパスフレーズが、ボリュームの暗号化メタデータに追加されます。 pvenable アクション・パラメーターは、 authinit アクション・パラメーターも実行して、物理ボリューム上の認証を初期化します。 authinit アクション・パラメーターには、以下のフラグまたは値を指定できます。
-e
データ暗号化のアルゴリズム、モード、および鍵の長さを指定します。 以下は、 -e フラグの有効な値である：
プロンプト
コマンドの実行時に暗号化アルゴリズムの詳細を示すプロンプトを出すことを指定します。
[algorithm]:[b|B][key_len][:w]
暗号化アルゴリズム詳細を指定します。 サポートされるアルゴリズムは、Advanced Encryption Standard XTS モード (AES-XTS) の 128 ビットまたは 256 ビットです。 デフォルトでは、 b はキーのビット数、 B はキーのバイト数、 key_len はキーの長さである。 :w パラメーターは、指定した値を持つボリューム・グループのデフォルト値を上書きします。 デフォルトでは、暗号化が有効になっているボリューム・グループまたは物理ボリュームが作成されると、デフォルトの暗号化アルゴリズムはAES-XTS 128ビットになります。
-n
鍵保護方式の名前を指定します。 名前は 1 ～ 15 文字の範囲で変更でき、A～Z、a～z、0～9、アンダースコア（_）、マイナス記号（-）、ピリオド（.）それ以外の文字は無効とみなされます。
device
鍵保護方式を初期化する必要がある論理ボリューム、ボリューム・グループ、または物理ボリュームのデバイス名を指定します。
authadd
構文
hdcryptmgr authadd [ -h ] [ -t type [ -m method_detail ] ] [ -n name ] device
すでにキープロテクト方式が初期化されている暗号化ボリュームに、さらにキープロテクト方式を追加する。 暗号化されたボリュームに追加した認証方式をアクティブ化するには、暗号化されたボリュームをアンロックする必要があります。 このアクション・パラメーターは、以下のフラグまたは値で指定できる：
-t
鍵保護タイプを指定します。 有効な値は、 pwd、 keyfile、 keyserv、 kms、および pks です。
-m
以下の詳細を含む、鍵保護方式に関する追加情報を指定します。
  • 認証キーファイルへのパスを入力してください
  • KeySvr Object Data Manager (ODM) クラス内の鍵サーバー ID
  • ODM クラスにおけるキーサーバー名
-n
鍵保護方式の名前を指定します。 名前は 1 ～ 15 文字の範囲で、A～Z、a～z、0～9、アンダースコア（_）、マイナス記号（-）、またはピリオド（.）それ以外の文字は無効とみなされます。
device
鍵保護方式を追加する必要がある論理ボリュームまたは物理ボリュームのデバイス名を指定します。

hdcryptmgr authadd コマンドの実行時に必要なフラグまたは値を指定しないと、同じフラグまたは値を指定するように求めるプロンプトが出されます。 鍵サーバー情報の登録については、 keysvrmgr コマンドを参照してください。

authunlock または authunl
構文
hdcryptmgr authunlock [ -h ] [ -t type [ -m method_detail ] ] [ -A] device
暗号化されたボリュームに対して認証し、暗号化されたボリュームをアンロックします。 このアクション・パラメーターは、以下のフラグまたは値で指定できる：
-A
ユーザー入力を必要としない自動鍵保護方式を使用して、暗号化論理ボリュームを認証する。 このフラグをボリュームグループレベルで使用するのは、そのボリュームグループが、キーサーバー管理ソリューションや PKS などの自動キー保護方式を採用している場合に限ります。
-t
鍵保護方式のタイプを指定します。 有効な値は、 pwd、 keyfile、 keyserv、 kms、および pks です。
-m
以下の詳細を含む、鍵保護方式に関する追加情報を指定します。
  • 認証キーファイルへのパスを入力してください
  • KeySvr ODM クラス内の鍵サーバー ID
  • ODM クラスにおけるキーサーバー名
device
認証が必要な論理ボリュームまたは物理ボリュームのデバイス名を指定します。その後、鍵保護方式をアンロックする必要があります。 この値は -A フラグで指定する。

装置名を指定する場合、 -t フラグおよび -m フラグを使用して鍵保護方式を指定できます。 複数の鍵保護方式が基準を満たす場合は、特定の鍵保護方式の選択を求めるプロンプトが出されます。

注: ブート操作中に鍵サーバー認証方式を使用して論理ボリュームを暗号化解除する暗号化論理ボリュームの場合、サーバーまたはクライアント証明書は、 /etc ディレクトリー、またはブート操作シーケンスの初期にマウントされたファイル・システムに配置する必要があります。
authcheck または authchk
構文
hdcryptmgr authcheck [ -h ] [ -t <type> [ -m <method_detail> ] ] [ -i <index> ] [ -n <name> ] <device>
これは、認証方式の妥当性を検査します。 このアクション・パラメーターは、以下のフラグまたは値で指定できる：
-h
ヘルプ情報を表示します。
-t
鍵保護方式のタイプを指定します。 有効な値は、 pwd、 keyfile、 keyserv、 kms、および pks です。
-m
以下の詳細を含む、鍵保護方式に関する追加情報を指定します。
  • 認証キーファイルへのパスを入力してください
  • KeySvr ODM クラス内の鍵サーバー ID
  • ODM クラスにおけるキーサーバー名
-i
これは、指定の索引のみの認証を検査します。 認証タイプは、選択されたインデックスに従って自動的に強制される。
-n
これは、検査が必要となる鍵保護方式の名前を指定します。 名前は 1 ～ 15 文字の範囲で、A～Z、a～z、0～9、アンダースコア（_）、マイナス記号（-）、ピリオド（.）それ以外の文字は無効とみなされます。
device
検査する必要がある論理ボリュームまたは物理ボリュームのデバイス名を指定します。
authdelete または authdel
構文
hdcryptmgr authdelete [ -h ] [ -t type [ -m method_detail ] ] [ -i index] [ -n name ] [ -f ] device
初期化された鍵保護方式を削除します。 このアクション・パラメーターは、以下のフラグまたは値で指定できる：
-t
鍵保護タイプを指定します。 有効な値は、 pwd、 keyfile、 keyserv、 kms、および pks です。
-m
以下の詳細を含む、鍵保護方式に関する追加情報を指定します。
  • 認証キーファイルへのパスを入力してください
  • KeySvr ODM クラス内の鍵サーバー ID
  • ODM クラスにおけるキーサーバー名
-i
削除する必要のある鍵保護方式の索引を指定します。
-n
削除する必要のある鍵保護方式の名前を指定します。 名前は 1 ～ 15 文字の範囲で、A～Z、a～z、0～9、アンダースコア（_）、マイナス記号（-）、またはピリオド（.）それ以外の文字は無効とみなされます。
-f
強制オプションを指定します。 このフラグは、鍵保護方式を削除するために、認証方式チェックをバイパスします。
device
鍵保護方式を削除する必要がある論理ボリュームまたは物理ボリュームのデバイス名を指定します。

一度に削除できる鍵保護方式は 1 つのみです。 鍵保護方式の正しい索引または名前がわかっている場合は、-i フラグまたは -n フラグを使用して鍵保護方式を指定できます。 -t フラグと -m フラグを使用して、既存の鍵保護方式のリストをフィルターに掛けることができます。 指定した基準に複数のエントリーが一致する場合は、削除する必要のある鍵保護方式の選択を求めるプロンプトが出されます。

-f フラグを使用しない限り、鍵保護方式を削除する前に、鍵保護方式の妥当性が検査されます。 選択した鍵保護方式でボリュームを認証する。

注: authdelete 操作を実行した後、ボリュームに少なくともパスフレーズ・キー保護方式があることを確認する。
authsetrvgpwd または setrvgpwd
構文
hdcryptmgr authsetrvgpwd [-h]
これは、rootvg のリカバリー・パスワードを設定します。 LPARにオペレーティングシステムをインストールする際、論理ボリュームの暗号化を有効にすると、暗号化された論理ボリュームに対しては「 PKS 」認証方式のみが作成されます。 インストールが完了し、LPAR が通常モードでブートした後、 hdcryptmgr authsetrvgpwd コマンドを実行して rootvg のリカバリー・パスワードを追加する必要があります。
authmod
構文
hdcryptmgr authmod [ -h ] [ -t <type> ] [ -i <index> ] [ -n <name> ] <device>
選択したキー保護方法を変更します。 このアクション・パラメーターには以下のフラグを指定できる：
-h
ヘルプ情報を表示します。
-t
鍵保護方式のタイプを指定します。 有効な値は pwd である。
注： hdcryptmgr authmod コマンドを実行する際、 -t pwd を指定しない場合、デフォルトでキープロテクト方式は pwd に設定される。 キープロテクションのインデックスや名前がわかっていれば、 -i または -n フラグを使ってキープロテクションの方法を指定することができる。
-i
指定されたインデックスのみの変更を対象とする。
-n
認証方法に与える名前を指定します。 名前は 1 文字から 15 文字で、A-Z、a-z、0-9、アンダースコア(_)、マイナス記号(-)、ピリオド(.)の文字のみを含むことができます。それ以外の文字は無効とみなされます。
device
検査する必要がある論理ボリュームまたは物理ボリュームのデバイス名を指定します。
注：AIX 7.3 Technology Level (TL) 4 Service Pack (SP) 1 以降、 IBM では、 Hyper Protect Crypto Services (HPCS) が非推奨となり、 IBM Cloud® Key Protect Dedicated Server に置き換えられます。 この hdcryptmgr コマンドのオプションでは -t 、有効な値として「 hpcs 」の代わりに 「kms 」が追加されました。 互換性の観点から、 hpcs 値は引き続き受け入れられていますが、 kms 値を使用する必要があります。 HPCSから Key Protect サーバーへ移行するには、 「HPCSから Key Protect サーバーへの移行」 のセクションを参照してください。

PKS 鍵の管理

PKS は、 IBM Power® E950 の IBM PowerVM® ファームウェアで利用可能な、安全なキー保護機能です。 暗号化された論理ボリュームに、 PKS キー保護方式を追加することができます。 認証用の PKS キーを管理するには、以下のアクションパラメータを使用できます：

pksshow
構文
hdcryptmgr pksshow [-h]
PKS キーに関連付けられているボリュームの「 PKS 」ラベルと、 PKS キーの状態を表示します。 PKS とボリュームのメタデータの両方に保存されている PKS ラベルが表示されます。
# hdcryptmgr pksshow

Used  PKS size: 479 bytes
Estimated encryption key slots: 747

PKS_Label (LVid)                         Status		Device

00fb293100004c0000000174c0a994b7.2       UNKNOWN

pksclean

hdcryptmgr pksclean [ -h ] <pks_label>
無効な鍵を PKS から削除します。 削除したい無効なキーに関連付けられている「 PKS 」ラベルを指定してください。 このコマンドは、 hdcryptmgr pksshow コマンド出力に UNKNOWNという状況でリストされているキーを除去するために使用する必要があります。
pksexport

hdcryptmgr pksexport [-h] -p ExportFile device
指定したファイルに PKS 鍵をエクスポートします。 論理ボリュームまたは物理ボリュームのデバイス名を指定すると、その論理ボリュームまたは物理ボリュームに関連付けられている PKS キーがエクスポートされます。 VG デバイス名を指定した場合は、ボリューム・グループ内の論理ボリュームに関連付けられているすべての PKS 鍵がエクスポートされます。

論理ボリュームの暗号化状況の変換

通常の論理ボリュームを暗号化論理ボリュームに、暗号化論理ボリュームを通常の論理ボリュームに変換することができます。 この変換操作は、アクティブでオンラインになっている論理ボリュームに対してのみ実行できます。
警告以下の変換コマンドを実行する前に、データをバックアップしてください。
注: 論理ボリュームの暗号化状況の変換は、アクティブなブート、ダンプ、ページング、および aio_cache 論理ボリューム・タイプではサポートされません。
rootvgには、論理ボリュームの暗号化ステータスを暗号化から非暗号化、非暗号化から暗号化に変換するための空きパーティションが少なくとも1つ必要です。 rootvg 内の論理ボリュームの暗号化状況を変換する場合、hdcryptmgr コマンドは、暗号化状況変化時に生成されるリカバリー・データを保管するためのリカバリー論理ボリュームを作成します。 一方、ユーザー・ボリューム・グループ内の論理ボリュームの暗号化の場合、 hdcryptmgr コマンドはリカバリー・ファイルを使用してリカバリー・データを保管します。 SIGKILL シグナルを受信した変換処理を中断しないでください。中断すると、論理ボリュームがダーティ状態になる可能性があります。 ブートプロセスに必要な論理ボリュームがダーティな状態の場合、論理パーティションが起動しないことがあります。 論理パーティションを修復するか、メンテナンスモードでリカバリする必要があります。 以下のアクションパラメーターを使用して、暗号化ステータスを変更することができます：
plain2crypt
構文
hdcryptmgr plain2crypt [-h] [-e algo_detail] [-n name] [-f] device
論理ボリュームの暗号化を有効にし、暗号化設定を構成し、論理ボリュームデータを暗号化する。 このアクション・パラメーターは、以下のフラグと値で指定できる：
-e
データ暗号化のアルゴリズム、モード、および鍵の長さを指定します。 以下は、 -e フラグの有効な値である：
プロンプト
コマンドの実行時に暗号化アルゴリズムの詳細を示すプロンプトを出すことを指定します。
[algorithm]:[b|B][key_len][:w]
暗号化アルゴリズム詳細を指定します。 サポートされるアルゴリズムは、Advanced Encryption Standard XTS モード (AES-XTS) の 128 ビットまたは 256 ビットです。 デフォルトでは、 b はキーのビット数、 B はキーのバイト数、 key_len はキーの長さである。 :w パラメーターは、指定した値を持つボリューム・グループのデフォルト値を上書きします。 デフォルトでは、暗号化が有効になっているボリューム・グループまたは物理ボリュームが作成されると、デフォルトの暗号化アルゴリズムはAES-XTS 128ビットになります。
-n
鍵保護方式の名前を指定します。 名前は 1 ～ 15 文字で、A～Z、a～z、0～9、アンダースコア(_)、マイナス記号(-)、ピリオド(.)のいずれかを含むことができる。それ以外の文字は無効とみなされます。
-f
強制オプションを指定します。 このフラグを使用しない場合、 hdcryptmgr コマンドはデータがバックアップされていることを確認するプロンプトを表示します。 強制オプションはこのプロンプトを抑止します。
device
暗号化状況を変換する必要のある論理ボリュームのデバイス名を指定します。
crypt2plain
構文
hdcryptmgr crypt2plain [ -h ] [ -f ] device
指定した論理ボリュームの暗号化データを復号し、指定した論理ボリュームの暗号化状況を無効にします。 このアクション・パラメーターは、以下のフラグと値で指定できる：
-f
強制オプションを指定します。 このフラグを使用しない場合、 hdcryptmgr コマンドはデータがバックアップされていることを確認するプロンプトを表示します。 強制オプションはこのプロンプトを抑止します。
device
暗号化状況を変換する必要のある論理ボリュームのデバイス名を指定します。

物理ボリューム暗号化の管理

物理ボリュームの暗号化は、物理ボリュームに書き込まれるデータを暗号化することで、ユーザーデータを保護します。 基本オペレーティング・システムは、入出力操作中に物理ボリューム・データの暗号化と暗号化解除を実行します。 物理ボリュームの暗号化について詳しくは、 暗号化された物理ボリュームを参照してください。

注記: 1 つの論理パーティション (LPAR) で pvenable または pvdisable アクションパラメーターを使用して共有物理ボリュームの暗号化を有効または無効にした場合、他の LPAR で共有物理ボリュームの rmdev および mkdev コマンドを実行するか、他の LPAR を再起動して、共有物理ボリュームの暗号化状態の変更を認識します。

暗号化された物理ボリュームに対して、 hdcryptmgr コマンドの以下のアクション・パラメーターを実行できます。

pvenable
構文:
hdcrpytmgr pvenable [ -h ] [e algo detail ] [ -n <name> ] [ -f ] device
物理ボリューム上で暗号化を有効にし、1 次鍵を構成し、最初の認証方式を初期化します。
-h
ヘルプ情報を表示します。
-e
データ暗号化のアルゴリズム、モード、および鍵の長さを指定します。 以下は、 -e フラグの有効な値である：
プロンプト
コマンドの実行時に暗号化アルゴリズムの詳細が表示されることを示します。
[algorithm]:[b|B][key_len][:w]
暗号化アルゴリズム詳細を指定します。 物理ボリュームでサポートされるアルゴリズムは、Advanced Encryption Standard XTS モード (AES-XTS) 128 ビットまたは 256 ビットです。 デフォルトでは、文字 bは鍵のビット（デフォルト）、文字 Bは鍵のバイト、変数 key_lenは鍵の長さを示す。 :w パラメーターは、指定した値を持つボリューム・グループのデフォルト値を上書きします。 デフォルトでは、データ暗号化が有効になっているボリューム・グループまたは物理ボリュームを作成すると、デフォルトの暗号化アルゴリズムは AES-XTS 128 ビットに設定されます。
-n
これは、検査が必要となる鍵保護方式の名前を指定します。 名前は 1 ～ 15 文字で、A～Z、a～z、0～9、アンダースコア（_）、マイナス記号（-）、またはピリオド（.）その他の文字は無効です。
-f
強制オプションを指定します。 -f フラグを使用しない場合、 hdcryptmgr コマンドは、データ暗号化が有効になっている物理ボリューム内のデータを削除できるかどうかを確認するよう求めるプロンプトを表示します。
device
暗号化が有効になっている物理ボリュームの名前を指定します。
pvdisable
構文:
hdcryptmgr pvdisable [ -h ] [ -f ] device
物理ボリュームの暗号化を無効にします。
-h
ヘルプ情報を表示します。
-f
強制オプションを指定します。 -f フラグを使用しない場合、 hdcryptmgr コマンドは、データ暗号化が無効になっている物理ボリューム内のデータを削除できるかどうかを確認するプロンプトを表示します。
device
暗号化が無効になっている物理ボリュームの名前を指定します。
pvsavemd
構文:
hdcryptmgr pvsavemd [-h] -p file device
物理ボリュームの暗号化メタデータをファイルに保存します。 pvenable アクション・パラメーターを使用して物理ボリュームで暗号化が有効になっている場合、 AIX オペレーティング・システムは、暗号化メタデータを保管するために物理ボリューム上のスペースを予約します。 暗号化メタデータは、物理ボリュームが入出力操作のためにアンロックされるときに使用されます。 pvsavemd アクション・パラメーターは、暗号化メタデータのコピーを保存します。 pvrecovmd アクション・パラメーターは、暗号化メタデータとブート・レコードを検証し、以前に保存されたファイルから暗号化メタデータを復元します。
注: pvsavemd および pvrecovmd アクション・パラメーターは、物理ボリューム上の暗号化メタデータのみを保存およびリカバリーします。 action パラメータは pvsavemd 、 PKS のキーや外部キーサーバーに保存されている暗号化の詳細などの外部データを保存しません。 暗号化の詳細は個別にバックアップする必要があります。
-h
ヘルプ情報を表示します。
-p
暗号化メタデータを保存するファイル・パスを指定します。
device
指定されたファイルへの暗号化メタデータのコピー元の物理ボリュームの名前を指定します。
pvrecovmd
構文:
hdcryptmgr pvrecovmd [-h] [-c] [-f] [-v] [-p File] device
pvrecovmd アクション・パラメーターは、暗号化された物理ボリューム上の暗号化メタデータを検証し、破損した暗号化メタデータを復元しようとします。

暗号化された物理ボリュームには、暗号化メタデータのコピーが 2 つあります。 pvrecovmd アクション・パラメータは、物理ボリューム内の暗号化メタデータのコピーを検証し、比較する。 いずれかの暗号化メタデータ・コピーが正しくない場合、 pvrecovmd アクション・パラメーターは、正しくない暗号化メタデータを正しい暗号化メタデータで上書きします。 pvrecovmd アクションパラメータはブートレコードを検証し、物理ディスクが暗号化されていることを示す正しいタグをブートレコードに含めます。 以前に保存した暗号化メタデータを含むファイルを指定した場合、 pvrecovmd アクション・パラメーターは、指定されたファイルの内容を使用して、物理ボリューム上の暗号化メタデータをリストアします。

-h
ヘルプ情報を表示します。
-f
強制オプションを指定します。 暗号化メタデータに修正可能な問題がある場合、 hdcryptmgr コマンドが破損した暗号化メタデータを修正する前に、 pvrecovmd action パラメータで確認を求める。 –f オプションが指定されている場合、 pvrecovmd アクション・パラメーターはプロンプトを出さずに物理ボリュームに書き込みます。
-v
冗長モードを指定する。 物理ボリューム・デバイス名が指定されている場合は、より詳細な出力を表示します。
-p
この pvsavemd コマンドが保存するメタデータを含むファイルのパスを指定します。
-c
物理ボリュームの暗号化メタデータをチェックしますが、物理ボリュームは更新しません。
device
暗号化メタデータが検証される物理ボリュームの名前を指定します。
pvrecovmd アクション・パラメーターは、暗号化対応の物理ボリュームでのみ使用する必要があります。 暗号化されていない物理ボリュームに対して pvrecovmd アクション・パラメーターを使用すると、 hdcryptmr コマンドによって、暗号化されていない物理ボリューム上のユーザー・データが上書きされる可能性があります。

暗号化論理ボリュームのコマンドと機能の制限

論理ボリュームが暗号化されている場合にサポートされない論理ボリュームのコマンドや機能の詳細については、 論理ボリュームの暗号化の制限事項のセクションを参照してください。

例

シナリオ: パスフレーズ鍵保護方式を使用した暗号化論理ボリュームの作成

シナリオ: 暗号化が有効になっている論理ボリュームに対する認証
ボリュームグループをオフにするか、システムを再起動すると、暗号化された論理ボリュームに対する認証は失効します。 暗号化された論理ボリュームを認証し、そのデータにアクセスする。 暗号化された論理ボリュームに設定されたキー保護方法を使用する。 暗号化が有効な論理ボリュームを認証するには、以下の手順を実行します：
  1. VG をオンに変更します。
    # varyonvg vg00
varyonvg: 1 encrypted LV defined in VG vg00.
To check if a LV is encrypted and if it is unlocked, use:
        hdcryptmgr showlv vgname    or
        hdcryptmgr showlv lvname
In order to unlock a LV, use:
        hdcryptmgr authunlock lvname
  2. パスフレーズ鍵保護方式を使用して認証を行います。
    # hdcryptmgr authunlock -t pwd fslv00
Enter Passphrase:
Password authentication succeeded
シナリオ：オペレーティングシステムの起動に必要な、暗号化された論理ボリューム内の破損した PKS キーを修復する

オペレーティングシステムの起動に暗号化された論理ボリュームが必要な場合、その論理ボリュームには有効な PKS キーが設定されている必要があります。 そうでなければ、ブートプロセスは成功しない。 このようなシナリオでは、LPAR をメンテナンス・モードでブートする必要があります。 次の手順は、NIM サーバーを使用してメンテナンス・モードでオペレーティング・システムをブートする場合に適用できます。 この hdisk0 ディスクには、論理ボリューム内の rootvg および PKS キーが含まれていますが、論理ボリューム hd3 が破損しています。
  1. 次の画面で 3を選択する：
           Maintenance 

Type the number of your choice and press Enter.

    1 Access a Root Volume Group 
    2 Copy a System Dump to Removable Media
>>> 3 Access Advanced Maintenance Functions
    4 Erase Disks
    5 Configure Network Disks (iSCSI)
    6 Select Storage Adapters
  2. 次の画面で 0を選択する：
    Information for Advanced Maintenance Functions

-------------------------------------------------------------------------------
 To return to the Maintenance Menu after completing maintenance
 activities, type exit on the command line and press Enter.

-------------------------------------------------------------------------------

 Type the number of your choice and press Enter.

>>> 0 Enter the Limited Function Maintenance Shell
  3. 以下のコマンドを実行して、暗号化された論理ボリュームを修復します：
    # LIBPATH=/SPOT/usr/lib:$LIBPATH
# importvg hdisk0
# hdcryptmgr32 authunlock hd3
# hdcryptmgr32 authdel -t pks hd3
# hdcryptmgr32 authadd -t pks -n initpks hd3
  4. 修復が必要なすべての暗号化論理ボリュームについて、ステップ 1 から 3 を繰り返します。
シナリオオペレーティングシステムの起動に必要な論理ボリュームの変換操作の失敗の復旧


通常の論理ボリュームから暗号化された論理ボリュームへの変換、または暗号化された論理ボリュームから通常の論理ボリュームへの変換が中断された場合は、先ほど実行したのと同じ hdcryptmgr 変換コマンドを再度実行してください。 conversion コマンドは hdcryptmgr 、変換の復旧情報を読み取り、前回の実行で中断した箇所から変換処理を再開します。 この hdcryptmgr 変換コマンドは、論理ボリュームがブートプロセスで使用されるかどうかに関係なく実行されます。 ただし、変換処理の途中でLPARが再起動し、LPARがダーティ状態になった場合、再起動処理が失敗する可能性があります。 例えば、変換されるデータブロックが部分的に暗号化されており、変換される論理ボリュームがオペレーティングシステムの起動に必要である。 このようなシナリオでは、LPAR をメンテナンス・モードでブートし、変換操作を再開する必要があります。

次の手順では、NIM サーバーを使用してメンテナンス・モードでオペレーティング・システムをブートすることを想定しています。 この hdisk0 ディスクには rootvg が含まれており、変換プロセスが中断されたため、 hd3 という論理ボリュームがダーティ状態になっています。
  1. Maintenance メニューから 3 Access Advanced Maintenance Functions を選択する。
  2. Advanced Maintenance Functions で 0 Enter the Limited Function Maintenance Shell を選択する。
  3. 以下のコマンドを実行します。
    # LIBPATH=/SPOT/usr/lib:$LIBPATH
# importvg hdisk0
# hdcryptmgr32 plain2crypt hd3
シナリオ: 暗号化された物理ボリュームの作成
暗号化された物理ボリュームを作成すると、デフォルトでは、パスフレーズ鍵保護方式が暗号化された物理ボリュームに追加されます。 以下のコマンドを使用して、物理ボリューム (hdisk3) の暗号化を有効にすることができます。
# hdcryptmgr pvenable -f hdisk3
Enter Passphrase: 
Confirm Passphrase: 
Passphrase authentication method with name "initpwd" added successfully.

-f フラグは、 hdcryptmgr pvenable コマンドが確認のプロンプトを出さずに物理ボリューム内のデータを上書きできることを示します。 hdcryptmgr pvenable コマンドが正常に実行されると、物理ボリュームの暗号化が有効になり、I/O操作のロックが解除されます。 暗号化された物理ボリュームに書き込まれるデータはすべて暗号化され、暗号化された物理ボリュームから読み取られるデータはすべて暗号化解除されます。

シナリオ: 暗号化されたボリューム・メタデータの検査と修正
hdcryptmgr pvrecovmd -c コマンドは、暗号化された物理ボリューム上の暗号化メタデータを検証します。 物理ボリュームに暗号化メタデータのコピーが 2 つある場合、 pvrecovmd アクション・パラメーターは、暗号化メタデータの両方のコピーを検証して比較します。
物理ボリューム (hdisk24) 上の暗号化メタデータを検証するには、次のコマンドを入力します。
# hdcryptmgr pvrecovmd -cv hdisk24
物理ボリューム (hdisk24) 上の暗号化メタデータの両方のコピーが有効な場合、以下のメッセージが表示されます。
Metadata area 1 is valid.
Metadata area 2 is valid.
IPL record is valid for an encrypted disk.
All encryption fields for disk hdisk24 are valid.
Check of metadata on PV hdisk24 is complete.
pvrecovmd action complete.
物理ボリューム（hdisk24 ）上の暗号化メタデータのいずれかのコピーが破損すると、次のメッセージが表示されます：
Metadata area 1 is valid.
Disk metadata copy #2 is corrupt.
IPL record is valid for an encrypted disk.
Check of metadata on PV hdisk24 is complete.
pvrecovmd action complete.
破損した暗号化メタデータを物理ボリューム (hdisk24) 上の正しい暗号化メタデータで上書きするには、次のコマンドを入力します。
# hdcryptmgr pvrecovmd hdisk24 -v
hdcryptmgr pvrecovmd コマンドは、以下のメッセージを表示し、破損した暗号化メタデータを上書きできるかどうかを確認するプロンプトを出します。
Metadata area 1 is valid.
Disk metadata copy #2 is corrupt.
IPL record is valid for an encrypted disk.
Preparing to write the following fields to the disk:
    Backup metadata
Warning, about to write to disk hdisk25
Do you wish to continue?  y(es) or n(o)?
破損した暗号化メタデータを上書きしたい場合は、 y と入力する。 hdcryptmgr pvrecovmd コマンドは、破損した暗号化メタデータを正しい暗号化メタデータで上書きし、以下のメッセージを表示します。
Encrypted disk recovery attempt complete.
pvrecovmd action complete.
