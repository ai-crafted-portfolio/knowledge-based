目的

ctsyschk コマンドは、Reliable Scalable Cluster Technology (RSCT) クラスターをノード上に作成しているときに発生した問題を識別します。

構文

ctsyschk [V 値] [-U (U) username] [-P password] [-C cluster_type] [I ip-addr-type] [P- checking_subsys_port] [-m (M)] [N] [-s session_auth_type] node_name1 [node_name2...]

説明

ctsyschk コマンドは、さまざまな RSCT ベースのクラスタリング・ソリューションにおいて問題を発生させる可能性がある、システム設定およびネットワーキング動作を検証します。 オプションを付けずに ctsyschk コマンドを実行すると、コマンドの使用法が出力として表示されます。 ホスト名の指定なしで ctsyschk コマンドを実行すると、このコマンドは、ローカル・システム設定を検査します。 1 つ以上のホスト名または IP アドレスを指定すると、 ctsyschk コマンドは ssh または rshなどのリモート・シェル・コマンドを実行して、リモート・ターゲットから収集します。 ctsyschk コマンドは、ローカル・ノード、使用可能なインターフェースとノード ID、およびリモート・ノード上のポート番号可用性に関する情報を使用して、RSCT クラスターでの作成における座標を決定します。

リモート・コマンドを実行するためには、ctsyschk コマンドは、ユーザーが以下のいずれかをセットアップすることを必要とします。
  • パスワードなしの ssh/rsh
  • tcl/tk は、コマンドが実行されるノード上で予期します。 この場合、ユーザー名には -U オプション (デフォルトでは root ) を使用し、すべてのノードへのリモート・ログインのパスワードを指定するには -P オプションを使用する必要があります。
    制限: リモート・ログインが機能するためには、すべてのノードが同じユーザー名とパスワードを持っている必要があります。

フラグ

-V
ctsyschk コマンドの詳細メッセージを標準出力に書き込みます。
-U username
リモート・ログインのためのユーザー名を指定します。 デフォルト・ユーザーは rootです。 複数のノードが入力となっている場合、すべてのノードにおいてユーザー名は 1 つでなければなりません。
-P password
リモート・ユーザーのパスワードを指定します。 パスワードなしのリモート・ログイン ( rsh または ssh) が設定されていない場合は、 -U オプションで指定されたユーザー名のパスワードを指定する必要があります。 ユーザー名が指定されていない場合は、 root ユーザーのパスワードを指定する必要があります。 複数のノードが入力となっている場合、すべてのノードにおいて、リモート・ログイン用のパスワードは 1 つでなければなりません。
-C cluster_type
クラスター・タイプを指定します。 有効な値は次のとおりです。
p (ピア・ドメイン)
ctsyschk コマンドが cluster_type オプション p で実行されると、以下の項目が検査されます。
  • 指定された入力ノード間に IPv4 接続または IPv6 接続が存在するかどうか。
  • 入力ノードにおける Resource Monitoring and Control (RMC) ポート、High Availability Group Services (HAGS) ポート、または Host Access Transformation Service (HATS) ポートの可用性。
  • 指定された入力ノード間において、ファイアウォールが RMC ポートに構成されているかどうか。
  • ノード間の最大伝送単位 (MTU) サイズの互換性。
  • 入力ノードにおけるノード ID の固有性。
m (管理ドメイン)
ctsyschk コマンドが cluster_type オプション m で実行されると、以下の項目が検査されます。
  • RMC ポートの可用性 (論理区画 (LPAR) とハードウェア管理コンソール (HMC) との間で、RMC ポートにファイアウォールが構成されているかどうかを判別)。
  • LPAR と HMC との間の MTU サイズ互換性。
a (ピア・ドメインおよび管理ドメイン)
ctsyschck コマンドが cluster_type オプション a で実行されると、以下の項目が検査されます。
  • 指定された入力ノード間に IPv4/IPv6 接続が存在するかどうか。
  • 指定された入力ノードでの RMC/HAGS/HATS ポートの可用性。
  • 指定された入力ノード間において、ファイアウォールが RMC ポートに構成されているかどうか。LPAR 上の RMC ポートの可用性も検査されます。
  • LPAR と HMC との間で、ファイアウォールが RMC ポートに構成されているかどうか。
-p checking_subsys_port
ポートの可用性を検査するサブシステムを指定します。 有効な値は次のとおりです。
r
RMC ポート。
s
HATS ポートおよび HAGS ポート
a
すべてのポート (RMC、HAGS、および HATS)

デフォルト RMC ポートは 657 です。 ctsyschck コマンドが -r オプションで実行されると、このコマンドは、デフォルト・ポートがアプリケーション用に使用されるか、またはファイアウォールが RMC ポートに構成されているかを判別します。 トポロジー・サービス用のデフォルト・ポートは 12347 で、グループ・サービス用のデフォルト・ポートは 12348 です。 ctsyschck コマンドが s オプションで実行されると、これらのデフォルト・ポートが、使用できるよう解放されているかどうかが検査されます。 デフォルト・ポートが解放されていない場合、警告メッセージまたはエラー・メッセージが表示されます。

-i ip_addr_type
IP アドレス・タイプを指定します。 有効な値は次のとおりです。
4
IPv4 インターフェース

ctsyschck コマンドがインターフェース値 4 で実行されると、このコマンドは、有効な IPv4 インターフェースおよび互換サブネットを入力ノード上で検査します。 同じサブネット ID を持つサブネットには、互換性があります。 2 つのノードに、共通のサブネット ID を持つサブネットがない場合、ctsyschck コマンドは、それらのサブネットに関する情報を報告します。

コマンドの結果に応じて、考えられるネットワーク構成を変更し、RSCT クラスターを作成することができます。

6
IPv6 インターフェース

ctsyschck コマンドが値 6 で実行されると、このコマンドは、非リンク・ローカル・インターフェースおよび有効な IPv6 インターフェースを検査します。IPv6 インターフェースのサブネット互換性検証を行うわけではありません。

注: リモート・ノード上の有効なインターフェースに関する情報を確認するには、 rsh または ssh プロトコルが使用されます。 rsh または ssh プロトコルの使用法は、 CT_SYSCHK_SHELL 環境変数によって異なります。
a
IPv4 インターフェースおよび IPv6 インターフェースの可用性を検査します。
–m

ctsyschk コマンドは、いくつかの条件に基づいて、指定された入力ノード間で互換性のある MTU サイズを検査します。

ツールが、ノード間において有効な IPv4 通信パスを識別していること。 有効な通信パスが存在すれば、その間のインターフェース名を使用して、MTU サイズの互換性検査が実行されます。

-n

ノード ID 検査が実行されるかどうかを指定します。

この検査は、複数のノードに対して有効です。 1 つのノードを指定すると、この検査は実行されません。デフォルト状況 success が返されます。

ctsyschk コマンドが -n オプションで、複数のノード名が入力として指定されて実行されると、このコマンドは、指定されたすべてのノードにおけるノード ID の固有性を検査します。

-s

検証する RMC セッション認証タイプを指定します。 有効な値は次のとおりです。

u
ローカル・ノードからリモート・ノードへの非認証 RMC セッション。 例えば、この u オプションは、リモート・ノードの IBM.HostPublic リソース・クラスの照会を試みます。
a
ローカル・ノードからリモート・ノードへの認証済み RMC セッション。 例えば、この a オプションは、リモート・ノードの IBM.Host リソース・クラスの照会を試みます。

パラメーター

node_name1 [node_name2...]
ctsyschk コマンドの実行によってピア・ドメイン定義に組み込まれるノードを指定します。 このノード名は、ドメイン・ネーム・システム (DNS) ホスト名のロング・ネームまたはショート・ネームです。

環境変数

CT_SYSCHK_SHELL
リモート・ノードに到達するためのシェル。 ssh および rsh は、リモート・ノードに接続するために使用されるシェルの 2 つの例です。
CT_SYSCHK_TS_PORT
HATS 用のユーザー構成ポート。 この環境変数が設定されていると、デフォルト・ポート 12347 は使用されません。
CT_SYSCHK_GS_PORT
HAGS 用のユーザー構成ポート。 この環境変数が設定されていると、デフォルト・ポート 12348 は使用されません。

終了状況

0
コマンドは正常に完了しました。
1
指定されたノード間に有効な IP 接続はありません。
2
指定されたノード間に互換サブネットは存在しません。
3
ポート検査が失敗しました。
4
ファイアウォール設定によって、先に進むために必要な通信が許可されていません。
5
NodeId は、指定されたノードにわたって固有ではありません。
6
指定されたノード間で互換性のない MTU サイズが検出されました。
7
接続障害が発生しました。 リモート・ノードに到達できません。
8
その他のエラー。

制約事項

  • このコマンドの実行元のノードから、すべての入力ノードが到達可能でなければなりません。入力ノード名はいずれも、IP アドレスにしないでください。
  • ctsyschk コマンドは、 AIX® オペレーティング・システム用の RSCT ファイルセットの一部です。
  • -h フラグが指定されると、コマンドの使用法ステートメントが標準出力に書き込まれます。 すべての詳細メッセージが標準出力に書き込まれます。
  • すべてのエラー・メッセージが標準エラーに書き込まれます。

例

  1. ノード nodeA および nodeB がピア・ドメインを形成できるかどうかを確認するには、次のコマンドを実行します。
    ctsyschk -C p nodeA nodeB
  2. IPV4 通信パスがノード nodeA とノード nodeB との間に存在するかどうかを確認するには、次のコマンドを実行します。
    ctsyschk -i 4 nodeA nodeB
  3. HMC ノード nodeH と LPAR ノード nodeA との間の管理ドメイン互換性を確認するには、次のコマンドを実行します。
    ctsyschk -C m nodeH nodeA
  4. ノード nodeA とノード nodeB との間の RMC 接続を確認するには、次のコマンドを実行します。
    ctsyschk -s {u/a} nodeA nodeB
  5. ノード nodeA とノード nodeB との間の、ピア・ドメインを形成するための MTU 互換性を確認するには、次のコマンドを実行します。
    ctsyschk -m -C p nodeA nodeB
  6. ローカル・ノード上での RMC ポート、HAGS ポート、および HATS ポートの可用性を確認するには、次のコマンドを実行します。
    ctsyschk -p a -C p
  7. ノード nodeA および nodeB がピア・ドメインを形成できるかどうかを確認するには、次のコマンドを実行します。
    ctsyschk -p a -C p
