目的
システム・ダンプ・イメージまたはライブ・ダンプ・イメージからトレース・バッファーを取り出します。

説明
トレース機能がアクティブの間にシステムが停止した場合は、内部トレース・バッファーの内容がシステム・ダンプ内に取り込まれます。 あるいは、ライブ・ダンプも、適切な疑似コンポーネントであれば、内部トレース・バッファーの一部または全部を取り込むことができます。
trcdead
コマンドを使用して、8 つのアクティブなシステム・トレース・チャネル、すべてのコンポーネント・トレース・バッファー、および単純なメモリー・トレース・バッファーをシステム・ダンプまたはライブ・ダンプから取り出します。 フラグを指定しない場合は、システム・トレース・チャネル
0
が取り出されます。 チャネル
0
以外のチャネルのトレースは、
-channelnum
フラグによって識別されます。 コンポーネント・トレース・バッファーの識別には、
-c
フラグを使用します。 単純なメモリー・トレース・バッファーの識別には、
-M
フラグを使用します。 一回に取り出せるのは、トレース・バッファーの 1 つのタイプ、または 1 つの固有のシステム・トレース・チャネルのみです。
-o
フラグを使用すると、取り出されたバッファーをデフォルト以外のトレース・ログ・ファイルまたはディレクトリーに書き込むべきであることを示すことができます。 システム・トレース・チャネルは、トレース・ログ・ファイルに取り出されます。 コンポーネント・トレース・バッファーおよび単純なメモリー・トレース・バッファーは、ディレクトリーに取り出されます。
-o
フラグが選択されない場合は、
trcdead
コマンドがデフォルトのトレース・ログ・ファイルまたはディレクトリーに書き込みます。 デフォルトのログ・ファイル名とディレクトリー名は、
trcctl
コマンドを使用して表示および変更できます。
トレース・ログ・ファイルからレポートをフォーマットするには、
trcrpt
を使用します。

構文
trcdead [ -1 -2 -3 ... -7 ] [ -c ] [ -M ] [ -o Name ] DumpImage [ UnixFile ]

オプション
フラグ
項目 | 説明
-1, ..., -7 | チャネル 1、 2、 3、 4、 5、 6、および 7 のトレース・バッファー項目を取得します。 デフォルトはチャネル 0です。
-c | アクティブなすべてのコンポーネント・トレース・コンポーネントのすべてのバッファーを取り出します。
-M | 単純なメモリー・トレース・バッファーを取り出します。
-o 名前 | データが書き込まれるファイルまたはディレクトリー ( -c 、 -M ) を指定します。

例
“
注:
ご使用のシステムにより適切な例を判別するには、
sysdumpdev
コマンドを使用して、現在のダンプ・デバイス割り当てを表示してください。
”
システム・トレース・バッファーを次の名前のファイルに抽出します。
trace_extract
/var/adm/ras/dumpfile
にあるダンプから、次のように入力します。
trcdead -o trace_extract /var/adm/ras/dumpfile
装置に書き込まれたダンプ・イメージからシステム・トレース・バッファーを抽出するには、次のように入力します。
trcdead /dev/hd7
ダンプ・イメージ
vmcore.0
から軽量メモリー・トレース情報を抽出し、それを
/tmp
ディレクトリーに入れるには、次のように入力します。
trcdead -o /tmp -M vmcore.0
vmcore.3
/tmp/unix_64
によって作成されたダンプ・イメージからコンポーネント・トレース・バッファーを抽出するには、次のように入力します。
trcdead -c vmcore.3 /tmp/unix_64
