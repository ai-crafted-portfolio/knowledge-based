目的

XCOFF 実行可能ファイルのヘッダーを変更します。

構文

ldedit -b Option [ -V ] File

説明

ldedit コマンドを使用して、実行可能ファイルの XCOFF ヘッダーまたは補助ヘッダー内のさまざまなフィールドを変更できます。 ldedit コマンドによって、アプリケーションを 'large page data' プログラムとしてマークを付けたり、そのマークを外したりすることが可能になります。 ldedit コマンドによって、再リンクしないで MAXDATA および MAXSTACK の値を追加または変更することも可能になります。

-b フラグのフォーマットは、リンケージ・エディター ld コマンドが使用するフォーマットと類似しています。 -b フラグは、コマンド・ラインで複数回使用することができます。

フラグが指定されていない場合、'ldeditコマンドは標準エラー出力を使って使用法メッセージを表示する。

-b Option Option で指定されたように、実行可能ファイルを変更します。 Option で指定できる値は次のとおりです。
aslrまたは 'aslr:[[+-][tdsmp]*]*.
aslr または aslr:[[+-][tdsmp]*]* は、プログラムのアドレス・スペース・レイアウト・ランダム化を指定します。 aslrオプションは、このオプションのみを使用する場合、すべてのランダム化属性を有効にする。
aslr オプションの後にコロンを付けると、個別の属性を有効にできます。 プラス記号（＋）はランダム化を有効にし、マイナス記号（-）はランダム化を無効にする。 属性 t、d、s、m、および p を使用すると、テキスト、データ、スタック、マップ、および専用ライブラリーを指定できます。 ここにリストされていない属性であれば、ランダム化設定は無効になったままです。
注: m および p 属性は、32 ビット・プログラムには指定できません。
再配置可能アドレスがテキスト・セクションにマッピングされるよう、一部のプログラムはコンパイルおよびリンクされています。 このオプションでは、プログラム実行時にアドレスを再配置する必要がある。 ランダム化がテキストまたはデータに対して有効になっていると、これらのプログラムは失敗します。 その結果、テキストセクションの再配置が存在する場合、'aslrオプションの使用時にt属性とd属性が明示的に指定されない限り、テキストとデータのランダム化は有効にならない。
noaslr
プログラムのランダム化属性設定をクリアします。
datapsize:psize
データのページサイズをバイト単位でpsize要求する。 この値は、10 進数、16 進数、または 8 進数で指定できます。 数値の指定はC言語と同じである。 また、ページサイズは数字の後に1文字のサフィックスを付けて指定することもできる：
  • k または K はキロまたは 0x400 バイト
  • m または M はメガまたは 0x100000 バイト
  • g または G はギガまたは 0x40000000 バイト
  • t または T はテラまたは 0x10000000000 バイト
  • p または P はペタまたは 0x4000000000000 バイト
  • x または X はエクサまたは 0x1000000000000000 バイト
例えば、「-b datapsize:16kまたは「-b datapsize:0x4000どちらかがデータとして0x4000を要求し、「XCOFFヘッダーに「F_VARPGビットをセットする。 これは、補助ヘッダーの対応するメンバを、与えられた値psizeの底2の対数に設定することで実現される。 値が0と異なる場合、'XCOFFヘッダーの'f_flagsメンバの'F_VARPGビットも設定される。 それ以外の場合、このビットは消去されます。
forkpolicy:ポリシー
Fileが64ビットプログラムである場合、XCOFF補助ヘッダーの_AOUT_FORK_POLICYフラグを設定する。 policyが corの場合、_AOUT_FORK_COWも設定され、コピーオンライトフォークツリーポリシーの使用を要求する。 ポリシーが カウの場合、_AOUT_FORK_COWフラグがクリアされ、コピーオンリファレンスフォークツリーポリシーの使用が要求される。 Fileが32ビットプログラムの場合、変更はない。
noforkpolicy
ファイルが64ビットプログラムの場合、XCOFF補助ヘッダーの_AOUT_FORK_POLICYと_AOUT_FORK_CORフラグをリセットする。 fork ツリー・ポリシーが VMM_CNTRL 環境変数と一緒に指定されていない限り、デフォルトの fork ツリー・ポリシーが使用されます。 Fileが32ビットプログラムの場合、変更はない。
llu
実行可能ファイルをライブラリ更新機能（LLU）対応としてマークします。
ノルル
実行可能ファイルをライブラリ更新機能（LLU）に対応していないものとしてマークします。
lpdata
ファイルをラージページデータ実行可能ファイルとしてマークする。
nolpdata
ラージページデータ実行可能ファイルとしてのマークを解除する。
noshrsymtab
XCOFF 補助ヘッダー内で _AOUT_SHR_SYMTAB フラグをクリアします。 Fileが32ビット・オブジェクトの場合、変更はない。
M:<モッドタイプ
ファイルにあるモジュール・タイプ・フィールドおよび共有オブジェクト・フラグを更新します。 F_SHROBJフラグは、モジュール・タイプがS文字で始まり、長さが3文字のときにXCOFFヘッダーにセットされる。
maxdata:値
MAXDATA の値を設定します。 value は、 0 で開始する場合は 8 進数、0x で開始する場合は 16 進数、 それ以外はすべて 10 進数です。
maxdata:値/dsa
MAXDATA 値および DSA ビットを設定します。 value は、 0 で開始する場合は 8 進数、0x で開始する場合は 16 進数、 それ以外はすべて 10 進数です。
 
maxstack:値
MAXSTACK の値を設定します。 value は、 0 で開始する場合は 8 進数、0x で開始する場合は 16 進数、 それ以外はすべて 10 進数です。
norwexec
ファイルの書き込み可能セクションおよびマップ可能セクションにマークを付け、 実行不可ファイルとしてスタックします。
shmpsize:psize
共有メモリのpsizeページサイズをバイト単位で要求する。 指定する値は2のべき乗でなければならない。 そうでない場合、その値は最も近い2の累乗に切り捨てられる。 この値は、10 進数、16 進数、または 8 進数で指定できます。 また、ページサイズは数字の後に1文字のサフィックスを付けて指定することもできる：
  • k または K はキロまたは 0x400 バイト
  • m または M はメガまたは 0x100000 バイト
  • g または G はギガまたは 0x40000000 バイト
  • t または T はテラまたは 0x10000000000 バイト
  • p または P はペタまたは 0x4000000000000 バイト
  • x または X はエクサまたは 0x1000000000000000 バイト
例えば、'-b shmpsize:64kまたは'-b shmpsize:0x10000は、共有メモリーに64KBのページサイズを要求する。 指定された値が0でない場合、'XCOFFヘッダーのf_flagsメンバのF_VARPGビットが設定される。 0が指定された場合、F_VARPGはクリアされる。 このプログラムでは、共有メモリーにデフォルトのページ・サイズを使用する。 ファイルが32ビット・オブジェクトの場合、変更は行われない。
shrsymtab
XCOFF ヘッダー内で _AOUT_SHR_SYMTAB フラグをセットします。 ファイルが64ビット・プログラムの場合、プログラム実行時に共有シンボル・テーブルが作成される。 Flagが64ビット・オブジェクトで64ビット・プログラムでない場合、_AOUT_SHR_SYMTABフラグを設定することができるが、実行時には何の効果もない。 Fileが32ビット・オブジェクトの場合、変更はない。

プロセスのメインスレッドスタックのページサイズをバイト単位で要求する。 この値は、10 進数、16 進数、または 8 進数で指定できます。 数値の指定はC言語と同じである。 また、ページサイズは数字の後に1文字のサフィックスを付けて指定することもできる：

textpsize:psize
テキストのページサイズをバイト単位でpsize要求する。 この値は、10 進数、16 進数、または 8 進数で指定できます。 数値の指定はC言語と同じである。 また、ページサイズは数字の後に1文字のサフィックスを付けて指定することもできる：
  • k または K はキロまたは 0x400 バイト
  • m または M はメガまたは 0x100000 バイト
  • g または G はギガまたは 0x40000000 バイト
  • t または T はテラまたは 0x10000000000 バイト

例えば、「-b textpsize:16kまたは「-b textpsize:0x4000」は、0x4000のテキストを要求し、「XCOFFヘッダーに「F_VARPGビットをセットする。 これは、補助ヘッダーの対応するメンバを、与えられた値psizeの底2の対数に設定することで実現される。 値が0と異なる場合、'XCOFFヘッダーの'f_flagsメンバの'F_VARPGビットも設定される。 それ以外の場合、このビットは消去されます。
-V ldedit コマンドのバージョンを、標準エラー出力に印刷します。

例

  1. システムが選択したテキスト、データ、およびスタックのページ・サイズを要求するには、下記のコマンドを入力します。
    ldedit -b textpsize:0 -b datapsize:0 -b stackpsize:0
    これは「XCOFFヘッダーの「F_VARPGビットをクリアする。
  2. すべてのランダム化属性を有効にするには、次のように入力します。
    -baslr

    テキスト・セクションの再配置が存在する場合は、テキストおよびデータのランダム化を有効にしないでください。

  3. テキストのランダム化を有効にし、スタックのランダム化を無効にし、その他の値を変更しないままにしておくには、次のように入力します。
    -baslr:+t-s
