目的
Resource Monitoring and Control (RMC) サブシステムに定義されているセンサーまたはマイクロセンサーをリフレッシュします。

説明
refsensor
コマンドは、RMC サブシステムに定義されているセンサー・リソースまたはマイクロセンサー・リソースをリフレッシュします。
センサー
および
マイクロセンサー
は、モニターが可能な属性を含む RMC リソースです。
refsensor
を正常に実行するには、センサーとマイクロセンサーをモニターする必要があります。
センサー・リソースに対して定義されているセンサー・コマンドを実行するか、特定のセンサー属性の値を指定するかのいずれかの方法で、
refsensor
を使用してセンサーをリフレッシュできます。 マイクロセンサーは、
refsensor
を使用してマイクロセンサーのロード・モジュールの値を照会することでリフレッシュできます。 マイクロセンサーをリフレッシュするには、
-m
フラグを使用します。
refsensor
コマンドの実行時に、センサー・コマンドの実行またはマイクロセンサー・ロード・モジュールの照会のために (
mksensor
を使用して) 定義された間隔があっても、その間隔には影響しません。 つまり、モニター対象のセンサーまたはマイクロセンサーが 60 秒ごとに更新される場合、
refsensor
を実行しても、インターバル・タイマーが 60 秒にリセットされることはありません。
refsensor
コマンドは、任意のノードで実行されます。 ドメイン内のすべてのノードで
refsensor
を実行する場合は、
-a
フラグを使用します。 ドメイン内のノードのサブセットで
refsensor
を実行する場合は、
-n
フラグを使用します。
-n
フラグを使用して複数のノード名を指定する代わりに、
-N
node_file
フラグを使用して、ノード名がファイル内にあることを示すことができます。 標準入力からノード名を読み取るには、
-N
"–"
を使用します。
システムにクラスター・システム・マネージメント (CSM) がインストールされている場合は、CSM 定義のノード・グループをノード名の値として使用して、複数のノードを参照できます。 CSM ノード・グループの処理および CSM
nodegrp
コマンドの使用については、「
CSM: Administration Guide
」および「
CSM: Command and Technical Reference
」を参照してください。
refsensor
に特定のセンサー属性を更新させるには、1 つ以上の
attr
=
value

パラメーターを指定します。 更新されるのは指定された属性だけです。 それ以外のセンサー属性は更新されません。 パラメーターとして指定できるセンサー属性は、次のとおりです。
Float32
このセンサー・リソースの
float32
タイプの属性。
Float64
このセンサー・リソースの
float64
タイプの属性。
Int32
このセンサー・リソースの
int32
タイプの属性。
Int64
このセンサー・リソースの
int64
タイプの属性。
Quantum
このセンサー・リソースの
quantum
タイプの属性。
ストリング
このセンサー・リソースの
string
タイプの属性。
Uint32
このセンサー・リソースの
uint32
タイプの属性。
Uint64
このセンサー・リソースの
uint64
タイプの属性。
例えば、
Sensor1
という名前のセンサーの
Int32
および
Float32
センサー属性を更新するには、次のように入力します。
refsensor Sensor1 Int32=45 Float32=7.8
マイクロセンサー属性は単独で更新することはできません。

構文
センサーをリフレッシュするには、次のように実行します。 refsensor [ –a | –n host1 [ , host2 ...] | –N { node_file | "–" }] [ –h ] [ –v | –V ] sensor_name マイクロセンサーをリフレッシュするには、次のように実行します。 refsensor –m [ –a | –n host1 [ , host2 ...] | –N { node_file | "–" }] [ –h ] [ –v | –V ] sensor_name

オプション
フラグ
–a
ドメイン内のすべてのノード上の、指定された名前と一致するセンサーをリフレッシュします。 クラスターの有効範囲は、CT_MANAGEMENT_SCOPE 環境変数によって決まります。 CT_MANAGEMENT_SCOPE が設定されていない場合、コマンドにとって有効な有効範囲になるまで、最初に管理ドメイン有効範囲 (存在する場合) を選択し、次にピア・ドメイン有効範囲 (存在する場合) を選択し、次にローカル有効範囲を選択します。 コマンドは、最初に見つかった有効な有効範囲に対して、1 回実行されます。 例えば、管理ドメインとピア・ドメインの両方が存在する場合、CT_MANAGEMENT_SCOPE が設定されていない
refsensor -a
は管理ドメインで実行されます。 この場合、ピア・ドメインで実行するには CT_MANAGEMENT_SCOPE を 2 に設定します。
–m
リフレッシュするリソースがマイクロセンサー・リソースであると指定します。
-n
host1
[,
host2
...]
センサーをリフレッシュする 1 つ以上のノードを指定します。 デフォルトでは、ローカル・ノード上のセンサーがリフレッシュされます。 このフラグは、管理ドメインまたはピア・ドメインでのみ使用します。
-N
{
node_file
|
"-"
}
ファイルまたは標準入力からノード名を読み取ることを指定します。
ノード名がファイル内にあることを示すには、
-N
node_file
を使用します。
node_file
では 1 行に 1 つのノード名を指定します。
1 桁目の番号記号 (
#
) は、その行がコメントであることを示します。
ノード名の前のブランク文字はすべて無視されます。
ノード名の後の文字はすべて無視されます。
標準入力からノード名を読み取るには、管理ドメインまたはピア・ドメインで
-N "–"
を使用します。
–h
コマンドの使用ステートメント (使用法) を標準出力に書き込みます。
–v | –V
コマンドの詳細メッセージを標準出力に書き込みます。

例
定義されたセンサー・コマンドが実行されるように
Sensor1
というセンサーをリフレッシュするには、次のように入力します。
refsensor Sensor1
Sensor1
というセンサーをリフレッシュして、
Int32
が
50
に設定され、
Float32
が
123.45
に設定され、
String
が
"test input"
に設定されるようにするには、次のように入力します。
refsensor Sensor1 Int32=50 Float32=123.45 String="test input"
/u/joe/common_nodes
ファイルにリストされているノード上の
Sensor1
というセンサーをリフレッシュして、
Sensor1
の定義済みセンサー・コマンドを実行するには、次のように入力します。
refsensor -N /u/joe/common_nodes Sensor1
ここで、
/u/joe/common_nodes
には、以下の
# common node file
#
node1.myhost.com main node
node2.myhost.com backup node
定義済みのマイクロセンサー・ロード・モジュールを使用して属性値が照会されるように、
IBM.Sensor1
というマイクロセンサーをリフレッシュするには、次のように入力します。
refsensor -m IBM.Sensor1
