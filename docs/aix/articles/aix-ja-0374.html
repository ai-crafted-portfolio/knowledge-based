目的
ドメイン・ネーム・システム・セキュリティー拡張 (DNSSEC) ゾーン署名ツール。

説明
dnssec-signzone
コマンドは、ゾーンに署名します。 次セキュアレコード(NSEC)とリソースレコード署名(RRSIG)レコードを生成し、 署名されたバージョンのゾーンを生成する。 各子ゾーンの鍵セットファイルの有無は、署名付きゾーンからの委任の セキュリティステータスを決定する。

フラグ
項目 | 説明
-3 ソルト | 指定された 16 進エンコード・ソルトを使用して NSEC3 チェーンを生成します。 ダッシュ（-）は、NSEC3チェーンの生成に塩を使用してはならないことを示す。 注： 「 -3 オプションは、引数なしで使用することを推奨する。 塩を加え ても実用的なメリットはない。
-A | NSEC3チェーンを生成するために、BIND 9はすべてのNSEC3レコードに' OPTOUT フラグを 設定しなければならず、安全でない委任に対してNSEC3レコードを生成しては ならないことを示す。 注： このオプションは、その意味を完全に理解してから使うことができる。 このオプションは、安全な委任がまばらな大規模ゾーン(「 com. 匹敵する)のみを対象としている。 このオプションを2回使う（ -AA ）と、すべてのレコードの' OPTOUT フラグがオフになる。 このオプションは、' -u オプションを使用して、' OPTOUT フラグが設定されているNSEC3チェーンを修正するときに便利である。

-C | ゾーンの署名時に「 dsset-zonename ファイルに加えて「 keyset-zonename ファイルを生成する 互換モードを設定する。 これらのファイルは、旧バージョンの' dnssec-signzone コマンドで使用される。
-c class | ゾーンのドメインネームシステム（DNS）クラスを指定する。
-D | RRSIG、NSEC、NSEC3、NSEC3PARAMレコードなど、' dnssec-signzone コマンドによって自動的に管理されるレコードタイプのみを出力に含めなければならないことを示す。 スマート署名( -S フラグ)を使用する場合、DNSKEYレコードも含まれる。 結果のファイルは、 $INCLUDE を使用して元のゾーン・ファイルに組み込むことができます。 このオプションは、' -O raw またはシリアル番号の更新操作と組み合わせることはできない。
-d ディレクトリー | BIND 9 が ' dsset- または ' keyset- ファイルを探すディレクトリを示す。

-E エンジン | 署名に使用する安全なキーストアなど、暗号処理に使用するハードウェアを指定する。 BIND 9 がOpenSSL,とともにビルドされる場合、このフラグには暗号アクセラレータまたはハードウェア・サービス・モジュールを駆動するOpenSSLエンジン識別子を設定する必要があります（通常はpkcs11）。
-e 終了時刻 | 生成された RRSIG レコードが期限切れとなる日付および時刻を指定します。 start-time 引数と同様、絶対時刻は YYYYMMDDHHMMSS 表記で示されます。 開始時刻 (start time) に対する相対時刻は、 +N (開始時刻から N 秒) で示されます。 現在時刻に対する相対時刻は、 now+N で示されます。 end-time 引数を指定しない場合、コマンドは開始時刻から 30 日をデフォルトとして使用します。
-f 出力ファイル | 署名されたゾーンを含む出力ファイルの名前を指定します。 デフォルトでは、 .signed が入力ファイルの名前に追加されます。 output-file が' - に設定されている場合、符号付きゾーンは標準出力に書き出され、 デフォルトの出力形式は' full である。
-g | dsset- または ' keyset- ファイルから子ゾーンの DS レコードを生成します。 このフラグにより、既存の DS レコードが除去されます。
-h | dnssec-signzone コマンドのオプションと引数の簡単な要約を表示する。
-H 反復 | NSEC3チェーンを生成するために、BIND 9は指定された反復回数を使用しなければならないことを示す。 デフォルト値は 10 です。 注： 0 より大きい値は相互運用性の問題を引き起こし、またCPUを使い果たすDoS攻撃のリスクを高める。
-I 入力形式 | 入力ゾーン・ファイルのフォーマットを指定します。 使用可能なフォーマットは「 text （デフォルト）と「 raw 。 このオプションは動的署名付きゾーンに使用され、ダンプされた非テキスト 形式の更新付きゾーンファイルが直接署名されるようにする。 このオプションは、非ダイナミック・ゾーンでは役に立たない。

-i 間隔 | 署名済みゾーンが入力として渡された場合、レコードが放棄される可能性が あることを示す。 interval オプションは、サイクル間隔を現在時刻からのオフセットとして秒単位で指定する。 RRSIGレコードがサイクル間隔後に期限切れになった場合、RRSIGレコードは保持される。 そうでなければ、RRSIGレコードは間もなく期限切れになるとみなされ、置き換えられる。 デフォルトのサイクル間隔は、 署名の終了と開始時刻間の差の 4 分の 1 です。 end-time 引数または start-time 引数を指定した場合、「 dnssec-signzone コマンドは、7.5日のサイクル間隔で30日間有効な署名を生成する。 したがって、7.5日未満で期限切れとなる既存のRRSIG記録はすべて置き換えられる。
-j ジッター | 修正された署名ライフタイムのあるゾーンに署名する場合は、署名時に発行されたすべての RRSIG レコードが同時に期限切れになります。 例えば、ゾーンが増分して署名される場合は、前に署名されたゾーンが入力として署名者に渡され、期限切れのすべての署名がほぼ同時に再生成されなければなりません。 jitter 引数は、シグネチャの有効期限をランダム化するために使用される ジッターウィンドウ を指定する。 署名有効期間のジッターは、キャッシュの有効期限を分散させることによって、 バリデータとサーバに利益をもたらす。 たとえば、大量のRRSIGレコードがすべてのキャッシュから同時に失効しない場合、すべてのバリデータが同時にリフェッチしなければならない場合に比べて、輻輳は軽減される。
-K ディレクトリー | DNSSECキーを検索するディレクトリを指定する。 指定しない場合は、デフォルトで現行ディレクトリーになります。
-k キー | 指定された鍵を、鍵フラグを無視して鍵署名鍵として扱う。 このオプションは、複数回指定できます。
-L シリアル | 符号付きゾーンを' raw フォーマットまたは' map フォーマットに書き込む 際、このオプションはヘッダーの' source serial 値を指定された シリアル 番号に設定 する。 このフラグは主にテスト目的で使用される。

-M 最大値 | 署名付きゾーンの最大TTL(time-to-live)を設定する。 入力ゾーンで maxttl より高い TTL は、出力では maxttl に削減されます。 これにより、署名されたゾーンで可能な最大の TTL に対する確実性が得られます。これは、ローリング・キーの場合に役立ちます。 maxttl は、リゾルバによって検索されるシグネチャがリゾルバの キャッシュから失効するまでの可能な限り長い時間である。 このオプションで署名されるゾーンは、「 named.conf ファイルで一致する「 max-zone-ttl 使用するように設定されなければならない。 注意: このオプションは、出力ゾーンの非DNSSECデータを変更するため、 「 -D フラグとは互換性がない。
-N soa-シリアル-フォーマット | 署名済みゾーンのSOA(State of Authority)シリアル番号形式を指定する。 soa-serial-format 引数は以下のいずれかの値を取る： keep SOA製造番号を変更しません。 これがデフォルト値です。 increment RFC 1982 の演算を使用して SOA シリアル番号を増加させます。 unixtime SOAのシリアル番号に、Unixエポックの開始からの秒数を設定します。ただし、シリアル番号がすでにその値以上である場合を除き、その場合は1増やされます。 日付 シリアル番号がその値以上である場合を除き、SOAシリアル番号を' YYYYMMDDNN 形式で現在の日付に設定する。
-n ncpus | 使用するスレッドの数を指定します。 デフォルトでは、このコマンドは検出されたCPUごとに1つのスレッドを起動する。
-O 出力形式 | 署名されたゾーンを含む出力ファイルのフォーマットを指定します。 以下の値が可能なフォーマットである： text (デフォルト)は、ゾーンの標準的なテキスト表現である。 full 、これは外部スクリプトで処理するのに適した形式のテキスト出力である。 raw と' raw=N は、' named コマンドによる迅速なロードのために、ゾーンをバイナリ形式で 格納する。 raw=N オプションは、生ゾーンファイルのフォーマットバージョンを指定する。 N が 0 の場合、どのバージョンの' named コマンドでも生ファイルが読み込まれる。 N が 1 の場合、ファイルはリリース9.9.0以降で読み込まれる。 デフォルト値は 1 である。

-o 起点 | ゾーンの起点を指定します。 指定されない場合、ゾーン・ファイルの名前が 起点であると想定されます。
-P | 署名後の検証テストを無効にします。 署名後の検証テストは、各アルゴリズムについて、少なくとも1つの破棄されていない自己 署名鍵（KSK）が存在することを保証する。 また、破棄されたKSK鍵がすべて自己署名され、ゾーン内のレコードが アルゴリズムによって署名されていることを保証する。 このオプションは、これらのテストをスキップします。
-Q | アクティブでなくなった鍵から署名を削除します。 以前に署名されたゾーンが入力として署名者に渡され、DNSKEYレコードが削除されて 新しいレコードに置き換えられる場合、有効期間内の古い鍵の署名は保持される。 これにより、ゾーンは古いDNSKEY RRセットのキャッシュされたコピーを使用して 検証し続けることができる。 -Q オプションは、「 dnssec-signzone コマンドに、アクティブでなくなったキーの 署名を削除させる。 これにより、 RFC 4641#44.2.1.1 (発行前鍵のロールオーバー)に記述されている 手順を使用して、ゾーン署名鍵(ZSK)のロールオーバーが可能となる。
-q | 抑止モードを有効にします。これにより、不要な出力が抑止されます。 このオプションがない場合、「 dnssec-signzone コマンドを実行すると、以下の3つの情報が標準出力に出力される： 使用中のキーの数。 ゾーンが正しく署名されているかどうかを検証するために使用される アルゴリズムと、その他のステータス情報。 署名済みゾーンを含むファイル名。 このオプションを使用すると、出力は抑制され、ファイル名のみが保持される。
-R | 公開されなくなった鍵から署名を削除します。 このオプションは -Q と似ていますが、公開されなくなった鍵から署名を削除するよう dnssec-signzone コマンドに強制する点が異なります。 これは、 RFC 4641#44.2.1.2 （二重署名ゾーン署名鍵のロールオーバー）に記載されている 手順を使用することで、ZSKのロールオーバーを可能にする。

-S | スマート署名を有効にする。 dnssec-signzone コマンドは、署名するゾーンにマッチする鍵を鍵リポジトリから検索し、 適切であればゾーンに含めるように指示する。 キーが見つかると、そのタイミングのメタデータが調べられ、以下のルールに従って、どのように使用しなければならないかが決定される： 鍵にタイミングメタデータが設定されていない場合、その鍵はゾーンで公開され、 ゾーンの署名に使用される。 鍵の公開日が設定され、それが過去の場合、鍵はゾーンで公開される。 鍵の有効化日が設定され、かつ過去である場合、鍵は(公開日に関係なく)公開され、 ゾーンの署名に使用される。 鍵の失効日が設定され、それが過去のものであり、かつ鍵が公開されている場合、 鍵は失効し、ゾーンの署名に使用される。 鍵の公開解除日または削除日が設定され、かつ過去である場合、他のメタデータに関係なく、 その鍵は公開されず、ゾーン署名にも使用されない。 キーの同期公開日が設定され、過去である場合、同期レコード（タイプCDSまたはCDNSKEY、あるいはその両方）が作成される。 キーの同期削除日が設定され、過去である場合、同期レコード（タイプCDSまたはCDNSKEY、あるいはその両方）は削除される。 連続する各ルールは、それ以前のルールよりも優先される。
-s 開始時刻 | 生成された RRSIG レコードが有効になる日付および時刻を指定します。 絶対時間か相対時間か。 絶対的な開始時間は「 YYYYMMDDHHMMSS 表記の数字で示される。 例えば、20000530144500は2000年5月30日の14:45:00 UTCを表す。 相対開始時刻は +N (現在時刻から N 秒) で示されます。 start-time 引数を指定しない場合、' dnssec-signzone コマンドは現在時刻から1時間を引いた時刻を使用する（クロックスキューを考慮するため）。

-T トル | キー・リポジトリーからゾーンにインポートされる新しい DNSKEY レコードに使用する TTL を指定します。 ttl が指定されない場合、デフォルトでゾーンのSOAレコードのTTL値が使用される。 このオプションは、以下のシナリオでは無視される： -S オプションなしで署名した場合、DNSKEYレコードは鍵リポジトリからインポートされないためです。 ゾーン頂点に既存のDNSKEYレコードが存在する場合、新しいレコードのTTL値は それらに一致するように設定される。 インポートされたDNSKEYレコードにデフォルトのTTL値があった場合。 インポートされたキーのTTL値が競合する場合、最も短い値が使用される。
-t | 完了時に統計情報を印刷します。
-u | 以前に署名したゾーンが再署名された場合、NSECまたはNSEC3チェインを更新する。 このオプションを使用すると、NSECで署名されたゾーンをNSEC33に切り替えたり、NSEC33で署名されたゾーンをNSECに切り替えたり、異なるパラメータを持つNSEC33に切り替えたりすることができる。 このオプションがない場合、「 dnssec-signzone コマンドは再署名時に既存のチェーンを保持する。
-V | バージョン情報を表示する。
-v レベル | デバッグのレベルを設定します。
-X 拡張終了時刻 | DNSKEY RRセットの生成されたRRSIGレコードの有効期限が切れる日時を指定する。 これは, DNSKEY シグニチャーが他のレコードのシグニチャーより長く持続する必要がある場合に使用されます。 例えば、KSK のプライベート・コンポーネントがオフラインのままで、KSK 署名を手動でリフレッシュする必要がある場合などです。 終了時刻 と同様に、絶対時刻は「 YYYYMMDDHHMMSS 表記で示される。 開始時刻 (start time) に対する相対時刻は、 +N (開始時刻から N 秒) で示されます。 現在時刻に対する相対時刻は、 now+N で示されます。 拡張終了時間 が指定されていない場合、デフォルトで 終了 時間の値が使用される。 終了時間 のデフォルトは、開始時間から30日間である。 延長された終了時刻 は、 開始時刻 より後でなければならない。
-x | BIND 9のみがDNSKEY、CDNSKEY、CDS RRセットに鍵署名し、ゾーン署名鍵からの 署名を省略しなければならないことを示す。

-z | BIND 9が、署名の対象を決定する際に、鍵のKSKフラグを無視しなければならないことを示す。 これにより、KSKフラグ付き鍵はDNSKEY RRセットだけでなく、全てのレコードに 署名するようになる。
