目的
ソフトウェア・パッケージまたはセットをシステムに転送します。

説明
pkgadd
は、ソフトウェア・パッケージまたはセットの内容を、
システムにインストールするために配布メディアまたはディレクトリーから転送します。 パッケージは、個別にインストールできる、関連するファイルおよび実行可能ファイルの集合です。 セットはセット・インストール・パッケージ (SIP) と呼ばれる特殊目的のパッケージと、
そのセットのメンバーである 1 つまたは複数のパッケージのコレクションからなります。 SIP はセットのインストールを制御します。
pkgadd
は、コマンド・ラインにリストされたすべてのパッケージが
インストール・メディアに含まれているかどうかを検査します。 リストされているパッケージのいずれかが存在しない場合、システムに対する変更は行われません。つまり、リストされているパッケージはいずれもインストールされません。
注:
非 root ユーザーが
pkgadd
コマンドを正常に実行するには、以下の条件を満たす必要があります。
ユーザーには、
pkgmap
ファイルで指定されたパスに対する書き込み権限が必要です。
現在の
user: group
は、
pkgmap
ファイルに指定されている
user: group
と一致する必要があります。
ユーザーには、
/var/sadm/install
ディレクトリーおよび
/var/sadm/pkg
ディレクトリーに対する書き込み権限が必要です。
-d
フラグを指定せずに使用すると、
pkgadd
はデフォルトのスプール・ディレクトリーでパッケージ (
/var/spool/pkg
) を探します。
-s
フラグとともに使用すると、パッケージはインストールされずにスプール・ディレクトリーに書き込まれます。
エラー・メッセージはすべてログに記録されます。 さらに、
pkgadd
が終了すると、すべてのエラー・メッセージと、どのパッケージが完全にインストールされているか、部分的にインストールされているか、またはまったくインストールされていないかの要約が記載されたメールが (デフォルトでは
root
に) 送信されます。

構文
ソフトウェア・パッケージをインストールするには pkgadd [ -d Device] [ -r Response] [ -n ] [ -a Admin] [ -P Path ] [ Pkginst1 [ Pkginst2 [. . .]]] ソフトウェア・パッケージを指定のスプール・ディレクトリーにコピーするには、以下のようにします。 pkgadd -s Spool [ -d Device] [ Pkginst1 [ Pkginst2 [. . .]]]

オプション
フラグ
表 1. フラグ
項目 | 説明
-d Device | Device からパッケージまたはセットをインストールまたはコピーします。 Device には、ディレクトリー、ファイル、または名前付きパイプへの絶対パス名、または標準入力から読み取られるデータ・ストリーム形式のパッケージを指定する - を指定できます。 デフォルト・デバイスはインストール先のスプール・ディレクトリー ( /var/spool/pkg ) です。
-r 応答 | ファイルまたはディレクトリー Response を識別します。このファイルまたはディレクトリーには、対話モードで実行された前の pkgask セッション中に request script によって提示された質問に対する回答が含まれています ( pkgask コマンドを参照)。 Pkginst がパッケージである場合、 Response には 絶対パス名またはディレクトリーを指定することができ、 Pkginst が SIP である場合、 Response にはディレクトリーを指定しなければなりません。
-n | インストールが非対話式モードで行われることを指定します。 デフォルト・モードは対話式です。
-a 管理者 | デフォルトの管理ファイルの代わりに使用されるインストール管理ファイル Admin を定義して、インストール・チェック (スペース量のチェック、システム状態のチェックなど) を実行するかどうかを指定します。 トークン none は、すべての admin ファイルの使用をオーバーライドするため、ユーザーとの対話を強制します。 絶対パス名を指定しない限り、 pkgadd は /var/sadm/install/admin ディレクトリー からファイルを探します。 デフォルトでは、そのディレクトリー内のファイル default が使用されます。 default は、パッケージをインストールするための十分なスペースがあるかどうか、および他のパッケージに対する依存関係があるかどうかを確認する以外は、検査を行わないことを指定します。 Pkginst が SIP の場合、 -a フラグは使用できません。
-P パス | インストールのための代替ルート・ディレクトリー・パスを指定します。 ファイルはこの場所にインストールされます。

プッギンスト | パッケージまたはセット名の省略形を指定するために使用される短ストリングを定義します。 ( package instance という用語は、疎に使用されます。これは、 Pkginst のすべてのインスタンス化を指します。) pkginfo コマンドおよび pkginfo ファイル・フォーマットを参照してください。 Pkginst が SIP の場合、SIP は、要求スクリプトとプリインストール・スクリプトを使用してセットのインストールを制御します。 ユーザーに応答の入力をプロンプト指示したり適切なアクションを行ったりするのは、 パッケージ・インストール・ツールではなく、SIP 要求スクリプトです。 要求スクリプトが失敗した場合、SIP だけが処理されます。 パッケージのすべてのインスタンスを示すには、「 Pkginst .*' 」を指定し、示されているようにコマンド行を単一引用符で囲み、シェルが * 文字を解釈しないようにします。 ソース・メディアで使用可能なすべてのパッケージを参照するには、"all" というトークン を使用してください。
-s スプール | パッケージをインストールする代わりに、ディレクトリー Spool に読み込みます。
特記事項
-r
フラグを使用して、ディレクトリー名とファイル名を示すことができます。 このディレクトリーには、多数の
Response
ファイルを含めることができます。各ファイルは、関連付ける必要があるパッケージの名前を共有します。 これは、例えば、
pkgadd
の 1 回の呼び出しで複数の対話式パッケージを追加する場合に使用できます。 要求スクリプトを持つ各パッケージには、
Response
ファイルが必要です。 パッケージと同じ名前の応答ファイル (例えば、
Package1
や
Package2
) を
作成した場合、
-r
フラグの後に、
それらのファイルが入っているディレクトリーの名前を指定してください。
-n
フラグを使用すると、インストールを完了させるためになんらかの対話が必要な場合には、
インストールは一時停止します。
コマンド行に
Pkginst
を指定せずに呼び出すと、メディア上に少なくとも 1 つの SIP が存在する場合、
pkgadd
はセットの名前を表示します。 このため、一部がセットのメンバーで、一部がセットのメンバーでない場合は、同じメディアにパッケージを含めないでください。 これを行うと、セットのメンバーではないパッケージをインストールできるのは、そのパッケージの

pkginst
名がコマンド行に指定されている場合のみになります。
pkgadd
コマンドは、
Pkginst
内のいずれかのファイルが既にシステムにインストールされているかどうかを検査し、既にインストールされている場合は、インストールを続行する前にその事実を保存します。 その後、
pkgadd
はそのようなファイルをシステムにインストールしません。 パッケージのインストール・スクリプトのいずれかがそのようなファイルを削除すると、パッケージのインストールが完了した時点で、そのファイルはシステム上に存在しなくなります。
pkgadd
コマンドは、
pkgmk
によって処理される前に既に圧縮されていたファイル (つまり、
.Z
形式のファイルのみ) は圧縮解除しません。
