目的
論理ボリュームおよび物理ボリュームの暗号化管理を行います。

説明
この
hdcryptmgr
コマンドは、暗号化された論理ボリュームを管理します。 IBM® AIX® 7.3 Technology Level 1 ( TL1 ) 以降では、この
hdcryptmgr
コマンドを実行して、暗号化された論理ボリュームおよび暗号化された物理ボリュームを管理できます。 暗号化された論理ボリュームまたは物理ボリュームを管理し、以下のいずれかの操作を実行するには、
action
パラメータを指定します
注：
アクションパラメータの属性の一部は、論理ボリュームまたは物理ボリュームに固有である。
アクション
パラメータの一部の属性は、論理ボリュームと物理ボリュームの両方で使用できます。
表 1. hdcryptmgr コマンド操作
カテゴリー | action パラメーター | 説明
暗号化設定の表示 | showvg | ボリュームグループのデータ暗号化ステータスを表示します。
showlv | 論理ボリュームのデータ暗号化ステータスを表示します。
showmd | 特定のボリュームの暗号化メタデータを表示します。
showconv | 暗号化論理ボリュームから復号化論理ボリュームへの、および復号化論理ボリュームから論理ボリュームへの、アクティブおよび停止中の変換操作のステータスを表示します。
showpv | 暗号化された物理ボリュームの状況を表示します。
認証方式の制御 | authinit | ボリューム内のデータ暗号化用のプライマリ・キーを初期化する。
authunlock または authunl | 暗号化ボリュームを認証し、ボリュームのプライマリキーのロックを解除する。
authadd | 認証方法を追加。
authcheck または authchk | これは、認証方式の妥当性を検査します。
authdelete または authdel | 認証方法を削除します。
authmod | パスフレーズ鍵保護方式のパスワードを変更する。
authsetrvgpwd または setrvgpwd | BOSインストール後のルート・ボリューム・グループ（rootvg）の回復パスワードを設定します。
Platform キーストア（ PKS ）のキーを管理する | pksimport | PKS のキーをインポートします。
pksexport | PKS のキーをエクスポートします。
pksclean | PKS キーを削除します。
pksshow | PKS キーの状態を表示します。

論理ボリュームの暗号化状況の変換 | plain2crypt | 論理ボリュームの暗号化を有効にし、論理ボリュームデータを暗号化する。
crypt2plain | 論理ボリュームデータを復号化し、論理ボリュームの暗号化を無効にする。
物理ボリュームの暗号化 | pvenable | 物理ボリュームの暗号化を有効にする。
pvdisable | 物理ボリュームの暗号化を無効にします。
pvsavemd | 物理ボリュームのメタデータを指定したファイルに保存します。
pvrecovmd | 物理ボリュームのメタデータを復元します。
注記:
非揮発性メモリエクスプレス (NVMe) および仮想永続メモリ ( vPMem ) ディスクは暗号化をサポートしていません。

構文
hdcryptmgr action [ -h ] [ flags ] devicename

例
シナリオ: パスフレーズ鍵保護方式を使用した暗号化論理ボリュームの作成
暗号化を有効にしてボリューム・グループを作成します。
# mkvg -k y hdisk1 hdisk2
vg00
サイズ32 MBの暗号化論理ボリュームを作成する。
# mklv -k y vg00 32M
mklv: Please run :
# hdcryptmgr authinit lvname [..] to define LV encryption options.
lv00
1 次鍵とパスフレーズ鍵保護方式を使用して、論理ボリューム上の暗号化構成を初期化します。
# hdcryptmgr authinit -n default lv00
Enter Passphrase:
Confirm Passphrase:
Password authentication method added successfully
シナリオ暗号化された論理ボリュームにファイルシステムを作成する
暗号化が有効になっているボリュームグループを作成し、サイズが32 MBの論理ボリュームを作成し、その論理ボリュームの暗号化設定を初期化する。
# mkvg -k y hdisk1 hdisk2
vg00
# mklv -t jfs2 -k y vg00 32M
mklv: Please run :
# hdcryptmgr authinit lvname [..] to define LV encryption options.
fslv00
# hdcryptmgr authinit -n default fslv00
Enter Passphrase:
Confirm Passphrase:
Password authentication method added successfully
通常の論理ボリュームでの作成と同様に、暗号化論理ボリュームでファイルシステムを作成します。
# crfs -v jfs2 -d fslv00 -m /mnt/myfs -A no
File system created successfully.
32560 kilobytes total disk space.
New File System size is 65536
シナリオ: 暗号化が有効になっている論理ボリュームに対する認証

ボリュームグループをオフにするか、システムを再起動すると、暗号化された論理ボリュームに対する認証は失効します。 暗号化された論理ボリュームを認証し、そのデータにアクセスする。 暗号化された論理ボリュームに設定されたキー保護方法を使用する。 暗号化が有効な論理ボリュームを認証するには、以下の手順を実行します：
VG をオンに変更します。
# varyonvg vg00
varyonvg: 1 encrypted LV defined in VG vg00.
To check if a LV is encrypted and if it is unlocked, use:
hdcryptmgr showlv vgname or
hdcryptmgr showlv lvname
In order to unlock a LV, use:
hdcryptmgr authunlock lvname
パスフレーズ鍵保護方式を使用して認証を行います。
# hdcryptmgr authunlock -t pwd fslv00
Enter Passphrase:
Password authentication succeeded
シナリオ：オペレーティングシステムの起動に必要な、暗号化された論理ボリューム内の破損した PKS キーを修復する
オペレーティングシステムの起動に暗号化された論理ボリュームが必要な場合、その論理ボリュームには有効な PKS キーが設定されている必要があります。 そうでなければ、ブートプロセスは成功しない。 このようなシナリオでは、LPAR をメンテナンス・モードでブートする必要があります。 次の手順は、NIM サーバーを使用してメンテナンス・モードでオペレーティング・システムをブートする場合に適用できます。 この
hdisk0
ディスクには、論理ボリューム内の rootvg および PKS キーが含まれていますが、論理ボリューム
hd3
が破損しています。
次の画面で
3を
選択する：
Maintenance
Type the number of your choice and press Enter.
1 Access a Root Volume Group
2 Copy a System Dump to Removable Media
>>> 3 Access Advanced Maintenance Functions
4 Erase Disks
5 Configure Network Disks (iSCSI)

6 Select Storage Adapters
次の画面で
0を
選択する：
Information for Advanced Maintenance Functions
-------------------------------------------------------------------------------
To return to the Maintenance Menu after completing maintenance
activities, type exit on the command line and press Enter.
-------------------------------------------------------------------------------
Type the number of your choice and press Enter.
>>> 0 Enter the Limited Function Maintenance Shell
以下のコマンドを実行して、暗号化された論理ボリュームを修復します：
# LIBPATH=/SPOT/usr/lib:$LIBPATH
# importvg hdisk0
# hdcryptmgr32 authunlock hd3
# hdcryptmgr32 authdel -t pks hd3
# hdcryptmgr32 authadd -t pks -n initpks hd3
修復が必要なすべての暗号化論理ボリュームについて、ステップ
1
から
3
を繰り返します。
シナリオオペレーティングシステムの起動に必要な論理ボリュームの変換操作の失敗の復旧
通常の論理ボリュームから暗号化された論理ボリュームへの変換、または暗号化された論理ボリュームから通常の論理ボリュームへの変換が中断された場合は、先ほど実行したのと同じ
hdcryptmgr
変換コマンドを再度実行してください。 conversion コマンドは
hdcryptmgr
、変換の復旧情報を読み取り、前回の実行で中断した箇所から変換処理を再開します。 この
hdcryptmgr

変換コマンドは、論理ボリュームがブートプロセスで使用されるかどうかに関係なく実行されます。 ただし、変換処理の途中でLPARが再起動し、LPARがダーティ状態になった場合、再起動処理が失敗する可能性があります。 例えば、変換されるデータブロックが部分的に暗号化されており、変換される論理ボリュームがオペレーティングシステムの起動に必要である。 このようなシナリオでは、LPAR をメンテナンス・モードでブートし、変換操作を再開する必要があります。
次の手順では、NIM サーバーを使用してメンテナンス・モードでオペレーティング・システムをブートすることを想定しています。 この
hdisk0
ディスクには rootvg が含まれており、変換プロセスが中断されたため、 hd3 という論理ボリュームがダーティ状態になっています。
Maintenance
メニューから
3 Access Advanced Maintenance Functions
を選択する。
Advanced
Maintenance Functions
で
0 Enter the Limited Function Maintenance Shell
を選択する。
以下のコマンドを実行します。
# LIBPATH=/SPOT/usr/lib:$LIBPATH
# importvg hdisk0
# hdcryptmgr32 plain2crypt hd3
シナリオ: 暗号化された物理ボリュームの作成
暗号化された物理ボリュームを作成すると、デフォルトでは、パスフレーズ鍵保護方式が暗号化された物理ボリュームに追加されます。 以下のコマンドを使用して、物理ボリューム (
hdisk3
) の暗号化を有効にすることができます。
# hdcryptmgr pvenable -f hdisk3
Enter Passphrase:
Confirm Passphrase:
Passphrase authentication method with name "initpwd" added successfully.
-f
フラグは、
hdcryptmgr
pvenable
コマンドが確認のプロンプトを出さずに物理ボリューム内のデータを上書きできることを示します。
hdcryptmgr pvenable

コマンドが正常に実行されると、物理ボリュームの暗号化が有効になり、I/O操作のロックが解除されます。 暗号化された物理ボリュームに書き込まれるデータはすべて暗号化され、暗号化された物理ボリュームから読み取られるデータはすべて暗号化解除されます。
シナリオ: 暗号化されたボリューム・メタデータの検査と修正
hdcryptmgr pvrecovmd -c
コマンドは、暗号化された物理ボリューム上の暗号化メタデータを検証します。 物理ボリュームに暗号化メタデータのコピーが 2 つある場合、
pvrecovmd
アクション・パラメーターは、暗号化メタデータの両方のコピーを検証して比較します。
物理ボリューム (hdisk24) 上の暗号化メタデータを検証するには、次のコマンドを入力します。
# hdcryptmgr pvrecovmd -cv hdisk24
物理ボリューム (hdisk24) 上の暗号化メタデータの両方のコピーが有効な場合、以下のメッセージが表示されます。
Metadata area 1 is valid.
Metadata area 2 is valid.
IPL record is valid for an encrypted disk.
All encryption fields for disk hdisk24 are valid.
Check of metadata on PV hdisk24 is complete.
pvrecovmd action complete.
物理ボリューム（
hdisk24
）上の暗号化メタデータのいずれかのコピーが破損すると、次のメッセージが表示されます：
Metadata area 1 is valid.
Disk metadata copy #2 is corrupt.
IPL record is valid for an encrypted disk.
Check of metadata on PV hdisk24 is complete.
pvrecovmd action complete.
破損した暗号化メタデータを物理ボリューム (hdisk24) 上の正しい暗号化メタデータで上書きするには、次のコマンドを入力します。
# hdcryptmgr pvrecovmd hdisk24 -v
hdcryptmgr
pvrecovmd
コマンドは、以下のメッセージを表示し、破損した暗号化メタデータを上書きできるかどうかを確認するプロンプトを出します。
Metadata area 1 is valid.

Disk metadata copy #2 is corrupt.
IPL record is valid for an encrypted disk.
Preparing to write the following fields to the disk:
Backup metadata
Warning, about to write to disk hdisk25
Do you wish to continue? y(es) or n(o)?
破損した暗号化メタデータを上書きしたい場合は、
y
と入力する。
hdcryptmgr pvrecovmd
コマンドは、破損した暗号化メタデータを正しい暗号化メタデータで上書きし、以下のメッセージを表示します。
