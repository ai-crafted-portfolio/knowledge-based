目的

クラスター・セキュリティー・サービス・トラステッド・ホスト・リスト・ファイルの内容を表示および変更します。

構文

ctsthl {-a | -d | -h | -l | -s } [ -f trusted_host_list_file ] [ -n host_name ] [ -m method ] [ -p IDER_値 ]

説明

このコマンドは、クラスター・セキュリティー・サービス・トラステッド・ホスト・リスト・ファイルの内容を表示および変更します。 -f フラグが指定されていない場合、コマンドはトラステッド・ホスト・リスト・ファイル ctcasd.cfg ファイルで構成されているに対してその操作を実行します。 ctsthl を使用すると、コマンド・ユーザーは、特定のホストのトラステッド・ホスト・リスト内の項目を追加、変更、または除去することができます。 ホストを追加または変更する場合、このコマンドのユーザーは以下の情報を提供しなければなりません。
  • ホストの ID (例えば、zathras.ibm.com または 129.34.128.54など)
  • このホストに使用される、ID の 16 進値を表す文字ストリング・フォーマットのホスト ID 値 (例えば、b87c55e0)
  • ホスト ID の生成に使用された方式 ( ctskeygen -i コマンドの説明を参照してください)
このコマンドは、生成方式名を妥当性検査し、文字列表記をバイナリー形式に変換して、このホスト用のトラステッド・ホスト・リスト・ファイル内にエントリーを新規作成します。 通常、ホスト ID の値は非常に大きいです。 例えば、RSA 1024 ビットで生成された ID の文字表現では、そのサイズが 256 文字を超えます。 これは、AIXのようなコマンドラインの長さを小さく制限しているシステムで問題を引き起こす可能性がある。 この問題を回避するには、シェル・スクリプトから、または xargs コマンドと一緒に ctsthl -a コマンドを使用します。
トラステッド・ホスト・リスト・ファイルの内容が表示されると、 ctsthl は各項目について以下の情報を提供します。
  • ホストのネットワーク ID
  • 文字列として表現されたそのホストのホスト ID 値
  • そのホスト ID の生成に使用された方式

フラグ

-a
トラステッド・ホスト・リストにホスト・エントリーを追加するか、またはこのリストのエントリーを交換します。 -n、 -m、および -p フラグも指定する必要があります。 指定されたホストがトラステッド・ホスト・リスト・ファイル内に既に存在している場合、そのホストのエントリーは、このコマンドに提供された情報と一致するように変更されます。
-d
あるホストのエントリーをトラステッド・ホスト・リスト・ファイルから除去します。 除去するホストを示すために、 -n フラグも指定する必要があります。
-h
コマンドの使用ステートメント (使用法) を標準出力に書き込みます。
-l
トラステッド・ホスト・リスト・ファイルの内容をリストするようコマンドに指示します。 このフラグを -a または -d フラグと組み合わせると、これらのフラグが処理された後に内容が表示されます。 このフラグを -s フラグと組み合わせて使用すると、コマンドによって作成されたすべての新規エントリーと、ローカル・システムによってサポートされるホスト名および IP アドレスについて検出された公開鍵の不一致が表示されます。
-信頼できるホスト・リスト・ファイル
トラステッド・ホスト・リスト・ファイルの完全修飾パス名を指定します。 このフラグを指定しない場合は、 ctcasd.cfg ファイルで構成されたトラステッド・ホスト・リスト・ファイルが使用されます。
--n ホスト名
この操作で使用するホストの ID を指定します。 この ID は、ホスト名または IP アドレスで指定したものでなければなりません。 これにより、クラスターのネットワークはホストを認識します。
-メソッド
ホスト ID キーを作成する際には指定されたキー生成方式を使用するようコマンドに指示します。 ctskeygen -i コマンドを使用して、 methodの有効な値を表示することができます。
--p identifier_value
そのホスト用として保管されるホスト ID の値を指定します。 これは、この ID として保管されるホスト ID の 16 進値を表す文字列です。 例えば、ホスト ID の値が 0xB87C55E0の場合、このフラグは -p b87c55e0と指定されます。 一般にAIX®では、ホスト識別子キーはこの例よりもずっと長くなり、AIXのような一部のシステムでは、コマンドラインの制限には大きすぎる。 結果のコマンド行が大きすぎる場合は、 xargs を使用して拡張するか、シェル・スクリプトからコマンドを発行してください。
-s
デーモンが検出できる AF_INET 構成されたアクティブなアダプターに関連付けられた、 すべての既知の IP アドレスとホスト名をローカル・システムの中で探索します。 ローカル・システムのホスト名または IP アドレスが、ローカル・システムのトラステッド・ホスト・リスト・ファイルで検出されなければ、 1 つのエントリーがその値をローカル・システムの公開鍵値に関連付けるために追加されます。

パラメーター

ネットワーク ID (network_ID)
マップするセキュリティー・ネットワーク ID を指定します。 これは、トラステッド・サービスのクライアント・アプリケーションが想定できる ID でなければなりません。

セキュリティー

ctsthl コマンドに対する許可は、 root のみがコマンドを実行することを許可します。

終了状況

0
コマンドは正常に完了しました。
4
呼び出し元がこのコマンドを正しくない方法で起動しました。必須フラグおよびパラメーターが省略されているか、または相互に排他的なフラグが同時に使用されています。 このコマンドは要求を処理せずに終了しました。
6
このコマンドの操作中にメモリー割り当て要求が失敗しました。 このコマンドは要求されたアクションを完了できませんでした。
10
コマンドは、 -s フラグの処理中に、ローカル・システムの構成済みでアクティブなネットワーク (AF_INET) インターフェースを見つけることができませんでした。 ローカル・システムの ID はトラステッド・ホスト・リストに適切に記録されない可能性があります。 最低 1 つの AF_INET または AF_INET6 インターフェースがローカル・システムで定義されていて、 アクティブであることを検査し、コマンドを再発行してください。
12
コマンドのユーザーはトラステッド・ホスト・リスト・ファイルの内容を表示または変更するための十分なアクセス権を持っていません。
21
トラステッド・ホスト・リスト・ファイルが検出できなかったか、あるいは、新規の公開鍵値を含めるように拡張できませんでした。
30時間まで
ctsthl は、トラステッド・ホスト・リスト・ファイルの排他使用を取得できませんでした。 このコマンドの別のインスタンスが実行中でキーを変更しようとしているか、 ctcasd デーモンがこれらのファイルを調べている可能性があります。 後で、コマンドを再実行してください。
31
-p フラグによって指定された公開鍵の値が、フル・バイト境界で終了していません。 この値が偶数桁を含んでいることを確認してください。
37
キー・ファイルが破壊されているようです。 -d フラグを使用して公開鍵の値を表示し、ファイルが破損しているかどうかを確認してください。 エラー・メッセージが表示した問題解決アドバイスに従ってリカバリー・アクションをとってください。

制約事項

  • クラスター・セキュリティー・サービスがサポートするのは、独自のホスト ID フォーマットおよびトラステッド・ホスト・リスト・ファイル・フォーマットだけです。
  • トラステッド・ホスト・リストを変更できるのは、このコマンドを使用する場合だけです。
  • クラスター・セキュリティー・サービスには、クラスター全体を通じてトラステッド・ホスト・リストを作成、管理、および保守するための自動化されたユーティリティーは用意されていません。 これは、システム管理者またはクラスター管理ソフトウェアのいずれかに対する手順です。

標準出力

-h フラグを指定すると、このコマンドの使用状況ステートメントが標準出力に書き込まれます。 -l フラグを指定すると、トラステッド・ホスト・リスト・ファイルの内容が標準出力に書き込まれます。

標準エラー

あらゆる検出済み障害条件に関する記述情報が標準エラーに書き込まれます。

例

  1. ファイル /mythlに含まれているトラステッド・ホストの内容を表示するには、次のように入力します。
    ctsthl -l -f /mythl
  2. システム zathras.ibm.comのデフォルトのトラステッド・ホスト・リスト・ファイルにエントリーを追加するには、次のように入力します。
    ctsthl -a -n zathras.ibm.com -m rsa1024 -p 120400a9...
    この例では完全な ID 値の途中までしか書かれていないことに注意してください。
  3. システム 129.23.128.76のデフォルトのトラステッド・ホスト・リスト・ファイルにエントリーを追加するには、次のように入力します。
    ctsthl -a -n 129.23.128.76 -m rsa1024 -p 120400a9...
    この例では完全な ID 値の途中までしか書かれていないことに注意してください。
  4. デフォルトのトラステッド・ホスト・リストから zathras.ibm.com 用のエントリーを除去するには、次のように入力します。
    ctsthl -d -n zathras.ibm.com

場所

/opt/rsct/bin/ctsthl
ctsthl コマンドが入っています。

ファイル

/opt/rsct/cfg/ctsec_map.global
デフォルトの ID マッピング定義ファイルです。 このファイルには、RSCT クラスター・トラステッド・サービスが必要とする定義が含まれています。それらの定義は、これらのシステムがソフトウェアのインストール後すぐに適切に実行されるために必要なものです。 クラスター全体の ID マッピング定義ファイル /var/ct/cfg/ctsec_map.global がシステム上に存在する場合、このファイルは無視されます。 したがって、クラスター全体の ID マッピング定義ファイルが存在する場合、その定義ファイルにはこのファイル内の定義もすべて含まれている必要があります。
/var/ct/cfg/ctsec_map.local
クラスター全体の ID マッピング定義に対するローカル・オーバーライドです。 このファイル内の定義をクラスター内のノード間で共有することは期待されません。
/var/ct/cfg/ctsec_map.global
クラスター全体の ID マッピング定義です。 このファイルにはクラスター全体を通じて共通の ID マッピング定義が含まれていることが期待されます。 このファイルがシステムに存在する場合、デフォルトの ID マッピング定義ファイルは無視されます。 したがって、このファイルが存在する場合は、デフォルトの ID マッピング定義ファイル内でも検出される可能性のあるすべてのエントリーがこのファイルにも含まれている必要があります。
