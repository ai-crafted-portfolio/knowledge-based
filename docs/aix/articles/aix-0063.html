目的

mksysb インストール・イメージを使用して代替ディスクをインストールするか、 または現在実行中のシステムのクローンを代替ディスクに作成します。 このコマンドはAIX 5.33で廃止された。
注: AIX 5.3では、 alt_disk_install コマンドは、 alt_disk_copy、 alt_disk_mksysb、および alt_rootvg_op コマンドに置き換えられています。 alt_disk_install モジュールはこれらの新規コマンドに対するラッパーとして出荷され続けていますが、 alt_disk_install コマンドは新しい関数、フラグ、または機能のいずれもサポートしていません。

説明

注: AIX 5.3 では、 alt_disk_install コマンドは、 alt_disk_copy、 alt_disk_mksysb、および alt_rootvg_opの 3 つのコマンドに分割されています。 このコマンドに追加された新機能はありません。

alt_disk_install コマンドは、 オペレーティング・システムを次のリリース、メンテナンス・レベル、またはテクノロジー・レベルに更新するための方法を提供するもので、 これを使うとマシンが長時間にわたってダウン状態になることがありません。 これを行うには、別のディスクに mksysb イメージをインストールするか、現行システムを複製してから更新を適用して次の保守レベルまたはテクノロジー・レベルに達するようにするかの 2 つの方法があります。

重要: alt_disk_install は、 alt 接頭部を使用して、ボリューム・グループ、論理ボリューム、特殊装置ファイル、およびファイルシステムを作成します。 システムで alt_disk_install を使用する場合、管理者は、ボリューム・グループ、論理ボリューム、特殊デバイス・ファイル、または alt prefix- alt_disk_install 操作を持つファイルシステムを不注意で除去、変更、または損傷させないようにする必要があります。

最初の機能である mksysbのインストールには、 AIX 4.3 以降 mksysb のイメージ、 AIX 4.3 以降 mksysb のテープ、または AIX 4.3.3 以降 mksysb の CD が必要です。 alt_disk_install コマンドは、現在使用されていない 1 つ以上のディスクを指定して呼び出され、 mksysb は、ユーザーが選択した場合に、次のリブートで AIX 4.3 以降のシステムでシステムがブートされるように、それらのディスクに復元されます。

注:
  1. alt_disk_install を使用して、現在システムにインストールされているものより前のバージョンの AIX をインストールすることはできません。 例えば、 AIX 4.3 mksysb を AIX 5.1 システムにインストールすることはできません。
  2. 必要に応じて、新しいディスクをブートした後で bootlist コマンドを実行し、 旧バージョンのオペレーティング・システムにブート・バックするようにブート・リストを変更できます。

第 2 の、実行中の rootvg のクローンを作成する機能を使うと、root ボリューム・グループのバックアップ・コピーを作成できます。 このコピーは、rootvg が失敗した場合のバックアップとして使用されるか、追加の更新をインストールすることによって変更される可能性があります。 一例として、4.2.0 システムのクローンを作成し、次に更新をインストールして、クローンを作成した rootvg を 4.2.1.0 の状態にすることなどができます。 この方法を使えば、システムの実行中にシステムを更新でき、その後で新しい rootvg からリブートすると、実行中のシステムのレベルが 4.2.1 になります。 このレベルに問題がある場合は、ブート・リストを 4.2.0 のディスクに戻してリブートすれば、システムは 4.2.0 に戻ります。 さらに例を挙げるなら、rootvg のクローンを作成し、個々のフィックスを適用し、システムをリブートし、適用したフィックスをテストして、問題があれば、元の rootvg に戻してリブートするということもできます。

注: NIM 代替ディスクの移行 (バージョンまたはリリース・レベルのアップグレード) は、 AIX 5.1 以降の nimadm コマンドでサポートされます。 詳しくは、 nimadm の資料を参照してください。

現在、上記の 2 つの機能を実行するために、4.1.4.0 以降のシステムで alt_disk_install コマンドを実行できます。 alt_disk_install コマンドを実行するには、 bos.alt_disk_install.rte ファイル・セットがシステムにインストールされている必要があり、代替ディスクへの mksysb のインストールを実行するには、 bos.alt_disk_install.boot_images ファイル・セットもインストールされている必要があります。

使用される mksysb イメージは、事前に作成されている必要があり、インストール先のシステムに必要なすべてのデバイスおよびカーネル・サポートを備えている必要があります。 新たにインストールしたディスクからシステムをリブートする前に、新しいデバイス・サポートまたはカーネル・サポートをインストールすることはできません。

注: インストールする mksysb のバージョン・リリース保守またはテクノロジー・レベルは、 bos.alt_disk_install.boot_images ファイル・セットのレベルと一致している必要があります。

rootvg ボリューム・グループのクローン作成時に、 bosboot コマンドを使用して新規ブート・イメージが作成されます。 mksysb イメージのインストール時に、 mksysb およびプラットフォーム・タイプのレベルのブート・イメージが、新しい代替 rootvg のブート論理ボリュームにコピーされます。 システムをリブートすると、ブートの初期段階で bosboot コマンドが実行され、システムが再度リブートされます。 これは、復元された mksysb とブート・イメージを同期するためです。 その後、システムは通常モードにブートされます。

インストールの終了時に、ボリューム・グループ altinst_rootvgは、プレースホルダーとしてオフに変更された状態のターゲット・ディスク上に残されます。 これを vary on した場合、このグループは論理ボリュームを 1 つも所有していないものとして示されますが、実際には論理グループが含まれています。しかし、これらの論理グループの名前は実行中のシステム上の論理ボリュームの名前と衝突するため、ODM からは除去されています。 altinst_rootvg ボリューム・グループをオンに変更せずに、定義をプレースホルダーのままにしておくことをお勧めします。

システムが新しい代替ディスクからリブートした後、 alt_disk_install バージョンが 4.3.2 以上でない限り、以前の rootvg ボリューム・グループは lspv リストに表示されません。

alt_disk_install 4.3.2 以上の場合

新しい代替ディスクからリブートすると、以前の rootvg ボリューム・グループが lspv リストに old_rootvgとして表示され、すべてのディスクが元の rootvg に組み込まれます。 この以前の rootvg ボリューム・グループは、リブート時に NOT varyon に設定され、 -X フラグ (つまり、 alt_disk_install -X old_rootvg) でのみ除去する必要があります。

元の rootvg に戻る必要がある場合は、 bootlist コマンドを使用して、元の rootvg からリブートするように bootlist を変更します。

どのディスクが特定のボリューム・グループのブート・ディスクであるかが不明の場合は、 -q フラグを使用してブート・ディスクを判別することができます。 これは、ボリューム・グループが複数のディスクで構成されており、 bootlist の変更が必要な場合に役立ちます。

代替ルート・ファイル・システムは /alt_instとしてマウントされるため、他のファイル・システムにはその接頭部 (/alt_inst/usr、 /alt_inst/var) が付きます。 これは、カスタマイズ・スクリプトを使用する場合のアクセス方法です。

重要: alt_disk_installを使用して代替 rootvg を作成したが、それを使用しなくなった場合、または alt_disk_install コマンドを実行したい場合は、 exportvg を altinst_rootvgで実行しないでください。

単に alt_disk_install -X コマンドを実行して、 ODM データベースから altinst_rootvg 定義を削除します。 exportvg コマンド (または reducevg コマンド) を実行できない理由は、論理ボリューム名とファイルシステムが現在実名を持っており、 exportvg が実 rootvg の /etc/filesystems から実ファイルシステムのスタンザを除去しているためです。

exportvg が誤って実行されている場合は、システムをリブートする前に、必ず /etc/filesystems ファイルを再作成してください。 正しい /etc/filesystems ファイルがないと、システムはリブートされません。

この機能は、ネットワーク・インストール・マネージメント (NIM) によっても使用できます。 詳しくは、「NIM Guide」を参照してください。

AIX 4.3.1 以降のバージョンの alt_disk_install は、段階的に実行できます。 インストールは 3 つのフェーズに分割され、デフォルトでは 3 つのフェーズをすべて実行します。

表 1. フェーズ
項目
説明
Phase 1 altinst_rootvg ボリューム・グループ、 alt_ 論理ボリューム、 /alt_inst ファイルシステムを作成し、mksysb または rootvg データを復元します。
Phase 2 指定されたカスタマイズ・スクリプトを実行し、更新、新規ファイル・セット、フィックス、またはバンドル (クローン作成のみ) をインストールし、指定された場合は resolv.conf ファイルをコピーし、指定された場合は NIM クライアントのままにするためにファイルをコピーします。
Phase 3 /alt_inst ファイル・システムをアンマウントし、ファイル・システムおよび論理ボリュームの名前を変更し、 alt _ logical ボリュームを除去し、 ODM という名前を付け、 altinst_rootvgをオフに変更します。 bootlist を設定し、指定されている場合はリブートします。

各フェーズを個別に実行することも、フェーズ 1 と 2 を一緒に実行することも、フェーズ 2 と 3 を一緒に実行することもできます。 フェーズ 2 は、フェーズ 3 を実行する前に複数回実行することができます。

フェーズ 3 を実行して、使用可能な rootvg であるボリューム・グループを取得します。 フェーズ 1 および 2 を実行すると、 /alt_inst ファイル・システムはマウントされたままになります。

フェーズ 1 か 2、またはその両方を実行した後にもう一度最初からやり直す (altinst_rootvg を除去する) 場合は、alt_disk_install -X コマンドを実行してクリーンアップを行います。

元の rootvg と新しい代替ディスクとの間でデータ・アクセスが必要な場合は、ブートされていないボリューム・グループで、 -W フラグを使用してボリューム・グループ wake-up を実行できます。 wake-up は、ボリューム・グループをポスト alt_disk_install フェーズ 1 状態にします (つまり、 /alt_inst ファイルシステムがマウントされます)。
注: wake-up が発生したボリューム・グループは、 altinst_rootvgに名前変更されます。
制限

稼働中のシステムのオペレーティング・システムのバージョンは、 wake-upの下にあるボリューム・グループのオペレーティング・システムのバージョン以上でなければなりません。 これは、 altinst_rootvg および wake-up old_rootvgからブートする必要があることを意味する場合があります。

例えば、 4.1.5 稼働中のシステム上の alt_disk_install 4.3.3 mksysbから代替ディスクが作成されます。 2 つのボリューム・グループ間のデータにアクセスするには、 4.3.3 代替ディスクおよび wake-up 4.1.5 old_rootvg ボリューム・グループからブートする必要があります。

この制限は、 jfs ログ項目の非互換性が原因で発生します。 より大きなオペレーティング・システム・バージョンを含むボリューム・グループを wake-up することは可能ですが、そのボリューム・グループがシステムの rootvg になったことがない可能性があります。 その場合、ボリューム・グループは、ボリューム・グループで wake-upが発生していたときに、古いオペレーティング・システム・バージョンの rootvg によって解釈されない可能性がある jfs ログ項目を作成することになります。 JFS ログ項目は、リブートの前にアンマウントされなかったファイル・システムに対して存在します (例: /,/usr. )。

FORCE 環境変数が yesに設定されていない限り、 alt_disk_install コマンドは、より高いオペレーティング・システム・バージョンを持つボリューム・グループでの wake-up の実行を許可しません。

重要: 稼働中のオペレーティング・システムよりも高いオペレーティング・システム・バージョンを含むボリューム・グループに対して FORCE wake-up が試行された場合、 AND waking ボリューム・グループはシステム rootvg であり、エラーが発生します。
注: データ・アクセスが不要になった場合は、 -S フラグを使用してボリューム・グループをスリープ状態にすることができます。
注: wake-up が発生したボリューム・グループをブートして rootvg として使用するには、その前にそのボリューム・グループを put-to-sleep する必要があります。

-V 詳細出力をオンにします。 これによって、rootvg クローン作成のためにバックアッ プしようとするファイルが表示されます。 このフラグは、 mksysb alt_disk_install 用にリストアされたファイルを示します。
-L mksysb_level (mksysb_level) このレベルとプラットフォーム・タイプを組み合わせて、使用するブート・イメージ名を作成します (例えば、 AIX 5.1 以前では rspc_4.3.0_boot )。 これは V.R.M のフォーマットでなければなりません。 mksysb イメージはこのレベルと比較され、両者が一致するかどうかが確認されます。
-n NIM クライアントのままにします。 /.rhosts ファイルと /etc/niminfo ファイルは、代替 rootvg ファイル・システムにコピーされます。
-X altinst_rootvg ボリューム・グループ定義を ODM データベースから削除します。 これにより、ボリューム・グループの lspv リストが Noneに戻されます。 これはボリューム・グループから実データを除去しません。 そのため、 bootlistをリセットしても、そのボリューム・グループからリブートすることができます。

alt_disk_install 4.3.2 またはそれ以上の場合、このフラグを使用すれば、 指定のボリューム・グループ名の ODM データベース定義を除去することができます (例 -X old_rootvg)。

注:
  1. -B フラグと -X フラグを同時に指定することはできません。
  2. -X フラグを指定すると、他のフラグはすべて無視されます。
-O ターゲット altinst_rootvg 上でデバイスのリセットを 実行します。 これにより、 alt_disk_install はユーザー定義の装置構成を保持しなくなります。 このフラグは、1 つ以上のターゲット・ディスクが、異なるシステムの rootvg になる場合に便利です (例えば、論理区画化を行う場合または システム・ディスクの交換を行う場合に便利です)。

-e の除外リスト rootvg のクローン作成時に使用するオプションの exclude.list。 除外規則は、grep コマンドのパターン・マッチング規則に準拠します。 exclude_list は絶対パス名でなければなりません。
注 : バックアップから特定のファイルを除きたい場合は、 ASCII エディターを用いて /etc/exclude.rootvg ファイルを作成し、 システムのバックアップ・イメージに組み込みたくないファイル名のパターンを入力します。 この ファイル内のパターンは、バックアップからどのファイルを除外するかを判別するための、 grep コマンドのパターン・マッチング規則の入力になります。 /etc/exclude.rootvg ファイルにリストされているファイルを除外する場合は、「Excluded Files」フィールドを選択し、Tab キーを 1 回押してデフォルト値を yes に変更します。

例えば、scratch というディレクトリーのすべての内容を除外するには、除外ファイルを以下のように編集します。

     /scratch/

例えば、 /tmpというディレクトリーの内容を除外し、パス名に /tmp を持つ他のディレクトリーを除外しないようにするには、除外ファイルを以下のように編集します。

     ^./tmp/

すべてのファイルは相対的にバックアップされます。 (現在の作業ディレクトリー) に関係するファイルのバックアップが作成されます。 行の先頭にあるストリングと検索を一致させることが重要なファイル・ディレクトリーを除外するには、検索ストリングの先頭文字として ^ (脱字記号文字) を使用し、その後に . (ドット文字) を続けて、除外するファイル名またはディレクトリーを指定します。

除外するファイル名またはディレクトリーが別のファイル名またはディレクトリーの文字列の一部である場合は、^. (脱字記号の後にドット文字) を使用して検索を行の先頭から開始すべきことを指示するか、または $ (ドル記号文字) を使用して検索を行の最後で終了すべきことを指示します (あるいは、その両方を行います)。
-f fix_bundle オプションのファイルと、rootvg のクローン作成後にインストールする APAR のリスト。 このオプションを指定するときは、-l フラグも使用する必要があります。
-Ffixes rootvg のクローンの後にインストールする APAR (例えば IX123456) のオプションのリスト。 このオプションを指定するときは、-l フラグも使用する必要があります。
-I installp_flags (IBM installp_flags) 複製された alt_inst_rootvg に新規ファイル・セットを更新またはインストールするときに使用するフラグ。 デフォルト・フラグは -acgX です。 -l フラグは、このオプションと一緒に使用する必要があります。
-l images_location rootvg のクローンの後で適用される installp のイメージまたは更新情報の場所。 これは、ディレクトリーの絶対パス名またはデバイス名 ( /dev/rmt0など) にすることができます。
-w ファイルセット rootvg のクローン作成後にインストールするファイル・セットのリスト。 このオプションを指定するときは、-l フラグも使用する必要があります。

alt_disk_install バージョン 4.3.2 またはそれ以上の場合は、 次に示すフラグが使用できます。

例

  1. 実行中の 4.2.0 rootvg のクローンを hdisk3 に作成し、次に /updates から更新を適用して、クローン作成した rootvg を 4.2.1 レベルのものにするには、次のように入力します。
    alt_disk_install -C -F 4.2.1.0_AIX_ML -l /updates hdisk3

    これで、次回のリブート時には hdisk3 からブートされるように、ブート・リストが設定されます。

  2. 4.3 mksysb イメージを hdisk3にインストールするには、次のようにカスタマイズされたスクリプト (/home/myscript) を実行して、リブート前に一部のユーザー・ファイルを代替 rootvg ファイルシステムにコピーします。
    alt_disk_install -d /mksysb_images/4.3_mksysb -s /home/myscript hdisk3
  3. 新規代替ディスクからのブート後に元の rootvg ODM データベース・エントリーを除去するには、次のようにします。
    alt_disk_install -X old_rootvg

    元の rootvg の lspv リストは、 Noneに変更されます。 したがって、それらのディスク上に新規ボリューム・グループが作成される可能性があります。

  4. 複数の物理ボリュームを持つボリューム・グループのブート・ディスクを判別するには、次のようにします。
    alt_disk_install -q hdisk0

    以下に出力の例を示します。

    # lspv
hdisk0          00006091aef8b687     old_rootvg
hdisk1          00076443210a72ea     rootvg
hdisk2          0000875f48998649     old_rootvg
# alt_disk_install -q hdisk0
hdisk2

    この場合、 old_rootvg のブート・ディスクは hdisk2です。 したがって、ブート・リストを hdisk2 にリセットし、元の rootvg ボリューム・グループにリブートすることができます。

  5. alt_disk_install ボリューム・グループ名を変更するには、次のように入力します。
    alt_disk_install -v alt_disk_432 hdisk2

    以下に出力の例を示します。

    # lspv
hdisk0          00006091aef8b687     rootvg
hdisk1          00000103000d1a78     rootvg
hdisk2          000040445043d9f3     altinst_rootvg
hdisk3          00076443210a72ea     altinst_rootvg
hdisk4          0000875f48998649     None
hdisk5          000005317c58000e     None
# alt_disk_install -v alt_disk_432   hdisk2
#lspv
hdisk0          00006091aef8b687     rootvg
hdisk1          00000103000d1a78     rootvg
hdisk2          000040445043d9f3     alt_disk_432
hdisk3          00076443210a72ea     alt_disk_432
hdisk4          0000875f48998649     None
hdisk5          000005317c58000e     None
  6. 新しい代替ディスクからブートした後で、元の rootvg を wake_up するには、次のようにします。
    alt_disk_install -W hdisk0

    以下に出力の例を示します。

    # lspv
hdisk0          000040445043d9f3     old_rootvg
hdisk1          00076443210a72ea     rootvg
# alt_disk_install -W hdisk0
# lspv
hdisk0          000040445043d9f3     altinst_rootvg
hdisk1          00076443210a72ea     rootvg

    altinst_rootvg ボリューム・グループがオンに変更され、 /alt_inst ファイルシステムがマウントされます。

  7. wake-upを経験したボリューム・グループを put-to-sleep するには、次のようにします。
    alt_disk_install -S

    以下は、出力の例です。

    # lspv
hdisk0          000040445043d9f3     altinst_rootvg
hdisk1          00076443210a72ea     rootvg
# alt_disk_install -S
# lspv
hdisk0          000040445043d9f3     altinst_rootvg
hdisk1          00076443210a72ea     rootvg

    altinst_rootvg はオンに変更されなくなり、 /alt_inst ファイル・システムはマウントされなくなります。 altinst_rootvg ボリューム・グループ名を old_rootvgに戻す必要がある場合は、 -v フラグを使用してこれを行うことができます。
