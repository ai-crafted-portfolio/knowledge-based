目的

中間修正マネージャー、'emgrマネージャーがインストールできる'中間修正パッケージを作成する。

構文

epkg [ -w WorkDirectory ] [ -a APARrefFile ] [ -p PrerequisiteFile ] [ -d DescriptionFile ] [ -e interimfixControlFile ] [ -g PrerequisiteFile ] [ -l LockFile ] [ -S SupersedeFile ] [ -u {y|n} ] ] [ -r {y|n|o} ] [ -s ] [ -T {y|n} ] [ -X ] [ -v ] interimfixLabel

説明

epkgツールは、対話型とテンプレートベースの2種類のモードで実行できる。 インタラクティブ・モードでは、いくつかの質問を投げかけ、その答えに基づいて中間修正パッケージを作成する。 テンプレート・ベース・モードでは、対話型モードで質問された答えとともに提供される中間修正コントロール・ファイルを使用する。 暫定修正パッケージは、「emgrコマンドで起動する暫定修正マネージャによってインストールされる。

対話モード

epkg コマンドは、デフォルトでは対話モードで実行されます。 必要なパラメーターは中間フィックスのラベルのみ。 epkgセッションを中断すると、中間修正コントロールファイルが保存される。 同じ中間修正ラベルで新しいセッションを開始する場合、以前の中間修正コントロール・ファイルで作業を続けるかどうかを尋ねられます。 対話型 epkg セッションを開始する前にこの情報を提供するには、 epkg を -u フラグをつけて実行する。

epkgコマンドは質問順の記録を保持し、サブコマンドを使用して質問間を移動することができます。 また、'epkgコマンドは、あなたが以前に入力した答えを記憶し、その答えをデフォルトの答えとして設定します。 epkgサブコマンドについては、サブコマンドのセクションで説明している。

すべての質問に答えた後、'epkgコマンドは中間修正コントロールファイルを検証し、'emgrコマンドでインストールできる圧縮された'tarパッケージを作成する。

コントロールファイル・テンプレートの使用

中間修正コントロールファイルをテンプレートとして使用して、'中間修正パッケージを非インタラクティブに作成する。 次のファイルは、完成した中間修正コントロールファイルの例である：

# interim fix control file complete example 
ABSTRACT=This is a test of epkg. 
PRE_INSTALL=/tmp/pre_install 
POST_INSTALL=. 
PRE_REMOVE=/tmp/pre_remove
POST_REMOVE=.
REBOOT=yes 
PREREQ=/efixprereq.epkg
DESCRIPTION=/tmp/description 
EFIX_FILES=2
APARREF=/tmp/aparref
LKU_CAPABLE=yes

EFIX_FILE:
        EFIX_FILE_NUM=1
        SHIP_FILE=/usr/lib/drivers/random 
        TARGET_FILE=/usr/lib/drivers/random
        TYPE=1 
        INSTALLER=1  
        ACL=DEFAULT
        AR_MEM=.
        FILESET_NAME=bos.rte.security

EFIX_FILE:
        EFIX_FILE_NUM=2
        SHIP_FILE=/home/test/mystrcat.o 
        TARGET_FILE=/usr/ccs/lib/libc.a
        TYPE= 2
        INSTALLER= 1  
        ACL= root:system:555
        AR_MEM=strcat.o
        FILESET_NAME=bos.rte.libc

以下のフィールドが中間修正コントロールファイルに含まれる：

ABSTRACT
暫定修正 パッケージについて簡単に説明します。 abstract は 38 バイト以内に制限されています。
PRE_INSTALL
インストール・プレビューの後、 暫定修正 ファイルがインストールされる前に実行されるスクリプトの場所を指定します。 PRE_INSTALLスクリプトの失敗により、暫定修正パッケージのインストールが中断された。 このコンポーネントはオプションです。
POST_INSTALL
すべての中間修正ファイルが正常にインストールされた後に実行されるスクリプトの場所を指定します。 このコンポーネントはオプションです。
PRE_REMOVE
削除プレビューの後、削除操作中に 暫定修正 ファイルが削除される前に実行されるスクリプトの場所を指定します。 このコンポーネントはオプションです。
POST_REMOVE
削除操作中に 暫定修正 ファイルが削除された後に実行されるスクリプトの場所を指定します。 このコンポーネントはオプションです。
REBOOT
この 暫定修正にリブートが必要かどうかを指定します。 有効な値はyesまたはnoである。 この値をyesに設定すると、「emgrコマンドは必要に応じてブートイメージを変更し、インストール後に再起動するように指示するメッセージを発行する。
PREREQ
installp の前提条件を含むファイルのロケーションを指定します。 このコンポーネントはオプションです。
APARREF
この中間修正に関連する1つ以上のAPAR参照番号と抄録を含むファイルの場所を指定します。 このファイルの各行には、APAR 参照番号、APAR 番号、および APAR の要約が含まれています。 APARREFファイルのフォーマットは以下の通り：
APAR reference|:|APAR number|:|APAR abstract
有効な APARREF ファイルを作成するには、すべてのフィールドが必要なわけではありません。 特定のフィールドが不明または必須でない場合は、「NONE指定するか、フィールドを空白にする。 以下の例は、有効なAPARREFファイル形式を示している：
  • 123456|:|IV12345|:|This is the APAR abstract
789012|:|IV67890|:|This is another APAR abstract
  • 123456|:|NONE|:|NONE
789012|:|NONE
345678
  • NONE|:|IV12345|:|This is the APAR abstract
  • NONE
APAR 参照ファイルを APAR 参照番号と一緒に提供すると、installp コマンドによる自動除去機能が、暫定修正に対して有効になります。 この installp コマンドによる自動除去とは、installp が適用中のテクノロジー・レベル、Service Pack、あるいは PTF に該当の修正が含まれている場合に、暫定修正を自動的に除去する機能を指します。 APAR参照ファイルに「NONE指定されている場合、中間修正の自動削除機能は有効になりません。
DESCRIPTION
インストールされる 暫定修正 パッケージの詳細な説明が含まれているファイルの場所を指定します。
EFIX_FILES
暫定修正内のファイルの総数を指定します。
EFIX_FILE_NUM
中間修正のファイル数を指定する。 暫定修正 内の各ファイルには、1 から 400 までの固有の番号が必要です。 epkgコマンドは、1つの中間修正につき最大400ファイルをサポートする。
SHIP_FILE
epkg 中間修正パッケージにアーカイブするファイルの場所を指定する。 このファイルへの絶対パスまたは相対パスを指定する。
TARGET_FILE
SHIP_FILEインストールされている場所を指定する。 この場所は、暫定修正パッケージがインストールされているシステム上にあります。 このファイルへの絶対パスを指定する。 このファイルがRPM Package Manager(RPM) や 'installpパッケージなど、登録されたパッケージの一部である場合は、追跡する場所を指定する必要がある。
TYPE
インストールされるファイルのタイプを指定します。 TYPEフィールドには以下の有効な値がある：
1
ファイル (標準ファイルまたは実行可能ファイル)
※2
ライブラリーまたはアーカイブ・メンバー
INSTALLER
中間修正パッケージを追跡するインストーラがある場合は、その種類を指定します。 INSTALLERファイルには以下の有効な値がある：
1
installp によって現在追跡される
※2
現在 「RPM」 によって追跡されています
3
現在ISMPによって追跡されている
4
別のインストーラーによって現在追跡される
5

90万

ACL
ファイルのアクセス属性 (モードおよび所有権) を指定します。 この属性が DEFAULT に設定されていると、emgr コマンドは、 置換されるファイルの現行アクセス権を保持します。 しかし、ターゲット・ファイルが新しいファイルである場合、またはユーザが'-vフラグでパーミッションを指定したい場合、'ACL属性は、Owner:Group:OctalModesという構文で入力される：
ACL= root:system:555
AR_MEM
アーカイブ・メンバーの名前を指定します。 このオプションは、TYPE=2 の場合にのみ有効です。 この場合、'SHIP_FILEは出荷されるアーカイブメンバーのローカルロケーション、'TARGET_FILEはターゲットアーカイブ、'ACLアーカイブメンバーに適用される。 例えば、以下の値の設定は、ローカルファイル'myshr.oをターゲットアーカイブ'/usr/ccs/lib/libc.aのメンバ'shr.oにする：
TYPE=2
SHIP_FILE=/home/myshr.o
TARGET_FILE=/usr/ccs/lib/libc.a
AR_MEM=shr.o
FILESET_NAME
フィールド SHIP_FILE で指定されたファイルのファイルセットを指定します。
BUILD_BOOT_IMAGE
ブート・イメージを再作成する必要があるかどうかを指定します。 有効な値はyesまたはnoである。 このフィールドが「はい」に設定されている場合は、リブートが必要です。 このフィールドがyesに設定され、'REBOOTフィールドがnoに設定されている場合、'epkgはエラーを返す。
E2E_PREREQ
暫定修正 制御ファイル内の 暫定修正 前提条件ファイルの場所を指定します。
PKGLOCKS
暫定修正 制御ファイル内のパッケージ・ロック・ファイルのローカル・ファイル・ロケーションを指定します。
SUPERSEDE
暫定修正 制御ファイル内の置き換えられたファイルのローカル・ファイル・ロケーションを指定します。
FIXTESTED
この暫定修正をテストするかどうかを指定する。 有効な値はyesまたはnoである。
LKU_CAPABLE
この暫定修正が ライブ・アップデート 操作と互換性があるかどうかを指定します。 有効な値はyesまたはnoである。 理想的には、すべてのインテリム・フィックスに ライブ・アップデート 対応のマークを付ける必要があります。 この互換性は、複数の暫定修正を 1 つのグループとしてインストールするために必要です。 暫定修正がライブ・アップデートの操作に適さない場合、「LKU_CAPABLE属性は「no値に設定されますが、ほとんどの暫定修正では、この属性は「yes値に設定されています。
上乗せサポート
パッケージャは、'epkgがインストールされたときに置き換えられる暫定的な修正ラベル名を含むファイルを指定することができる。 これにより、'emgrコマンドは、'emgrコマンドが暫定修正パッケージを インストールする前に、このファイルに指定されている暫定修正ラベルを (インストールされていれば) 削除する。 インストールされている優先中間修正プログラムを削除しないと、中間修正パッケージのインストールが中止されます。 置き換えられるラベルは、最大 32 までサポートされます。 パッケージャーは、epkg コマンドで置き換えファイルを次のように指定できます。
  • -S supersede_fileフラグでファイルの場所を指定するには、以下のコマンドを入力する：
    epkg -S /tmp/superseded.epkg myefix
  • 対話型モードで拡張オプション '-vフラグが使われている場合、 'epkgコマンドは上書きされたファイルの入力を求める。
    Enter the location for the supersede file or "." to skip.
-> /tmp/superseded.epkg
  • SUPERSEDE属性に、中間修正コントロール・ファイル内の、置き換えられたファイルのローカル・ファイルの場所を設定する。
    SUPERSEDE=/tmp/superseded.epkg
置き換えられるファイルのフォーマットは、1 行に 1 つの 暫定修正 ラベルが置き換えられます。 # 記号で始まるコメントと、先頭の空白は無視されます。
# Requisites for efix myefix3
myefix1
myefix2
prereqsとxreqsのサポート

パッケージャは、中間修正パッケージをインストールするために必要な中間修正のラベル名を含むファイルを指定することができます。 暫定修正ラベルに必要なタイプが明記されていない場合、 または暫定修正前提条件ファイル内で変数 RequisiteType を使用して NONE と指定されている場合、デフォルトの必要条件タイプが採用されます IFREQ。 ただし、レガシーな暫定的な修正については、デフォルトの必須タイプは PREREQ. です。

指定 IFREQ された前提条件タイプは、暫定修正管理ファイル内の前提条件エントリで指定された範囲レベル間に暫定修正ラベルがインストールされているかどうかを確認するコマンド emgr をトリガーします。 インストールされた暫定修正ラベルが要求されるレベル範囲内にない場合、コマンド emgr は暫定修正パッケージのインストールを中止します。 暫定修正ユーザー指定パッケージのコンポーネントに関する詳細については、 「暫定修正ユーザー指定パッケージのコンポーネント 」トピックを参照してください。

PREREQフィールドは、'emgrコマンドに中間修正ラベルが取り付けられているかどうかをチェックさせる。 必要なものがインストールされていない場合、 'emgrコマンドは暫定修正パッケージのインストールを中止する。 ユーザーは、XREQ中間フィックス・ラベルを指定することもできる。 これにより、xreqという名前の暫定修正がインストールされている場合、'emgrコマンドは暫定修正をインストールしない。

パッケージャは、'epkgコマンドで中間修正前提条件ファイルを以下の方法で指定することができます：
  • -g efix_prereq_fileフラグでファイルの場所を指定するには、以下のコマンドを入力する：
    epkg -g /tmp/efixprereq.epkg myefix
  • 対話モードで拡張オプションフラグ (-v) を使用した場合、 'epkgコマンドは中間修正prereq ファイルの入力を求める。
    Enter the location for the efix prerequisite file or "." to skip.
-> /tmp/efixprereq.epkg
  • E2E_PREREQ 属性を、 暫定修正 制御ファイル内の 暫定修正 前提条件ファイルのローカル・ファイルの場所に設定します。
    E2E_PREREQ=/tmp/efixprereq.epkg
次の書式は、中間修正前提条件ファイルのエントリーの書式である：
EfixLabel  RequisiteType: PREREQ/XREQ
以下の例では、EfixLabelフィールドの値は'oldefix1であり、RequisiteTypeは'PREREQである：
oldefix1 PREREQ  # Make sure oldefix1 is already installed
以下の例では、EfixLabelフィールドの値は'oldefix4であり、RequisiteTypeは'XREQである：
oldefix4 XREQ    # Make sure oldefix4 is NOT installed

サポートされる 暫定修正 前提条件の最大数は 32 です。

installpによる中間修正の自動削除のサポート

パッケージャは、APAR参照番号を含むAPAR参照ファイルを指定することができる。 APAR参照番号により、'installpは中間修正を、その修正が出荷されたすべての技術レベルのAPARにマッピングすることができる。 installp、適用された技術レベル、サービスパック、またはPTFに暫定修正が含まれていると判断した場合、「installpアップデートを適用する前に暫定修正を自動的に削除する。

-r {y|n|o} epkg'REBOOT属性を設定する。 これにより、「emgrコマンドはブートイメージに必要な変更を加え、インストール後に再起動を指示するメッセージを発行する。 y引数は、リブートとボスブートが必要であることを指定する。 引数nは、再起動が不要であることを指定する。 o引数は再起動が必要であることを示すが、'emgrbosbootを呼び出してはならない。
-S SupersedeFile 暫定修正 ラベル名が入っている 暫定修正 置き換えファイルの場所を指定します。 これらのラベルは、'epkgがインストールされたときに置き換えられる。
-s epkgコマンドは、スクリプトと前提条件ファイルに関する質問をスキップする。
-T この 暫定修正 がテストされたかどうかを示します。 有効な値はyesまたはnoである。 デフォルトは no です。
-u {はい|いいえ} 既存の中間修正コントロールファイルを使用するかどうかを指定します。
-v epkg コマンドが拡張オプションに関してさらに質問を加えます。 このオプションには、すべての中間修正ファイルのパーミッションを指定する質問が含まれています。
-w WorkDirectory epkgコマンドが使用する代替作業ディレクトリを指定する。 デフォルトの作業ディレクトリーは $HOME/epkgwork です。
-X emgrコマンドは、暫定修正がインストールされたときに、スペースが必要で拡張が可能であれば、ファイルシステムを自動的に拡張するようにする。
