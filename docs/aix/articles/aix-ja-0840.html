目的
ワークロード・パーティション
の特性をリストします。

説明
lswpar
コマンドは、指定された 1 つ以上の
ワークロード・パーティション
(指定されていない場合はすべての
ワークロード・パーティション
) に関する情報を標準出力に出力します。
-s
フラグを使用して、以下の
ワークロード・パーティション
状態に従ってすべてのリストをフィルターに掛けることができます。
項目 | 説明
定義済み | ワークロード区画 は mkwpar コマンドによって定義され、使用する準備ができていますが、アクティブではありません。 startwpar コマンドを使用して、この状態で ワークロード・パーティション を開始します。
ロード済み | ワークロード・パーティション がカーネルで構成されていますが、プロセスはまだ開始されていません。 注: この状態は、 lswpar コマンドを使用して ワークロード・パーティション を開始するプログラマチック・コンシューマーにのみ表示されます。
アクティブ | ワークロード・パーティション は正常に実行されています。
凍結 | チェックポイント操作が開始され、 ワークロード区画 のプロセスが静止し、保管フェーズを待機します。 注: Frozen 状態が表示されるのは、 lswpar コマンドを使用して ワークロード・パーティション のチェックポイントを指定した場合のみです。 チェックポイントまたは再始動機能には、基本 WPAR 以外の追加ソフトウェア・パッケージが必要です。
一時停止 | チェックポイントまたは再始動操作が実行され、 ワークロード区画 のプロセスを再開または強制終了する準備ができました。 チェックポイントまたは再始動機能には、追加のソフトウェアが必要です。
保守 | ワークロード区画は、 startwpar コマンドを指定して保守モードにすることができます。 保守モード中に、ワークロード区画がカーネル内に構成され、ファイルシステムがマウントされましたが、プロセスが開始されません。
移動中 | 非同期チェックポイント・リスタート操作が実行されました。 ワークロード区画 は到着サーバー上で 「アクティブ」 ですが、 ワークロード区画 は、すべてのリソースが正常に転送されるまで、出発サーバー上で 「移動中」 状態で表示されます。 チェックポイントまたは再始動機能には、追加のソフトウェアが必要です。
移行 | 管理操作が進行中です。 ワークロード区画 は、作成中、開始中、停止中、構成中などです。

中断 | 管理操作が失敗し、この ワークロード・パーティション は使用不可の状態のままです。
ERROR | ワークロード区画名やフラグなどの無効なエレメントのために、エラーが発生しました。
-t
フラグを使用すると、以下の
ワークロード・パーティション
・タイプに従ってすべてのリストをフィルターに掛けることができます。
項目 | 説明
アプリケーション | このタイプは、分離されたシステム・サービスなしで単一プロセス (またはその方法で呼び出されるプロセスのグループ) を実行するアプリケーション・ ワークロード・パーティション です。 プロセスまたはプロセスのグループは、その稼働環境 (ファイル・システム、セキュリティー、デバイス) を継承します。 アプリケーション・ ワークロード・パーティション が作成された環境から (以下同様)。
システム | このタイプは、オペレーティング・システムの独立した完全に機能するインスタンスをエミュレートするシステム・ ワークロード・パーティション です。
追加のチェックポイントまたは再始動ソフトウェアがインストールされる場合は、以下のタイプも指定することができます。
項目 | 説明
チェックポイント指定可能 | この ワークロード区画 は、チェックポイント機能または再始動機能に対して使用可能になっています。 ヒント: このタイプは、相互に排他的な ワークロード・パーティション ・タイプではありません。 チェックポイント指定可能 ワークロード・パーティション は、引き続き System または Application ワークロード・パーティション のいずれかです。
追加のバージョン管理された
ワークロード・パーティション
・ソフトウェアがインストールされている場合は、以下のタイプを指定することもできます。
項目 | 説明
Versioned | この ワークロード・パーティション は、オペレーティング・システム互換モードで実行されています。 ヒント: このタイプは、相互に排他的な ワークロード・パーティション ・タイプではありません。 バージョン管理された ワークロード・パーティション は、引き続き システム ワークロード・パーティション です。

D ... name if S : T : U : V : W : X : Y : Z R ... -c または -d フラグを使用すると、次の例に示すような区切り文字形式の出力が生成されます。 name:interface:address:mask_prefix:broadcast -N フラグを -a フラグと一緒に使用することにより、出力を次のフィールドの任意の組み合わせに制限することができます。 名前 ( WPAR 名) インターフェース Address (IPv4 または IPv6 アドレス) Mask_Prefix (IPv4 netmask フィールドまたは IPv6 prefixlen フィールド) Broadcast WPAR に 1 つ以上の名前がマップされたインターフェースが含まれている場合、 lswpar コマンドは、 WPAR が 「定義済み」 状態のときに構成ファイルに指定された情報のみを表示します。 WPAR が アクティブ 状態の場合、実際のランタイム・ネットワーク属性が表示されます。 注: 区切り文字で区切られている出力に IPv6 アドレスが含まれることが予期される場合は、 IPv6 アドレスにはコロンが含まれるため、 -d フラグを使用して代替区切り文字を指定してください。
-q | 表の見出しを抑止 (静止) します。 このフラグは、表形式と区切り文字形式の出力の場合にのみ有効です。

-R | 要求された WPAR ごとに詳細なリソース制御情報を生成します。 このフラグは、 -G 、 -I 、 -L 、 -M 、 -N 、 -D 、 -S 、または -T フラグと同時には使用できません。 -c または -d フラグを指定しないと、各 ワークロード・パーティション 出力は以下の段落フォーマットになります。 ================ Name - State ================ Active: {yes|no} RSet: rset CPU Shares: n CPU Limits: m %- S %, H % Memory Shares: n Memory Limits: m %- S %, H % Per-Process Virtual Memory Limit: n MB Total Processes: n Total Threads: n Total PTYs: n Total Large Pages: n Max Message queue IDs: n % Max Semaphore IDs: n % Max Shared memory IDs: n % Max Pinned memory: n % -c または -d フラグを使用すると、区切り文字で区切られた出力は以下の例のようになります。 name:state:active:rset:shares_CPU:CPU:shares_memory:memory: procVirtMem:totalProcesses:totalThreads:totalPTYs: totalLargePages:pct_msgIDs:pct_semIDs:pct_shmIDs:pct_pinMem
-s {[D] [L] [A] [F] [P] [N] [M] [T] [B]} | workload partition の状態に基づいて出力をフィルターに掛けます。 複数の状態コードを使用することができます。 状態コードについては、 -c フラグを参照してください。

-S | 要求された WPAR ごとに詳細なセキュリティー特権情報を生成します。 このフラグは、 -D 、 -G 、 -I 、 -L 、 -M 、 -N 、 -R 、または -T フラグとは一緒に使用できません。 -c または -d フラグを指定しないと、各 ワークロード・パーティション 出力は以下の段落フォーマットになります。 =============================== Name - State =============================== Privileges: comma-separated list of privileges assigned to the workload partition
-t {[A][S][C][L]} | ワークロード・パーティション ・タイプに基づいて出力をフィルタリングします。 複数のタイプ・コードを使用することができます。 タイプ・コードについては、 -c フラグを参照してください。
-T | 要求された ワークロード・パーティション ごとに詳細なロック情報を生成します。 このフラグは、 -D 、 -G 、 -I 、 -L 、 -M 、 -N 、 -R 、 -S 、または -s フラグと同時には使用できません。 このフラグは、 -c フラグも指定されていない限り、 -q フラグと同時には使用できません。 -c フラグを指定しない場合、各 ワークロード・パーティション 出力の形式は次のようになります。 ================ Name - State ================ Operation: % c Process ID: % p Start time: % t -c または -d フラグを使用すると、次の例に示すような出力が生成されます。 name:state:opname:oppid:opstart

-X | 要求されたワークロード区画ごとに詳細なカーネル・エクステンション情報を順に生成します。 このフラグは、 -D 、 -G 、 -I 、 -L 、 -M 、 -N 、 -R 、 -S 、または -T フラグと同時には使用できません。 -c または -d フラグが指定されていない場合、各 ワークロード・パーティション 出力は以下の表形式になります。 Name Extension Name Local Major Status checksum --------------------------------------------------------------- name /path/to/extension local major status checksum ...
wparname (wparname) | 1 つ以上の ワークロード・パーティション を指定します。 このパラメーターは、コマンド・ラインの最後のパラメーターでなければなりません。 複数の ワークロード・パーティション 名と一致するシェル・スタイルのワイルドカードを含めることができます。 (この場合、 lswpar コマンドがメタキャラクターを受け取る前に、シェル拡張を防ぐための適切なシェル引用符を使用します。)
