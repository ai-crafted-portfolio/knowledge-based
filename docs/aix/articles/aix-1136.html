目的

パフォーマンス・モニター・イベントの生成を開始、リセット、または停止します。

構文

PMCTL [ { [ -E (E) [ モード ] ] [ 「-f」 間隔 ] {[ -y (Y) コマンド ]}} | [ -O (O) オプション ] | [ -h ] | [ - ] | [ -S (S) ] ] [ -s ] [ { -a 値 -y (Y) コマンド [ 「-f」 間隔 ] }]

説明

pmctl コマンドは、PMAPI サブシステムでパフォーマンス・モニター・イベントの生成を開始、リセット、または停止して、tprof -E コマンドを使用した人手によるオフライン・モードをサポートします。 また、 PMAPI サブシステムの現在の状況もレポートします。

フラグ

項目
説明
-a 大規模ページ分析をオンにします。
-E (E) [ モード ] イベント・ベースのプロファイル作成を可能にします。 以下のいずれかのモードを指定できます。
PM_イベント
プロファイルを作成するハードウェア・イベントを指定します。 -E フラグにモードを指定しない場合、デフォルトのイベントはプロセッサー・サイクル (PM_CYC) です。
EMULATION
エミュレーション・プロファイル作成モードを使用可能にします。
ALIGNMENT
調整プロファイル作成モードを使用可能にします。
ISLBMISS
命令セグメント索引バッファー・ミス・プロファイル作成モードを使用可能にします。
DSLBMISS
データ・セグメント索引バッファー・ミス・プロファイル作成モードを使用可能にします。
「-f」 間隔 使用すべきサンプリング間隔を指定します。
  • プロセッサー・サイクルの場合、EMULATION、 ALIGNMENT、ISLBMISS、および DSLBMISS の各イベントでは、1 から 500 ミリ秒を指定します (デフォルトは 10 ミリ秒)。
  • パフォーマンス・モニター・イベントの場合、10000 から最大 MAXINT 発生数を指定します (デフォルトは 10000)。
-f フラグを -y フラグと一緒に使用すると、他のパフォーマンス・モニター・イベントの場合は 1 から最大 MAXINT 発生数まで指定します (デフォルトは 10000)。
-O オプション この -O オプションには、以下の値を指定できます。
threshold_cmp_val=値
しきい値比較浮動小数点値を設定します。

Power ® プロセッサーには、しきい値カウンター機能があります。 しきい値カウンターは、1 次パフォーマンス・モニター・カウンター (PMC) とは異なります。これは、コア・サブシステム、キャッシュ・サブシステム、およびメモリー・サブシステムの指定された開始イベントと終了イベントの別個のセットの間で発生するイベントの数をカウントできるためです。

このオプションは、指定された開始イベントと終了イベントの間のイベント数を比較するために使用できるしきい値を指定します。

threshold_event_sel=名前
しきい値カウントで考慮する必要があるイベントを指定します。 threshold_event_sel オプションの有効な値は以下のとおりです。
しきい値サイクルの数
制御レジスター (CTRL) 実行ラッチが設定されている、発生したイベントまたはサイクルの数をカウントします。 AIX® オペレーティング・システムは、制御レジスター (CTRL) ビットを使用して、アイドル状態または実行状態を示します。 パフォーマンス・モニター・ユニット (PMU) もこのビットを使用して、アイドル期間中のイベントのカウントを回避します。 このビットは通常、 実行ラッチと呼ばれます。 このオプションは、凍結条件に依存しません。 これは、PMU がイベント・カウンターの内容を凍結した場合でも、イベントがカウントされることを意味します。
しきい値カウント数コンポーネント・インスタンス
CTRL 実行ラッチが設定されている場合に、完了した命令の数をカウントします。

このオプションは、凍結条件に依存しません。 これは、PMU がイベント・カウンターの内容を凍結した場合でも、イベントがカウントされることを意味します。

THRESHOLD_COUNT_PMC1_EVENTS
PMC1 イベントをカウントします。

PMC1 - PMC4 は 32 ビット・レジスターであり、プログラムによってカウント可能なイベントが指定されるため、プログラマブル・カウンターと呼ばれます。 このオプションは、凍結条件によって異なります。 これは、PMU がイベント・カウンターの内容を凍結したときにイベントがカウントされないことを意味します。

THRESHOLD_COUNT_PMC2_EVENTS
PMC2 イベントをカウントします。 このオプションは、凍結条件によって異なります。 これは、PMU がイベント・カウンターの内容を凍結したときにイベントがカウントされないことを意味します。
THRESHOLD_COUNT_PMC3_EVENTS
PMC3 イベントをカウントします。 このオプションは、凍結条件によって異なります。 これは、PMU がイベント・カウンターの内容を凍結したときにイベントがカウントされないことを意味します。
THRESHOLD_COUNT_PMC4_EVENTS
PMC4 イベントをカウントします。 このオプションは、凍結条件によって異なります。 これは、PMU がイベント・カウンターの内容を凍結したときにイベントがカウントされないことを意味します。
-o Options (続き)
threshold_eve_start_sel=名前
しきい値カウントを開始するイベントを指定します。 このオプションの有効な値については、 threshold_eve_stop_selを参照してください。
threshold_eve_stop_sel=名前
しきい値カウントを停止するイベントを指定します。 threshold_eve_start_sel オプションおよび threshold_eve_stop_sel オプションには、以下の値を設定できます。
PM_MRK_INST_DECODED (PMMR)
サンプリングされた命令はデコードされます。
pm_mrk_inst_disp
サンプリングされた命令がディスパッチされます。
PM_MRK_INST_ISSUED (PMR)
サンプル命令が発行されます。
PM_MRK インストール _FIN
サンプル命令が終了しました。
PM_MRK_INST_CMPL (PMR)
サンプル命令が完了しました。
PM_MRK_LD_MISS_L1
サンプル命令レベル 1 (L1) ロード・キャッシュが欠落しています。
PM_MRK_L1_RELOAD_VALID
サンプリングされた命令レベル 1 (L1) の再ロードは有効です。
EVE_SEL_PMC1
PMC1 のモニター・モード制御レジスター (MMCR) 1 で選択されたイベントが発生しました。
EVE_SEL_PMC2
PMC2 の MMCR1 で選択されたイベントが発生しました。
EVE_SEL_PMC3
PMC3 に対して MMCR1 で選択されたイベントが発生しました。
EVE_SEL_PMC4
PMC4 の MMCR1 で選択されたイベントが発生しました。
PM_MRK_NTF_FIN (PMR)
サンプリングされた命令は次の終了状態になっています。
PM_MRK_L2_RC_DISP
サンプリングされた命令に対して RC マシンがディスパッチされました。
PM_MRK_ST_DONE_L2
サンプリングされた命令に対して RC マシンが実行された。
-o Options (続き)
random_samp_ele_crit=名前
サンプリングする命令を選択するためのランダム基準を指定します。 このオプションの有効な値は、以下のとおりです。
すべての STR
すべての命令が適格です。 この値がデフォルト設定です。
ロード・ストア
操作はロード・ストア・ユニット (LSU) にルーティングされます。例えば、ロード・ストアにルーティングされます。
プロブノップ
特殊な操作なし命令のみをサンプリングします。これは、プローブ NOP イベントと呼ばれます。
LARX_STCX (X)
索引付き (LARX) 命令のロードと予約、および条件付き索引付き保管 (STCX) 命令のサンプル。
サンプルのロード
ロード指示のみをサンプリングします。
長い待ち時間の操作
長い待ち時間の命令のみをサンプリングします (div/sqrt/mul)。
ストア・サンプリング
ストアの指示のみをサンプリングします。
ロード・ミス
ロード・ミス命令のみをサンプリングします。
LOAD_HIT_STORE
ロード・ヒット・ストア命令のみのサンプル。 この値は、ロード操作でストア・キューから終了状態にデータを転送できる場合にのみ適用されます。 この値は、ロード・ヒット・ストア命令がストア・キューにあるが、ロード操作が部分的にストアとオーバーラップしている場合には適用されません。
BRANCH_MISPREDICTS (予測の誤り)
ブランチの誤予測命令のみをサンプリングします。
branch_mispredicts_dir_cr_ctr
分岐-誤予測イベント (方向、CR、または CTR) のみをサンプリングします。
ブランチの予測の不一致
分枝誤予測イベント (TA) のみをサンプリングします。
ブランチ_解決済み
解決策のあるサンプル・ブランチ。
分岐の繰り返しなし
非反復ブランチのみをサンプリングします。
すべての BRANCHES_REQ_PRED
予測が必要なすべてのブランチをサンプリングします。
グループ番号 =event_group
pmctl コマンドに使用する必要があるグループ番号を指定します。 このオプションはオプションの属性です。 この値を指定する場合、グループにはしきい値イベントが必要であり、同じイベントを -E フラグとともに使用する必要があります。
-h man ページ情報を表示します。
-r PMAPI サブシステムの解放とリセットを行います。
-S パフォーマンス・モニター・イベントの生成を停止します。
-s PMAPI サブシステムの現在の状況を表示します。
-y コマンド イベント・ベースのプロファイル作成をオンにするのは、指定コマンドとその子孫に限定されます。

セキュリティー

アテンション RBAC ユーザー: このコマンドは特権操作を実行できます。 特権命令を実行できるのは特権ユーザーのみです。 権限および特権について詳しくは、「セキュリティー」の『特権コマンド・データベース』を参照してください。 このコマンドに関連した特権および権限のリストについては、lssecattr コマンドまたは getcmdattr サブコマンドの項を参照してください。

例

  1. パフォーマンス・モニター・イベントの生成を停止するには、以下のコマンドを入力します。
    pmctl –S
  2. パフォーマンス・モニター・イベントの生成をリセットするには、以下のコマンドを入力します。
    pmctl –r
  3. PMAPI サブシステム内の現在の状況をレポートするには、以下のコマンドを入力します。
    pmctl –s
  4. パフォーマンス・モニター・イベントの生成を開始するには、以下のコマンドを入力します。
    pmctl –E
  5. 指定の workload コマンドとその子孫に対してのみパフォーマンス・モニター・イベントの生成を開始するには、以下のコマンドを入力します。
    pmctl –E –y workload
  6. 人手によるオフライン・モードで tprof -Eをサポートするには、以下のコマンドを入力します。
    trace -adf -o mydata.trc
trcon
pmctl –E 
sleep 10; trcstop
gensyms > mydata.syms
tprof –suker mydata
  7. 指定の workload コマンドとその子孫に対してプロファイル作成するための人手によるオフライン・モード状態で、tprof -Eをサポートするには、以下のコマンドを入力します。
    trace -adf -o mydata.trc
trcon
pmctl –E –y workload
trcstop
gensyms > mydata.syms
tprof –suker mydata
  8. しきい値開始イベントと終了イベントの別個のペアの間で経過したしきい値カウント・イベントの数をカウントし、比較のためにしきい値を指定するには、次のコマンドを入力します。
    trace -adf -o mydata.trc
trcon
pmctl -E PM_THRESH_MET-O threshold_cmp_val=10000 -O
threshold_event_sel=THRESHOLD_COUNT_CYCLES -O
threshold_eve_start_sel=PM_MRK_L1_RELOAD_VALID -O
threshold_eve_stop_sel=PM_MRK_ST_DONE_L2 -O
random_samp_ele_crit=ALL_INSTR -O group_num=607
sleep 10; trcstop
gensyms > mydata.syms
tprof -suker mydata
