目的
ワークロード・パーティション
を活動化します。

説明
startwpar
コマンドは、
mkwpar
コマンドによって定義された
ワークロード区画
を活動化します。 これには、以下が含まれます。
グローバル環境から
ワークロード区画へのデバイスのエクスポート
ワークロード・パーティション
・ファイル・システムのマウント
ワークロード・パーティション
IP アドレスの割り当てと活動化
ワークロード区画
WLM クラスの活動化 (ある場合)
init
コマンドの作成
指定された名前の
workload partition
が存在しない場合、
startwpar
コマンドは失敗します。

構文
/usr/sbin/startwpar [ -a ] [ -m ] [ -v ] [ -1 [ -R ] | -2 [ -e 付加価値税 = 値． ] | | -I ] WparName

オプション
フラグ
項目 | 説明
-1 | フェーズ 1: ロード済み状態。 startwpar コマンドを、プロセスの作成または実行前に停止するように指定します。 この -1 フラグを使用できるのは、プログラマチック・コンシューマー (管理ロックを持つコンシューマー) のみです。
-2 | フェーズ 2: 初期プロセスを開始する。 ワークロード・パーティション が startwpar-1 オプションで既に構成されている場合は、 -2 フラグを使用して、登録されたアプリケーション（ アプリケーション・ワークロード・パーティション ）、init（ システム・ワークロード・パーティション ）、または ワークロード・パーティション が mkwpar コマンドまたは wparexec コマンドの -c （チェックポイント可能）オプションで作成された場合は登録された 代替initを スポーンして、 ワークロード・パーティション の起動を完了します。 操作コンテキストは、照会される ワークロード・パーティション のタイプに対する通常の startwpar 操作のコンテキストと同じです。 このオプションは、 -I オプションと対照的で、 startwpar プロセスが ワークロード・パーティション・プロセス に置き換えられる。 この -2 フラグを使用できるのは、プログラマチック・コンシューマーのみです。
-a | 静的設定の競合が発生した場合は、自動的に解決します。 解決可能な設定には、ホスト名およびネットワーク構成があります。
-e VAR = 値 ... | startwpar -2 フラグによって作成された初期プロセスに、環境のカスタマイズが可能になります。 パラメーターは、 VAR = value ... の形式の単一の引数 (適切に引用符で囲まれ、エスケープされます) でなければなりません。 プログラマチック・コンシューマーのみがこの -e フラグを使用できます。

-I | startwpar コマンドが ワークロード・パーティション の初期プロセスを exec することを指定します。 /usr/lib/wpars/wparinit (システム ワークロード・パーティション の場合) および /usr/lib/wpars/vinit (アプリケーション・ ワークロード・パーティション の場合)。 alternate init コマンドは、登録されていても、このフラグによって実行されることはありません。 このプロセスは、作成され、 exec を介して実行し、 startwpar プロセスを置き換えます。 これは -2 フラグとは対照的で、従って、初期プロセスはその通常のコンテキストで実行されます。 この -I フラグを使用できるのは、プログラマチック・コンシューマーのみです。
-m | ワークロード・パーティション を保守モードで開始することを指定します。 ワークロード・パーティション ワークロード・パーティション に関連付けられているネットワークは構成されていないため、 ワークロード・パーティション へのアクセスはグローバル・システムからのみです。 -m フラグを使用して、 ワークロード・パーティション を NFS ファイルシステムで構成しないでください。
-R | -1 フラグと一緒に使用すると、 -R フラグは、 ワークロード区画 がフレッシュ・スタートではなく再始動用に構成されることを指定します。 この -R フラグを使用できるのは、プログラマチック・コンシューマーのみです。
-v | 詳細出力を表示することを指定します。

例
roy
という名前の
ワークロード・パーティション
を開始するには、次のように入力します。
startwpar roy
