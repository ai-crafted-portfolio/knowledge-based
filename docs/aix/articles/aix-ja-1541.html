目的
従来のシステムダンプおよびファームウェア支援型システムダンプに関連する情報と設定を表示および変更します。

説明
この
sysdumpdev
コマンドは、稼働中のシステムにおいて、プライマリ・ダンプ・デバイスまたはセカンダリ・ダンプ・デバイスの指定を変更します。 プライマリ・ダンプ・デバイスとセカンダリ・ダンプ・デバイスは、システム構成オブジェクトで指定されます。 新しいデバイス指定は、再度コマンド
sysdumpdev
を実行するかシステムを再起動するまで有効です。
コマンド
sysdumpdev
をオプション
no
付きで実行すると、コマンド
sysdumpdev
はプライマリおよびセカンダリのダンプデバイスの現在の属性を特定し、その属性値をオブジェクトデータマネージャ（ ODM ）オブジェクトクラスおよび不揮発性ランダムアクセスメモリ（NVRAM）に書き込みます。 デフォルトのプライマリ・ダンプ・デバイスは
/dev/hd6
ページング・スペースです。 デフォルトの 2 次ダンプ・デバイスは
/dev/sysdumpnull
です。 システムのメモリが4 GB以上の場合、デフォルトのダンプデバイスは であり
/dev/lg_dumplv
、 は専用の
/dev/lg_dumplv
ダンプデバイスです。 AIX® 7.1 その後、プラットフォームがサポートしている場合、ファームウェア支援型ダンプ機能を拡張し、これをデフォルトのシステムダンプ方式とする。
注:
ミラーリングされたページング領域をダンプデバイスとして使用できます。
フロッピーディスクドライブをダンプデバイスとして使用しないでください。
ページングデバイスを使用する場合は、プライマリページングデバイスである hd6 のみを使用してください。 AIX オペレーティングシステムでは、ルートボリュームグループ（rootvg）内の任意のページングデバイスをセカンダリダンプデバイスとして使用できます。
テープやDVDなどのリムーバブルデバイスを使用する場合、ダンプはボリュームをまたがって実行されません。 ダンプは単一のボリュームに収まる必要がある。
ルートボリュームグループ（rootvg）内の
iSCSI
ソフトウェアイニシエーターデバイスを、ファームウェア支援システムダンプ用のダンプデバイスとして設定できます。これは、
テクノロジーレベル6100-01を搭載した AIX バージョン 6.1
で有効です。
シン・サーバーのリモート・ダンプは、
AIX 6.1

でサポートされます。 NIM（Network Installation Management）マスター上で相対ダンプリソースを定義すると、NIMクライアント上のダンプリソースを、プライマリ・ダンプ・デバイスのみを設定できる iSCSI （）ディスクとして表示できるようになります。 iSCSI ディスクデバイスでは、ファームウェア支援型システムダンプのみを設定できます。
非揮発性メモリ・エクスプレス・オーバー・ファブリックス（NVMe-OF）ディスクデバイスでは、ファームウェア支援型システムダンプのみを設定できます。
AIX バージョン 6.1 （テクノロジーレベル6100-06）では
、カーネルメモリのファームウェア支援型ダンプを設定できます。
暗号化されてロックされている論理ボリュームのダンプ・デバイスを構成すると、エラー・メッセージが表示される場合があります。
論理ボリュームの暗号化または復号が進行中である場合、その論理ボリュームのダンプ・デバイスを構成することはできません。
AIX 6.1
以降のバージョンの場合、すべてのダンプが圧縮されます。 コマンド
savecore
を使用して、ダンプデバイスからファイルへダンプをコピーします。
この
sysdumpdev
コマンドは、ファームウェア支援システムダンプを以下の機能でサポートします：
ダンプサイズ推定の復活。
最新のダンプに関する情報の表示。
新たな投棄物の検出
この
sysdumpdev
コマンドは
、従来の
ダンプタイプまたは
FW支援型
ダンプタイプを含むダンプの種類を提供します。
この
-t
オプションはダンプの種類を指定します。 可能な値は
、traditional
と
fw-assisted
です。
この
-f
オプションは、完全なメモリシステムダンプモードを指定します。 このモードは、ファームウェア支援システム・ダンプの場合のみ該当します。 このモードでは、ダンプはオペレーティングシステムとは独立して実行されます。 パーティションメモリはダンプに保存される。

構文
sysdumpdev -P { -p device | -s device } [ -q ] [ -i ] sysdumpdev [ -p device | -s device ] [ -q ] sysdumpdev [ -d directory | -D directory | -e | -I | [ -k| -K ] | -l | [ -n | -N ] | -p device | -q | -s device | -z ] sysdumpdev [ -i ] sysdumpdev -L { -v | -S device } sysdumpdev [ -t { traditional | fw-assisted } ] [ -f { disallow, allow, require } ]

例
現在のダンプデバイス設定を表示するには、次のコマンドを入力してください：
sysdumpdev -l
コマンド
sysdumpdev
が表示するダンプの種類については、オプションを
-l
参照してください。
次のコマンドを入力して、論理ボリュームを
hd7
プライマリダンプデバイスとして指定します:
sysdumpdev -p /dev/hd7
以下のコマンドを入力して、テープデバイスを
rmt0
セカンダリダンプデバイスとして指定してください:
sysdumpdev -s /dev/rmt0
前回のダンプ実行からの情報を表示するには、次のコマンドを入力してください：
sysdumpdev -L
プライマリダンプデバイスのデータベースオブジェクトを恒久的に変更するには
/dev/newdisk1
、次のコマンドを入力してください：
sysdumpdev -P -p /dev/newdisk1
新しいシステムダンプが存在するかどうかを確認するには、次のコマンドを入力してください：
sysdumpdev -z
最近システムダンプが発生した場合、次のような画面に類似した出力が表示されます：
4537344 /dev/hd7
システムクラッシュ後にダンプがコピーされるディレクトリを指定するには、次のコマンドを入力します（ダンプデバイスが の場合
/dev/hd6
）：
sysdumpdev -d /tmp/dump
システムクラッシュ後にファイル
/dev/hd6
からファイル
/tmp/dump
へダンプをコピーしようとする試み。 コピー中にエラーが発生した場合、システムは起動を継続し、ダンプは失われます。
システムクラッシュ後にダンプがコピーされるディレクトリを指定するには、次のコマンドを入力します（ダンプデバイスが の場合
/dev/hd6
）：
sysdumpdev -D /tmp/dump
このコマンドは、クラッシュ後に
/dev/hd6
ディレクトリから
/tmp/dump
ディレクトリへダンプをコピーしようとします。 コピーが失敗した場合は、メニューが出されます。 このメニューを使用して他の外部メディアに手動でダンプをコピーすることができます。
ダンプデバイスをスキャンしてダンプを検索するには、次のコマンドを入力します:
sysdumpdev -L -S /dev/hd6
