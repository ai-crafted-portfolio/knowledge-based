目的
rootvg
上で基本オペレーティング・システム (
BOS
) の複数のバージョンを作成、更新、および管理します。

説明
multibos
コマンドを使用すると、root ユーザーが
rootvg
ボリューム・グループに基本オペレーティング・システム (BOS) のインスタンスを作成できます。
注:
ミラーリングされた
rootvg
ボリューム・グループに対して
multibos
コマンドを使用することはできません。
multibos
セットアップ操作は、別個のブート論理ボリューム (BLV) からブートするスタンバイ基本オペレーティング・システム (BOS) を作成します。
これにより、所定の
rootvg
上に
BOS
の 2 つのブート可能セットが作成されます。 管理者は、
bootlist
コマンドの引数としてそれぞれの BLV を指定するか、システム・ファームウェアのブート操作を使用して、BOS のいずれかのインスタンスからブートすることができます。 BOS の 2 つのブート可能なインスタンスを同時に維持することができます。 ブート
された BLV に関連する BOS のインスタンスは、
アクティブ
BOS と呼ばれます。 ブートされていない BLV に関連する BOS のインスタンスは、
待機
BOS と呼ばれます。 現在、
rootvg
ごとにサポートされる BOS のインスタンスは 2 つのみです。
multibos
コマンドを使用すると、管理者は、セットアップ時またはそれ以降のカスタマイズ操作時に、スタンバイ
BOS
にアクセスし、その保守レベルとテクノロジー・レベルをインストールし、更新し、カスタマイズすることができます。 スタンバイ
BOS
に保守更新およびテクノロジー更新をインストールしても、アクティブな
BOS
上のシステム・ファイルは変更されません。 これにより、アクティブ BOS が実動状態のままで、スタンバイ
BOS
の並行更新が可能になります。
さらに、
multibos
コマンドは、論理ボリュームとファイルシステムをコピーまたは共用します。 デフォルトでは、
BOS
ファイルシステム (現在は
/
、
/usr
、
/var
、および
/opt
) とブート論理ボリュームがコピーされます。 管理者は、追加の
BOS
オブジェクトのコピーを作成できます (
-L
フラグを使用)。
他のすべてのファイルシステムおよび論理ボリュームは、
BOS
のインスタンス間で共用されます。 分離されているログ・デバイスの論理ボリューム (例えば、ファイルシステム内部に含まれていないもの)
についてコピーはサポートされていませんが共有はされます。

AIXバージョン '6.1と 6100-02 テクノロジーレベル

注:
multibos
コマンドの実行中に、システム活動状況が最小限であることを確認します。
より高いレベルのオペレーティング・システムにとって新規のどの論理ボリューム属性またはファイルシステム属性も、待機インスタンスの作成時にインプリメントされません。その理由は、より低いレベルのオペレーティング・システムはそれらの属性を認識しないためです。

『構文』セクションに示すフラグに加え、
-V
フラグを指定すると、ブート時に inittab から検証操作が実行されます。 このエントリーを変更しないようにすることが重要です。 検証操作を行うと、
multibos
ユーティリティーにより、論理ボリュームとファイルシステムの変更をアクティブ・インスタンスとスタンバイ・インスタンスの間で同期化することができます。 また、このエントリーにより、

mksysb
バックアップのファイルシステム・タイプ (JFS または JFS2) は、

コマンドが実行されるシステムのタイプと同じである必要があります。 例えば、

mksysb
バックアップの
/usr
ファイルシステムも JFS2 ファイルシステムである必要があります。

コマンドの実行後、ログは

ファイルに保管されます。

コマンドを使用してログ・ファイルを表示できます。

multibos -s [ -l 装置 { -a | -f ファイル | -b ファイル | -x (X) ファイル }] [ -e ファイル ] [ -i ファイル ] [ -L ファイル ] [ -p n t N X ] multibos -c -l デバイス { -a | -f ファイル | -b ファイル | -x ファイル } [ -p n N X ] multibos -m [ -p n X ] multibos -u [ -p n X ] multibos -B [ -n t X ] multibos -S [ -n X ] multibos -R [ -p t X ] multibos -C [ VG 名 ] multibos -s -M ファイル [ -p n t N X ]

オプション
フラグ
項目 | 説明
-a | update_all インストール・オプションを指定します。 セットアップとカスタマイズ操作の場合に有効です。
-B | ブート・イメージ作成操作。 スタンバイ・ブート・イメージは、 AIX bosboot コマンドを使用して作成され、スタンバイ BLV に書き込まれます。
-b ファイル | セットアップまたはカスタマイズ操作時にインストールされるインストール・バンドルを指定します。 インストール・バンドルの構文は、 geninstall の規則に従う必要があります。
-c | スタンバイ BOS のソフトウェアのカスタマイズ更新を実行します。
-C VG 名 | rootvg ボリューム・グループのようにリブート時に自動的にオンに構成変更されないボリューム・グループを同期するために、ボリューム・グループを同期に対してオンに構成変更することができます。 multibos -C VG name コマンドは、 multibos コマンドがディスク上に代替ルート・ボリューム・グループ (オペレーティング・システム) を作成してブートした後に、自動的にオフに変更されたボリューム・グループで使用する必要があります。
-e ファイル | セットアップ操作中に除外するアクティブな BOS ファイルを正規表現構文でリストします。
-f ファイル | セットアップまたはカスタマイズ操作時にインストールされる修正情報 (APAR など) をリストします。 リストの構文は、 instfix の規則に従います。
-i ファイル | 現行の rootvg から作成されたデフォルトの image.data ファイルの代わりに使用するオプションの image.data ファイルを指定します。
-L ファイル | スタンバイ BOS に含める追加の論理ボリュームのリストを含むファイルを指定します。
-l 装置 | セットアップまたはカスタマイズ操作時にソフトウェア更新の デバイスまたはディレクトリーをインストールします。
-m | スタンバイ BOS をマウントします。
-M ファイル | mksysb イメージを含むファイルを指定します。 mksysb イメージは、 AIX 6.1 (6100-02 適用) 以降の mksysb -M コマンドを使用して作成されている必要があります。
-N | ブート・イメージ処理をスキップします。 このフラグは、 AIX ブート・プロセスをよく理解している経験のある管理者のみが使用してください。

-n | 失敗時に終結処理を行わないようにします。 このオプションは、操作が失敗した後に multibos データを保持するのに役立ちます。
-p | 所定の操作のプレビューを行います。 セットアップ、除去、マウント、アンマウント 、およびカスタマイズの各操作の場合に有効です。
-R | すべてのスタンバイ BOS オブジェクトを削除します。
-S | スタンバイ BOS ファイル・システムへの chroot アクセスを使用して対話式シェルを開始します。
-s | スタンバイ BOS のインスタンスを作成します。
-t | multibos がブート・リストを変更しないようにします。
-u | スタンバイ BOS をアンマウントします。
-x ファイル | update_all ( -a )、インストール・バンドル・ファイル ( -b )、フィックス・リスト・ファイル ( -f ) などの他のすべてのカスタマイズ・パラメーターの前に、オプションのカスタマイズ・スクリプトを実行します。 スクリプトの絶対パス名を使用する必要があります。
-X | multibos に関連したタスクを実行するためにスペースが必要な場合に、自動ファイル・システム拡張を可能にします。 すべての multibos 操作は、このフラグを指定して実行することをお勧めします。
