目的

ネットワークファイルシステム( NFS )のチューニングパラメータを管理する。

構文

nfso [ -p | -r ] [ -c ] { -o Tunable [ = newvalue ] }

nfso [ -p | -r ] { -d Tunable } 

nfso [ -p | -r ] -D

nfso [ -p | -r ] -a [ -F ] [ -c ]

nfso -h [ Tunable ] 
nfso -l [ hostname ] 
nfso [ -F ] -L [ Tunable ] 
nfso [ -F ] -x [ Tunable ] 
nfso [ -@ WparName ] [ -p | -r ] -a [ -c ]

nfso [ -@ WparName ] [ -p  |  -r ] [ -c ] { -o Tunable [ = newvalue ] }

nfso -H {ha operation}
注： -o、 -d、 -x、 -L のような複数のフラグを使用することができる。

説明

nfso コマンドは NFS チューニング・パラメーターを設定する。 nfso コマンドは、 NFS チューニング・パラメーターの現在または次のブート値を設定または表示する。 このコマンドは、恒久的な変更を加えることも、次の再起動まで変更を延期することもできる。 付随するフラグは、コマンドがパラメーターを設定するか表示するかを決定する。 -o フラグは、パラメーターの値を表示したり、パラメーターに新しい値を設定したりできます。

調整可能なパラメーターを変更した場合の効果
nfso コマンドを誤用すると、システムが操作不能になることがあります。

チューナブル・パラメーターの変更とその目的についての詳細は、チューナブル・ パラメーターのセクションのチューナブル・パラメーターの特性を参照のこと。

調整可能なパラメータの「診断」と「調整」のセクションが、あなたの状況に当てはまることを確認してください。 チューナブル・パラメーターの値を変更することで、システムのパフォーマンスが向上する可能性があります。

Diagnosis（診断）セクションとTuning（チューニング）セクションの両方が「N/A」のみの場合、開発部からの指示がない限り、チューニング可能なパラメータを変更しないでください。 AIX の指示がない限り、調整可能なパラメータを変更しないでください。

-o、 -d、 -D フラグを使用して制限された調整可能パラメータを変更した場合、警告メッセージが表示されます。 警告メッセージは、使用制限タイプの調整可能パラメータが変更されたことを示す。 コマンドラインで -r または -p フラグも指定した場合、制限付きチューナブル・パラメータの変更の確認を求めるプロンプトが表示される。 さらに、システム再起動時に、 /etc/tunables/nextboot ファイルにある制限付き調整可能パラメーターの存在が、デフォルト値とは異なる値に変更される。 この値は、 -r または -p フラグを指定するコマンドラインを使って変更する。 制限された調整可能パラメータを変更すると、変更された調整可能パラメータのリストを特定するエラーログエントリーが発生する。

-o、-d、 -D フラグを使用して、 Mount タイプの調整可能パラメータを変更すると、ユーザーに警告メッセージが表示される。 警告メッセージには、この変更は将来のマウントにのみ有効であると書かれている。

-o、 -d、または -D フラグによる変更、 connect タイプの調整可能パラメータへの変更は、コマンドを再起動する。 inetd コマンドを再起動する。 この変更は将来のソケット接続に対してのみ有効である旨の警告メッセージをユーザに表示する。

互換モード

pre520tune と呼ばれる sys0 属性によって制御される、 5.2 以前の互換モードでチューナブル・パラメータを実行する場合、 Bosboot を除くチューナブル・パラメータのリブート値は意味を持たない。 5.2 以前の互換モードでは、ブート時に適用されません。 詳しくは、 AIX 5.2 互換性モードを参照)。

5.2 （英語）以前の互換モードでは、チューニング・パラメーターへのリブート値の設定は、ブート・シーケンス中に呼び出されるスクリプトにチューニング・コマンドの呼び出しを組み込むことで実現されます。 そのため、 Reboot 型のパラメータは、 -r フラグなしで設定することができ、既存のスクリプトはそのまま動作する。

5.2 以前の互換モードは、マシンを次のように移行するときに自動的にオンになります。 AIX 5L5.2. 完全なインストレーションの場合、この機能はオフになり、調整可能なパラメータのリブート値は、リブートシーケンス中に /etc/tunables/nextboot ファイルの内容を適用することで設定されます。 このモードでのみ、 -r と -p のフラグが完全に機能する。 プリ 5.2 互換モードについての詳細は、『 パフォーマンス・ツール・ガイド＆リファレンス 』の「 カーネル・チューニング 」を参照。

チューナブル・パラメーター

などのチューニング・コマンドで操作されるチューナブル・パラメーター。 no, nfso, vmo, ioo, schedoおよび raso コマンドは、以下の調整可能なパラメーターカテゴリーに分類される：
表2. 調整可能なパラメーターカテゴリー
項目
説明
Dynamic 調整可能なパラメータがいつでも変更できる場合。
Static 調整可能なパラメーターが絶対に変更できない場合。
Reboot 調整可能なパラメータが再起動時にのみ変更可能な場合。
Bosboot 調整可能なパラメータが、 Bosboot コマンドを実行してマシンをリブートすることでしか変更できない場合。
Mount 調整可能なパラメータの変更が、将来のファイルシステムまたはディレクトリマウントにのみ有効な場合。
Incremental チューナブルパラメーターが、ブート時以外はインクリメントしかできない場合。
Connect チューナブルパラメータを変更した場合、その変更は将来のソケット接続に対してのみ有効である。
Deprecated チューナブル・パラメーターの変更が、現在のリリースの AIX.
Bosboot タイプの調整可能パラメータについては、変更が実行されるたびに、チューニングコマンドは自動的に、そのコマンドを実行するかどうかをユーザーに尋ねます。 bosboot コマンドを実行するかどうかを自動的に尋ねる。 Connect、チューニング・コマンドは自動的にデーモンを再起動する。 inetd デーモンを自動的に再起動する。
注： nfso コマンドによって管理される現在の調整可能パラメータ・セットには、 Dynamic、 Mount、 Incremental タイプの調整可能パラメータのみが含まれる。

チューニング

nfs_server_clread
目的
NFS サーバーが積極的にファイルを読めるようにする。 NFS サーバーは、NFS クライアントからの特定の NFS 読み取り要求にしか応答できません。 しかし、 NFS ・サーバーは、現在の読み取り要求の直後に存在するファイルのデータを読み取ることができる。 これは通常、「先読み」と呼ばれます。 NFS サーバーは、デフォルトで「先読み」を実行します。
チューニング
このパラメータは、サーバーのメモリが少なく、ディスクからメモリへのアクティビティが多数行われている場合に有効である。 nfs_server_clread オプションを有効にすると、 NFS サーバーは、 NFS クライアントのリードアヘッドに積極的になる。 チューニング値が 1の場合、積極的な先読みが行われる。 チューニング値が 0の場合、通常のシステム・デフォルトのリード・アヘッド方式が使用される。 通常のシステム・リード・アヘッドは、Virtual machine Manager（VMM：ジャーナ ル・ファイル・システム（JFS）ファイル・システム用）および JFS2 （ JFS2 ファイル・システム用）によって制御される。 このアグレッシブなトップハーフは、 nfs_server_clread オプションでリードアヘッドが有効になっているため、 NFS サーバーのケースでよくある、リクエストの順序がずれているためにリードア ヘッドが破綻することが少ない。 このメカニズムが起動すると、LVMの論理トラックグループサイズである128KBのクラスタ全体を一度に読み込む。
nfs_server_close_delay
目的
予想される遅延がそれほど長くない場合に、 NFS バージョン4サーバーが NFS4ERR_DELAY 応答の送信を避けなければならないかどうかを決定する。 サーバーから NFS4ERR_DELAY レスポンスに遭遇したときにアプリケーションを長時間一時停止する NFS クライアントを使用している場合、サーバーは nfs_server_close_delay オプションを使用してサーバー上で遅延処理を試み、アプリケーションの一時停止を回避する。
チューニング
チューニング値を 0にすると、この機能はオフになる。 チューニングのデフォルト値は 0 である。 チューニング値を 1にすると、サーバー側で短い遅延をローカルに処理できるようになる。
nfs_use_reserved_ports
目的
非予約IPポート番号で指定。
チューニング
チューニング値 0は、 NFS クライアントが NFS サーバーと通信するときに、予約されていないIPポート番号を使用します。
nfs_v3_server_readdirplus
目的
READDIRPLUS コールがサーバーでサポートされているかどうかを判断する。
チューニング
チューニング値 0は、 READDIRPLUS の処理を無効にする。
nfs_v4_fail_over_timeout
目的
NFS バージョン 4 クライアントの操作が、 NFS バージョン 4 サーバーが提供するレプリカにフェイルオーバーするタイムアウト時間を指定します。 タイムアウトの単位は秒。
チューニング
チューニング値として 0 が指定された場合、タイムアウト値は ` TCP ` のタイムアウト値に 4 を掛けた値となります。 1 から 4 までのチューニング値は予約済みであり、 NFS バージョン 4 のクライアントではこれらを 0 として扱います。 NFS バージョン4では、メインサーバーが応答しない場合、クライアントは他のレプリカサーバーにフェイルオーバーできるようになっています。 この値は、クライアントがサーバーからの応答を待つ時間を決定するもので、この時間が経過すると、そのリクエストに関するすべての NFSfsid バージョン4のリクエストが他のレプリカサーバーに切り替えられます。
nfs_v4_persistent_clientid
目的
既存の NFSv4 永続的な clientid 実装を使用するか、最新の 永続的な 実装を使用するかを指定します。
チューニング
このオプションにより、 NFSv4 のクライアントは、 clientid の最新または既存の実装のいずれかを選択することができる。 チューニング値 1が最新の実装をオンにし、チューニング値 0が最新の実装をオフにする。 clientid の最新の実装は、既存の clientid の特徴を継承している。 さらに、 clientid 。 チューニングのデフォルト値は 0 である。 調整可能なパラメータは Mount 型である。
注意： nfs_v4_persistent_clientid チューナブルの値を変更する前に、既存の NFSv4 マウントをすべてアンマウントしてください。
portcheck
目的
NFS リクエストが特権ポートから発信されているかどうかをチェックする。
チューニング
チューニング値 0は、 NFS サーバーが行うポートチェックを無効にします。 チューニング値 1を指定すると、 NFS サーバーは、受信する NFS リクエストのポートをチェックするようになる。 これは、最低限のパフォーマンス結果を伴う構成決定です。
server_delegation
目的
NFS バージョン 4 サーバーが、開いているファイルに対して読み取り委任を発行するかどうかを決定する。
チューニング
調整値 0は、委任の許可を無効にする。 チューニング値 1を指定すると、デリゲーションが有効になる。
utf8_validation
目的
NFS バージョン4のクライアントとサーバーが、 UTF-8 の文字列データが正しいかどうかをチェックするかどうかを決定する。
チューニング
チューニング値 0は、 UTF-8 のチェックを無効にする。 チューニング値を 1にすると、 UTF-8 のチェックが有効になる。
gss_window
目的
GSS（Generic Security Service）ウィンドウサイズのチェックを有効または無効にする。
チューニング
チューニング値 0は、GSSウィンドウサイズチェックを無効にする。 チューニング値を 1にすると、GSSウィンドウ・サイズのチェックが有効になる。 チューニングのデフォルト値は 1。

例

  1. portcheck チューナブル・パラメーターの値をゼロに設定するには、以下のコマンドを入力する：
    nfso -o portcheck=0
  2. 次回の再起動時に udpchecksum tunable パラメータをデフォルト値の 1 に設定するには、以下のコマンドを入力します：
    nfso -r -d udpchecksum
  3. すべての調整可能なパラメーターとその現在の値のリストをコロン区切りのフォーマットで表示するには、以下のコマンドを入力する：
    nfso -a -c
  4. nfso コマンドが管理するチューナブル・パラメーターの現在値およびリブート値、範囲、単位、タイプ、依存関係を一覧表示するには、以下のコマンドを入力します：
     nfso -L
  5. nfs_tcp_duplicate_cache_size パラメーターのヘルプ情報を表示するには、以下のコマンドを入力する：
    nfso -h nfs_tcp_duplicate_cache_size
  6. nfs_dynamic_retrans パラメータを恒久的にオフにするには、以下のコマンドを入力する：
    nfso -p -o nfs_dynamic_retrans=0
  7. NFS チューニング・パラメーターのリブート値を一覧表示するには、以下のコマンドを入力する：
    nfso -r -a
  8. nfso コマンドが管理するチューナブル・パラメーターの現在およびリブート値、範囲、単位、タイプ、依存関係をスプレッドシート形式で一覧表示するには、以下のコマンドを入力します：
    nfso -x
