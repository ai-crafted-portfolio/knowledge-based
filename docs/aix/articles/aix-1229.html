目的

RAS (Reliability (信頼性)、Availability (可用性)、Serviceability (保守性)) の各パラメーターを管理します。

構文

raso [-p | -r [-K]] [-y] [-o Tunable [= Newvalue] ]
raso [-p | -r [-K]] [-y] [-d Tunable]
raso [-p] [-r [-K]] [-y] -D
raso [-p] [-r | -K] [-F] -a
raso -h [Tunable]
raso [-F] [-K] -L [Tunable]
raso [-F] [-K] -x [Tunable]
注: 複数の -o、 -d、 -x、および -L フラグを指定できます。

説明

注: raso コマンドには root 権限が必要です。

raso コマンドは、信頼性、可用性、保守性のチューニング・パラメーターを構成するために使用します。 raso コマンドは、すべての RAS チューニング・パラメーターの現行値または次のブート値を設定または表示します。 raso コマンドを使用して、永続的な変更を行ったり、次のリブートまで変更を延期したりすることもできます。 指定されたフラグは、 raso コマンドがパラメーターを設定または表示するかどうかを決定します。 -o フラグを使用して、パラメーターの現行値を表示したり、パラメーターに新しい値を設定したりすることができます。

チューナブル・パラメーターの変更の影響を理解する

raso コマンドを誤用すると、パフォーマンスが低下したり、オペレーティング・システムの障害が発生したりする可能性があります。 チューナブル・パラメータを変更する前に、まず「チューナブル・パラメータ」のセクションでパラメータのすべての特性を読み、パラメータの目的を完全に理解してください。 そして、このパラメータに関する「診断」と「チューニング」のセクションがあなたの状況に当てはまること、およびこのパラメータの値を変更することでシステムのパフォーマンスが向上することを確認してください。 Diagnosis（診断）」セクションと「Tuning（調整）」セクションの両方に「N/A」しかない場合は、AIX開発部からの指示がない限り、パラメータを変更しないことをお勧めします。

チューナブル・パラメーターのタイプ

チューニング・コマンド（「no、「nfso、「vmo、「ioo、「schedo、「raso）によって操作されるすべての調整可能なパラメーターは、これらのカテゴリーに分類される：
項目
説明
Dynamic パラメーターをいつでも変更できる場合
Static パラメーターをいかなる時にでも変更できない場合
Reboot パラメーターをリブート時にのみ変更できる場合
Bosboot bosboot を実行してマシンをリブートすることによってのみパラメーターを変更できる場合
Mount パラメーターの変更が将来のファイルシステムまたはディレクトリーのマウントにのみ有効である場合
Incremental ブート時を除き、 パラメーターを増やすことが可能な場合
Connect パラメーターの変更が将来のソケット接続にのみ有効である場合。 パラメーターは Bosboot タイプでなければなりません。
タイプ Bosboot のパラメーターの場合は、変更が加えられるたびに、 チューニング・コマンドは自動的に、 bosboot コマンドを実行したいかどうかを尋ねるプロンプトを出します。 タイプ Connect のパラメーターの場合は、チューニング・コマンドは自動的に inetd デーモンを再始動します。

現在「schedoコマンドで管理されているパラメーターは、DynamicタイプとRebootタイプのみである。

互換モード

sys 0の'pre520tune属性によって制御される5.2以前の互換モードで'rasoコマンドを実行する場合、このモードでは、Bosboot型を除くパラメータのリブート値は、ブート時に適用されないため、考慮されない。 詳細については、パフォーマンス管理ガイドのクライアントNFSチューニングを/span>のを参照してください。

5.2以前の互換モードでは、チューニングパラメータへのリブート値の設定は、ブートシーケンス中に呼び出されるスクリプトにチューニングコマンドの呼び出しを埋め込むことで実現されます。 したがって、「Reboot型のパラメータは、「-rフラグを付けずに設定することができ、既存のスクリプトはそのまま動作する。

このモードは、マシンがAIX 5.22にMIGRATEDされると自動的にオンになる。 完全なインストールの場合、これは OFF になり、パラメーターのリブート値は、 リブート中に /etc/tunables/nextboot ファイルの内容を適用することにより設定されます。 このモードでのみ、「-r」と「-pフラグが完全に機能する。 詳細については、『パフォーマンス・ツール・ガイド＆リファレンス』の「カーネル・チューニング」を参照してください。
