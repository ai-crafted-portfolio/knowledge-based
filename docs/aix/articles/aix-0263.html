目的

ボリュームグループ（VG）の特性を設定します。

構文

chvg [-s Sync {y|n}][-h Hotspare {y|Y|n|r}][-a AutoOn {y|n}][-c|-l] [-L LTGSize][-Q {y|n}][-X {none|SSD}][-u][-r {y|n}][-x {y|n}][-S|-R][-t [factor]][-B|-G][-P][-v][-C][-f][-g][-b {y|n}][-I][-O {y|n}][-M {y|n|s}][-N o|n][-j {y|n}][-e y|n][-k y|n] VolumeGroup

説明

chvg コマンドはVGの特性を変更する。 このコマンドは、System Management Interface Tool (SMIT) smit chvg 高速パスを使用して実行することもできます。

フラグ

注:
  1. スナップショットVGを持つVGでは、 -a、 -R、 -S、 -u、 -h のオプションのみが許可される。
  2. スナップショットVGでは、 -a、 -R、 -S、 -u のオプションのみが使用可能です。
  3. VGをビッグVGフォーマット (-B flag) またはスケーラブルVGフォーマット (-G flag) に変更し、データ暗号化オプション (-k flag) を指定することは、他の変更操作と組み合わせることはできない。
  4. 4KBブロックの物理ボリュームで作成されたVGでは、バッドブロックリロケーションポリシーがサポートされません。
項目
説明
-a AutoOn システム起動時にVGを自動的に起動するかどうかを決定する。 以下の値は AutoOn 変数に有効な値です：
y
VGはシステム起動時に自動的に起動する。
n
VGはシステム起動時には自動的に起動しない。
-b VGの不良ブロック再配置ポリシーを設定する。 デフォルト値はyです。
y
VGの不良ブロック再配置ポリシーをオンにする。
n
VGの不良ブロック再配置ポリシーをオフにする。
-B VGを、最大128の物理ボリュームと512の論理ボリュームを収容するBig VGフォーマットに変更します。
注:
  1. -B フラグは、不整合物理区画がある場合は、使用 できません。
  2. 一度変換されたVGは、 AIX バージョン 6.1 または以前のバージョンにインポートすることはできません。
  3. コンカレント・モードでVGが変化している場合、 -B フラグは使用できない。
  4. 操作を成功させるには、各物理ボリュームにボリューム・グループ記述子領域（VGDA）の拡張に十分な空きパーティションがなければなりません。
  5. VGDA はディスクのエッジにあり、拡張のための連続スペースを必要とするので、空き区画はディスクのエッジに必要です。 これらのパーティションがユーザー用に割り当てられている場合、同じディスク上の他の空きパーティションに移行される。 残りの物理パーティションは、VGディスクリプタ領域（VGDA）使用のためのパーティションの損失を反映して、番号が変更される。 これにより、このVGのすべての物理ボリュームの論理パーティションと物理パーティションのマッピングが変更されます。 論理ボリュームのマッピングがリカバリ操作の可能性のために保存されている場合、変換操作の完了後にマップを再度生成する必要があります。 また、マップオプションを使用してVGのバックアップを取得し、そのマップを使用してリストアを計画している場合、パーティション番号が（削減により）存在しなくなる可能性があるため、リストア操作が失敗する可能性があります。 マップオプションを使用する場合は、変換前と変換直後にバックアップを取ることをお勧めします。
  6. VGDA領域が大幅に増加するため、VGDAの更新操作（論理ボリュームの作成と変更、物理ボリュームの追加など）のたびに実行時間がかかる可能性があります。
-c -C フラグと同じです。 AIX バージョン 6.1 以降では、エンハンスド・コンカレント・ケイパブル VG のみが作成される。
-C VG を Enhanced Concurrent Capable VG に変更する。 ノンコンカレントモードでオンになっているVGをエンハンスド・コンカレント・ケイパブルに変更する。 このため、エンハンスド・コンカレント・モードでアクティブ化する前に、他のすべてのノードにVGを再インポートする必要がある。 コンカレントモードでオンになっているVGをエンハンスドコンカレントモードVGに変更する。 -C フラグは PowerHA SystemMirror ES. HACMP ES製品を使用していないVGやシステムには影響しません。

エンハンスド・コンカレントVGはグループ・サービスを使用する。 グループ・サービスは PowerHA SystemMirror ESに同梱されており、このモードでVGをアクティブにする前に設定する必要がある。

このフラグを使用して、VGを拡張同時接続可能VGに変更する。
注:
  1. エンハンスド・コンカレントVGはグループ・サービスを使用する。 グループ・サービスは HACMP ESに同梱されており、このモードでVGをアクティブにする前に設定する必要がある。
  2. 64ビットカーネルで実行する場合は、エンハンスド・コンカレント・ケイパブルVGのみがサポートされる。 64ビットカーネルで実行する場合、コンカレント・ケーパブルVGはサポートされない。
  3. Enhanced Concurrent Capable VGは、常にマルチノード・バリエーション・プロテクションが有効になっています。 マルチノード・バリエーション・プロテクションの詳細については -N フラグを参照してください。
-e はい | いいえ VG の Critical PVs オプションを有効にする。 このフラグは、 IBM® AIX® 7.2 テクノロジーレベル（TL）1以降で使用可能。
y
VG の Critical PVs オプションを有効にする。 ミラー化された論理ボリュームで書き込み要求の失敗が発生すると、物理ボリュームは欠落としてマークされ、失敗したミラー化された論理ボリュームへのI/O要求の送信を停止します。 もし Critical PVs オプションが VG で有効になっている場合、 TL 1 以降を搭載した IBM AIX 7.2 に VG のみをインポートできます。
n
Critical PVs オプションは使用されません。 これはデフォルト値です。
-f 物理ボリュームがデバイス構成データベース内の別のVGの一部であるか、アクティブなVGでない限り、指定された物理ボリューム上にVGを強制的に作成します。
-g VG内のすべてのディスクを調べ、サイズが大きくなっているかどうかを確認する。 ディスクのサイズが大きくなった場合、VGは物理ボリュームに物理パーティションを追加しようとします。 必要に応じて、適切な1016倍を決定し、ビッグVGに変換する。
注： ディスクのサイズ変更を確認するには、論理ボリューム・マネージャー（LVM）用の VG で varyoffvg コマンドを実行し、次に varyonvg コマンドを実行する必要があるかもしれません。
-G VGをスケーラブルVGフォーマットに変更する。 こうすれば、最大 で 1024 個の物理ボリュームと 4096 個の論理ボリュームを収容できます。
注:
  1. -G フラグは、不整合物理区画がある場合は、使用 できません。
  2. 一度変換されたVGは、 AIX バージョン 6.1 またはそれ以下のバージョンにはインポートできません。
  3. -G フラグは、VGがオンになっている場合にのみ使用できる。
  4. この操作を正常に実行するためには、VGDA 拡張用の各物理ボリュームに、使用可能な空き区画が十分にある必要があります。
  5. VGDA はディスクのエッジにあり、拡張のための連続スペースを必要とするので、空き区画はディスクのエッジに必要です。 これらのパーティションがユーザー用に割り当てられている場合、同じディスク上の他の空きパーティションに移行される。 残りの物理区画は、VGDA 用に区画が減少したことを反映するために、番号が振り直されます。 これにより、このVGのすべての物理ボリュームの論理パーティションと物理パーティションのマッピングが変更されます。 論理ボリュームのマッピングを回復操作の可能性のために保存している場合は、変換操作の完了後にマップを再度生成する必要があります。 また、マップオプションを使用してVGのバックアップを取得し、そのマップを使用してリストアを計画している場合、パーティション番号が（削減により）存在しなくなる可能性があるため、リストア操作が失敗する可能性があります。 マップオプションを使用する場合は、変換前と変換直後にバックアップを取ることをお勧めします。
  6. VGDA領域が大幅に増加するため、すべてのVGDA更新操作（論理ボリュームの作成、論理ボリュームの変更、物理ボリュームの追加など）の実行にかなりの時間がかかる可能性があります。
  7. 既存のVGをスケーラブルVGフォーマットに変更すると、以前のサブタイプに関係なく、関連するすべての論理ボリュームのデバイスサブタイプ（IOCINFO ioctl() コールで報告される）がDS_LVZに変更されます。 この変更は、報告されたサブタイプを超える論理ボリュームの動作を変更するものではない。
-h hotspare パラメータで指定されたVGのスペア特性を設定する。 VolumeGroup パラメータで指定されたVGのスペアリング特性を設定する。 障害ディスクの自動マイグレーションを許可する （y ）か、または障害ディスクの自動マイグレーションを禁止する （n ）。 このフラグは、ミラーリングされていない論理ボリュームには何ら影響しません。
y
故障ディスクからスペアディスクへのパーティションの1対1の移行を許可することにより、故障ディスクの自動移行を強化する。 VG スペアプールの中で、1 対 1 の移行に十分な大きさの最小のディスクが使用される。
Y
故障したディスクの自動移行を許可し、パーティションのスペアへの1対1の移行とは対照的に、スペアディスクのプール全体への移行を許可する。
n
失敗したディスクの自動マイグレーションを禁止します。 これはVGのデフォルト値である。
r
VG の Hotspare プールからすべてのディスクを削除します。
注： このフラグはコンカレント可能なVGではサポートされていない。
-I AIX バージョン 6.1 にインポートできるように VG を修正する。 LTGSize は、VG が AIX バージョン 6.1 より前に作成されたものとして動作する。 ストリップサイズ(ストリップサイズにアレイ内のディスク数を掛けたものがストリップサイズとなる)が AIX バージョン 6.1 でサポートされているストリップサイズより大きいストライピングされた論理ボリュームがVGに含まれている場合、この操作は失敗する可能性があります。 AIX バージョン 6.1 でサポートされているストリップサイズより大きいストリップサイズで論理ボリュームを作成した場合、 AIX バージョン 6.1 に VG をインポートすることはできません。
-j はい | いいえ Enhanced Journaled File System ( JFS2 ) がマウントされている場合、LVMの再同期操作は、 JFS2 によってのみ割り当てられるブロックを再同期します。 このフラグに指定できる値は以下のとおりです。
y
JFS2 によって割り振られたブロックのみを再同期します。
n
JFS2 のブロック割り当てに関係なく、すべてのブロックを再同期する。 これはデフォルト値です。
-k はい | いいえ VGのデータ暗号化オプションを変更する。 -k フラグは、 IBM AIX 7.2 (テクノロジー・レベル 5)以降で使用できます。 このフラグに指定できる値は以下のとおりです。
y
VGのデータ暗号化オプションを変更する。 VG でデータ暗号化オプションが有効になっている場合、その VG を IBM AIX 7.2 (テクノロジーレベル 5 以降)が稼働している AIX 論理パーティション (LPAR) にインポートすることができます。
n
VGのデータ暗号化オプションを無効にする。
注:
  • -k フラグは rootvg では使用できません。
  • この操作が正常に完了するためには、暗号化メタデータ用に十分な空き区画が各物理ボリュームに必要です。
  • 暗号化メタデータはディスク・セクターの終わりにあり、拡張のために連続スペースを必要とします。 そのため、ディスク・セクターの終わりには空き区画が必要です。 区画が使用中か、論理ボリュームに割り振られている場合、論理区画は同じディスク上の他の空き区画に移行されます。 物理ボリューム上の残りの物理区画は、暗号化メタデータ使用のための区画がなくなると、再番号付けされます。 この再番号付けによって、VG のすべての物理ボリュームでの論理区画から物理区画へのマッピングが変わる可能性があります。 回復操作用に論理ボリュームのマッピングを保存していた場合は、データ暗号化オプションを変更した後にマップを再作成する必要があります。 また、マップオプションを使用してVGのバックアップを保存し、そのマップを使用してVGをリストアしようと計画している場合、物理パーティションのリナンバリングによりパーティション番号が存在しない可能性があるため、リストア操作が失敗する可能性があります。 ベスト・プラクティスとしては、マップ・オプションを使用している場合に、データ暗号化オプションを変更する前と後とで、VG をバックアップしてください。

VGでデータ暗号化を有効にすると、ディスクの終端セクタにディスク領域が確保される。 暗号化メタデータ用に十分な空き領域を確保するため、ディスクの終端セクタにある物理パーティションをいくつか取り戻す。 必要な物理パーティションが使用中の場合、 chvg コマンドはエラーを返します。

VGでデータ暗号化を無効にすると、その操作の有効性がチェックされる。 VGに暗号化された論理ボリュームが含まれている場合、 chvg コマンドはエラーを返します。
-l VGをNon-Concurrent Capable VGに変更する。 このコマンドを有効にするためには、VGが非同時モードでオンになっていなければならない。
-L AIX Version 6.1 で作成されたVGについては、 -L フラグは無視される。 VGが変化したとき、論理トラックグループサイズはディスクの共通の最大転送サイズに設定される。

AIX バージョン 6.1 より前に作成された VG の場合、 -L フラグは VG の論理トラック・グループ・サイズ（キロバイト数）を変更する。 LTGSize パラメーターの値は、0、128、256、512、または 1024 でなければなりません。 さらに、VG内のすべてのディスクの最大転送サイズ以下でなければならない。 デフォルトのサイズは 128 キロバイトです。 LTGSize が 0 の場合、次の varyonvg は論理トラックグループサイズをディスクの共通最大転送サイズに設定する。
-M VGのミラープールの厳密性を変更する。
y
VGに作成される各論理ボリュームコピーは、ミラープールに割り当てられなければならない。
n
ミラープールのユーザーに制限はない。 これはデフォルト値です。
s
VGでは超厳格なミラープールが実施されている。
注:
  1. ローカル物理ボリュームおよびリモート物理ボリュームは同一のミラー・プールに所属できません。
  2. VGには最大3つのミラープールを設置できる。
  3. 各ミラープールには、VG内の各論理ボリュームのコピーが少なくとも1つ含まれていなければならない。
-N o | n
o
複数のノードで同時に非同期モードで変動することを許可するVGを変更する。
n
複数のノードで同時に非同期モードで変動することを禁止するVGを変更する。
注:
  • このフラグをサポートしない AIX のバージョンには、その VG をインポートできなくなります。
  • このオプションは、コンカレント・モードでオンになっているVGでは利用できない。
-O はい | いいえ VGの無限リトライオプションを変更する。
y
VGの無限リトライオプションを有効にする。 失敗した入出力要求は、成功するまで再試行されます。
n
VGの無限リトライオプションを無効にする。 VG上の失敗したI/Oは再試行されない。 このことは論理ボリュームの厳密再試行オプションには影響しません。
注： GLVM（Geographic Logical Volume Manager）環境では、無限再試行はサポートされません。
-P PhysicalPartitions VGが収容できる物理パーティション数を増やす。 変数 PhysicalPartitions 変数の有効値は 64k, 128k, 256k, 512k, 768k, 1024k, および 2048k である。 値は、 64k、 64K、64、65536など、さまざまな形式で表すことができる。 この値は、VGが収容できる現在の物理パーティション数より大きくなければならない。 このオプションはスケーラブルタイプのVGでのみ有効である。
-Q 物理ボリュームのクォーラムを失った後、VGを自動的にオフにするかどうかを決定します。 この変更は直ちに有効になります。
n
VGは、その物理ボリュームをすべて失うまでアクティブなままである。
y
物理ボリュームのクォーラムを失うと、VGは自動的にオフになる。 この値はデフォルト値です。
-X なし ｜ SSD VGの物理ボリュームタイプの制限を設定または変更します。 物理ボリュームの制限がオンになると、物理ボリュームタイプの制限をサポートしていないバージョンの AIX では、VG をインポートできなくなります。 物理ボリューム制限VGでの -I フラグの使用は禁止されている。
なし
VGの物理ボリュームタイプの制限を削除します。 このフラグは、VGが以前に物理ボリューム制限を受けていなかった場合には、何の効果もない。
SSD
基礎となるディスクがすべてSSDタイプである場合、VGに物理ボリュームタイプの制限を設けます。 VG内の既存の物理ボリュームの1つ以上が制限を満たしていない場合、エラーメッセージを表示します。
-r はい | いいえ VGのクリティカルオプションを変更する。
n
VGのクリティカルVGオプションを無効にする。
y
VGのクリティカルVGオプションを有効にする。 VGがクリティカルVGに設定されている場合、I/O要求に失敗すると、LVMメタデータの書き込み処理が開始され、I/O失敗を返す前にディスクの状態がチェックされます。 クリティカルVGオプションがrootvgに設定されていて、VGがクォーラムのディスクセット（クォーラムが無効な場合はすべてのディスク）へのアクセスを失った場合、VGをオフライン状態に移行する代わりに、ノードがクラッシュし、コンソールにメッセージが表示されます。
注:
  • クリティカル VG は、-r フラグをサポートしていないバージョンの AIX にはインポートできなくなっています。
  • クリティカルVGオプションは、コンカレント・モードでオンになっているVGでは使用できない。
-R VGの通常のI/O操作を再開する。
-s 同期 パラメータで指定されたVGの同期特性を設定する。 VolumeGroup パラメータで指定されたVGの同期特性を設定します。 不整合区画の自動同期を許可する (y) か、 (n) 禁止します。 このフラグは、ミラーリングされていない論理ボリュームには何ら影響しません。 自動同期は、LVMデバイス・ドライバが errpt で LVM_SA_STALEPP を記録した後にのみ試行されるリカバリ・メカニズムである。 他のパス（たとえば、 mklvcopy ）によってステアになったパーティションは、自動的に再同期されません。
y
不整合区画を自動的に同期化しようとします。
n
不整合区画の自動同期を禁止します。 このオプションはVGのデフォルトである。
注： このフラグはコンカレント可能なVGではサポートされていない。
-S このVGのI/Oをドレインし、将来のI/Oを一時停止する。
-t 要因 物理ボリュームあたりの物理パーティション数の上限を変更する。 factorの値は、32ディスクVGの場合は1以上16以下、128ディスクVGの場合は1以上64以下でなければならない。

factorが提供されない場合、VG内の最大ディスクの物理パーティション数が factorと 1016の積より小さくなるような最小値に設定される。

factorが指定された場合、このVGの物理ボリュームあたりの物理パーティションの最大数は、 factorと 1016の積に変更されます。

注:
  1. このオプションはスケーラブルタイプのVGでは無視される。
  2. VG内に古い物理パーティションがある場合、 factorの値を変更することはできません。
  3. このフラグは、コンカレント・モードでVGが変化している場合には使用できない。
  4. このVGに含めることができる物理ボリュームの最大数は、物理ボリュームの最大数（MAXPVS）を因子変数の指定値で割った値に減少する。
  5. 既存のVGをスケーラブルVGフォーマットに変更すると、以前のサブタイプに関係なく、関連するすべての論理ボリュームのデバイスサブタイプ（IOCINFO ioctl() コールで報告される）がDS_LVZに変更されます。 この変更は、報告されたサブタイプを超える論理ボリュームの動作を変更するものではない。
-u VGのロックを解除する。 このオプションは、他のLVM操作の異常終了（コマンドコアのダンプやシステムのクラッシュなど）によってVGがロック状態になった場合に提供されます。
注： -u フラグを使用する前に、VG が他の LVM コマンドで使用されていないことを確認すること。
-v LogicalVolumes 作成できる論理ボリューム数を 増やします。 有効値は 512、1024、2048、および 4096 です。 この値は現在値より大きくなければならない。 このオプションはスケーラブルタイプのVGでのみ有効である。
-x コンカレント可能なVGがオンに変化するモードを変更する。 このコマンドを有効にするためには、VGが非同時モードでオンになっていなければならない。
注： エンハンスド・コンカレント・ケイパブルVGの自動サポートはありません。 AIX バージョン 6.1 以降では、エンハンスド・コンカレント・ケイパブル VG のみが作成されます。
y
コンカレント・モードでVGをオートバリオン。
n
無交流モードでVGをオートバリオン。
注： VGがConcurrent Capableに作成されていない場合、このコマンドはVGに影響しません。
VGのコンカレンシーへの自動バリオンを有効にするには、 /etc/inittab ：
rc_clvmv:2:wait:/usr/sbin/clvm_cfg 2>&1
注意： このエントリーは、 srcmstr を開始するために使用されるエントリーの後に追加されなければならない。

例

  1. システム起動時にVG vg03 を自動的に起動させるには、以下のコマンドを入力する：
    chvg -a y vg03
  2. VG vg03 が物理ボリュームあたり1016個の物理パーティション制限に違反している場合に、サポートされる状態に変更するには、次のコマンドを入力します：
    chvg -t vg03
  3. 物理ボリュームあたりの物理パーティションの最大数を2032に変更し、VG vg03 の物理ボリュームの最大数を16に変更するには、次のコマンドを入力します：
    chvg -t 2 vg03
