目的

First Failure Data Capture 実行環境を確立し、継承します。

構文

BourneおよびKornシェルの場合
 /opt/rsct/bin/fcinit.sh [ [ -l ] [ -s {c | i } ] ] | [ -h ]
Cシェルの場合
source /opt/rsct/bin/fcinit.csh [ [ -l ] [ -s { c | i } ] ] | [ -h ]

説明

このインターフェイスは、AIXエラーログ、BSD システムログ、または FFDC エラースタックに情報を記録するために FFDC インターフェイスを使用したいスクリプトプログラムによって使用されなければならない。

アプリケーションでは、次のいずれかの理由で FFDC 環境を確立する必要がある場合があります。

  • スクリプトは、AIXエラーログ。 スクリプトはfcinit基本的なFFDC環境を確立する
  • スクリプト自身、およびスクリプト自身によって作成されたすべての子孫プロセス または子プロセスを使用して、障害情報を FFDC エラー・スタックに記録したい場合。 この場合、スクリプトは、複数の「下位レベル」アプリケーションを作成する「最上位レベル」アプリケーションであるとみなされ、「最上位レベル」アプリケーションの成功は、これらの「下位レベル」アプリケーションの成功に依存します。 使用する場合fcinitこの方法では、プロセスは確立するまたは作成するFFDC エラー スタック環境。
  • スクリプトは、これらのデバイスに記録される障害情報またはトレース情報を必要とする祖先プロセスによってスクリプトが呼び出された場合にのみ、FFDC エラー スタックまたは FFDC トレースを使用します。 つまり、それ以外のときは、 スクリプトでこれらのデバイスを使用したくない場合です。 使用する場合fcinitこの方法では、プロセスは継承するFFDC エラー スタック環境。

FFDC インターフェースを介して AIX エラー・ログまたは BSD システム・ログに情報を記録するプロセスは、FFDC 環境を確立する必要があります。 プロセス が FFDC エラー・スタックを利用したくない場合、このプロセスは、 FFDC エラー・スタックを利用しない基本 FFDC 環境を確立することができます。 プロセスが、プロセス自身、プロセスが作成するすべてのスレッド、 およびプロセスが作成するすべての子孫プロセスからの障害情報を、FFDC エラー・スタックに 記録したい場合は、FFDC エラー・スタックを含む FFDC エラー・スタック環境がこの プロセスによって確立されます。 アンFFDC エラー スタック環境FFDC エラー スタックを含む は、そのプロセスが FFDC エラー スタック ファイルに障害情報を記録する場合、そのプロセスが継承されます。ただし、そのプロセスが FFDC エラー スタック ファイルに障害情報を記録するのは、そのプロセスが属する祖先の 1 つに対してそのように要求された場合のみです。それ以外の場合、プロセスは FFDC エラー スタックに障害情報を記録しません。

FFDCエラースタック環境にはFFDCエラースタックが含まれており、FFDCエラースタックファイルを予約して、障害情報をファイルに記録します。/var/adm/ffdc/stacksディレクトリ。 これらのファイルでは、script_name.PID.date_and_time の 命名フォーマットが使用されます。script_name はスクリプト自身の 名前、PID はスクリプトのプロセス ID、date_and_time は、 スクリプトが実行されたときの日付/時刻です。 このスクリプトまたはこのスクリプトの子プロセスが FFDC エラー スタックに障害情報を記録するたびに、このファイルに記録されます。

プロセスによってFFDCエラースタックに情報が記録されるためには、プロセスはfcpushstkFFDC インターフェースであり、プロセスは確立された FFDC エラー スタック環境内で動作している必要があります。 FFDCエラースタック環境が存在しない場合、またはfcpushstkFFDC エラー スタック環境が存在するときにインターフェイスが使用されない場合、そのプロセスによって FFDC エラー スタックに情報が記録されません。 この機能を使用すると、障害デバッグ情報が不必要なときに、プロセスを通常モードまたは 「サイレント」モードで実行することができます。ただし、プロセスが特別なデバッグ環境 内で呼び出されたときには、この情報を入手することもできます。

fcinitFFDCクライアントのプロセス環境内で実行する必要があります（sourced ) を実行して、スクリプトの FFDC 環境を適切に設定します。 このコマンドを使用するスクリプトベースのFFDCクライアントは、fcinitクライアントのプロセス イメージ内で実行します。 これを行わないと、FFDC インターフェースは独自のプロセス イメージ内で実行され、FFDC インターフェースが完了した後に FFDC 環境の設定はすべて失われます。 スクリプトベースのアプリケーションがどのようにsourceのfcinitコマンドを使用すると、Korn Shell プログラムは次の命令を発行できます。

. fcinit.sh <options and arguments>

AC シェル スクリプトは次の操作を実行できます。

source fcinit.csh <options and arguments>

fclogerr FFDC インターフェースを使用するプロセスは、 FFDC 環境 を確立する必要があります。 プロセスが fclogerr インターフェースだけを使用したい場合は、 FFDC エラー・スタックのない FFDC 環境 を確立することができます。

スクリプトが FFDC 環境を作成しようとしたときに FFDC 環境が存在する場合、スクリプトは独自の FFDC 環境を作成するのではなく、既存の FFDC 環境を継承します。

フラグ

-h
ヘルプ・メッセージを標準出力に表示し、終了します。 指定したオプションにかかわりなく、 それ以外の処理は実行されません。
-l
プロセスがAIXエラー ログのみ。 このオプションは、-sオプションが指定されている場合は、AIXエラー ログは FFDC エラー スタック環境内で許可されます。
-s
FFDC エラー・スタック環境を確立することを指示します。 利用を希望する申請fcpushstkインターフェースはこのフラグを指定する必要があります。 このコマンド が正常に完了すると、FFDC エラー・スタック・ファイルが、スクリプト用 に /var/adm/ffdc/stacks ディレクトリーに確保されます。 このフラグは、指定可能な次の 2 つのオプションのどちらか 1 つと一緒に指定する必要があります。
c
FFDCエラースタック環境が作成した。 FFDC エラー スタック環境が祖先プロセスによって作成されていない場合は、作成されます。 そのような環境が以前に祖先プロセスによって作成された場合、このプロセスは継承するFFDCエラースタック環境は、iオプションが指定されます。
i
FFDC エラー・スタック環境が祖先プロセスによって既に確立されている場合は、 それを 継承 するように指定します。 FFDC エラー・スタック環境が以前に祖先プロセスによって確立されていなかった場合、このプロセスに対して FFDC エラー・スタック環境は確立されません。このプロセスは FFDC エラー・スタックを使用できません (ただし、 AIX エラー・ログおよび BSD システム・ログを使用できます)。

パラメーター

file_name
FFDC 障害 ID の検索対象となるファイルの名前。 複数のファイルを指定することができます。 ファイル名が指定されていない場合は、fcfilter標準入力から読み取ります。

終了状況

fcinit完了時に次の終了ステータス コードを返します。

0
FFDC 環境が正常に確立されました。
1
FFDC 環境が正常に継承されました。
※2
ヘルプ情報が表示され、処理が終了します。

fcinit失敗を検出すると、次の終了ステータス コードを返します。

12
FFDC 環境が確立または継承されていません - 不明な関数パラメータが指定されました。
13
FFDC エラー スタック環境が確立または継承されていません - 呼び出し元は、FFDC 環境を作成して継承する必要があることを示しました。
14
この呼び出しで FFDC 環境が確立されませんでした - 呼び出し側は、 自分のために、既に FFDC 環境を確立しています - 複数回このルーチンが実行されている 可能性があります。
15
FFDC エラー スタック環境が確立または継承されていません - FFDC エラー スタック環境が存在せず、FC_INHERIT オプションが指定されました。
16
FFDC 環境が確立または継承されていません。クライアントのプロセス環境はこのルーチンによって変更されない可能性があります。
17
FFDC 環境が確立または継承されていません。FFDC 環境は破損している可能性があり、使用できないと見なす必要があります。
18
FFDC 環境が確立または継承されていない - ルーチンは、クライアントのプロセス環境を変更するために必要なメモリを割り当てない可能性があります。
19
FFDC エラー スタック環境が確立または継承されていません - 呼び出しプロセス用の FFDC エラー スタック ファイルを予約できません - FFDC エラー スタック ディレクトリが存在しないか、使用できません。
21
FFDC エラー スタック環境が確立または継承されていません - 呼び出しプロセス用の FFDC エラー スタック ファイルを予約できません - ファイルは存在します
  42
FFDC エラー スタック環境が確立または継承されていません。FFDC エラー スタックの作成と使用はシステム管理者によって無効にされています。 スクリプトは、 AIX エラー・ログおよび BSD システム・ログを使用する基本 FFDC 環境のみを確立できます。

FFDC環境が確立または継承されていない - 予期しない内部障害が発生しましたfcinit。 この状態のときは、お客様は注意する必要があります。また、 アプリケーション・サポート・サービスが必要となる場合があります。

例

AIX エラー・ログおよび BSD システム・ログのみを使用するための基本 FFDC 環境を確立する Korn シェル・スクリプトの場合 (FFDC エラー・スタックは使用または予約されません):

# Set up an FFDC Environment to use the AIX Error Log only. An FFDC Error
# Stack is not needed for this script.
. fcinit.sh -1
rc=$?
if ((rc != 0))
    then
         print "fcinit failed with exit code of $rc"
         exit 1
fi
# Normal processing starts

スクリプトおよびすべての子孫プロセスが、障害情報を FFDC エラー・スタック に記録するようになる FFDC エラー・スタック環境を Korn シェル・スクリプトで確立するには、 次のようにします。

# Set up FFDC Environment to record failure information to the FFDC Error
# Stack
. fcinit.sh -sc
rc=$?
if ((rc != 0))
then
    print "fcinit failed with a code of $rc"
    exit 1
fi
# Normal processing starts
注記： FFDCクライアントは、FFDCエラースタック環境が、fcinit電話。 このようになるのは、祖先プロセスによって既に FFDC エラー・スタック環境が 確立されている場合です。

プロセスの親プロセスから FFDC エラー・スタック環境を継承するには、次のようにします。

# Inherit an FFDC Environment from parent process if it exists - otherwise,
# operate in a normal "silent" mode
. fcinit.sh -si
rc=$?
if ((rc != 0))
then
    print "fcinit failed with a code of $rc"
    exit 1
fi
# Normal processing starts

実行の特性

このコマンドは、Reliable Scalable Cluster Technology (RSCT) ファイルセットの一部です。
