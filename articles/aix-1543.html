目的

従来のシステムダンプおよびファームウェア支援型システムダンプに関連する情報と設定を表示および変更します。

構文

sysdumpdev -P { -p device | -s device } [ -q ] [ -i ]

sysdumpdev [ -p device | -s  device ] [ -q ]

sysdumpdev [ -d directory | -D directory | -e | -I | [ -k| -K ] | -l | [ -n | -N ] | -p device | -q | -s device | -z ]

sysdumpdev [ -i ]
sysdumpdev -L { -v | -S device }

sysdumpdev [ -t { traditional | fw-assisted  } ] [ -f { disallow, allow, require } ]

説明

この sysdumpdev コマンドは、稼働中のシステムにおいて、プライマリ・ダンプ・デバイスまたはセカンダリ・ダンプ・デバイスの指定を変更します。 プライマリ・ダンプ・デバイスとセカンダリ・ダンプ・デバイスは、システム構成オブジェクトで指定されます。 新しいデバイス指定は、再度コマンド sysdumpdev を実行するかシステムを再起動するまで有効です。

コマンド sysdumpdev をオプション no 付きで実行すると、コマンド sysdumpdev はプライマリおよびセカンダリのダンプデバイスの現在の属性を特定し、その属性値をオブジェクトデータマネージャ（ ODM ）オブジェクトクラスおよび不揮発性ランダムアクセスメモリ（NVRAM）に書き込みます。 デフォルトのプライマリ・ダンプ・デバイスは /dev/hd6 ページング・スペースです。 デフォルトの 2 次ダンプ・デバイスは /dev/sysdumpnull です。 システムのメモリが4 GB以上の場合、デフォルトのダンプデバイスは であり /dev/lg_dumplv 、 は専用の /dev/lg_dumplv ダンプデバイスです。 AIX® 7.1 その後、プラットフォームがサポートしている場合、ファームウェア支援型ダンプ機能を拡張し、これをデフォルトのシステムダンプ方式とする。
注:
  • ミラーリングされたページング領域をダンプデバイスとして使用できます。
  • フロッピーディスクドライブをダンプデバイスとして使用しないでください。
  • ページングデバイスを使用する場合は、プライマリページングデバイスである hd6 のみを使用してください。 AIX オペレーティングシステムでは、ルートボリュームグループ（rootvg）内の任意のページングデバイスをセカンダリダンプデバイスとして使用できます。
  • テープやDVDなどのリムーバブルデバイスを使用する場合、ダンプはボリュームをまたがって実行されません。 ダンプは単一のボリュームに収まる必要がある。
  • ルートボリュームグループ（rootvg）内の iSCSI ソフトウェアイニシエーターデバイスを、ファームウェア支援システムダンプ用のダンプデバイスとして設定できます。これは、 テクノロジーレベル6100-01を搭載した AIX バージョン 6.1 で有効です。
  • シン・サーバーのリモート・ダンプは、 AIX 6.1でサポートされます。 NIM（Network Installation Management）マスター上で相対ダンプリソースを定義すると、NIMクライアント上のダンプリソースを、プライマリ・ダンプ・デバイスのみを設定できる iSCSI （）ディスクとして表示できるようになります。 iSCSI ディスクデバイスでは、ファームウェア支援型システムダンプのみを設定できます。
  • 非揮発性メモリ・エクスプレス・オーバー・ファブリックス（NVMe-OF）ディスクデバイスでは、ファームウェア支援型システムダンプのみを設定できます。
  • AIX バージョン 6.1 （テクノロジーレベル6100-06）では、カーネルメモリのファームウェア支援型ダンプを設定できます。
  • 暗号化されてロックされている論理ボリュームのダンプ・デバイスを構成すると、エラー・メッセージが表示される場合があります。
  • 論理ボリュームの暗号化または復号が進行中である場合、その論理ボリュームのダンプ・デバイスを構成することはできません。

AIX 6.1 以降のバージョンの場合、すべてのダンプが圧縮されます。 コマンド savecore を使用して、ダンプデバイスからファイルへダンプをコピーします。

この sysdumpdev コマンドは、ファームウェア支援システムダンプを以下の機能でサポートします：
  • ダンプサイズ推定の復活。
  • 最新のダンプに関する情報の表示。
  • 新たな投棄物の検出
この sysdumpdev コマンドは、従来のダンプタイプまたは FW支援型ダンプタイプを含むダンプの種類を提供します。

この -t オプションはダンプの種類を指定します。 可能な値は、traditional と fw-assisted です。

この -f オプションは、完全なメモリシステムダンプモードを指定します。 このモードは、ファームウェア支援システム・ダンプの場合のみ該当します。 このモードでは、ダンプはオペレーティングシステムとは独立して実行されます。 パーティションメモリはダンプに保存される。

非rootvgボリュームグループでコマンド sysdumpdev を実行する

ダンプ論理ボリュームが、永続的なダンプ・デバイスでなく、従来型のシステム・ダンプ専用であれば、 それをルート・ボリューム・グループ以外で使用できます。 たとえば、オプション -P が指定されていない場合。 ただし、ページング領域を選択した場合、ダンプデバイスはrootvg内にない限りコピーできません。 ダンプデバイスをコピーする必要がある場合、ページングを開始する前にrootvgのみがアクティブである。

1 次ダンプ・デバイスは、常に永続的なダンプ・デバイスのルート・ボリューム・グループになければなりません。 セカンダリデバイスは、ページング領域でない限り、rootvgの外にある可能性があります。

説明

allow_full
完全なメモリシステムダンプモードを許可するが、オペレーティングシステムがダンプ要求を処理できない場合にのみ実行することを指定する。
完全な要求
完全なメモリシステムダンプモードが許可され、常に実行されることを指定します。

-i sysdumpdev コマンドがシステム機能から呼び出されたことを示します。 このオプションはシステムユーティリティのみが使用します。 この -i オプションは、対象となる値が IBM の自動関数以外によって変更された場合、要求された変更を行いません。 この -i オプションは以前の変更を上書きしません。
-I 以前の変更の指示をリセットします。 オプション -I を指定した後、変更はオプション -i で許可されます。
-k お使いのシステムにキーモードスイッチが搭載されている場合、ダンプキーシーケンスを使用して強制的にダンプを実行するには、そのスイッチを「サービス」の位置に設定する必要があります。
-K お使いのシステムにキーモードスイッチが搭載されている場合、リセットボタンまたはダンプキーの操作により、キーが通常位置にある状態でダンプが強制実行されます。また、キーモードスイッチがないマシンでも同様です。
注： キーモード切り替えスイッチがないシステムでは、この値が設定されていないと、キーシーケンスによるダンプの実行を強制することはできません。
-l 1 次および 2 次ダンプ・デバイスの現在の値、コピー・ディレクトリー、および forcecopy 属性をリストします。 この -l オプションは現在のダンプタイプを表示します。 以下のリストは、表示される可能性のある値を示しています：
fw-assisted
推奨されるダンプタイプはファームウェア支援型システムダンプです。
FW支援（サスペンド）
推奨されるダンプタイプはファームウェア支援システムダンプですが、プライマリダンプデバイスが設定されていないか、ファームウェア支援システムダンプをサポートしていません。 後者の場合は、従来のシステム・ダンプが起動されます。
traditional
このシステムではファームウェア支援型システムダンプがサポートされていないため、コマンド sysdumpdev -t traditional 実行後は従来のシステムダンプのみが利用可能です。 ファームウェアによるシステムダンプをサポートするには、システムの起動時に十分なメモリが確保されている必要があり、 POWER6 以降のハードウェアと、対応するファームウェアがインストールされている必要があります。
-n Nest Accelerator GZIP（NX GZIP）のダンプ圧縮を無効にします。 システム・ダンプは、NX GZIP を使用せずに圧縮されます。
-N NX GZIPによるダンプ圧縮を有効にします。 NX GZIPダンプ圧縮は、ファームウェア支援型のシステムダンプにのみ適用されます。
-L 直近のシステムダンプに関する統計情報を表示します。 最終ダンプの日時、書き込まれたバイト数、および完了ステータスを含みます。 この -L オプションは、ダンプの圧縮サイズと非圧縮サイズの両方を表示します。 圧縮サイズは、ダンプデバイスに書き込まれたデータのサイズです。 不揮発性メモリに以前のダンプが記録されていない場合、このオプションは既存のダンプをダンプデバイスからスキャンします。
注:
  1. 表示されるダンプサイズは、メディア上のダンプの正確なサイズを反映していない可能性があります。 ディスクおよびコピー・ブロックのサイズにより、わずかな差が生ずる可能性があります。
  2. I/Oエラーによりダンプが失敗した場合、メジャー番号とマイナー番号は、エラーが発生したデバイスの番号となります。
-P `-d` または `-d` -p-s オプションで指定されたダンプデバイスを永続化します。 この -P オプションは、または -s-p オプションと組み合わせてのみ使用できます。
-p 装置 1 次ダンプ・デバイスを指定されたデバイスに一時的に変更します。 デバイスは、論理ボリューム、書き込み可能DVD、テープデバイス、またはNIMによってリモートダンプ用に構成された iSCSI ディスクである可能性があります。
-q すべてのメッセージを標準出力に抑制します。 このオプションが -l, -z, または -L オプションと併用された場合、 オプション -q は無視されます。
-s 装置 Device は、2 次ダンプ・デバイスを指定されたデバイスに一時的に変更します。 オプション -p に有効なデバイスは、ここでも有効です。
-S 装置 特定のダンプ・デバイスをスキャンして、有効な圧縮ダンプがあるか調べます。 ダンプは、並列ダンプサポートを備えたリリース AIX からのものでなければなりません。 このオプションは、オプション -L と組み合わせてのみ使用できます。
-t{ 繁体字 | FW支援 } 実行するダンプのタイプを指定します。 この -t オプションには以下の変数があります：
traditional
従来のシステムダンプを実行することを指定します。 このダンプタイプでは、システム再起動前にダンプデータが保存されます。 以下のいずれかの状況では、 従来の変数のみを指定できます：
  • ファームウェア支援システム・ダンプがサポートされていない。
  • システム始動時に十分なメモリーがない。
  • POWER6 以降のハードウェアがインストールされていません。

従来のシステム・ダンプを iSCSI ソフトウェア・イニシエーター ・ダンプ・デバイスで使用することはできません。

fw-assisted
ファームウェア支援システムダンプを実行することを指定します。 このダンプタイプでは、システム再起動時にダンプデータが並列ダンプサポートに保存される。 システムが低メモリ構成で起動する場合、オプション -f を使用して完全メモリダンプを明示的に有効にする必要があります。 具体的には、 iSCSI ソフトウェアイニシエーター の構成において、フルメモリダンプが許可されていない場合、ファームウェア支援によるシステムダンプが従来のシステムダンプに切り替わらない場合を指します。

fw-assisted 変数を指定した場合でも、プライマリダンプデバイスが設定されていないか、ファームウェア支援型システムダンプをサポートしていない場合、従来のシステムダンプが実行されます。

ファームウェア支援型システムダンプ方式が設定時に許可されていない場合、またはダンプ要求時に強制されない場合、従来のシステムダンプが実行される。 さらに、スクラッチ領域は初期化時にのみ確保されるため、従来のシステムダンプからファームウェア支援型システムダンプへの設定変更は、システムを再起動するまで有効になりません。
-v ダンプ状態が 0 でない場合、このオプションは利用可能なダンプデバッグ情報を表示します。 デバッグデータが利用可能な場合、サービスはこれをダンプ失敗の診断に使用します。 このオプションは、オプション -L と組み合わせてのみ使用できます。
-z 新しいシステムダンプが存在するか否かを判定する。 存在する場合、ダンプのサイズ（バイト単位）とダンプデバイスの名前を含む文字列が標準出力に書き込まれる。 新規のシステム・ダンプが存在しなければ、何も出力されません。 sysdumpdev -z コマンドが既存のシステム・ダンプ上で実行された後は、そのダンプは最新とは見なされなくなります。

コマンド sysdumpdev にオプションを指定しない場合、デフォルトのダンプデバイスが使用されます。

セキュリティー

アクセス制御 - このコマンドを実行できるのはrootユーザーのみです。

RBAC ユーザーへの注意: このコマンドは特権命令を実行できます。 特権命令を実行できるのは特権ユーザーのみです。 権限と特権の詳細については、セキュリティの 特権コマンドデータベースを参照してください。 このコマンドに関連する特権と権限のリストについては、'lssecattrコマンドまたは'getcmdattrサブコマンドを参照のこと。

例

  1. 現在のダンプデバイス設定を表示するには、次のコマンドを入力してください：
    sysdumpdev -l
    コマンド sysdumpdev が表示するダンプの種類については、オプションを -l 参照してください。
  2. 次のコマンドを入力して、論理ボリュームを hd7 プライマリダンプデバイスとして指定します:
    sysdumpdev -p /dev/hd7
  3. 以下のコマンドを入力して、テープデバイスを rmt0 セカンダリダンプデバイスとして指定してください:
    sysdumpdev -s /dev/rmt0
  4. 前回のダンプ実行からの情報を表示するには、次のコマンドを入力してください：
    sysdumpdev -L
  5. プライマリダンプデバイスのデータベースオブジェクトを恒久的に変更するには /dev/newdisk1、次のコマンドを入力してください：
    sysdumpdev -P -p /dev/newdisk1
  6. 新しいシステムダンプが存在するかどうかを確認するには、次のコマンドを入力してください：
    sysdumpdev -z
    最近システムダンプが発生した場合、次のような画面に類似した出力が表示されます：
    4537344 /dev/hd7
  7. システムクラッシュ後にダンプがコピーされるディレクトリを指定するには、次のコマンドを入力します（ダンプデバイスが の場合 /dev/hd6）：
    sysdumpdev -d /tmp/dump
    システムクラッシュ後にファイル /dev/hd6 からファイル /tmp/dump へダンプをコピーしようとする試み。 コピー中にエラーが発生した場合、システムは起動を継続し、ダンプは失われます。
  8. システムクラッシュ後にダンプがコピーされるディレクトリを指定するには、次のコマンドを入力します（ダンプデバイスが の場合 /dev/hd6）：
    sysdumpdev -D /tmp/dump
    このコマンドは、クラッシュ後に /dev/hd6 ディレクトリから /tmp/dump ディレクトリへダンプをコピーしようとします。 コピーが失敗した場合は、メニューが出されます。 このメニューを使用して他の外部メディアに手動でダンプをコピーすることができます。
  9. ダンプデバイスをスキャンしてダンプを検索するには、次のコマンドを入力します:
    sysdumpdev -L -S /dev/hd6
