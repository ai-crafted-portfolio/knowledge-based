目的

システムまたはライブ・ダンプ、あるいは実行中のカーネルの検査を可能にします。

構文

kdb -h 
kdb [ -c CommandFile ] [ -cp ] [ -i HeaderFile ] [ -l ] [ -script ] -w -u  KernelFile
kdb [ -c CommandFile ] [ -cp ] [ -i HeaderFile ] [ -l ] [ -script ] [ -v ] [  SystemImageFile [  KernelFile [KernelModule ... ]]]
kdb [ -c CommandFile ] [ -cp ] [ -i HeaderFile ] [ -l ] [ -script ] [ -v ] [ -m  SystemImageFile ] [ -u  KernelFile ] [ -k KernelModule ]

説明

kdb コマンドは、オペレーティング・システムの イメージまたは実行中のカーネルを検査するための対話式ユーティリティーです。 kdb コマンドは、システム内の制御構造の解釈およびフォーマットを行い、ダンプを検査するための各種の機能を提供します。

アクティブ・システムで kdb コマンドを使用する場合、/dev/pmem スペシャル・ファイルが使用されるため、root 権限が必要です。 アクティブ・システムで kdb コマンドを実行するには、次のように入力します。
kdb
注: 実行中のシステム上の現行プロセスのスタック・トレースが機能しません。
システム・イメージ・ファイルで kdb コマンドを起動するには、次のように入力します。
kdb SystemImageFile

kdb が開始すると、ユーザーのホーム・ディレクトリー内および現在の作業ディレクトリー内で .kdbinit ファイルを検索します。 これらの場所のいずれかに'.kdbinitファイルが存在する場合、'kdbコマンドは、あたかも対話型kdbプロンプトで入力されたかのように、ファイル内のすべてのコマンドを実行する。 この両方の場所に .kdbinit ファイルが見つかった場合、ホーム・ディレクトリー内のファイルが最初に処理され、続いて現在の作業ディレクトリー内のファイルが処理されます (ただし、現行ディレクトリーがホーム・ディレクトリーである場合を除く。この場合はファイルが一度だけ処理されます)。

フラグ

表 1. フラグ
項目
説明
-c CommandFile 始動スクリプト・ファイルの別の名前を指定します。 このオプションを使用すると、kdbは'.kdbinitファイルではなく、ホームディレクトリとカレントディレクトリのCommandFileパラメータを検索する。
-cp これを使用すると、始動スクリプト・ファイル内の各コマンドが実行されるときに、kdb はそのコマンドを出力します。 これは、'.kdbinitファイルや、'-cフラグで指定されたその他のファイルのデバッグを助けるために使うことができる。 出力される各コマンドの前には、プラス (+) 符号が付きます。
-h コマンド・ラインの使用法に関する簡略ヘルプ・メッセージと、使用可能なコマンド・ライン・オプションの簡単なリストが表示されます。
-i HeaderFile HeaderFileパラメータで定義されたすべての C 構造体を kdb 'printサブコマンドで使用できるようにする。 このオプションを使用するには、C コンパイラーがシステムにインストールされていなければなりません。 HeaderFile変数がコンパイルするために追加の'.hファイルを必要とする場合、これらは別の'-iオプションでも指定しなければならないかもしれない。
-k モジュール 指定されたModuleパラメータを、カーネル自体にないシンボル定義を解決するための 追加カーネルモジュールとして使うように、'kdbコマンドに指示する。 このオプションの使用は、KernelModuleパラメータでカーネルモジュールを指定することと同じである。
-l インライン・ページャー (つまり、more (^C to quit) ? プロンプト) を kdb 内で使用できなくします。 この場合、kdbの'set scrollサブコマンドは何の効果もなく、スクロールの設定に関係なく、インラインページャーは常に無効になる。
-m 画像 kdbコマンドに、指定されたImageパラメータをシステムイメージファイルとして使うように指示する。 このオプションの使用は、SystemImageFileパラメータでシステム・イメージ・ファイルを指定するのと同じである。
-script kdb の始動時にインライン・ページャー (つまり、more (^C to quit) ? プロンプト) を使用不可にして、ほとんどの状況情報の出力を不可にします。 このオプションは、kdbのフロントエンドとして動作するスクリプトやその他のプログラムによる'kdbコマンドの出力の解析を容易にする。
-u カーネル シンボル定義を解決するためのカーネルファイルとして、指定されたカーネルを使用するように 'kdbコマンドに指示する。 このオプションの使用は、KernelFileパラメーターでカーネルを指定することと同じである。
-v kdb コマンドを開始したときに、ダンプ・ファイル内のすべてのコンポーネント・ダンプ・テーブル (CDT) のリストを表示します。 CDT は、ダンプに実際に含まれるメモリー領域をリストします。 kdb コマンドが稼働中のシステムで使用された場合、このオプションは無視されます。
-w システム・イメージではなく、カーネル・ファイルを直接検査します。 通常、システム・イメージ・ファイルからメモリー位置を表示するすべての「kdbサブコマンドは、代わりにKernelFileから直接データを読み込む。 メモリーに書き込むサブコマンドは使用できません。

パラメーター

表2. パラメーター
項目
説明
KernelFile kdbコマンドがカーネルシンボル定義の解決に使用するAIXカーネルを指定する。 カーネル・ファイルが使用可能でなければなりません。 ダンプを検査する場合、カーネル・ファイルはシステム・ダンプまたはライブ・ダンプを取るときに使用されたカーネルと同じでなければなりません。 デフォルト値は/unixです。

例

次の例で、kdb コマンドの起動オプションを説明します。

  1. デフォルトのシステム・イメージ・ファイルとカーネル・イメージ・ファイルを使用して kdb コマンドを起動するには、次のように入力します。
    kdb

    kdbプログラムは、(0)>プロンプトを返し、サブコマンドの入力を待つ。

  2. /var/adm/ras/vmcore.0名前のダンプ・ファイルと「/unix」という名前のUNIXカーネル・ファイルを使って「kdbコマンドを実行するには、次のようにタイプする：
    kdb /var/adm/ras/vmcore.0 /unix

    kdbプログラムは、(0)>プロンプトを返し、サブコマンドの入力を待つ。

  3. /var/adm/ras/livedump/trc1.nocomp.200705222009.00名前のライブ・ダンプ・ファイルと「/unixカーネル・ファイルを使って「kdbコマンドを起動するには、次のようにタイプする：
    kdb /var/adm/ras/livedump/trc1.nocomp.200705222009.00
    注意：デフォルトのカーネルファイルは「/unixである。 システム・ダンプと違い、ライブ・ダンプでは、選択されたデータのみがあります。 例えば、ダンプに明示的に含まれたスレッドのカーネル・スレッド・データのみがあります。
