目的

AIX環境における新しいハードウェアの導入を容易にします。

構文

nim_move_up {[ -S ] | [ -K [ -h control_host ]] | [ -r [ -R ] [ -u ]]} | {[ -c NIM_client ] [ -i target_ip [ -ending_ip ]] [ -s subnet_mask ] [ -g gateway ] [ -h control_host ] [ -m managed_sys ] [ -V vio_server [ -e ] [ -D ]] [ -I img_src ] [ -l resource_dir ] [ -t 秒 ] [ -p ループ ] [ -j nimadm_vg ] [ -L lpp_source ] [ -U spot ] [ -B bosinst_data ] [ -E exclude_files ] [ -C script_resource ] [ -b installp_bundle ] [ -f fix_bundle ] {{[ -n ] [ -d ]} | -O} [ -q ] [ -T ] [ -M manual_configuration_filenames ]}

説明

nim_move_up コマンドを使用すると、既存の AIX 環境のユーザーは、新しい POWER ® サーバーで使用可能な機能を利用できます。 このコマンドは、既存の AIX システムを POWER サーバー上の LPAR にマイグレーションするインターフェースを提供します。 元のマシンの AIX のレベルが、新しいハードウェアでの操作をサポートするレベルに引き上げられます。 元のシステムのハードウェア・リソースは、より新しいハードウェア上で厳密に複製されます。 マイグレーションの終了までに、同じシステムが新しい LPAR上で完全に稼働しています。

さらに、 nim_move_up は、オプションで仮想化ハードウェア (仮想ディスクや仮想イーサネットなど) にクライアントをマイグレーションすることにより、POWER サーバーの仮想入出力機能を使用できます。

nim_move_up コマンドは、NIM の機能と、ネットワーク上の NIM クライアントをリモートで管理およびインストールする NIM マスターの機能に依存します。 nim_move_up コマンドは、NIM マスターと nimadm コマンドを使用して、既存の NIM クライアントに対して以下のアクションを実行しようとします。

  1. クライアントのシステム・バックアップを作成する。
  2. バックアップのレベルの AIX のマイグレーション
  3. 新しい POWER サーバーにある LPAR にバックアップをインストールします。このサーバーは、NIM 環境では新しいスタンドアロン・クライアントとして表されます。

新規ハードウェアのインストール前に、NIM マスター (nim_move_up コマンドが実行される場所) と、既存ハードウェア上の NIM クライアントを構成する必要があります。 クライアントはマイグレーションの開始点であり、最終的には新しい LPARになります。

移行が正常に終了した後の状態は、次のとおりです。
  • NIM マスターはそのまま変わりありません。
  • 新しい POWER サーバー上の LPAR は、元の NIM クライアントに対応し、NIM マスターによって制御されます。
  • HMC は、SSH を介して NIM マスターと通信することにより、新しい POWER サーバー上の LPAR を制御します。
  • 元の NIM クライアントは影響を受けないままの状態で、依然として NIM マスター の制御下に置かれています。

移行全体は、元のクライアントの一部では必要とされた停止時間もなく行 われます。 このプロセスは、順番に実行して行く各フェーズの中で完了させることができます。 これにより、このプロセスに対する一層の制御が可能となります。また、別の方法 としてフェーズの全体を一気に実行可能であり、それによって処理時にユーザー 応答のための介入は不要となります。 このコマンドは、 bos.sysmgt.nim.master ファイルセットの一部として配布され、実行するには NIM 環境が機能している必要があります。

必須フラグ

項目
説明
-c NIM_クライアント NIM スタンドアロン・クライアント (スタンドアロン・オブジェクト・タイプ) または NIM マシン・グループ (mac_group オブジェクト・タイプ) のいずれかを指定します。 ここで指定されたクライアントはネットワークを使用して NIM マスターか らアクセス可能である必要があり、このクライアントは、このクライアント上で NIM マスターがコマンドを実行可能にする必要があります。 この引数の中に NIM マシン・グループを指定した場合は、このグループが同じ NIM ネットワークに置かれていることが必要です。 クライアントは、POWER サーバー上の新しい LPAR にマイグレーションされるターゲット・マシンです。
-g ゲートウェイ クライアントが POWER サーバーへのマイグレーション後に構成されるデフォルト・ゲートウェイの IP アドレスを指定します。
-h コントロール・ホスト POWER サーバーのハードウェア制御に使用される HMC のホスト名または IP アドレスを指定します。
-i target_ip [-ending_ip］ 新しくマイグレーションされたクライアントが POWER サーバーにインストールされた後に構成される IP アドレスを指定します。 NIM マシン・グループを -c オプションに指定する場合は、ここに IP アドレスの範囲を指定する必要があります。また、移行するクライアントの数を列挙するのに十分なアドレスが範囲内になければなりません。
-I img_src インストール・イメージのソースに至るパスを指定します。このソースを使用して移行とインストールに必要な NIM リソースを作成します。 このパスは、デバイス ( AIX 製品メディアを使用している場合は dev/cd0 など)、またはインストール・イメージを含むファイル・システム上のロケーションへのパスにすることができます。
-l リソース・ディレクトリー nim_move_up コマンドによって作成された新しい NIM リソースが入るファイルシステム上の場所へのパスを指定します。 -L および -U オプションを使用して既存のリソースが提供された場合を除き、 LPP_Source およびスポットを収容するのに十分なスペースがロケーションになければなりません。
-m 管理対象システム HMC によって追跡される POWER サーバーに対応する管理対象システムの名前を指定します。
-s サブネット・マスク クライアントが POWER サーバーへのマイグレーション後に構成されるサブネット・マスクを指定します。

実行と制御のフラグ

項目
説明
-d nim_move_up をバックグラウンドで実行し、端末の制御を呼び出し元に戻します。 nim_move_up の進行状況は、 -S フラグを使用して追跡できます。
-K 指定された HMC に関する SSH キーを構成します。 これにより、パスワード・ プロンプトを必要としない、NIM マスターからのコマンドのリモート側での 無人実行が可能となります。 このフラグは、 -h オプション以外のオプションと一緒に使用することはできません。
-n nim_move_up マイグレーション・プロセスの次のフェーズのみを実行します。 フェーズが完了するか失敗すると、 nim_move_up コマンドは終了します。 このフラグを指定しない場合、後続のすべてのフェーズが実行され、すべてのフェーズが実行されるか、いずれかのフェーズが失敗すると、 nim_move_up は終了します。
-O 指定された値のみを保管します。 他のオプションを介して 指定された値を保管してから、どのフェーズも実行せずに終了します。 このフラグを、他の実行と制御のフラグと共に使用することはできません。
-q 抑止モードを指定します。 出力は端末装置では表示されません (ただしログには保持されます)。 nim_move_up が -d フラグを指定して実行されている場合、このフラグは無効です。
-r nim_move_upを構成解除します。 これにより、保管済み オプションを含めた、すべての保管済みデータ、フェーズ固有のデータ、および現 行フェーズ情報がリセットされます。 この操作を実行する必要があるのは、新しいクライアントまたはクライアント・セットの移行処理が繰り返し開始される場合です。
-R 環境の構成解除に加えて、 nim_move_up によって作成されたすべての NIM リソースを除去します。 このフラグは、 -r オプションと一緒にのみ使用できます。
-S 現行フェーズまたは次に実行されるフェーズの状況を表示します。 保管される値も全部が同様に表示されます。 nim_move_up コマンドは、情報を表示した直後に終了します。 このフラグを他のオプションと一緒に使用することはできません。

オプショナル・フラグ

項目
説明
-b installp_bundle 既存の installp_bundle NIM リソースを指定します。このオプションが指定されている場合は、フェーズ 10 (インストール後のカスタマイズ) で新しく移行された各 LPAR にそのソフトウェアがインストールされます。
-B bosinst_data 新規クライアントを新規 LPARにインストールするために nim_move_up が使用する既存の bosinst_data NIM リソースを指定します。 このオプションを指定しない場合、 nim_move_up は、デフォルトの無人インストール値を使用して bosinst_data リソースを生成します。
-C スクリプト・リソース 既存のスクリプト NIM リソースを指定します。このリソースが提供されている場合、 nim_move_up は、移行されたすべての新規 LPAR上でフェーズ 10 (インストール後のカスタマイズ) で実行されます。
-D Virtual I/O Server LPAR が指定されている場合に、POWER サーバー上に新しい LPAR を作成する際に、仮想 SCSI アダプターの代わりに物理ストレージ・コントローラーを強制的に使用します。 このフラグは、 -V オプションと一緒に使用された場合にのみ有効です。
-e Virtual I/O Server LPAR が指定されている場合に、POWER サーバー上に新しい LPAR を作成する際に、共用イーサネット・アダプターの代わりに物理ネットワーク・アダプターを強制的に使用します。 このフラグは、 -V オプションと一緒に使用された場合にのみ有効です。
-E 除外ファイル nim_move_up が元のクライアントの mksysb を作成するために使用する既存の exclude_files NIM リソースを指定します。 このオプションを指定しない場合、 nim_move_up は、 /tmp の内容をバックアップから除外する exclude_files リソースを生成します。
-f フィックスバンドル フェーズ 10 (インストール後のカスタマイズ) で新しく移行された各 LPARに APAR がインストールされている既存の fix_bundle NIM リソースを指定します (このオプションが指定されている場合)。
-j ニマドム データ・キャッシングのために、基礎となる nimadm 呼び出しによって使用されるボリューム・グループを指定します。 このオプションを指定しない場合、デフォルト値は rootvg です。
-L lpp_source ターゲット・クライアントの移行先の AIX レベルの既存の LPP_Source NIM リソースを指定します。 このオプションが指定されていない場合、 nim_move_up は、 -I オプションによって提供されるインストール・イメージ・ソースから新しい LPP_Source を作成しようとします。
-M 手動設定ファイル名 phase4 を指定して、関連するバックレベル AIX マシンに対してこれらの手動構成ファイルを使用します。 このフラグが有効になるのは、 nim_move_up コマンドの phase4 の中だけです。 このフラグについて詳しくは、「 拡張使用法 」セクションを参照してください。
-p ループ リソースの使用状況を分析する段階で、ターゲット NIM クライアント上で システム分析ツールの実行回数を指定します。 最終のリソース使用データは、各実行ループから得られた値の平均となります。 このデータは、マイグレーションされた LPAR の派生元となる同等の POWER サーバー・リソースを決定する際に考慮されます。 このオプションを指定しない場合、デフォルトは 1 ループです。
-t 秒 各ループが実行される時間を秒数で指定します。 このオプションを指定しない場合、デフォルトは 10 秒です。
-T ユーザー定義のボリューム・グループを、元のクライアントから新しくマイグレーションされた LPARに転送します。
-u nim_move_up が nim_move_up マイグレーション全体を完全に「ロールバック」できるようにします。 -r フラグと一緒に使用する必要があります。
-U スポット 既存のスポット NIM リソースを指定します。このリソース は、クライアントの移行およびインストールで使用されます。 このオプションを指定しないと、 -L および -I オプションによって提供される lpp_source NIM リソースから新しいスポットが作成されます。
-V ヴィオサーバー -m フラグで示される POWER サーバーに常駐する Virtual I/O Server の LPAR 名を指定します。

セキュリティー

root ユーザーのみがこのコマンドを実行できます。

例

  1. 最初のフェーズを実行し、すべての必須指定のオプションを構成するには (nim_move_up が既に構成され、実行されていてはなりません)、次のように入力します。
    nim_move_up -c client1 -i 192.168.1.100 -s 255.255.255.0 -g 192.168.1.1 -h hmc1.mydomain.com -m \
my-p5 -l /big/dir -I /dev/cd0 -n
  2. nim_move_up コマンドの環境の状況 (保管されたすべての構成入力および次に実行するフェーズを含む) を表示するには、次のように入力します。
    nim_move_up -S
  3. 保管済みのホスト名を新しい名前に変更して、出力を抑止しながら次のフェーズを実行するには、次のように入力します。
    nim_move_up -h hmc2.mydomain.com -n -q
  4. 残る全フェーズをバックグラウンドで実行し、全ライセンスの受け入れ合意を保管 して、フェーズの実行開始後にプロンプトを戻すようにするには、次のように入力します。
    nim_move_up -Y -d
  5. nim_move_upを構成解除し、保存されているすべての入力を破棄し、フェーズ 1 を実行するようにコマンドをリセットするには、次のように入力します。
    nim_move_up -r
    nim_move_up によって以前に作成されたすべての NIM リソースは、NIM 環境では影響を受けず、別のクライアントを移行するために必要に応じて nim_move_up によって使用されます。

制約事項

nim_move_up アプリケーションを実行する前に、以下の NIM マスター要件を満たす必要があります。
  • AIX 5L バージョン 5.3 (5300-03 推奨メンテナンス・パッケージ適用)以降を実行する。
  • Perl 5.6 またはそれ以降
  • OpenSSH ( Linux® Toolbox CD から)
  • 環境内で AIX 4.3.3 update 以降を実行している 1 つ以上のスタンドアロン NIM クライアント
  • 製品メディア・バージョン AIX 5L バージョン 5.2 (5200-04 推奨メンテナンス・パッケージ 以降適用)、または製品メディア・バージョン AIX 5.3 以降 (同等の LPP_Source および spot NIM リソースも使用可能)。
さらに、以下の前提条件を満たす必要があります。
  • ターゲット・クライアントの同等の POWER サーバー構成をサポートするのに十分なハードウェア・リソースを持つ POWER サーバー。
  • クライアントの移行に仮想リソースを使用する場合に、バーチャル I/O サーバ ーがインストールされ、構成されている。
  • POWER サーバーを制御する HMC と、 LPARの電源オン、電源オフ、および作成を行うための十分な特権。

上記の要件がすべて満たされていない場合、または非 root ユーザーによってコマンドが実行された場合、 nim_move_up コマンドは正常に実行されません。

実行の特性

nim_move_up コマンドは、既存のクライアントを新しい LPARにマイグレーションするための段階的なアプローチを取ります。 処理を構成するのは以下のフェーズです。

  1. NIM リソースを作成します。 移行手順の実行に必要な NIM リソース がまだ存在していなければ、ここで作成します。
  2. 移行前ソフトウェアを評価する。 どのソフトウェ アをインストールし、どのソフトウェアが移行不能かの評価を、各ターゲット・ク ライアント上で行います。 LPP_Source から欠落しているソフトウェアは、 nim_move_upに提供されているインストール・イメージ (製品メディアなど) のソースから追加されます。
  3. クライアント・ハードウェアと使用データを収集する。 各ターゲット・ クライアントのハードウェア・リソースに関するデータを収集します。 また、これらハードウェア・リソースの平均的使用を、所定の時間の上で評 価してみます。
  4. POWER サーバー・リソース可用性データを収集し、クライアント・リソース・データを変換します。 指定される管理対象システム を検索して、使用可能なハードウェア・リソースを求めます。 前のフェーズで収集されたデータは、管理対象システムの使用可能なリソースを使用する同等の LPAR 構成を導出するために使用されます。 処理のために Virtual I/O Server LPAR が提供されている場合、物理 I/O リソースではなく仮想 I/O リソースを使用して派生クライアント LPAR が作成されます。 バーチャル I/O サーバー上には、必要に応じて、該当のアダプター と構成が作成 されます。
  5. ターゲット・クライアントのシステム・バックアップを作成する。 NIM が各ターゲット・クライアントの mksysb を実行すると、対応する mksysb NIM リソースが作成されます。
  6. 各システム・バックアップを移行する。 nim_move_upによって指定された NIM リソースを使用して、各 mksysb リソースは、 nimadm コマンドによって新しいレベルの AIX に移行されます。 元の mksysb NIM リソースは保持され、新しい移行済み mksysb リソース用に新しい mksysb NIM リソースが作成されます。
  7. NIM リソースを新しい LPARに割り当てます。 NIM スタンドアロン・クライアント・オブジェクトは、 nim_move_upに提供されたネットワーク情報を使用して、フェーズ 4 で作成された新しい派生 LPAR ごとに作成されます。 適切な NIM リソースが割り当てられ、各 NIM クライアントで bos_inst プル操作が実行されます (NIM はクライアントのブートを試行しません)。
  8. LPARへのインストールを開始します。 各 LPAR は、制御ホスト (HMC) を使用してリブートされ、インストールが開始されます。 このフェーズの実行は、インストール の開始後に停止します (すなわち、インストールの進行状況はモニターされません)。
  9. 移行後のソフトウェアを評価する。 それぞれの インストールの完了後に、移行が全体として正常に完了したかどうかの評価が行われ、 移行時に検出したソフトウェア上の問題に関するレポートが作成されます。 どのファイルセットの移行に失敗した場合も、そのファイルセットに対して報 告されたエラーを手動で訂正する必要があります。
  10. ポストインストールをカスタマイズする。 代替 LPP_Source、ファイルセット・リスト、またはカスタマイズ・スクリプトが指定されている場合は、指定された値を使用して、カスタマイズされた NIM 操作が各クライアントに対して実行されます。 これにより、追加ソフトウェア・アプリケーションまたは追加カスタマイズのオプショナル・インストールが可能となります。

NIM クライアントを新しい LPARに正常に移行するには、これらの各フェーズ (オプションのフェーズ 10 を除く) を完全に正常に実行する必要があります。 すべてのフェーズが正常に完了すると、新しい NIM クライアント・オブジェクトが、移行された LPARを表す NIM 環境に存在します。この LPAR は、インストール・リソースの nim_move_up ソースを介して提供される AIX のレベルを実行します。

nim_move_up を実行するために必要なすべての前提条件が満たされると、 nim_move_up コマンドは、構成とフェーズ実行の 2 つのフェーズで実行されます。

構成

nim_move_up コマンドがフェーズを開始する前に、アプリケーションに入力を提供する必要があります。 必要な入力情報には、移行対象のNIMクライアントのリスト、移行先の新しいLPARの TCP/IP 設定情報、およびPOWERサーバー名が含まれます。 必要な nim_move_up 構成オプションの完全なリストについては、「Required Flags」を参照してください (「 nim_move_up_config 」SMIT メニューに * (アスタリスク) も表示されます)。 オプションの入力 (Virtual I/O Server が指定されているかどうかなど) は、 nim_move_up の動作およびマイグレーション・プロセスの最終結果にも影響します (Virtual I/O Server が指定されている場合は、マイグレーションされた LPARを作成するために Virtual I/O リソースが使用されます)。

SMIT インターフェースを介して必須とオプショナルの入力を転送するには、次のいずれかのコマンドを入力します。
smitty nim_move_up_config
または
smitty nim_move_up
次に、「 Configure nim_move_up Input Values 」オプションを選択します。

メニューでは、ご使用の環境の要件を反映するオプションを値と共に指定します。 nim_move_up コマンドの SMIT インターフェースについて詳しくは、以下の SMIT の使用法のセクションを参照してください。

nim_move_up コマンドの環境が必要な入力で構成されると、 nim_move_up コマンド環境が構成解除されるまで、それらの値は nim_move_up コマンドの後続の実行によって記憶されます。 値はいつでも、SMIT メニュー・インターフェースを介して、あるいはコマンド・ラインのフラグを 使用して新しい値を指定することにより、変更することができます。 コマンド行インターフェースを使用して、 nim_move_up コマンド環境を構成することもできます。
注:
コマンド・ライン・インターフェースを使用する場合、 nim_move_up コマンドは、デフォルトでは、構成値が提供されるたびにフェーズの実行も試みます。 コマンドを直接呼び出すときにフェーズが実行されないようにするには、 -O フラグを使用します。

フェーズ実行

すべてが入力された後で、フェーズ 1 でフェーズ実行が開始され、これが順次 に継続されます。 フェーズでエラーが発生すると、 nim_move_up は次に実行するときに、失敗したフェーズを実行しようとします。 オプションで、 nim_move_up が次のフェーズのみを開始するように指定することも、残りのすべてのフェーズを試行するように指定することもできます。

SMIT インターフェースを使用して nim_move_up フェーズを開始するには、以下のいずれかのコマンドを入力します。
smitty nim_move_up_exec
または
smitty nim_move_up
次に、「 Execute the nim_move_up Phases 」オプションを選択します。 Execute All Remaining Phases? オプションに応答して、Enter キーを押します。 フェーズは実行を開始します。
nim_move_up がコマンド行を使用して次のフェーズのみを実行するように指定するには、次のコマンドを入力します。
nim_move_up -n
nim_move_up が残りのすべてのフェーズを実行するように指定するには、次のコマンドを入力します。
nim_move_up
各フェーズを実行する他に、このコマンドでは、該当のフラグが指定されてい る場合に保管済みの構成オプションを変更することもできます。

SMIT の使用法

nim_move_up SMIT メニューには、 nim_move_up 高速パスを使用してアクセスできます。 nim_move_upのルート・メニューを呼び出すには、次のコマンドを入力します。
smitty nim_move_up
ルート・メニューを介して、以下の SMIT 画面にアクセスすることができます。
nim_move_up の現在の状況の表示
-S フラグを指定して nim_move_up を実行することと同等です。 次に実行されるフェーズと保管済みの全オプションのリストが表示されます。
Configure nim_move_up Input Values (nim_move_up 入力値の構成)
この画面では、 nim_move_up への必須入力とオプション入力をすべて構成できます。 これらのフィールドに入力された値はすべて保管され、 nim_move_up の後続の実行と、この SMIT 画面の後続の使用によって記憶されます。 この画面をいつでも使用して、フェーズの実行後に、保管された値を変更することができます。
Execute nim_move_up Phases (nim_move_up フェーズの実行)
nim_move_up フェーズを実行するための単純なインターフェースを提供します。 このフェーズの問題の対応策に応じて、フェーズを 1 つずつ、あるいは同時に全部を実行することができます。
Configure SSH Keys on Target HMC (ターゲット HMC に関する SSH キーの構成)
リモート制御ホスト (HMC) に関する SSH キーをセットアップするために簡単なインターフェースを提供します。 これは、コマンド行で -K フラグを渡すことと同等の作業を行います。 リモート制御ホストに関する SSH キーの構成により、NIM マスターからのコマンドの リモートからの無人実行が可能となります。これは、フェーズの全部 (一部のフェー ズでは、このシステム上でコマンドをリモートで実行) を完了するために必要なことです。
Unconfigure nim_move_up (nim_move_up の構成解除)
nim_move_up コマンドの環境を構成解除するためのインターフェースを提供します。 これにより、次に実行するフェーズを含めたすべての状態情報、一部のフェーズの 実行結果として生成された保管済みデータ・ファイル、およびすべての保管済み入力値が除去されます。 オプションで、 nim_move_up を使用して作成されたすべての NIM リソースも除去できます。 この画面は、 -r コマンド行オプションと同等の操作を行います。

拡張使用法: mig2p5 フレームワークの理解

mig2p5 フレームワークは、 /var/mig2p5 ディレクトリーで構成され、 nim_move_up が後続の呼び出しの間にその状態を記憶する手段として機能します。 その存在と nim_move_up による使用は、ユーザーにはまったく認識されません。ディレクトリーは nim_move_up によって作成され、その値は存在しない場合は初期化されます。 これは、 nim_move_up が構成解除されると削除されます。 このディレクトリーの内容は読みやすく、 nim_move_upの問題のトラブルシューティングに非常に役立ちます。このディレクトリーには、フェーズで生成されたすべてのログが含まれ、コマンド・ラインで許可されない方法で nim_move_up の動作に影響を与える編集可能ファイルが含まれています (例えば、 nim_move_up に特定のフェーズを強制的に実行させるなど)。

以下のリストでは、 /var/mig2p5 ディレクトリー内の各ファイルの目的と内容について説明します。
config_db
コマンド・ライン引数または nim_move_up_config SMIT メニューを介して nim_move_up に渡されるすべての保管済み構成オプションが入っています。 ファイルの中の各行の形式は次のとおりです。
option_name:value
current_phase
nim_move_upの次回の呼び出し時に実行されるフェーズの番号が入っています。 このフェーズを実行する前に、 nim_move_up は、前のすべてのフェーズが正常に実行されたことを確認します。 この情報は、 mig2p5 フレームワークを使用する他の場所でも維持されます。
global_log
mig2p5 フレームワークが最後に初期化されてから実行されたすべてのフェーズの出力が含まれます。
client_data/
フェーズ 3 および 4 の間に nim_move_up によって生成されるファイルが含まれます。このフェーズでは、元のクライアントのシステム・リソースと使用率がそれぞれモニターされ、構成ファイルに定量化されます。 POWER サーバーで使用可能なリソースも、対応するテキスト・ファイルに定量化されます。 POWER サーバー上で新しく派生した LPAR のハードウェア・プロファイルを決定する際には、これらのファイル内のすべてのデータが考慮されます。 これらのファイルは、 nim_move_up コマンドの内部使用のための機械可読データ・ファイルです。 これらのファイルを手動で変更したり、作成したりしないでください。
フェーズ#/
名前の中の番号 ( # ) で示される、対応するフェーズに固有のデータが含まれます。 すべてのフェーズにディレクトリーがあります (例えば、 phase1/ 、 phase2/ など)。
フェーズ#/log
フェーズの実行時に表示される全出力を含みます。 フェーズを複数回実行すると (エラーが 修正された後など)、新しい出力がすべて、ファイル内に既に存在するテキスト の後ろに付け加えられます。 このログが役に立つのは、このフェーズに関連する失敗原因を失敗発生後に 調べる場合です。 global_log ファイルは、すべてのフェーズのログ・ファイルで構成され、そのファイル内のすべての出力は、最初に表示された順序で配置されます。
フェーズ#/状況
このフェーズが最後に実行された時点で正常に終了したか、失敗したかを示します。 このファイルは、後続のフェーズを実行できるかどうかを判別するために nim_move_up によって使用されます。 フェーズを実行できるのは、前のすべてのフェーズの status ファイルにストリング successが含まれている場合のみです。 最後に実行されたときにフェーズが失敗する原因となったエラーがフェーズで検出された場合、 status ファイルには failure ストリングが含まれます。
pid
nim_move_up がバックグラウンドで実行されている場合は、 nim_move_up プロセス ID 番号が入ります。 処理の終了時にこのファイルの終結処理が行われます。 このファイルが存在し、プロセス ID が含まれている限り、 nim_move_up はフェーズを実行できません。これは、 nim_move_up の並行実行がサポートされていないためです。
ログ・ファイルおよび client_data/ ディレクトリーの内容を除き、 mig2p5 フレームワークを構成する /var/mig2p5 内のファイルを読み取って変更することができます。これにより、 nim_move_up は、コマンド・ラインおよび SMIT インターフェースを介して実行しないタスクを実行できます。 ユーザーは、 nim_move_up が特定のニーズを満たし、マイグレーション・プロセス中に発生する可能性のある問題のトラブルシューティングを支援するために、 mig2p5 環境を操作することをお勧めします。
注: mig2p5 フレームワークのカスタマイズは高度な使用法と見なされ、正しく実行しないと満足できない結果が生じる可能性があります。 mig2p5 環境を直接変更するのは、実行される変更と、それらの変更が nim_move_up アプリケーションの動作に与える影響を理解しているユーザーのみにしてください。

人手による構成ファイルとは何か、およびこのファイルが必要な理由

このツールは、 nim_move_up コマンドの phase4 時に、バックレベルの AIX マシンに基づいてさまざまなリソース要件を計算し、ターゲット POWER サーバー上に LPAR を適切に作成します。 お客様が、以下の状態のいずれかである場合、人手による構成ファイルに、必要な変更を事前定義されたフォーマットを使用して指定し、nim_move_up コマンドを実行することができます。
  • nim_move_up コマンドで決定されたメモリーよりも多くのメモリーが必要である。
  • ボリューム・グループ用に使用したい仮想入出力サーバー上に作成された仮想 SCSI アダプター (vhost#) がある。
  • nim_move_up ツールで生成された仮想ローカル・エリア・ネットワーク (VLAN) ID とは異なる ID を使用したい。
nim_move_up コマンドが正常に完了すると、手動構成がターゲット LPARに適用されます。

人手による構成ファイルの作成方法

注: nim_move_up コマンドを開始する前に、手動構成ファイルを作成する必要があります。 マイグレーション対象のクライアントごとにこれらのファイルを作成し、 nim_move_up コマンドの -M フラグの引数としてこれらのファイルを指定することにより、このコマンドで人手による構成を使用することができます。 このファイル名の形式は、path/manual_cfginfo_ client_host_name にする必要があります。 ここで、path 値は、人手による構成ファイルがあるディレクトリーであり、 client_host_name 値は、マイグレーション対象のクライアント・マシンのホスト名です。

POWER プラットフォームにマイグレーションされるクライアントごとに、 nim_move_up コマンドは、デフォルトですべてのハードウェア構成関連の計算を行います。 このファイルを使用すると、お客様が選択するとおりにターゲット・マシンの構成の変更またはチューニングが行えます。

メモリー量、ボリューム・グループのサイズ、および使用対象の仮想入出力サーバー・リソースを変更できます。 例えば、ターゲット LPAR用に作成されたボリューム・グループに使用されるように VSCSI サーバー・アダプターを変更できます。 また、ターゲット LPAR用に作成されたイーサネット・アダプターに使用される VLAN ID を変更することもできます。

以下の例が、人手による構成ファイルです。
# manual_cfgfile_dennis file
# MEMORY = min_MB desired_MB max_MB
MEMORY = 256 512 1024
# VIO_VG_INFO = vgname_src, size_in_MB, vhost_to_use
#    Where vgname_src is the VG name in source machine, and
#    vhost_to_use is the virtual adapter to be used for
#    the VG specified in the VIO Server.
VIO_VG_INFO = rootvg,15344,vhost4
# VIO_VLAN_INFO = vlan_id, lpar_name, slot_number
VIO_VLAN_INFO = 1,VIO-server,2

このファイルにはブランク行が入ってもかまいません。 行の先頭に # を 1 つ指定して、このファイルにコメントを追加できます。

min_MB、desired_MB 、および max_MB の各値のすべてはメガバイト (MB) 単位にする必要があります。 これらの数値の間に入れるスペース数に関する制約はありません。
min_MB
AIX を実行するために必要な最小メモリー。
desired_MB
論理区画が活動化された時点でその区画に保有させたいメモリー量。
max_MB
動的論理区画操作がその区画上で行われる時の最大メモリー。

VIO_VG_INFO フィールドの各値はコンマで区切る必要があります。 vgname_src 値は、人手によるデータを指定する対象ソース・マシンのボリューム・グループです。 size_in_MB 値はターゲット・マシン上のボリューム・グループのサイズであり、 vhost_to_use 値はターゲット POWER サーバー上のこのボリューム・グループに使用される vhost * (仮想 SCSI サーバー・アダプター) です。

同様に、VIO_VLAN_INFO フィールドの各値はコンマで区切る必要があります。 vlan_id 値は、ターゲット LPAR のイーサネット・アダプターに対して、nim_move_up コマンドが使用する値の代わりに使用されます。 lpar_name 値は、共有イーサネット・アダプター (SEA) を装備した仮想入出力サーバーの LPAR 名であり、slot_number 値は、その仮想入出力サーバー上のこの SEA のスロット番号です。

これらの値は、必ずしもすべて指定する必要はありません。 nim_move_up コマンドは、指定された値を手書きファイルから受け取り、クライアント構成に基づいてその残りの値を生成します。
