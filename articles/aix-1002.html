目的

インターネット・ドメイン名システム（DNS）サーバーの運用管理。

構文

named9[ '-4] [ '-6] [ '-c config-file] [ '-d debug-level] [ '-D string] [ '-E engine-name] [ '-f] [ '-g] [ '-L logfile] [ '-M option] [ '-m flag] [ '-n #cpus] [ '-p port] [ '-s] [ '-S #max-socks] [ '-t directory] [ '-U #listeners] [-u user] [ '-v] [ '-V] [ '-X lock-file] [ '-x cache-file]

説明

named9デーモンはドメインネームシステム(DNS)サーバーで、Internet Systems Consortium(ISC)のBIND 9ディストリビューションの一部である。 DNSの詳細については、RFC 1033、RFC 1034、RFC 1035を参照のこと。 引数なしで起動されると、「named9デーモンはデフォルトの設定ファイル「/etc/named.conf」を読み込み、初期データを読み込み、クエリーを受け付ける。

-4 このオプションは、ホストマシンがInternet Protocol・バージョン6IPv6）に対応していても、Internet Protocolバージョン4IPv4）プロトコルのみを使用する。 -4」と「-6」は互いに排他的である。
-6 このオプションは、ホストマシンがIPv4を使用できる場合でも、IPv6のみを使用する。 -4」と「-6」は互いに排他的である。
-c config-file デフォルトの'/etc/named.conf、config-fileをコンフィギュレーション・ファイルとして使用する。 設定ファイル中の'directoryオプションが原因でサーバーの作業ディレクトリが変更された後でも、設定ファイルの再読み込みが機能し続けるようにする。 config-fileの値は絶対パス名でなければならない。
-d デバッグレベル named9デーモンのデバッグレベルをデバッグレベル値に設定する。 named9 デーモンからのデバッグ・トレースは、デバッグ・レベルが増すほど、詳細になります。
-D 文字列 プロセス一覧で「named9デーモンのインスタンスを識別するために使用される文字列を指定する。 string の内容は検査されません。
-E エンジン名

安全なキーストア方式による電子署名など、該当する場合はいつでも、暗号操作に使用するハードウェアを指定する。

BIND9が'OpenSSL,でビルドされている場合、暗号化アクセラレータまたは ハードウェア・サービス・モジュールを駆動する'OpenSSLエンジン識別子（'pkcs11など）と共に このフラグを指定する必要がある。 BINDがネイティブの公開鍵暗号化標準（PKCS）#11暗号（--enable-native-pkcs11）でビルドされている場合、デフォルトのフラグは、'--with-pkcs11使用して指定されたPKCS#11プロバイダ・ライブラリのパスに設定されます。
-f フォアグラウンドでサーバーを稼働します。
-g サーバーをフォアグラウンドで実行し、すべてのロギングを強制的に標準エラー stderr に行います。
-L ログファイル デフォルトのシステム・ログではなく、logfileファイルにロギング操作を設定する。
-M オプション デフォルトのメモリー・コンテキスト・オプションを設定します。 以下の値が有効な値である：
external
システム提供のメモリー割り振り関数の場合、内部メモリー・マネージャーはバイパスされます。
fill
メモリのブロックは、メモリ問題のデバッグを支援するために、メモリが割り当てられたり解放されたりするときにタグ値で満たされる。
Nofill
このオプションを無効にし、'named9デーモンが開発者オプション付きでコンパイルされない限り、デフォルト値を使用する。
-m フラグ メモリ使用量のデバッグフラグをオンにする。 可能なフラグは、 usage、 trace、 record、 size、および mctxです。 これらの値は、 <isc/mem.h>で説明されている ISC_MEM_DEBUGXXXX フラグに対応しています。
-n #cpus 複数 CPU を活用するため、#cpus ワーカー・スレッドを作成します。 無指定の場合、named9 デーモンは存在する CPU 数を判定し、 CPU ごとに 1 つのスレッドを作成します。 CPU 数が判定できない場合は、named9 デーモンは 1 つのワーカー・スレッドを作成します。
-p port ポートの問い合わせをリッスンする。 指定しないと、デフォルトはポート 53 です。
-s 終了時に標準出力 stdout にメモリー使用統計を書き込みます。
-S #マックス・ソックス named9デーモンが#max-socksソケットまで使えるようにする。 デフォルト値は、デフォルトの構成オプションで構築されたシステムでは 21000 であり、'configure --with-tuning=small で構築されたシステムでは 4096 である。
警告: このオプションは、デフォルト構成が原因でファイル記述子が使い尽くされ、操作環境が指定されたソケット数をサポートすることが分かっている場合にのみ設定してください。 このオプションを不必要に設定すると、指定された値が基礎となるシステム API の制限を超える可能性があるため、有害な結果が生じる可能性があります。 さらに、'named9は内部使用のためにいくつかのファイル記述子を予約しているので、最大数は通常、指定された値よりわずかに少ない。
-t ディレクトリ コマンドライン引数が処理された後、コンフィギュレーション・ファイルを読み込む前に、ルート・ディレクトリを指定されたディレクトリに変更する。
警告だ：このオプションは、'-uオプションと一緒に使用する。なぜなら、 rootとして実行されているプロセスのルート・ディレクトリを変更しても、たいていのシス テムではセキュリティは向上しないからである。
-U #リスナー 各アドレスで、デーモン named9 が受信する User Datagram Protocol （ UDP ）パケットをリッスンするために必要なワーカースレッドの数を指定します。 このオプションが指定されない場合、'named9デーモンは、検出されたCPU数に基づいてデフォルト値を計算する。 namedデーモンは、以下のルールを適用してワーカースレッドのデフォルト値を計算する：
  • CPUが1つしか検出されない場合、デフォルトのワーカースレッド数は1つです。
  • 複数のCPUが検出された場合、デフォルトの作業スレッド数は、検出されたCPU数から1を引いた数として計算される。
ワーカースレッドの数は、検出されたCPUの数より大きくすることはできません。
注意：'-nパラメータが検出されたCPU数よりも大きな値を設定した場合、ワーカースレッド数が'-nパラメータで指定されたCPU数まで増加する可能性がある。
-u ユーザー 特権ポートをリッスンするソケットの作成など、特権操作の完了時にプロセス・ユーザIDを指定されたユーザに設定する。
-v バージョン番号を報告して終了する。
-V バージョン番号とビルド・オプションを報告し、終了する。
-X ロックファイル 実行時に指定されたファイルをロックする。 このロックにより、重複する named9 インスタンスが同時に実行されないようにします。 このオプションを使用すると、 named.conf ファイルの lock-file オプションがオーバーライドされます。 noneに設定すると、ロック・ファイル検査は無効になります。
-x キャッシュファイル 指定された cache-file からデフォルト構成ファイルのキャッシュにデータをロードします。

シグナル

ルーチン操作で、このネーム・サーバーを制御するのにシグナルを使用できません。rndc コマンドを使用する必要があります。

説明
SIGHUP サーバーを強制的に再ロードします。

構成

namedデーモンのコンフィギュレーション・ファイル・フォーマットの詳細については、コンフィギュレーション・ファイル(named.conf)のトピックを参照のこと。

named9コマンドは、親プロセスの 'umaskオペレーション（ファイル作成モードマスク）を継承する。 ジャーナル・ファイルなど、 named9 コンフィギュレーション・ファイルによって作成されたファイルにカスタムパーミッションが必要な場合は、 named9 コマンドの起動に使用されるスクリプトで、 umask 操作を明示的に設定する必要があります。
