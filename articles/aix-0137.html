目的

指定したメール・ディレクトリーに自動的にバグ・レポートを格納します。

構文

bugfiler[-d ] [-m MessageMode] [-b BugUserName] [MailDirectory]

説明

bugfiler コマンドは、バグ・レポートを自動的に代行受信し、要約して、MailDirectory 変数で指定されたディレクトリー内の適切なフォルダーに格納します。

メール配布プログラムは、/etc/aliases ファイル内の行から bugfiler コマンドを呼び出します。 行の構文を以下に示します。

bugs:"|/usr/lib/bugfiler $HOME/bugstuff"

この例では、バグ・レポートは $HOME/bugstuff ディレクトリーに入ります。 ディレクトリーを指定しないと、bugfiler コマンドはデフォルトの $HOME/mail ディレクトリーにバグ・レポートを入れます。

“注: bugfiler コマンドでデフォルト・ディレクトリーとして使用するには、 $HOME/mail ディレクトリーを作成する必要があります。”

BugUserNameがbugsこの場合、/etc/aliasesファイルのエントリーには、次の例のように、-b BugUserNameフラグが含まれていなければならない：

hadley:"|/usr/lib/bugfiler -b hadley"

この例では以下のようにします。hadleyがBugUserNameとして宣言され、すべてのバグ報告は/home/hadley/mailデフォルトディレクトリに置かれます。 bugfiler コマンドによって使用されるすべてのディレクトリーは、以下の所有者でなければなりません。hadley.

bugfilerコマンドは標準入力からバグ報告を読み込み、各報告の書式をチェックし、受信を認めるメッセージ($HOME/MailDirectory/.ackファイル)を送るか、不適切な書式であることを示す($HOME/MailDirectory/.formatファイル)。

不適切にフォーマットされたバグ・レポートは、 errors ディレクトリーにファイルされます。このディレクトリーは、 bugfiler コマンドによって MailDirectory 変数のサブディレクトリーとして作成されます。 バグ・レポートは、/usr/lib/bugformat ファイルにあるフォーマットでなくてはなりません。 /usr/lib/bugformat ファイルの呼び出しには、 sendbug コマンドを使用します。 bugfiler コマンドは、有効なバグ・レポートを要約し、 で指定されたフォルダーにファイルします。Index:レポートの 行。 ソース・ディレクトリー名。Index:行はメール・ディレクトリー内のディレクトリー名の 1 つと一致していなければなりません。 bugfiler コマンドは、MailDirectory/summary ファイルに次の構文の行を追加します。

DirectoryName/MessageNumber IndexInformation SubjectInformation

“注: bugfiler コマンドは転送されたメールを認識しません。 送信側ではなくフォワーダーに通知します。Reply-To: 行がレポートのヘッダーに組み込まれます。”

バグ・レポートのフォーマット

バグ・レポートは ARPA RFC 822 フォーマットでなければなりません。 sendbug コマンドには、バグ・レポートを正しいフォーマットで構成し、送信するための情報が入っています。

正しく索引を付けるために、レポートには次のヘッダー行が必要です。

項目
説明
Date: bugfiler コマンドがレポートを受信した日付を示します。
From: 送信側の有効な戻りアドレスを指定します。
Subject: 問題の簡単な要約を示します。
Index: ソース・ディレクトリーとソース・ファイルのパス、バージョン番号、およびオプションで Fix キーワードを指定します。

バグ・レポートの本文には、次の行が必要です。

項目
説明
Description: 問題、提案、または苦情の詳細な説明が続きます。.
Repeat-By: 問題を再現するための手順を示します。
Fix: 新旧のソース・ファイルを比較する diff コマンド、 または問題を解決する方法を示します。 以下を含める:Fix:行が表示されるのは、 Fix キーワードがIndex:行。

バグ・レポートの再配布

バグ・レポートは、MailDirectory/.redist ファイル内の索引情報に従って再配布できます。 この場合、MailDirectory/.redist ファイル内に、タブが後ろについた索引名で始まる行があるかどうかが調べられます。 索引名とタブの後ろには、バグ・レポートのコピーを受信するメール・アドレスのリストがコンマで区切られて続きます。 リストが複数行になるときは、最後の行以外のすべての行に &#xa5; (円記号) を付けます。 次は、.redist ファイル内の索引情報の例です。

myindex   joe@hal,mary@mercutio,martha@banquo,sarah@mephisto,\
dee@hamlet,dewayne@ceasar

フラグ

項目
説明
-b BugUserName 新しいユーザー ID を指定します。 -b BugUserName フラグを指定しないと、bugfiler コマンドはデフォルトとしてログイン名を使用します。
-d デバッグ機能をオンにします。 -d フラグを指定すると、bugfiler コマンドはエラー・メッセージを標準出力に送信します。
-m MessageMode メッセージ保護を設定します。 -m MessageMode フラグは、bugfiler コマンドが作成したすべてのファイル対して、16 進フォーマットでファイル許可を指定します。

例

  1. bugfiler コマンドを 3 つのフラグすべてと共に使用し、 MailDirectory 変数を指定した場合の構文は、以下のとおりです。
    hadley:"|/usr/lib/bugfiler -d -m 755 -b hadley 
/home/hadley/bugdir"
    /etc/aliases ファイルに配置すると、この行はデバッグを開始し、ファイル許可を次のように設定します。rwxr-xr-x、宣言hadleyをBugUserNameとし、/home/hadley/bugdirディレクトリを指定します。
  2. バグ・レポートの例を以下に示します。
    Date: Mon, 27 Nov 89 11:26:15 -600
From: a@B
Subject: Read not setting errno correctly
Index: LFS/rdwr.c workstation 3.1
 
Description: Read not setting errno correctly
 
Repeat-By: Start an NFS daemon and it receives errors. Errno is
zero.
