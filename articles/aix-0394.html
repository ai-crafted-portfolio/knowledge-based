目的

子委任署名者 (CDS) および子ドメイン・ネーム・サーバー・キー (CDNSKEY) に基づいて、子ゾーンの委任署名者 (DS) レコードを変更します。

構文

dnssec-cds [-a alg ...] [-c class] [-D] {-d dsset-file} {-f child-file} [-i** [extension]] [-s** 開始時刻] [-T ttl] [-u] [-v level] [-V] {domain}

説明

dnssec-cdsコマンドは、子ゾーンで発行されている'CDSまたは'CDNSKEYレコードに基づ いて、デリゲーションポイントで'DSレコードを変更する。 子ゾーンに'CDSと'CDNSKEY両方のレコードが存在する場合、'CDSレコードが優先される。 これにより、子ゾーンは「dnssec-cdsコマンドを使用して定期的にポーリングすることで、 親ゾーンに鍵署名用鍵(KSK)の今後の変更を通知することができる。 親ゾーンはDSレコードを最新に保ち、KSKの自動ローリングを可能にする。

-f child-fileオプションは、子ファイルの「CDSレコードと「CDNSKEYレコー ド、およびリソースレコード署名（RRSIG）と「DNSKEYレコードを含むファイルを 指定するので、レコードは認証される。 -d pathオプションは、現在の「DSレコードを含むファイルの場所を指定する。 例えば、「dnssec-signzoneコマンドで生成された「dsset-ファイルであったり、「dnssec-dsfromkeyコマンドの出力であったり、以前の「dnssec-cdsコマンドの出力であったりする。

dnssec-cdsコマンドは、RFC7344で規定されている特別な'DNSSEC検証ロジックを使用する。 dnssec-cdsコマンドは、「CDS」と「CDNSKEYレコードが、既存の「DSレコードに表されているキーで署名されていることを要求する。 この要件は通常、既存のKSKである。

リプレイ・アタックから保護するために、子レコードの署名は、 dnssec-cds コマンドの前回の実行時より古いものであってはなりません。 シグニチャーの存続期間は、 dsset- ファイルの変更時刻から取得されるか、 -s オプションを使用して取得されます。

DSレコードを委任の破棄から保護するために、'dnssec-cdsコマンドは、 DNSKEYリソースレコードセット(RRset)が新しい'DSRRsetの全ての鍵アルゴリズムで 検証されることを保証する。 どの「DSダイジェスト・タイプも、同じ鍵セットをカバーしている。

デフォルトでは、 -i オプションを使うことで、 DS の置換レコードが標準出力に書き出され、入力ファイルは上書きされる。 変更の必要がない場合、置換される'DSレコードは既存のレコードと同じである。 CDSレコードと'CDNSKEYレコードが子ゾーンを安全でないものにする 必要があることを指定している場合、出力は空にすることができる。

注意： dnssec-cdsコマンドが失敗しても、'DSレコードを削除しないでください。 あるいは、'dnssec-cds -uコマンドを使って'nsupdateスクリプトを標準出力に書き出す。 -uと'-i両オプションは、'dsset-ファイルを保持し、'nsupdateスクリプトをトリガーするために使うことができる。

フラグ

-a アルゴリズム

CDNSKEYレコードを 'DSレコードに変換する際に使用するダイジェストアルゴリズムを指定する。 このオプションを再度使用すると、各「CDNSKEYレコードに対して複数の「DSレコードを作成することができる。 どのCDSレコードも許容できるダイジェストタイプを使用していない場合、「dnssec-cds代わりにCDNSKEYレコードを使用しようとする。 CDNSKEYレコードがない場合はエラーを報告する。

algorithmの値は'SHA-1、'SHA-256、'SHA-384いずれかである。 これらの値は大/小文字を区別せず、ハイフンは省略できます。 アルゴリズムが指定されていない場合、デフォルト値は「SHA-256である。

-c class

ゾーンの DNS クラスを指定します。

-D

子ゾーンに'CDSと'CDNSKEY両方のレコードが存在する場合、 'CDNSKEYレコードから'DSレコードを生成する。 デフォルトでは、「CDSレコードが優先される。

-d dsset-file

親'DSレコードの場所を指定する。 パスは「DSレコードを含むファイル名である。 ディレクトリであれば、「dnssec-cdsコマンドは、そのディレクトリにあるドメイン用の「dsset-ファイルを検索する。

リプレイ・アタックから DS レコードを保護するために、 dsset- ファイルの変更時刻より前に署名された子レコードは拒否されます。 -s オプションを使用して、タイミングを調整できます。

-f 子ファイル

子ファイルの'CDSレコードと'CDNSKEYレコード、および'DNSKEYレコードとそれをカバーするRRSIGレコードを含むファイルを指定し、それらを認証できるようにする。

-i拡張

DSレコードを標準出力に書き出す代わりに、'dsset-ファイルを更新する。

-i」と拡張子の間にはスペースを入れてはならない。 extension が指定されていない場合、古い dsset- は破棄されます。 拡張子が指定された場合、古い'dsset-ファイルのバックアップは、そのファイル名に付加された拡張子の値とともに保存される。

DSレコードをリプレイ攻撃から保護するために、'dsset-ファイルの修正時刻は、もしそれがファイルの現在の修正時刻より遅ければ、子レコードの署名開始時刻と一致するように設定される。

-s 開始時刻

RRSIG記録が受け入れ可能となる日時を指定する。 これは、絶対時刻または相対時刻のいずれかにすることができます。 絶対的な開始時間は「YYYYMMDDHHMMSS表記の数字で示される。 20170827133700は2017年8月27日の協定世界時（UTC）13:37:00を示す。 N dsset-ファイルからの相対時間は'-Nで示される。 現在時刻に対する相対時刻は、now+N で示されます。

start-time を指定しない場合は、 dsset- ファイルの変更時刻が使用されます。

-T トル

新しい'DSレコードに使わなければならないTTL(time-to-live)を指定する。 値が指定されない場合、デフォルト値は古い'DSレコードのTTLとなる。 古いDSレコードに明示的なTTLがない場合、新しいDSレコードにも明示的なTTLはない。

-u

新しい'DSレコードを表示する代わりに、'nsupdateスクリプトを標準出力に書き出す。 変更が不要な場合、出力は空になります。

注: 新しいレコードの TTL は、 -T フラグまたは nsupdate ttl コマンドを使用して、元の dsset- ファイルに指定する必要があります。
-V

バージョン情報を印刷します。

-v レベル

デバッグのレベルを設定します。 レベル1は、一般ユーザーに役立つことを目的としている。 より高いレベルは開発者向けである。

ドメイン (domain)

委任ポイントまたは子ゾーンの筆頭指定の名前を示します。

終了状況

dnssec-cdsコマンドは、成功すれば0を、エラーが発生すれば0以外のステータスを返して終了する。 成功すれば、'DSレコードを変更する必要はないかもしれない。

例

dnssec-signzone ・コマンドを実行する前に、 dsset- ・ファイルごとに dnssec-cds ・コマンドを使用して、デリゲーションが更新されていることを確認する。

dnssec-cdsコマンドで要求された子レコードを取得するには、次のスクリプトのように「digコマンドを起動する。 digコマンドが失敗しても、「dnssec-cdsコマンドは必要なチェックをすべて行う。

for f in dsset-*
do
    d=${f#dsset-}
    dig +dnssec +noall +answer $d DNSKEY $d CDNSKEY $d CDS |
    dnssec-cds -i -f /dev/stdin -d $f $d
done

dnssec-cdsコマンドと'nsupdateコマンドを併用し、指定されたコマンドが自動的に親ゾーンに 署名する場合にデリゲーションを維持するには、以下のコマンドを入力する：

dig +dnssec +noall +answer $d DNSKEY $d CDNSKEY $d CDS |
dnssec-cds -u -i -f /dev/stdin -d $f $d |
nsupdate -l

dsset-ファイルは、スクリプトが親の'DSレコードをフェッチして検証することを許さず、リプレイ攻撃防御時間を維持する。
