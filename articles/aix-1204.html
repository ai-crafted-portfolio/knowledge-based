目的

ローカル認証情報が正しいかどうかを検証します。

構文

pwdck { -p | -n | -t | -y } [-l]{ ALL | User ... }

説明

pwdck コマンドは、 ALL ユーザーまたは User パラメーターで指定されたユーザーの定義を検査することによって、ユーザー・データベース・ファイル内のパスワード情報が正しいかどうかを検証します。 複数のユーザーを指定する場合は、名前の間にスペースを追加します。

注: このコマンドは、そのメッセージを stderrに書き込みます。

システムが誤った属性を修正する必要があるかどうかを示すフラグを選択します。 /etc/passwd ファイル内ではローカル定義ユーザーについて次の属性が検査されます。

項目
説明
entry 各項目が読み取り可能で、少なくとも 2 つの: (コロン) を含んでいることを確認します。 システムがエラーを修正すべきであると指示した場合には、エントリー全体が廃棄されます。
passwd パスワード・フィールドが ! (感嘆符) であることを確認します。 システムは、エラーを修正する必要があることを示すと、パスワード・フィールド内の情報を /etc/security/passwd ファイルに転送し、 /etc/security/passwd ファイル内の lastupdate 属性を更新してから、 /etc/passwd ファイル内のパスワード・フィールドを an ! に置き換えます。一般的に、 /etc/security/user ファイル内で minalpha、 minother、または minlen のパスワード制限がゼロ以外の値に設定されている場合、パスワードが必要になります。
user ユーザー名が 8 バイト以下の固有のストリングであることを確認します。 a + (正符号)、 a : (コロン)、 a - (負符号)、または a ~ (波形記号) で始めることはできません。 ストリングに: (コロン) を含めることはできません。また、 ALL、 default、または * キーワードにすることもできません。 システムがエラーを修正すべきであると指示した場合には、このユーザーのエントリー行を /etc/passwd ファイルから取り除きます。 ユーザー名が + 記号または-記号で始まる場合、ユーザーはローカルに定義されず、検査は実行されません。

/etc/security/passwd ファイルで検査される属性は、以下のとおりです。

項目
説明
line 各行が読み取り可能で、スタンザの一部であることを保証します。 無効な行があれば破棄されます。
password password 属性が存在していることと、システム上でパスワードが必要な場合はブランクでないことを保証します。 システムがエラーを修正すべきであると指示した場合には、パスワードは * (アスタリスク) に設定され、lastupdate 属性が破棄されます。

一般に、 minalpha または minother のいずれかのパスワード制限が /etc/security/user ファイルでゼロ以外の値に設定されている場合は、パスワードが必要です。 ユーザーの flags 属性で NOCHECK キーワードが指定されている場合、このユーザーのパスワードは不要であり、検査は無視されます。
lastupdate 有効な非ブランク・パスワードの lastupdate 属性が存在すること、およびその時刻が現在時刻より前であることを確認します。 システムがエラーを修正すべきであると指示すると、password 属性に応じて lastupdate 属性が破棄または更新されます。 password 属性が存在しない場合、またはブランクまたは * (アスタリスク) に等しい場合、 lastupdate 属性は破棄されます。 そうでなければ、lastupdate の時刻が現在の時刻に設定されます。
flags 確実に、 flags 属性にキーワード ADMIN、 ADMCHG、および NOCHECKのみが含まれるようにします。 システムがエラーを修正すべきであると指示すると、未定義のフラグが削除されます。

/etc/security/user ファイルで検査される属性は、以下のとおりです。

項目
説明
auth1 ローカル・ユーザーに対して定義されている各 SYSTEM;username 項目が、 /etc/security/passwd ファイル内に username 項目を持つようにします。 システムがエラーを修正すべきであると指示すると、存在しないエントリーごとに /etc/security/passwd ファイルに以下のフォーマットでスタンザが追加されます。
username:
          password = *

ユーザー項目とデフォルト項目の両方が /etc/security/user ファイルから欠落している場合、システムは以下の値を想定し、 auth1 の検査を実行します。

auth1 = SYSTEM;user
注: auth1 属性は推奨されないため、使用しないでください。
auth2 ローカル・ユーザーに対して定義された各 authname;username エントリーが、 /etc/security/passwd ファイル内に username エントリーを持つようにします。 システムがエラーを修正すべきであると指示すると、存在しないエントリーごとに 1 つずつエントリーが追加されます。

ユーザー項目とデフォルト項目の両方が /etc/security/user ファイルから欠落している場合、システムは以下の値を想定し、 auth2 の検査を実行します。

auth2 = NONE

ALL を指定すると、 pwdck コマンドは、 /etc/security/passwd ファイル内の各スタンザが、 /etc/security/user ファイル内の SYSTEM;username エントリーとしてのローカル・ユーザーの認証名に対応するようにします。 システムがエラーを修正する必要があることを示すと、 /etc/security/user ファイル内のユーザー名エントリーに対応しないスタンザは、 /etc/security/passwd ファイルから破棄されます。

pwdck コマンドは、更新時に /etc/passwd ファイルと /etc/security/passwd ファイルをロックします。 この 2 つのファイルのどちらかが別のプロセスによってロックされると、pwdck コマンドはファイルがアンロックされるのを数分間待機して、この状態が発生しなければ終了します。

pwdck コマンドは、現行の pwdck プロセスの実行中に、 /etc/passwd ファイルと /etc/security/passwd ファイルが別のプロセスによって変更されているかどうかを確認します。 システムがエラーを修正する必要があることを示すと、 pwdck コマンドは /etc/passwd ファイルと /etc/security/passwd ファイルを更新し、他のプロセスによって行われた変更を上書きする可能性があります。

注: pwdck コマンドは、エラーを修正して報告するときに、ファイルに対するすべての拡張アクセス制御リスト (ACL) を使用不可にします。

また、 pwdck コマンドは、データベース管理セキュリティー・ファイル (/etc/passwd.nm.idx、 /etc/passwd.id.idx、 /etc/security/passwd.idx、および /etc/security/lastlog.idx) が、対応するシステム・セキュリティー・ファイルより新しいかどうかを検査します。 /etc/security/lastlog.idx が /etc/security/lastlogより新しいものであってはならないことに注意してください。 データベース管理セキュリティー・ファイルが最新の状態でない場合は、root ユーザーが mkpasswd コマンドを実行するよう指示する警告メッセージが表示されます。

一般に、sysck コマンドは、トラステッド・システムの検査の一部として pwdck コマンドをコールします。 また、このコマンドを入力できるのは、root ユーザーあるいはセキュリティー・グループのメンバーです。

注: auth2 属性は推奨されないため、使用しないでください。

フラグ

表 1. フラグ
項目
説明
-l 実行全体でファイルをロックします。
-n エラーを修正せずに報告します。
-p エラーを報告せずに修正します。
-t エラーを報告して、修正すべきかどうかを尋ねます。
-y エラーを修正して報告します。

例

  1. すべてのローカル・ユーザーが有効なパスワードを持っていることを確認するには、次のように入力します。
    pwdck  -y ALL
    ここでは、エラーが報告されて解決されます。
  2. ユーザー ariel が /etc/security/passwd ファイル内に有効なスタンザを持っていることを確認するには、次のように入力します。
    pwdck  -y ariel
